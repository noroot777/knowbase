# 同步中心 v2 布局提案（示意稿）

示意稿：`design/sync-center-v2-mock.html`，浏览器直接打开，不需要起 kb-web。
真实数据（本机 `/api/pipeline/runs` 的 9 轮留档、阶段 detail 原文、失败明细原文），
真实色板与字体（逐值抄自 `kb/static/css/base.css` 的 `:root`，示意稿是独立产物没法
import，同 `catgraph.css` 那几处的办法）。**尚未改动任何产品代码。**

## 现状的三处毛病（1440×900 实测）

| 区块 | 顶端 y | 高 |
|---|---|---|
| `.pipe-overview`（状态 + 失败明细 + 重试） | 84 | 213 |
| `.pipe-workbench`（步骤 \| 日志，日志框固定 440） | 317 | 710 |
| `.pipe-history-panel` | **1047** | 560 |

视口 900、文档高 1633。

1. **选择器在它控制的全部内容下面。** 点一行走 `viewPipeRun` → `renderPipeState`，
   整屏（状态、失败明细、进度、阶段、日志）按那一轮重渲染；被改写的那块起点 y=84，
   触发它的行在 y≥1047。`viewPipeRun` 末尾那句 `$('pipe-state-title').focus()` 是这件事
   的自供 —— 正常布局不需要把视线强行弹回一千像素外。退出入口 `#pipe-viewing` 又在页顶，
   一次「这轮不对，看上一轮」是两趟整页滚动。
2. **失败明细在一屏上出现两遍。** `pipe-issues-list` 的每个 `<li>` 念的就是
   `stages[k].detail`，而同一个字符串在阶段行的 `.pipe-stage-detail` 里已经写了一遍
   （seq-18 的 crawl detail 有 200 字）。同元规则「口径只有一份」。
3. **日志常驻 440px 深色块，和阶段并列。** 它是出事才看的东西，却占着整页的视觉重心。

## 改法

```
同步中心  9 轮留档 · 最近 10-16 11:13 · 已完成            [新建同步]
┌──────────────────────────────────────────────────────────┐
│ 当前状态 / 已完成 / 10-16 11:13 · 同步 · 大V观点    4 / 4 │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  用时 14 分钟      │
│ 1,364 抓到   860 入库   951 新向量                        │
│ [2 个步骤需处理] 明细在下面的步骤里   [重试失败项] 看第一个│
└──────────────────────────────────────────────────────────┘
┌───────────────────────────────┬──────────────────────────┐
│ 同步步骤（流水线）             │ 历史运行    保留最近 9 轮 │
│ ① 抓取内容              已完成 │ ◉ 10-16 11:13 最新  已完成│
│ ② 导出文章              需处理 │   同步 · 大V观点          │
│   ▸ 问题明细 · 22 项           │ ○ 10-16 00:11  2 个需处理 │
│ ③…⑥                            │   同步 · 公众号+大V+RSS   │
└───────────────────────────────┴──────────────────────────┘
▸ 运行日志 · 保留最近 80 条
```

- **轮次列与被它改写的内容并排**，`position: sticky` 钉住 —— 展开一条问题明细就能把
  步骤列拉长几百像素，选择器不能跟着滚出去。
- **列表自带「最新」那一档**：能证明「这一行就是此刻屏幕上那一轮」时标它、点它回到最新；
  运行中时那一档是正在跑的这一轮（它不在留档里，单独补）。挑一轮和回到最新在同一处。
  （示意稿里写的是「首行就是最新」，落地时改成了由后端证明 —— 见下面「差别」第 5 条。）
- **失败明细只留在步骤行里**，概况卡只报「几个」+ 给出口（重试 / 看第一个）。
- **翻历史改成整卡只读态**（边框转灰、顶上一行只读说明），不再靠页顶一条黄条。
- **日志默认收起，运行中自动展开**。
- **页头补上事实数字**（轮数 / 最近一轮时刻与结论），按「页头就一行」那条。
- **`<=1180px` 单列**：概况 → 轮次列 → 步骤 → 日志。sticky 关掉（单列下它会挡事）。
  （示意稿初稿写的是 1000px，产品 CSS 里本来就有一条 1180 的塌列断点 —— 见「差别」第 4 条。）

## 实测（chrome-headless-shell，CDP 直连，无头、临时 profile）

- **本次要钉的后果**：`scrollY=0` 点第二行（10-16 00:11，两个步骤需处理），被点的行
  （top 602 / bottom 671）和被改写的失败条（概况卡内）**同屏可见**，1440×900 与
  1280×800 两档都是 `bothInView: true`；对照现状是 1047 对 84。
- 钉住：滚到底（scrollY=761、两条明细全展开）轮次列仍在 top=14，选中行可见。
- 窄屏 420×860：概况@305 → 历史@599 → 步骤@934 → 日志@1626，选择器在步骤之前，
  点一行到概况的距离 294px（现状约 963px）。
- 切换路径六条全过：空闲初始 / 点第 4 行转只读 / 点首行回到最新 / 运行中初始（10 行）/
  运行中翻历史 / 点首行回到运行中。无页面异常。
- `/[↗↑↓→▾▴]/` 对 `body.innerText` 为空，箭头走的是抄自 `icons.js` 的内联 SVG。

## 落地时和示意稿的差别

1. **「抓到 / 入库 / 新向量」那三个数没做。** 它们只存在于各阶段的 detail 文本里,照文本
   正则解析不可靠;要做得后端先在 `stages[k]` 上补结构化计数字段。概况卡右侧保留的是原来
   那两个(完成步数、耗时)。
2. **保留口径从「最近 20 轮」改成「按天留」**(用户另提的):`_HISTORY_DAYS = 3` 是**唯一**
   会让一轮记录消失的判据,窗口之内一条都不删。另外两道 —— `_HISTORY_FLOOR`(下限,时钟往前
   跳和「一周只同步一次」那两档)和 `_HISTORY_BYTES`(体量预算,**只削重物:先日志正文、再把
   明细清单削到前 3 条,记录一条不删**)。天数由后端报给面板(`keep_days`),前端不写死。
   第 1 轮审查判红的就是这一处的初版:窗口裁完还 `kept[:400]`,401 轮落在 66 小时内也会掉
   一轮,而它距离到期还有五个多小时。
3. **`#pipe-viewing` 没有删掉,是搬进了概况卡**:它的元素 id 和那颗 `.ghost` 是浏览器探针
   点「回到最新」的入口,而「屏幕上要说清这不是最新状态」本来就是一条硬约束。
4. **窄屏断点是 1180px,不是示意稿里的 1000px。** 这一处示意稿错了:产品 CSS 里本来就有一条
   `@media (max-width: 1180px)` 在塌列,而且排在后面 —— 两条都命中时它赢,于是 1000~1180
   这一段**列已经塌成单列、选择器却还钉着、还排在它改写的内容后面**。合并成一个断点,
   探针按 1100 和 820 两个宽度各量一遍(只量 820 的话这一段一个字都测不到:定点注入时
   **全绿**)。

5. **「首行就是最新」这个假设落地时改掉了。** 清单和当前状态来自两条独立的请求、两份独立
   可失败的落盘,允许不同步:留档失败那一轮没写进历史文件,首行于是是上午那个红,而屏幕上
   是下午那一轮的成功 —— 点它会退出只读、换成下午那份结果,上午那个红再也打不开(第 1 轮
   审查实点出来的)。改成由后端给证明(`is_current`,过 `same_event` 只认可信身份),前端再
   和手上这份快照的版本对一次;证明不了就不标,那一行照旧打开它自己那一轮。
   **示意稿那份静态样例没跟着改**:它的两行是写死的样例数据,没有后端、也没有「两份状态
   不同步」这回事,改了只会让示意稿看起来多一个无从触发的分支。真实页面那一侧的回归在
   `tests/pipe_latest_probe.mjs`。

## 当时记下的两件事(第 1 条已按上面处理)

1. **「抓到 / 入库 / 新向量」三个数现在只存在于各阶段的 detail 文本里**（示意稿里用虚线
