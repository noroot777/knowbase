# 问题与待办：可处理的收录诊断原型

入口：同目录的 `intake-diagnostics-demo.html`，直接用浏览器打开即可，不需要安装依赖或启动后端。HTML、CSS、数据和交互分别保存，四个文件放在一起即可运行。

## 设计选择

面向维护个人知识库的人，页面只做一件事：找到没有顺利完成收录的内容，看到可靠原因，作出可追溯的处理决定。建议作为「我的订阅」「同步中心」旁的常驻入口，而不是把所有问题都塞进某一轮同步日志。

- 延续现有冷瓷白 `#F3F5F4`、墨蓝黑 `#14202B`、松绿 `#17604F`，辅以问题红 `#B3402F`、待确认琥珀 `#8A5A22`、分隔灰 `#DCE3E0`。
- 宋体只用于页面与内容标题，黑体用于操作与说明，等宽体用于编号、次数和时间，全部采用系统字体，不下载字体或图标。
- 不做四张大数字卡片。左边是需要作决定的条目，右边是解释和处理入口；视觉重心是「发现 → 正文 → 翻译 → 入库」上真正的断点。
- 移动端上下排列，顶部仍能切换状态、筛选与批量处理；支持键盘焦点、方向键切换页签、`/` 搜索、Esc 关闭弹窗和减少动画偏好。

```text
应用导航 │ 标题、处理记录、执行待办
         │ 演示说明 / 当前是否真的执行
         │ 需处理 | 待执行 | 执行中 | 已完成 | 已搁置
         │ 搜索、来源、环节    │ 内容标题与原文
         │ 勾选与批量处理      │ 收录断点
         │ 问题列表            │ 原因、建议、处理按钮
         │                     │ 尝试记录
```

## 状态契约

| 分组 | 意义 | 出口 |
| --- | --- | --- |
| 需处理 | 自动重试停止、人工挂起、来源受限或翻译失败 | 重新排队、补正文、换链接、暂缓、不再收录 |
| 待执行 | 只表示待办已登记，不表示在运行 | 明确范围后执行，或暂缓、不再收录 |
| 执行中 | 仅显示已经实际启动的本页模拟工作 | 结果成功后完成，失败则回到需处理 |
| 已完成 | 必要处理环节确实完成；本原型为模拟结果 | 查看记录 |
| 已搁置 | 暂缓与不再收录分别显示，绝不计为解决 | 手动恢复到原来的状态 |

真实状态应该按来源权威字段归一化，而不是从展示文案猜测。排队和执行必须有不同证据；正式版应显示执行批次、工作项与真实计划时间。首次取不到全文、需人工确认、确定失败预算耗尽也应保留区别，不能统称“抓取中”。

来源连接问题按「访问来源 → 读取时间线 → 检查覆盖 → 结束检查」显示，不套文章入库进度。来源复查恢复不代表发现了新文章，更不能计为新文章入库成功。

## 操作契约

- **重新排队**只开放新的处理机会，保留尝试记录，不宣称成功，也不直接开始网络请求。
- **执行待办**的确认框明确列出范围。顶部按钮执行全部待执行样例；单条按钮只执行所选的一条。确认范围不随页面过滤条件偷偷扩大或缩小。
- **执行已选**在待执行页勾选后出现，只运行所勾选的条目，与顶部执行全部待办区分。
- 对无法识别正文、需要人工确认的条目，优先展示「手动补正文」；网络连接失败则优先展示「重新排队」，处理建议与主按钮保持一致。
- **手动补正文**接受至少 40 个字符的纯文本。保存后进入待执行，后续从入库处理继续，不重复补抓；不把“正文已补入”算成“已入库”。正式版仍需接入实际正文准入规则，长度只是原型的空输入保护。
- **换链接**只接受 HTTP / HTTPS 网页地址，不把脚本或 PDF 地址直接当网页正文处理；保存后排队，保留历史。
- **暂缓**不定时自行恢复，保留原因与记录，用户手动恢复。
- **不再收录**只影响本条，确认范围，不关闭整个订阅，不删除已有文档。原型里允许撤销及从已搁置恢复；正式版的排除身份与恢复能力需另行实现，不能直接复用永久移除接口冒充可撤销操作。
- 来源连接问题不是一篇文章，不提供「不再收录」。批量勾选包含来源问题时也禁用此操作，避免误把单篇排除扩大成停用来源。
- **批量处理**只作用于当前可见并明确勾选的记录；切换状态或筛选会清空勾选。完成的内容不提供批量重试。
- 修改状态后的即时撤销恢复操作前快照，记录撤销本身；后续操作或执行开始后旧撤销失效。执行期间禁止修改工作项。

## 数据与边界

本页是独立交互原型，不是已接入的生产模块。不修改现有应用，不调用 API，不连接生产库，不请求真实原文，也不持久化到浏览器存储。刷新或重置即可恢复初始数据。

12 条样例的初始分布是需处理 7、待执行 4、已完成 1。题材参考本次排查，同时额外构造来源连接、人工挂起、公众号正文、简报翻译等案例。这些案例不代表生产库中存在对应问题；原型计数不能用于推导真实生产积压。

生产库 2026-10-26 10:27 的排查快照为 RSS 待补 212、RSS 重试耗尽 226、网页专栏重试耗尽 1；这是历史参考，不是页面实时计数。

模拟执行的确认框可以切换成功与失败分支，方便评审完整状态变化。成功仅意味着本页模拟完成，不意味着真实正文抓取、翻译、索引已经发生。

### 浏览器通道

先查询现有 Chrome 扩展通道，并尝试以具名会话 `🧭 收录诊断原型`、`visible: false` 创建后台标签。入口返回 `Capability is not available: visibility`，无法保证后台可见性约束，因此没有去掉限制强行开页，也没有接管、导航或激活用户已有标签。

按规范降级至独立无头 Chrome。Playwright CLI 启动参数含 `--headless`，使用临时 profile，没有连接用户 Chrome 的调试端口。CLI 禁止 `file:` 导航，因此点检时临时用仅监听 `127.0.0.1:8912` 的 Python 静态文件服务加载设计目录；这不是生产服务，也没有加载真实数据。本页不需要登录态。

### 实际交互结果

- 初始计数为需处理 7、待执行 4、执行中 0、已完成 1；合计 12 条样例。
- 空正文被拒绝；补入完整纯文本后变为需处理 6、待执行 5、已完成仍为 1。进度中仅发现与正文两步完成，未提前宣称翻译或入库完成。
- 勾选两条待办，确认框只列两条；开始后执行中为 1，其他条目仍排队。模拟失败结束后，需处理 8、待执行 3、已完成仍为 1。
- 单独执行补过正文的 Safeguards，确认范围只有这一条；成功分支结束后已完成变为 2，对应必要处理四步完成。
- 单条不再收录进入已搁置，已完成数不变；恢复回到原先状态。暂缓同样保留记录，并可恢复。
- 按 RSS 筛选并全选后，批量确认框只列三条；重排后需处理由 7 到 4、待执行由 4 到 7；撤销后恢复原计数，操作与撤销记录均保留。
- 更换链接时拒绝 `javascript:` 与 PDF 地址；合法 HTTPS 网页保存后仅排队，不发起网络请求，并可撤销。
- 来源连接样例显示独立的来源检查进度；不提供单篇不再收录，批量选择时也禁用该操作。来源模拟恢复后明确说明不代表新文章入库。
