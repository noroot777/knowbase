## 改之前是什么样

**同一个系统里有三套配色,点一下就换一种审美:**

| 界面 | 底色 | 重点色 |
| --- | --- | --- |
| 应用主体(`kb/static/css/`) | 雾灰 `#F1F3F7` | 靛蓝 `#3F43B9` |
| 阅读页(`kb/web/pages.py`) | 瓷白 `#F2F4F3` | 深松绿 `#17604F` |
| 三张图谱(`scripts/wiki/`) | 奶油白 `#f7f6f2` | 纯黑 + 高饱和彩虹 |

在搜索结果里点一条标题去读原文 = 从靛蓝跳到松绿;点侧栏「项目图谱」= 跳到奶油白。
单独看每一张都还行,连起来用就是三个产品。

**另外五处具体问题:**

1. **重点色换成了靛蓝。** `#3F43B9` 是 AI 产品的默认重点色(Tailwind indigo 一带),
   而「开源项目」占了图鉴 5530 个条目里的 2976 个 —— 类型色和重点色撞上之后,
   卡片上那枚类型标记在绝大多数卡片上什么也没区分。项目原本的 `深松绿` 还留在
   阅读页里没迁走,CLAUDE.md 里也仍然写着「瓷白×墨蓝黑调子」。
2. **字形签名被删了。** `--font-display` 从宋体 900 换成了 `"Avenir Next"`,
   但 `.td-hero .name` 和 `.chat-empty-title` 里的 `font-weight: 900` 原样留着 ——
   Avenir Next 没有 900 字重,这两处声明变成了死代码,整套界面再没有一个自己的字形。
3. **正字计数被读成错字。** 只画实笔的话,3 次提及那半个正字就是一个「下」;
   旁边还紧跟着「3 次提及」四个字,同一个数字说了两遍,其中一遍看着像渲染坏了。
4. **每个面板顶着一层落地页文案。** 英文 eyebrow(`FIND WHAT YOU REMEMBER`
   / `SAVED FOR A REASON`)+ 大标题 + 一句副标题,约 150px 首屏,每天打开都在
   重新介绍「搜索是用来搜索的」。问答空态更是照抄 ChatGPT 的居中大图标 + 标语。
5. **token 纪律没了。** 8 个 CSS 文件里 **61 个各写各的色值**:`#3A464F`
   `#4A565F` `#414C60` 三个几乎一样的灰、`#c33` `#b33` `#aa3325` 三个红、
   `#f8f9fc` `#f5f6fa` `#eef0f6` `#edeff5` 四个几乎一样的浅底。整体发灰发浑就是这么来的。
   还有没迁完的半路痕迹:`.td-links a:hover` 是绿色 `#CFE8DC` 压在靛蓝底上,
   `.badge.vec` 是绿字配靛蓝底。

## 改完是什么样

### 一套色板,三处抄同一份值

`kb/static/css/base.css` 的 `:root` 是唯一的源头。阅读页和图谱是独立产物
(iframe / 单文件 HTML,都拿不到这份 token),只能逐个抄,三处都写了互指的注释。

```
瓷白 --paper #F3F5F4    墨蓝黑 --ink #14202B    深松绿 --brand #17604F
```

灰阶收敛成三档(`--ink` / `--ink-2` / `--muted`)、线两档(`--line` / `--line-soft`)、
红绿褐各一个(`--danger` / `--ok` / `--warn`)。**61 个写死色值降到 0 个游离值**,
剩下的都在 `:root` 里或是注释。

类型五色谱重新拉开,主力类目认领品牌色:

| 开源项目 | 产品 | 模型 | 研究 | 公司 | 其他 |
| --- | --- | --- | --- | --- | --- |
| 松绿 `#17604F` | 靛蓝 `#3D5A80` | 紫 `#7D4E9E` | 深青 `#2F6D7A` | 褐 `#8C6A3F` | 灰 `#66727C` |

图谱的 13 个大类色同步压暗到和松绿同一档:原来是高饱和纯色,在瓷白底上比正文还抢眼,
一屏十三个圆点先跳出来,要看的项目名反而退到后面。色相没动,仍然一类一色。

### 字体三件套各归其位

- **宋体 900**(`Songti SC` / `STSong`)—— 页面大标题、详情抽屉工具名、
  图谱标题、阅读页标题。零下载的系统字体,是这套界面唯一的字形签名。
- **等宽体** —— 工具名、日期、计数、norm。工具名是标识符不是散文,等宽还能让
  一栏里的名字对齐(列表视图尤其明显)。
- **黑体** —— 正文。

### 正字计数改成「填格子」

没画到的那几笔留一道浅色底(`.ghost`),实笔盖在上面。同一个字形从「半个错字」
变成「5 格里填了 3 格」,而且每个正字宽度一致、能对齐。回归里钉住了
「实笔 + 虚笔恒为 5、实笔数等于 n」。

### 砍掉落地页那层壳

- 三处英文 eyebrow、四处副标题、`title-dot` 装饰点、图鉴右上角的「向知识库提问」
  推广按钮(问答本来就在侧栏一格之外)、问答空态的大图标 + 标语 —— 全部删掉。
- 页头压成一行:标题 + 同一行上的事实数字(`5,530 个工具 · 10,393 条收录记录`)。
  标题从 24px 降到 19px。
- 筛选区不再套一层白卡:搜索框是盒、类型段是盒、卡片是盒,外面再包一个白盒
  就是盒中盒中盒。改成上下两条细线分隔。
- 搜索结果里,**标题已经包含摘要时不再把摘要重复渲染一遍**(`dupSummary`)。
  条目化衍生条目的标题本身就是「名字:摘要」,原来一屏三条结果里三条都在复读自己。

### 密度

卡片内边距 18 → 15px、圆角 13 → 10px、摘要行高收紧、去掉 hover 位移。
1440×1000 视口下首屏卡片从 **9 张增到 12 张**;搜索结果从 3 条增到 4 条。

### 侧栏回到 80px

上一版为了给内容区多挤 16px,一路从 176 → 88 → 72px,结果 11 个入口的标签
只剩 59px 可用,得靠「字号留够余量并禁止折行」硬顶着。内容区宽度差这点根本
看不出来,标签挤不挤一眼就看得出来 —— 这笔交易反过来做。

### 原生控件

下拉框自绘箭头(`appearance: none` + 内联 SVG),勾选框 `accent-color` 走品牌色。
原来整页只有这几个控件是 macOS 系统蓝。

**注意**:各处覆盖下拉框样式时只许改 `background-color`,用 `background` 简写
会连箭头(`background-image`)一起清掉,下拉框就退化成一段看不出可点的纯文字。
`#ask-model`、`.gallery-view-controls select`、`.select-field select` 都踩过这个,
回归里专门钉了一条。

## 补一轮:箭头和齿轮(同日)

用户指着侧栏截图说「所有的箭头都换一下,太丑了」「那个齿轮是缺了一块吗」。

### 箭头原来是 23 处字符,现在是 1 份几何

页面里散着 `↗ ↑ ↓ → ▾ ▴` 六种字符、共 23 处(外加图鉴外链那一处**另写**的内联
SVG,同一个意思的第七种写法)。这些字在 PingFang SC 里本身就细长歪斜,缺字时还会
回退到系统 emoji 字体 —— 同一屏里「项目图谱 ↗」的钩子细得几乎看不见,
「查看同步进度 →」又长又平,跟这套 1.4px 描边的图标完全不是一家。

改成 `icons.js` 的 `ARROW_PATHS` 一份几何:viewBox 12、stroke 1.4、圆头圆角,
尺寸 `1em` 跟着所在文字缩放,颜色 `currentColor`。六个方向(`ext` / `right` /
`up` / `down` / `caretDown` / `caretUp`)覆盖全部 23 处。下拉框那个自绘箭头
用的也是里面的 `caretDown` —— 原来它是另写的一条 `viewBox 0 0 9 6` 路径,
跟旁边的 `▾` 长得不一样。

静态标记写 `<i data-arrow="ext">`(`renderIcons()` 一并替换),JS 里拼 `arrow('ext')`。
阅读页、分类图谱、话题图谱是三处独立产物(拿不到这个模块),各抄一份同样的几何,
三处都写了互指注释 —— 和配色 token 是同一个规矩。

### 齿轮:手画折线换成算出来的 8 齿

原来那条 `settings` 路径是手画的 21 段折线,齿不等分、首尾对不上,右下角明显塌一块。
齿轮是旋转对称形状,少一齿或齿距不匀一眼就看得出来,所以新路径按极坐标算:
8 齿等分,齿顶 R=9.3、齿根 r=7,齿顶半角 10°、齿根半角 16°(齿根略宽的梯形齿),
中间一个 r=3 的轴心圆。顺手把 `chevron` 从 7×14 收到 5.5×11 —— 原来那个在
20px 的格子里几乎顶满,比旁边的图标都大一圈。

### 回归

`tests/redesign_probe.mjs` 从 36 项加到 43 项(后来复审那轮又补到 48),新增七条:

- 页面上不许再出现箭头字符(遍历可见文本节点);
- 行内箭头都渲染成了 SVG、没有未替换的 `data-icon` / `data-arrow`;
- **齿轮 `r(θ)` 以 45° 为周期**(沿路径采 4000 点,按 1° 分箱取最大半径,
  逐箱和 +45° 的那箱比,偏差 < 0.25)—— 少一齿、齿距不匀、某一段塌进去,
  这条当场就不成立,正是「缺了一块」的判据;
- 齿轮 360 个角度都有轮廓、齿顶明显高于齿根、有轴心圆且路径闭合。

Python 套件 311 通过 1 跳过(跳过的那条要外部 Reader 运行时,与本轮无关);
其中 `tests/test_catgraph_browser.py` 会真建一张分类图谱页并在无头浏览器里打开

`node --check`,阅读页模板单独 format 过一遍(那份模板是 `.format()` 写的,

## 图谱页要重新生成才会变样

三张图谱是把 CSS **内联**进单文件 HTML 的产物,改 `catgraph.css` 只影响之后构建的页面,
Vault 里现有的 `graph*.html` 仍是旧样式。**`./kb.sh restart` 不管用** —— 它只重启进程,
kb-web 对 `/graph*` 就是把文件原样发出去。下一次 wiki 构建会自动带上;想立刻更新:

```bash
./kb.sh graph        # = build_graph_html + build_catgraph --no-llm,零模型调用,约 6 秒
```

### 为什么没把它塞进 `restart`

用户问过「适合放到重启命令里吗」。不适合:

- `restart` 现在是**纯进程操作**,失败了顶多服务没起来,磁盘上一个字节不动。塞进去
  之后,每次重启都在**原子替换 Vault 里三张正式页面** —— `build_catgraph` 里那一整套
  两阶段提交 / 发布 CAS / 质量验收,存在的理由就是这个动作有风险。重启一天十次就是
  对正式产物发布十次。
- `set -euo pipefail` 下,构建失败会让 restart 断在构建那一步。构建放在 `web_start`
  之后能避开,但语义还是错的:「重启服务」不该顺带改产物。
- `--force` 停服务时管道拦不住,restart 会跟正在跑的 wiki 阶段抢发布锁 —— CAS 保证
  不出坏产物,但会让管道那一轮的图谱发布被顶掉、要等下一次同步。

所以做成两件事:独立命令 `./kb.sh graph`,加上 `web_start` 之后的一行**陈旧提示**
(`graph_stale`:比 `catgraph.css/js`、`catgraph_page.py`、`build_catgraph.py`、
`graph_data.py`、`taxo_tables.py`、`build_graph_html.py` 的 mtime 和三张页面的 mtime,
旧了就说一句)。提示而不代劳 —— 每次重启都会告诉你该重建了,动不动 Vault 是你说了算。

### `./kb.sh graph` 用仓库内 `data/` 时只许在主检出跑

`cmd_graph` 解析完数据目录后,只要它就是仓库内的 `data/`,就用
`git rev-parse --git-common-dir` 把 worktree 挡掉。
本轮实测过照跑的后果:worktree 的 `data/` 是跑测试留下的 135 KB 空壳库,
`build_graph_html.py` 拿它建出一张 **0 节点的 `graph.html`,原子替换掉 Vault 里那张好的**
—— 它自己不做质量验收,`build_catgraph` 那套闸门只管它自己那两张。
(那次是我在验证新命令时踩的,随后从主检出重建修回:280 节点 1805 边。)

`KB_DATA_DIR` 指到仓库外时这条前提不成立 —— 数据是显式挂的,跟在哪个检出里跑无关,
那时只靠归类缓存那道检查把空目录挡住。见下面复审第 1 轮。

## 复审第 1 轮修的两条

### 1. `cmd_graph` 的前置检查没认 `KB_DATA_DIR`

`kb/config.py:20` 和 `scripts/wiki/taxonomy.py:32` 都从 `KB_DATA_DIR` 解析数据目录,
两个构建器因此本来就认它;可 `cmd_graph` 的归类缓存检查写死了 `$ROOT/data/`。
于是把数据放在仓库外的用户,数据明明是全的,却在**进构建器之前**就被一句
「缺 data/taxonomy_projects.json」拦下,三张图谱一张也重建不了。

改成先按同一个口径解析真实数据目录(`KB_DATA_DIR` 优先,没设才回退仓库 `data/`;
相对路径按构建器的 cwd `$ROOT` 解),再用这个路径检查缓存。worktree 那道闸门跟着
收窄到「数据目录就是仓库内 `data/`」这一种情形。

隔离验证(临时数据目录 + 临时 Vault,真 Vault 三张页面的 mtime 一个没动):

- worktree + 默认 `data/` → 照旧被 worktree 闸门拦下;
- worktree + `KB_DATA_DIR=<临时目录>`(放了两份归类缓存)→ 越过前置检查,进构建器;
- `KB_DATA_DIR=<空目录>` → 报缺文件,且报的是那个外置路径。

### 2. 图鉴列表视图的摘要选择器失效

上一轮删 `.list-view .gcard-arrow` 那条死规则时,把相邻两行并成了
`.list-view .list-view .gsum` —— 选择器匹配不到任何元素。页面不报错、不溢出,
只是切到列表视图后每行仍顶着卡片视图的两行摘要和 46px 占位:实测中位行高
**116.4px**,改回 `.list-view .gsum` 之后 **83.3px**(差的正是一行 23px + 那 10px 下边距)。

探针补了 4d 之后的一节(4e),把四件事各钉一道:算出来的 `-webkit-line-clamp` 必须是 1、
`min-height` 和 `margin-bottom` 必须归零、最长的那条摘要不许超过一行行高、中位行高
不到 96px(行高取中位数:带「全部出自软广?」角标的那几条会多占一行,那是内容不是回归)。
把 bug 注回去,这四条一起红。


## 浏览器通道
