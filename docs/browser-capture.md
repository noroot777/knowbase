# 从已打开的文章补正文

这一轮实现的是真实功能：订阅文章入口、Chrome 扩展、本机接收接口和原条目回填已经接通。诊断工作台本身仍是 `design/intake-diagnostics-demo.html` 演示页，不要拿演示编号替代真实 `feed_items.key`。

## 一问一答

**扩展只问一件事：你站着的这一页，此刻能做什么。** 它把地址交给本机服务，服务回答它是哪一条、写不写得了，弹窗照着给按钮。判据一处都不在扩展里。

原先这里是两块：一块问「这一页在不在库里」，另一块是「补回哪个待办」的下拉框，要你把服务端已经知道的事再回答一遍——地址栏里那一行就是答案。补一篇正文因此要跨三个界面走七步（知识库面板 → 补抓页复制密钥 → 核对最终网址 → 发起待办 → 回文章标签 → 在下拉框里挑出刚才那个 → 读取）。现在**待办退到幕后**：正文还缺着的那一档由服务端自己建好，有效期、复用、顶替那一套一个字没改，只是不再要你经手。

知识库这一侧也不再跳页：从「我的订阅」或「问题与待办」点「从浏览器采集」，开的是**左侧滑出的抽屉**，底下那一页原样留着。

服务端会答出这几种情形：

| 它说 | 你点 |
|---|---|
| 知识库里有这一条，但正文还缺着 | 「采集」；识别不准改点「改用所选文字」 |
| 这一页还不在知识库里 | 「采集」——只交地址，服务端自己去抓（走完整准入、能取到标题作者日期）。抓不到时才露出「改用这一页的正文」和「改用所选文字」 |
| 还在等采集的条目 | 核对是同一篇后点那一行的「这一页就是这一篇，改用它」。**有几条就摆几条**——两条待办同时指着别处时，你站着的这一页可能是第二条。**点下去那一下就是答案**，后面每一问都带着它走，不会再被按时间顺序换成另一篇 |
| 有 N 个条目都在等这一页的正文，点一下你要补的那一篇 | 同一页上不止一个条目在等、而你还没点过——这一档**一颗采集按钮都不给**。按时间顺序替你挑一个是在赌，赌错那一下是正文被另一篇覆盖、救不回来 |
| 你选的那个采集请求已经失效了 | 它过期了、被另一端取消了，或者那个条目变了——同样**一颗按钮都不给**。下面还在等的条目里点一下要补的那一篇；一个都没有就回采集抽屉重新发起。这一档不看「这一页还剩几个请求」：一个不剩时按地址另找一篇，正是把这一页的正文写给另一篇的那条路 |
| 这一次采集已经写进这一条了 | 做完了，没有可做的事。**这一档一直认着你刚选的那一篇**——要换另一篇得自己在下面的候选里再点一下。放掉这个身份的话，下一问只能按地址和「还剩哪几个请求」重判，同一颗「采集」就被另一篇接管了，再按一下正文落在它身上 |
| 已经在知识库里，正文也齐了 | 没有可做的事。要换掉现有正文回采集抽屉点「重新采集正文」 |
| 你在抽屉里发起过采集（改址、或重新采集正文） | 「采集」——指着这一页的那个请求排在库里那一行前面，所以改址和重采在扩展里都接得上 |

**点下去就写进知识库了，没有预览、也没有「我已核对」那道勾。** 你就站在那一页上，比屏幕清楚自己要的是哪一篇；撤掉的只是事前那一问，长度、网址、条目版本那几道准入全在服务端原样判，写完把标题和字数摆给你看。代价是登录墙或摘要页只要够长也会被写进去——不对就到知识库里那一条上点「重新采集正文」。收录新链接单条上限 6 万字符，**超了直接拒、不偷偷截断**（硬约束见 `docs/decisions/link-grab.md`）。

## 安装与使用

1. 更新代码并重启本机 Knowbase Web 服务，在「我的订阅」的文章卡片上或「问题与待办」里点「从浏览器采集」，左侧滑出采集抽屉。使用 `http://127.0.0.1:端口` 或 `http://localhost:端口`；此功能不向局域网开放。
2. **这个浏览器**还没配过扩展时，抽屉顶上就摊着「首次使用：装扩展并配对」；配好之后它自己收进底部折叠块（判据是扩展在知识库页面上留的那个标记，不是「全库采成过没有」）。在 Chrome 扩展管理页开启开发者模式，选择「加载已解压的扩展程序」，选中它给出的那个目录——**那就是本仓库里的 `kb/static/browser-extension/knowbase-capture`，不用下载解压**。以后改了扩展代码，在扩展管理页点一次「重新加载」即可；弹窗头部的版本号就是用来确认这一下点过没有的。浏览器不在这台机器上时才需要下载 ZIP。安装由用户完成，程序不会自动安装。
3. 在抽屉里显示并复制配对密钥，填入扩展的「连接本机知识库」，服务地址以抽屉显示的地址为准。默认端口 8787，地址和密钥保存在扩展本地存储，只需配对一次。
4. 在你已打开并加载好的文章标签上点击 Knowbase 扩展，或使用 `Command+Shift+Y` / `Ctrl+Shift+Y`，按它给出的那句话走（上面那张表）。此时只读页面。
5. 自动识别不准时，先在原页选好完整正文，再点「改用所选文字」那一颗，不用复制粘贴。
6. 结果就显示在弹窗里，不必回知识库看。正文已回填不等于翻译、导出或索引完成，可以等待下一轮同步，或到采集抽屉单独点击「继续导出与索引」。

抽屉里那颗「发起浏览器采集」**不是必经的第一步**，它留给一种情况：要让某一条去认一个和它自己网址不同的最终网址。勾上旁边的「同时在新标签打开这一篇」，发起的同时就把那一页开出来。待采集请求有效期 15 分钟，已保存回执不受此期限限制；同一篇、同一版本及最终网址的请求会复用，不另开重复待办。

重新采集不会撤销已保存的正文或回执，只有再采一次并通过服务端核验后才会替换。改主意时点「退出重新采集」即可回到原回执。抽屉按文章从服务端恢复最近一条有效回执及当前待办，不依赖标签的会话存储：关掉抽屉、另开标签、超过 15 分钟或服务重启后仍能找回已保存回执。未完成的请求在取消、过期或服务重启后可以重新发起。

条目被清理后又从同一链接重新收录时，旧回执不再属于这一世，页面按「没有回执」显示，不会留下「正文已被修改」那句红字。本篇的等待请求列出发起时间、到期时间及指定网址，即使由其他标签发起也能在这里取消；抽屉开着时每 2 秒刷新状态，关掉就停。正文被其他操作更新后，旧回执统一失效，成功区域隐藏且不能继续；条目删除或排除时同样拒绝旧回执。保存回执在内存中或从审计恢复时使用同一套有效性校验。

### 「继续导出与索引」不是单篇执行

这颗按钮跑导出与索引两段，复用既有管道，页面和确认框都写着范围：

- 本篇已有 `fulltext_at`，后续导出复用本次补入的正文，不因这一步重新抓取本篇网页。
- 同一类来源其他待办会一起导出，过程中可能联网补抓别的文章并调用翻译模型；索引阶段检查全库。
- **条目化提取不在这一步**：它的队列按全库取数，不该由一篇文章上的按钮买下。本篇已标记待重提取，
  下一轮同步会重新提取它，也可以到同步中心起跑弹窗里自己勾。
- 保存正文不会自动启动管道，真实结果以同步中心为准。忙碌时正文保留，允许稍后重试。
- 同步被禁用的来源不会因为保存正文自动启用，仍须按既有来源配置处理。

## 权限和边界

- 扩展只申请 `activeTab`、`scripting`、`storage` 和本机回环地址权限，没有 Cookie、历史记录、全站读取权限或常驻后台采集。用户在文章页主动调用扩展后还需点击读取；知识库页面不能替用户取得另一标签的临时权限。
- 不扫描其他标签，不刷新、导航、滚动或关闭原页。清洗发生在 DOM 克隆上，不修改文章 DOM。自动识别只选文章候选区域，排除导航、表单、隐藏节点和评论，没有整页 `body` 兜底，不上传整页 HTML、Cookie、表单值或浏览器凭据。
- Chrome 清单的回环 host 权限无法限定端口，扩展代码进一步固定为用户配置的本机 HTTP origin，连接不带 Cookie、拒绝重定向。密钥不放入 URL，不发给文章网站。
- 服务端同时校验真实客户端回环地址和 Host。本机页面操作需同源，密钥只可通过页面同源请求显示；扩展待办和上传接口另需 Bearer 密钥，普通网站 Origin 即使带密钥也被拒绝。
- 实际网址须与指定网址匹配，忽略片段，不信任网页自报的 canonical。跳转须重新核对，不能将另一篇文章静默补入。
- 沿用正文非重复字符门槛 400，最多 20 万字符，超限拒绝而非截断。长文本仍可能是登录墙或摘要，人工检查完整性不可省略。
- 只读已加载内容，不绕过登录、付费、验证码或访问控制。不要将配对密钥分享给网站或他人。
- 仅支持 `SourceType.body_from_link` 明确允许的现有 `feed_items` 文章：RSS、网页专栏和手动收录。简报摘要的外链不是摘要本身，禁止用外链文章替换；前端入口、绑定请求和保存均检查同一能力位，未知来源默认拒绝。暂不支持 X 观点 / 时间线、PDF、浏览器内部页、跨域 iframe 或独立公众号采集器文档。

## 回填和状态

- 不新增重复文档；用原 key、来源、原网址、内容指纹和单调递增 `content_rev` 共同做事务内条件更新，目标变化、排除或删除即拒绝覆盖。
- 保留原条目标题、路径及历史导出回执。替换原文、增加修订号、清除旧译文及翻译错误、标记待重提取，清除本篇补抓挂起和错误；补抓尝试次数保留作历史记录。
- `body_provenance` 记录采集方式、实际网址、页面标题、时间和人工确认，`browser_capture_audit` 在同一事务记录请求、条目、正文摘要和修订号。审计表纳入常规数据库 schema，以便重启后恢复已保存回执。
- 同一请求重复提交相同正文返回原回执，不再更新；已保存回执在期限后仍可幂等重放。不同正文、取消、被替代、过期未保存或陈旧请求不能覆盖；回执的内存命中、按请求恢复、按条目恢复及继续处理均使用统一的修订号和正文摘要校验。
- 密钥保存在本机 `feeds.db` 的 `feed_meta`；请求队列在单个 Web 进程内存中，最多 100 个等待中的请求，保存、取消和陈旧终态不占等待额度；额度撞满时顶掉最老的那个等待请求（它也最接近过期），不拒绝新请求，被顶掉的那一篇重新点一次即可。内存请求 15 分钟清理，目前不支持多 worker 请求共享。重启丢失未完请求，但不丢失已保存正文或审计回执。
- 页面与扩展共用 `api.js` 的错误解析，纯文本 500 保留 HTTP 状态，JSON 校验错误保留可读原因，不显示 JSON 解析器异常。重新采集及后续处理使用项目内确认框，可取消或按 Escape 关闭。

| 内容 | 文件 |
| --- | --- |
| 事务、版本保护、审计 | `kb/browser_capture.py` |
| 鉴权、下载、后续处理 | `kb/web/browser_capture_api.py` |
| 真实文章入口 | `kb/static/js/source_reader.js` |
| 采集抽屉 | `kb/static/js/capture_drawer.js`（外壳与模板）、`kb/static/js/browser_capture.js`（状态机）、`kb/static/css/browser_capture.css` |
| 扩展目录 | `kb/static/browser-extension/knowbase-capture/` |
| 页面与扩展共用的 HTTP 反馈 | `kb/static/browser-extension/knowbase-capture/api.js` |
| 验收阶段回归用例 | `tests/test_browser_capture.py`、`tests/test_browser_capture_feedback.py`(挂着四条 node 探针) |

API 前缀为 `/api/browser-capture`：`target/{key}`、`pairing`、`extension.zip`、`intents`、`intents/{id}`、`intents/{id}/continue`、`pending`、`precheck`、`upload`。`target/{key}` 除条目信息外返回 `pending`、最近有效 `saved` 及 `saved_error`，应用侧无需扩展密钥即可查看和取消本篇请求；扩展的全局待办接口仍须配对。扩展资源随 `kb` 包分发，ZIP 包含清单、popup HTML/CSS/JS、共用 `api.js`、提取器、回环页面上那个标记脚本 `present.js` 和 README 共八个文件，不依赖仓库外文件。`setup` 只答「装哪个目录」——「这个浏览器配过没有」服务端答不了，由 `present.js` 在页面上答。

## 判据在哪一边

网址是不是同一页、正文够不够、这条还写得了吗 —— **三问都由本机服务回答**。扩展在
读取页面之前先问一次，不通过就一个字都不读；读完之后、写进去之前再问一次（带上
正文），那一问同时答出字数。所以它不会让你读完整篇才说没写进去。网址按浏览器同一套规范化之后
比对，带中文的地址、默认端口、路径里的空格都算同一页；真的是另一篇照旧拒绝。

硬约束、事故形态与回归清单见 `docs/decisions/browser-capture.md`，**动这一块的代码
之前先读那一份**。

## 还没验过的

- 没有在真实站点的登录态文章上走完整条链：工具栏手势 / 快捷键授予 `activeTab`、
  第三方网站的提取覆盖率，都只能人工验收。
- 没有跑完整的翻译 / 导出 / 索引 / 提取链，不能声称全链路通过。
- 按项目约定，执行者与审查者都不跑回归测试，统一在验收阶段执行。
