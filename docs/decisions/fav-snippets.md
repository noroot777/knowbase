# 「收藏此段」长在所有能展示原文的地方(kb/static/js/snip.js、favorites 的 v4)

> **这一份整份都是这一块的记录:硬约束 + 事故形态、实测证据、回归清单和反向验证红数** ——
> 动这块代码之前先读它。CLAUDE.md 只留跨块的元规则和一张索引。

原来这个功能只长在 `/doc/…` 阅读页里(`kb/web/pages.py` 的 `_DOC_SNIP_JS`)。每日日报、
知识问答、我的订阅、图鉴条目各渲染一份正文,却都收藏不了。

## 硬约束

- **`favorites.path` 可空(v4),空值是 NULL、不是空串。** 日报写在 vault 的 `daily/` 下,
  **那个目录不在任何 `SOURCES.root` 底下**(`kb/config.py`),索引跑完它照旧不在 `documents`
  里;问答回答压根不是文件;订阅条目在导出之前只在 feeds.db 里。而 `path` 原来是
  `NOT NULL REFERENCES documents(path)`,外键在 `PRAGMA foreign_keys = ON` 下**对空串照查**
  (只有 NULL 豁免)—— 拿 `''` 占位的写法一条都存不进去,报 `FOREIGN KEY constraint failed`。
  **`path` 非空时外键和级联语义一个字没变**(只增不减)。
- **去掉 NOT NULL 只能重建整张表**(SQLite 没有 `ALTER COLUMN`),而重建是这条路上唯一会丢
  数据的一步。所以 `_rebuild_favorites_v4` 三条都得照办:
  - **按老表实际有的那几列拼 INSERT**(`_FAV_CARRIED` 过一遍 `PRAGMA table_info`)。v2 没有
    `action_json`,写死一份列名会让它在 `no such column` 上翻车。
  - **孤儿行的 path 落 NULL**(`CASE WHEN EXISTS (SELECT 1 FROM documents …)`)。外键是 ON 的,
    INSERT 回去逐行查 `documents` —— 历史上留下的、文档已经不在索引里的收藏(原来内连接下
    就看不见、却仍占着计数)会让那一句整条失败,于是 **`store.connect()` 本身再也成功不了**:
    页面 API、提取 worker、CLI 全挂,而迁移每次重试都会在同一行上失败。
  - **整段在一个写事务里,并在锁里重新读一次列集合**(口径同 `_add_columns`)。常态(已经
    是 v4)在函数外那句 `PRAGMA table_info` 就返回了,一次锁都不取。
  - **把自增高水位一起搬过去**(`_carry_sequence`,排在 `DROP TABLE` 之前 —— 临时表一删,
    它那行 `sqlite_sequence` 就跟着没了)。`RENAME TO` 会把那一行一起改名,而新表那行是按
    「插进去的最大 id」重新算的:**编号最大的那条已经删掉时,新表的高水位比历史分配过的
    低,下一条新收藏就复用一个已经发出去过的编号。** 后果不是编号不好看 —— 收藏列表上
    那几颗按钮、`favorites_api` 的 PATCH/DELETE、`favbrain` 的行动卡写回全都只拿着 id,
    不复用时过期那一页最多得到 404,复用之后同一个请求会**成功作用在另一条收藏上**。
    v1 那条分支也过这个函数(它没有自增行,函数自己返回)—— **不变量待在一处,不是每条
    分支各记一遍**。
- **索引只由 `_FAVORITES_DDL` 管一处。** `connect()` 在 `_migrate_favorites` 之后无条件跑一次
  `executescript(_FAVORITES_DDL)`,所以不论哪条迁移分支中间把它弄没了(索引跟着 `RENAME TO`
  挂到临时表上、临时表一删就跟着没),连接交出去之前都会被补回来。**迁移里不要再各自
  DROP/CREATE 一遍** —— 那是夹在两道带中间的死代码,见下面「反向验证」里注入 B2/B16。
- **列收藏用 LEFT JOIN,不是 JOIN**(`_FAV_SELECT`,`favbrain.extract_action` 和 `_inbox_rows`
  也是同一份)。内连接会让两类条目在列表里静默消失:没有 path 的(日报/问答片段),以及
  文档已经不在索引里的 —— 而**计数(`counts`)是全表数的**,于是标签上写着「待试 12」、列表
  里只有 9 条,剩下 3 条点不到也删不掉。
- **元数据有两个来源,顺序是「索引里那篇优先、收藏那一刻的快照兜底」**
  (`COALESCE(NULLIF(d.title, ''), f.origin_title)` 这一族)。`origin_title` / `origin_url` 是
  收藏那一刻存下的快照,**只在没有文档时顶上**:有文档时标题跟着索引走(重译、改标题之后
  列表里是新的那个)。
- **交给前端的 `path` 一律是空串,不是 null**(`item["path"] = item["path"] or ""`)。前端那套
  `docLink`/`obsLink` 直接拼,null 会拼出 `/doc/undefined`。
- **`doc_paths` 要排掉 NULL**(`WHERE quote='' AND path IS NOT NULL`)。整篇收藏只存在于 doc
  来源,但迁移置空过的孤儿行也满足 `quote=''` —— 不排掉就往这个数组里塞一个 null,而前端
  拿它当 Set 的成员去比对每张搜索卡片。
- **`path` 给了但不在索引里 → 404,后端不替调用方降级。** 把一条本该能定位回原文的收藏静默
  换成只有引文的那一类,是**调用方**该做的决定:它知道自己手里那篇有没有入库。订阅阅读器
  正是靠这一条退的(`sourceSnipSource` 的 `fallback`:md 落盘了、索引那一步还没跑的那几分钟
  里,`path` 是真的、`documents` 里却还没有行),退完还要如实告诉用户「这篇还没进检索索引,
  点回去会打开站外原文」。
- **绑了文档的收藏必须说清绑的是哪一版正文,落库前再核一次。** `POST /api/favorites` 带
  `doc_version`(缺了 400),后端按**盘上此刻**那一篇再算一次 `scanner.body_version`,不等就
  409。**核对和写入是两个请求**:调用方读 `/api/doc` 核对完、POST 还没到的那一下,重译写回
  (`translate._save`)、正文补抓(`fulltext`)照样会把那一篇换成另一版 —— 没有共同的事实,
  收藏照旧落成 `origin=doc` 返回 200,固化下来的是一条**点回去永远找不到那句话**的收藏,而
  当场一切正常。
  **「核验 → 写入 → 提交」整段待在同一个临界区里,不是「排得近一点」。** `doc_version` 是
  一次**取样**,临界区才是不变量:改那一篇的几条路(订阅同步导出末尾那句 `os.replace`、重译
  写回、正文补抓、展示层改写 `doc_rewrite`)**全都认同一把维护锁**(`kb/maintenance.py`),
  所以核验和 INSERT 一起圈进那把锁,它们就进不来;数据库那一头另有一道 —— `BEGIN IMMEDIATE`
  排在**读版本之前**,于是 INSERT 不会在「核完之后」再去排队等写锁。**只缩短间隔不算修**:
  INSERT 要等别人的写事务时,这个间隔由**对方**决定(实测核验与落库之间等了约 1 秒,期间另
  一路真走 `translate._save → sync.export` 把那一篇换成新译文,收藏照旧 200、回看 0 个高亮)。
  推论七条:
  - **版本号只认正文,不许用整份文件的哈希。** `body_version` 只哈希 `parse_frontmatter` 之后
    那一段;按 `file_hash`(也就是 `documents.content_hash`)算的话,提取回写那一刻的收藏会被
    **误拒** —— 那一步只往 frontmatter 里补 tags、写 extracted_at,正文一个字没变,收藏点回去
    照旧定位得到。和 `kb.extract_version.body_fingerprint` 算的是同一个数却各写一份:那一族判
    「模型结论针对的输入还是不是当前这份」,这一族判「收藏绑的目标还是不是用户看过的那份」。
  - **报版本号的三处和落库前再算一次的那一处,读法必须同一份**(`scanner.read_md_text`,解码
    一律 `errors="replace"`)。一处严格、一处 replace 的话,文件里有一个坏字节就会算出两个
    版本,把一条好收藏误拒成「原文已更新」。
  - **拒绝的三种形态各报各的:404 不在了 / 503 读不出来 / 409 已经是另一版**,口径同
    `/api/doc`(两头共用 `kb/web/common.py` 的 `read_doc_text`)。调用方按状态码决定退回哪一
    档、怎么跟用户说;合成一种的话,「这一刻读不出来」就被说成了「这篇还没进检索索引」,而
    后者是个**已经证明了的结论**(等索引跑完就好了),前者只是一次失败。
  - **三个绑文档的入口都得把版本号带上**:订阅阅读器从那次核对里带出来(`snipVerified` 把
    `doc_version` 挂到最终那个来源上)、图鉴条目从 `/api/projects/{norm}` 的 `version` 读
    (挂在每个 `.td-entry` 的 `data-snip-version` 上)、独立阅读页从渲染那一刻烤进 HTML
    (`DOC_VERSION`)。**有退路的那一个退一步**(409/503 退回 `origin=feed`,如实说退的是哪
    一种);**没有退路的那两个如实拒**,并且只许说「刷新页面再收藏」—— 同一个工具关掉重开
    抽屉用的是现成视图(`openToolDrawer` 的 `!changed && toolMeta`),版本号跟着那份视图一起
    还是旧的,说「重新打开这条记录」就是让用户再撞一次同一面墙。
  - **锁序是「先维护锁、再 `BEGIN IMMEDIATE`」,不许反**(反过来报的 `SQLITE_BUSY_SNAPSHOT`
    不受 `busy_timeout` 管),取维护锁之前**先把手里那个写事务落盘** —— 同
    `kb/extract.py` 的 `save_and_writeback`,口径在 `docs/decisions/maintenance-lock.md`。
  - **等不到那把锁按 503 收场、一个字节没写。** 这是「这一刻没法核对」,不是「那一篇不在了」
    (404)、也不是「已经是另一版」(409);等多久有上限(`_DOC_LOCK_WAIT`,比维护那一侧的
    900 秒短得多),等不到就出声,不许无限等、也不许跳过核验硬写。客户端那三条退路按状态码
    分(`RETRY_NOTE`)。
  - **只有绑文档的那一类取这把锁。** 日报、问答、订阅退回 feed 的那几类压根不读文件,把它们
    也串进去等于让一次维护把整个收藏入口堵住(回归反过来钉了这一边:维护锁被别人拿着时,
    没有 path 的日报片段照旧 200)。
- **`origin=doc` 成不成立,由「存之前去读那一篇、在里面找这条锚点」决定,不许用客户端手里的
  字段推断。** 判据只有一处(`snipVerified` + `snipDocText`):`describe()` 给一个
  `docText()`,它去读 `/api/doc?path=…`(**阅读页渲染的就是这个文件**,所以要照
  `doc_page` 同一条正则剥掉 frontmatter),**按阅读页那一头的规则**渲染、压平,再跑一遍
  `snipSeek`;找得到才存 `origin=doc`,否则落到 `fallback`(`origin=feed`,回跳走站外原文),
  **退的理由如实写进提示,而且「确定没有」和「不知道」要分开**(`absent` = 那一篇**确定**
  不在,只有 404 算;`unreadable` = 这一刻读不出来/不知道 —— 请求抛了、5xx、JSON 坏了、服务端
  没报版本号;`mismatch` = 读到了但这段话不在里面)。合成一种的话,一次暂时的失败会被说成
  「这篇还没进检索索引」,而那是个已经证明了的结论。
  这一道同时收掉三件**表现完全一样**的事 —— 收下来 HTTP 200、路径和引文都对,点回去 0 个
  高亮、一句「原文可能已更新」:
  - **盘上那篇可能不是「屏幕上这一份」正文。** `path` 是上一次导出留下的,而重译
    (`kb/feeds/translate.py` 的 `_save`)、正文补抓(`kb/feeds/fulltext.py`)都保留它。
  - **md 落盘了、索引那一步还没跑**:`/api/doc` 对它判 404 → `absent`。
  - **两头摊的不是同一种文本。** 订阅阅读器按 `textContent` 原样摊开正文(`**`、反引号、
    `[字](url)` 看得见),`/doc/…` 把同一份 md **按 markdown 渲染**(`marked.parse`),那些
    标记在那一头消失或变形。
  **原来这里拿 `exported_hash === content_hash` 推断「盘上那篇就是这份正文」(`sourceItemAtPath`),
  那个判据立不住,已经删掉。** 它是**原文**的哈希:`kb/feeds/sync.py` 导出成功那一句写的就是
  `exported_hash=content_hash`,而同一篇原文重译一遍、重导出一遍,这两个值一个字节都不变 ——
  「两个哈希相等」和「盘上那篇是哪一份译文」没有关系(审查实测:保留一页旧阅读器不刷新、
  后台重译重导出,两个哈希仍相等、旧判据照旧为真,收藏存成 doc 返回 200,点回去正文是另一份
  译文、0 个高亮)。**推断换成核对**:它不押在「谁改过正文」这件事上,下一个改正文的入口
  也不必来改这里。
  **核对要按「点回去那一页会看到的那份文本」算,不是按面板这一份算。** 两边差的是原始 HTML:
  面板的 `mdHtml` 把它交给 DOMPurify(标签成了元素、本身看不见),阅读页**把它当字面文字
  显示**(`_DOC_LITERAL_JS`,为的是 `List<T>`、`<dependency>` 这类示例在正文里看得见)。拿
  面板那套规则核的话,跨过一段 `<strong>` 的选区在面板上是连着的一句、核得过,点回去那一头
  中间却插着四个尖括号字、0 个高亮 —— 当场一切正常。所以共享层自己拿一份**独立的** marked
  实例照阅读页的规则渲染(`snipDocRenderer`,`new marked.Marked({renderer:{html}})`);
  **不许走 `marked.use()`** —— 那是全局的,图鉴、日报、问答、素材账本要的正是「标签当标签」
  (日报出处那一族还和它逐字节对齐)。这份规则**和阅读页那份是孪生的,改一处要改两处**
  (`kb/web/pages.py` 的 `_DOC_LITERAL_JS`,两处互指注释)。
  **核不过时怎么收场分两类:有退路的退回 feed;没有退路的照存、但当场说清。** 没有退路那
  几类(独立阅读页、图鉴条目)的原文就是 vault 里那一篇,退无可退 —— 悄悄存成功是最坏的一种
  (库里那条看着好好的,用户要到点回去那一刻才发现)。
  **核不过就把面板手里那一版原样送上去,不许把刚读到的新版本号带上。** 后端那道 409 于是
  正好替我们把两件事分开:两版**不等** = 面板旧了(改稿很可能正是把那句话换掉的那一下)
  → 409、一行不落、提示说「刷新再收藏」;**相等** = 文件没动过,核不过只是两头的文本不是
  同一份 → 照存、说清点回去可能定位不到。带上新版本号的话后面那道就永远判不出「面板旧了」,
  改稿把那句话删掉也照存。
  **`docText()` 读不到(404、请求失败、没报版本号)一律当「核不过」**,不许当成核过了:那会
  把一条永远定位不到的收藏固化下来,而退一步的代价只是回跳打开站外原文。
  **POST 被拒之后那三条退路留着,是第二道带子**(`RETRY_NOTE` 的 404/409/503):核对和 POST
  是两个请求,中间那一下索引行照样会没、正文照样会换一版、文件照样会读不出来;而不给
  `docText`、只给 `fallback` 的来源只有这一道。
  **这道核对是「类」约束:每个绑文档的入口都要过它,一个不许少。** 原先以为图鉴条目不需要
  (抽屉渲染的是 `mdHtml(e.body)`,`e.body` 就是那篇条目 md 去掉首行出处引用之后的正文,
  `kb/projects.py` 的 `get_tool` —— 看着是「同一个渲染器、同一份字符串」),可**阅读页那一头
  不是这个渲染器**:同一份字符串里那段原始 HTML 在抽屉里看不见、在阅读页上是四个字面字,
  同一个文件版本、两头的文本就不是同一份。所以图鉴条目也给 `docText`,和订阅阅读器、独立阅
  读页同一道。订阅阅读器只是额外多一座「纯文本 → markdown 文档」的桥(也是唯一有「盘上那篇
  停在旧版本」这个窗口的来源),那让它多一条退路,不是让它独占这道核对。
  **核对和保存契约各管一头,都不能省**:核对解决「两头摊的不是同一种文本」,契约解决「核对
  完到落库之间换了一版」(抽屉开着的这几分钟里那一篇被换掉,核对躲不过)。
  **这道判据待在订阅阅读器 + 共享采集层这一侧,不是 `favorites_api`**:后端认不得 markdown
  (渲染在浏览器里),也不许为了拿 `feed_items` 去 import `kb.feeds.*`(CLAUDE.md「仓库结构」)。
- **没有文档的收藏必须带 `origin_title` → 否则 400。** 列表、分诊、行动卡都靠它指代这一条,
  缺了就是一张无字卡片,而收藏当场是成功的。
- **快照字段的长度上限两头必须对齐:标题可以截,URL 只许整条丢。**
  `SNIP_MAX_TITLE = 300` / `SNIP_MAX_URL = 4096`(`snip.js`),和后端 `origin_title` /
  `origin_url` 的 `max_length` 是同一组数。这两个值是**内容自带的** —— 标题来自订阅条目和
  图鉴条目,URL 来自站外原文地址,带一长串跟踪参数的真实 URL 过 2048 是现实存在的,而各处
  `describe()` 都是原样往上传。两头对不上的后果是**整条 POST 被拒成 422**:用户选完才发现
  存不下,屏幕上只有一句「收藏失败」,而 404 那条退路接不住 422(它只认「这篇还没进索引」)。
  **URL 不许截**:半截 URL 点过去是另一个地方,比没有链接更坏 —— 超长就送空串。**而「送了
  空串」这件事,没有 path 的那一类要当场说**(「这条来源链接太长没能一起存下,点回去只能回到
  来源面板」):那时链接是回原文的唯一一条路。绑了文档的那一类回跳本来走阅读页,说它反而是
  噪音,所以那一句的判据是 `!eff.path && snipUrlDropped(eff)`,而 `eff` 是**最终真存下去的
  那个来源**(退过一步之后不是原来那个)。
- **`SNIP_ORIGINS`(前端)和 `_ORIGINS`(后端)是同一份名单**,加一种来源两边一起加;后端
  把不认识的 origin 拒成 400。
- **锚点坐标系必须和阅读页逐位对齐,而且只有一个:压平空白之后的全文。**
  `snipTextIndex` 用 TreeWalker 把容器里所有 text node 串成一条全文,**一段连续空白
  (空格、换行、制表、NBSP)一律当一个空格**,并记下每个字出自哪个节点的哪一位;前后文的
  截取、锚点的匹配、回跳的定位共用这一条全文。压平是必需的:同一份正文在两头的空白本来
  就不一样 —— 订阅阅读器摊的是 `textContent`(段落之间两个换行),阅读页把同一份 md 渲染
  成一串 `<p>`(串起来只剩一个换行),不压的话前后文锚点**一碰到段落边界就对不上**。
- **压平出来的那条全文只是「匹配表示」,不是收藏内容:`quote` 一律按原文逐字存。**
  采集那一刻拿 `snipOffsetRange` 把 `[a,b)` 换回 DOM Range、取它的 `String(range)`(端点
  落在元素边界那条退路取 `String(range)` 自己),只去两头空白;**压平留到读的时候才做**
  (`snipAnchor`、后端 `_anchor`)—— 对同一段话压一遍恰好等于 `idx.text.slice(a, b)`,所以
  匹配和保真同一个来源、不会差位。存压平版的后果是静默而且**不可恢复**:多行代码、带缩进
  的列表、分行的清单,存进库就成了接起来的一行,收藏面板、导出、行动卡上那段引文再也恢复
  不回去,而定位、回跳、高亮全都照旧好使 —— 没有任何一处会报错。推论三条:字数下限
  (`SNIP_MIN`)要判在**压平过的那一份**上(否则「冒号 + 四个空格 + 一个字母」算七个字),
  而且**弹按钮和存库同一份判据**(`showSnipBtn` 和 `saveSnip` 都过 `snipCollapse`)——
  两处分叉的话,这种选区会弹出按钮、点下去却静静收起,又是一颗点了什么也不会发生的按钮;
  后端 `_anchor` 只压 `prefix`/`suffix`,**不许把 `quote` 一起压**(那是同一个错换个地方犯)。
- **引文两头的空白在采集那一刻就挪出引文**(`snipSpec` 那两个 while 把 `[a,b)` 收到非空白
  上),读的时候再收一道(`snipAnchor` / 后端 `_anchor`:`q` 以空白开头就给 `p` 补一个空格、
  以空白结尾就给 `s` 补一个,接缝上只留一个)。不变量是 **压平之后 `prefix + quote + suffix`
  仍是正文里连着的一段**。只 `strip()` 引文是不行的:前后文照旧带着被剥掉的那几个空白,整段
  锚点就再也拼不回原文。两道带各自都够(见下面注入 C2/C6/C12)。
- **前后文最外侧的空白要剪掉**(`p` 去头、`s` 去尾,`snipAnchor` 和 `_anchor` 各一份)。接缝
  那一侧的空白**带着位置信息**(引文首尾那几个空白正是挪过来的),外侧那一侧**什么也不说
  明**,而且两种渲染给出来的还不一样:正文最后一段在订阅阅读器的 `textContent` 里后面跟着
  一个换行,渲染成 HTML 之后那儿什么都没有。不剪的话整段锚点差一个空格就失配,于是掉到更
  弱的档、或者干脆落到「没找到」—— 而路径、引文、HTTP 全是对的,页面上看不出哪儿错了。
- **定位按「候选集合」算,不按「档位顺序」挑;最后只剩一处才采信。**
  (`snipSeek` / 阅读页内联副本 `seek`,两头各一份、改一处要改两处。)
  - **每一侧都留全部候选,`snipAll`/`hitsOf` 回的是数组。** 前文那一侧(`p+q`)和后文那一侧
    (`q+s`)各有两种空法,**它们不是一回事**:0 个 = 这一侧的证据在这份文本里**用不上**;
    多个 = 这一侧**自己定不了位**,可它仍然把范围缩到了那几处。原来两种都回 `-1`
    (`snipOnly`/`only`),**后一件的证据就丢了** —— 前文明明说「只可能是第一处或第二处」,
    后文唯一指向第三处,丢掉前文那个集合之后只剩一个「唯一命中」,于是静默高亮一处前文已经
    明确排除掉的地方。
  - **两侧都还有候选就取交集**(交集正是整段 `p+q+s` 命中的那几处:`p+q` 在 x 处命中且
    `q+s` 在 x 处命中,等价于 `p+q+s` 在 `x-|p|` 处命中 —— 所以**不必再单列「整段」那一档**,
    它是这条规则的推论,不是另一道判据)。一侧用不上就只听另一侧,两侧都用不上才退到裸引文。
  - **最后一律要求只剩一处。** 剩两处是正文自己分不出的两处(一字不差重复的整段、模板说明、
    重复的代码块,连它两头三十个字都一样);剩零处是两侧的证据互相矛盾。**两种都如实说没
    找到** —— 锚点还在、位置说不清,比挑一处诚实:静默挑一处是把一句「没找到」换成一个落在
    错地方的高亮,而那几处的文字一模一样,用户从页面上看不出来。
  - **反过来钉一边:一侧有歧义不等于整条锚点作废。** 前文有两处候选、后文指着其中一处时,
    交集唯一 —— 那一条**照旧要落回那一处**。「一有歧义就全拒」也能让「不许高亮错地方」那几条
    全绿,而它把本来定得回去的收藏一起废掉(注入 F3/F4 各红 1 条就是这条反向判据)。
  - **「只听一侧」不是摆设。** 同一条锚点可能在另一种渲染里只对不上**一侧**:订阅阅读器摊的
    是 md 原文(`## 标题` 带着井号),`/doc/…` 把它渲染成 `<h2>`(井号没了)—— 前文跨过一个
    标题就失配,而后文那一侧分毫不差。少了这一支,带标记的正文里凡是前后文跨过标记的锚点
    **全都退到裸引文**,碰上重复文字就是一句「没找到」。这一格有自己的夹具(订阅那篇里靠
    小标题分隔的那对重复句),**两份实现各有自己的红**(注入 D4/D8)。
  - **数不完的那一侧也算说不清。** `snipAll` 数到 `SNIP_MAX_HITS`(64)就停,多出来那一个是
    「数不完」的信号,`snipSeek` 见到就回 null:截断过的集合拿去取交集会让交集**偏小**,而
    偏小正好是误采信的方向(交集恰好剩一处 → 采信一处位置可疑的高亮)。宁可多拒。
- **前后文长到「能唯一定位」为止,而且判据直接走回跳那个函数。** `snipContext` 按
  `SNIP_CTX_STEPS = [30, 80, 200]` 一档档加长,每档拿 `snipSeek` 在同一条全文上试一遍、
  **落回采集的那个偏移**才收;都做不到就回最短那档,并把 `locatable: false` 带到提示上
  (「这一篇里有几处一模一样的文字,点回去可能定位不到这一处」)。固定 30 字不够:一字不差
  重复的整段往往连两头三十个字都一样,那一刻存下的锚点**天生定位不到自己**,而收藏当场是
  成功的。**不许自己另写一遍「唯一吗」** —— 采集这头按一套规则算出「唯一」、回跳那头按另
  一套(候选集合 + 外侧空白)落在别处,是这条链上最难看出来的那种错:两处的文字一模一样。
  **独立阅读页那一份内联实现也要把这个标记传出来**(`contextOf` 回 `exact`,保存成功那句话
  按它分叉)—— 两份实现的**反馈契约**要对齐:那一页原来一律显示普通成功,于是同一条收藏在
  app 里会被告知「点回去可能定位不到」、在阅读页上什么也不说。
  反过来钉一边:**定得准的那一条不许乱提示**(「一律提示定位不到」把一句准话换成一句含糊话)。
- **每一处会进库的截断都不许切开一个字。** JS 的字符串按 UTF-16 存,emoji 一类字占两个单元
  (代理对),按单元 `slice` 会把它切成两半;**孤立的那一半 Python 的 str 装得下、UTF-8 编
  不出来** —— sqlite3 在 INSERT 绑参数那一句抛 `UnicodeEncodeError`,而那是 `try` 里的最后
  一步,于是整条 POST 变成一句 500。审查实测:正文里一个 emoji 后面隔着 29 个字母(正好让
  三十字那一档的前文窗口起点落在它的后一半上),选中再后面那句普通中文,**日报和独立阅读页
  都收藏失败、收藏数还是 0**,而用户选的那几个字里一个 emoji 都没有。
  口径只有一份(`snipWhole` / `snipClip`,阅读页那份内联副本里叫 `whole`),**截断处一律过
  它**:前后文窗口(`snipContext` / `contextOf`)、标题上限(`postSnip`、`chat.js` 的提问
  标题)。顺带把**选区端点**也收到整字上(端点落在代理对中间时往里收一格)—— 鼠标选不出这种
  端点,程序派的选区能。**只削掉边上那半个字,正文里合法的字一个不动**:替换合法原文动的是
  用户收下来的引文,那不是修法。
  后端还有一道,它拒而不改(`SnippetRequest._no_half_character`):**抛 `HTTPException(400)`
  而不是 `ValueError`,而且必须排在 `max_length` 前面**(`mode="before"`、字段写 `"*"`)——
  走 pydantic 的校验失败会变成 `RequestValidationError`,而那个错误体里带着 `input` 原串,
  序列化它又是一次 UTF-8 编码,于是「受控的 422」当场变成一个崩在错误处理里的 500(实测:
  带 `max_length` 的 `origin_title` 连 422 都发不出来)。这句 400 **不带原串**,所以一定
  编得出去。
- **`locateSnip` 读锚点时也过一遍规范化**(`snipAnchor`)。库里还有阅读页早先存下的、没压过
  空白的锚点;规范形态再压一次不变,所以两种都认。
- **弹按钮之前就得问清楚这一段收不收得下**(`showSnipBtn` 里那句 `snipSourceOf`)。一个注册
  过的容器里并不是每一处都是正文:问答空态那三颗建议按钮和回答同住 `#chat-msgs`、图鉴的
  小节标题和条目正文同住 `#td-entries`、会话还没落库时整块回答都没有落点。**一颗点了会失败
  的按钮比没有按钮更糟。**
- **高亮走 CSS Custom Highlight API,不许包 `<mark>`。** 包一层标记的话,那几个面板下一次
  重渲染就把标记连正文一起换掉,而且会打断 `dailyRefMap` 那类按节点结构找东西的代码。
- **回跳是「存一个待定位、再切面板,由面板自己消费」**(`dailyPendingSnip` / `chatPendingSnip`
  + `consumeSnipJump`,仿 `subsPendingKind`)。**不在 `jumpFavOrigin` 里 await 面板加载**:
  `switchTab` 会顺手起一轮 `loadDailyPanel` / `initChat`,那一轮自己也要决定「打开哪一份」,
  两边各发一次请求就是先发后到的旧回包盖掉新的(日报面板的 `dailyReadSeq` 为同一类竞态而
  存在)。
- **日报片段的出处写在正文容器自己的 `data-snip-ref` 上,由唯一写入口
  `setDailyBody`(kb/static/js/daily_body.js)和正文一起落下来。** 不许读 `dailyCurrent`:
  那是「列表里选中哪一天」,在请求发出之前就写好了,而这期间屏幕上还是上一份正文 ——
  拿它当出处,收下的就是一条**正文属于 A、出处记着 B** 的收藏,点回去永远找不到。
  绑在容器上同时收掉另外两种形态:正文已经被换掉时选区离开了文档树、`closest` 找不到
  容器,不收;读取失败/已删除那几个字(「读取失败」「已删除」)容器上压根没有出处,不收
  —— **那些字不是日报正文,一个字都不该收得下**。
- **问答那一侧「会话在库里」不等于「这一轮在库里」:落库标记写在消息元素自己的
  `data-snip-saved` 上**(`SNIP_SAVED`)。`renderMsg(m, true)` 给从库里读出来的历史消息写,
  NDJSON 的 `done` 帧回来之后 `chatMarkSaved` 给刚答完这一轮补上 —— **那一刻 `_save_qa` 才
  跑过**;`chatSnipSource` 见不到这个标记就不给落点。只问 `convId` 是不够的:一轮问答是**答
  完才整轮写进 `messages`** 的,追问时会话号早就有了,而流式途中、点了「停止」之后、出错那
  几种状态屏幕上已经有整段回答。那时收下来的片段 `origin_ref` 指着一个压根没有这几条消息的
  会话,**刷新之后那段话不存在、回跳永远打不开**,而收藏当场是成功的。同一轮的**提问**也要
  等这一刻(它和回答是同一条 `_save_qa` 写进去的)。图鉴详情抽屉里那块问答是同一个口径
  (两处都用 `renderMsg`,`toolConvId` 的第二轮条件一模一样)。
- **那个落库标记挂在整条消息上,可不是这条消息里每个字都落了库:可收范围收到正文那一份上。**
  同一个 `.msg` 里还住着相对时间、模型名、「存为笔记」那颗按钮(`renderMsg` 拼的 `.msg-meta`),
  以及按 `refs` 现拼的「来源 N 篇 / Obsidian / 原文」那一块(`.refs`)—— 它们是**界面文字**,
  不是落了库的正文:相对时间过一会儿就变成「3 小时前」,照着它找只会找不到。所以
  `chatSnipSource` 要求选区落在 `.bubble` 之内(`body.contains(range.commonAncestorContainer)`)
  且不碰 `.refs`(`range.intersectsNode`)。两处问答(问答面板、图鉴抽屉)共用这一处判据。
- **「哪里算正文」这件事,采锚点的范围也得跟着收 —— 而且采集和回跳要同一个口径。** 共享层
  为此认 `describe()` 的两个字段:`root`(正文那个元素,采前后文只在它里面走)和 `skip`(容器
  里那几块界面文字的选择器,`snipTextIndex` 直接跳过整棵子树)。缺了的后果不是按钮弹错地方,
  是**那条收藏带着一段目标文档里压根不存在的上下文**:图鉴抽屉里采到的后文实测是
  `原文 Obsidian 在阅读器打开 就这个工具提问`(那三颗链接按钮和小节标题),问答那一侧采到的
  是模型名和「3 小时前」。**回跳那一头必须传同一个 `skip`**(`consumeSnipJump` → `locateSnip`),
  不然采集时算出来的唯一性在定位时就不成立了 —— 这一道是**冗余带**(现在的后果由
  `snipSeek` 按内容找接住了,定点注入打不红),留着是因为「两头同一个坐标系」是这条链的前提,
  理由写在 `locateSnip` 的注释里。
  **图鉴那一处还要反过来拦住正文之外的选区**(`.body.contains(range.commonAncestorContainer)`):
  一个 `<details>` 里并排住着摘要行、正文、三颗链接按钮,选中按钮文案也能存下一条点回去必定
  落空的收藏。摘要行那一段浏览器自己就不交出来(`<summary>` 里设好 Range 之后
  `getSelection().toString()` 是空串),所以回归那条判据落在**那三颗按钮**上。
- **收藏「提问本身」时标题取它自己那一问**(`chatQuestionOf` 头上那句)。往前找 `.user` 的
  话会取到**上一轮**的提问,于是列表里那条片段挂在一个跟它无关的问题下面。
- **回跳目标那一份日报已经不在了,要当场说清楚并把这次回跳丢掉**(`loadDailyReports`)。
  退回「打开第一份」的话,屏幕上是另一天的日报、没有任何提示,而待定位还挂着:用户以为
  跳到了,其实在读别的东西。
- **回跳目标整个编进 `data-jump`,不去全局列表缓存里按 id 捞** —— 这几颗按钮的寿命比那份缓存
  长(分诊结果渲染完、下一次 `loadFavPanel` 之前它一直在屏幕上)。
- **`feed` 这一类回跳走站外原文,不去订阅列表里重新定位那条。** 那条条目可能已经翻过好几页、
  或者被历史裁剪带走了;有 URL 就开站外原文,没有就切回那个面板并说一句。**退回面板那一步要
  先确认 `origin_ref` 的头一段是来源目录里认得的 id**(`subsCatalog`):`switchTab` 对不认识的
  名字是直接 return、页面一动不动,而紧跟着那句提示写着「已切到它所在的来源」—— 一句假话。
- **列表排序是 `created_at DESC, f.id DESC`,`id` 那一半不能少。** `created_at` 只到秒
  (`kb/web/common.py` 的 `now()`),而「收藏此段」让人在同一段正文上连着选好几句 —— 同一秒
  落库的那几条排序就成了未定义。
- **`_read_body` 对空 path 直接回空串。** 拿 `VAULT_ROOT / None` 去读是 TypeError,会把整条
  行动卡打掉(那是个后台线程,屏幕上只表现为「这一条永远只有引文」)。
- **来源角标只给不是知识库文章的那几类**(`favOriginBadge`)。doc 占绝大多数,标了就是每张卡
  上一枚什么也没区分的徽章(同「图鉴类型色别撞重点色」那条理由)。
- **`kb/static/css/snip.css` 里那个 z-index 是 70**,夹在弹窗(60)和确认框(80)之间
  (要高过抽屉 30 和阅读器 41 —— 图鉴条目正文、订阅阅读器都在它们里面)。
  `kb/web/pages.py` 的 `_DOC_SNIP_JS` 自带一份内联副本(那是脱离 kb-web 也要能用浏览器直接
  打开的独立产物,口径同 CLAUDE.md「视觉语言」那节的三处产物),**色值、圆角、锚点口径改
  一处就要同步另一处**,两处都写了互指注释。两份一度在高亮文字色上对不上:
  内联那份写的是 `#17604F`(`--brand`),而高亮底色是 `--brand-soft`、按 base.css 的口径
  soft 底上的文字该用 `--brand-deep`(`#0E4A3B`)—— 已经按后者对齐。
- **图鉴详情抽屉里出处挂在每个 `.td-entry` 自己的 data 属性上**,按选区往上找宿主
  (`snipHostOf`)。那个容器里并排着一个工具的全部记录,各有各的 path;而小节标题
  (「记录时间线 · N 条」「就这个工具提问」)也住在里面 —— **找不到宿主要自己判空,
  不许靠访问 `dataset` 抛异常被 `snipSourceOf` 的 catch 吞掉**(行为上也对,但判据
  藏进 catch 里,读代码看不出这儿有个判断;见「反向验证」注入 A10)。
- **全文检索面板刻意没接。** 那张卡片渲染的是模型写的摘要和截到 160 字的 `best_chunk`,不是
  原文;而且它已经有整篇收藏的 ★。在摘要上选中收藏,存下来的引文在原文里找不到 ——
  回跳必然失败。

## 事故形态

- **`path` 非空 → 日报/问答片段一条都存不下。** 前端那颗按钮、toast、列表渲染全都写好了,
  POST 回来是 500,`FOREIGN KEY constraint failed`。拿 `''` 当「没有文档」的占位同样被拒 ——
  空串不是 NULL。
- **孤儿行把整次迁移带崩 → 库再也打不开。** 这一条最毒:迁移是在 `store.connect()` 里跑的,
  失败之后不是「收藏面板坏了」,是**所有要连库的入口一起失败**,而且每次重试都在同一行上
  失败,自己好不了。
- **内连接 → 计数和列表分叉。** 「待试 12」而列表里 9 条;剩下那 3 条**既点不到也删不掉**。
  行动卡那一侧是另一个形态:日报片段永远只是一段引文,没有卡,而**指纹是按 `_inbox_rows()`
  那批行算的** —— 漏掉等于新收一条日报片段之后分诊缓存仍判「新鲜」,整轮分诊不重跑。
- **位置证据只听了一半 → 高亮落在一处另一侧已经排除掉的地方。** 三处一字不差的重复句,
  收藏第二处;改稿只动后文之后,前文那一侧认得出第一、二处(两处候选)、后文那一侧唯一指向
  第三处。把「有两处」和「没有」压成同一个值的话,前文那个集合就丢了,只剩后文那个「唯一
  命中」—— 于是点回去高亮的是第三处,**而三处的文字一模一样,页面上看不出来**。
- **核对完到落库之间正文换了一版 → 固化一条永远找不到的收藏。** 订阅正文上点收藏,「收藏中」
  那一下同一篇完成重译并重导出;核对(读 `/api/doc`)读到的是旧那一版、这段话真在里面,而
  INSERT 落的是「绑着那个 path」—— HTTP 200、提示收藏成功,立刻回看是新译文、原句不存在、
  高亮 0 个。**这一件和「屏幕上这份不是盘上那篇」不是同一件**:后者核对拦得住,前者发生在
  核对之后,只有共同的版本号拦得住。
- **核对在临界区之外 → 间隔由对方决定,固化一条永远找不到的收藏。** 上一版把核对挪进了
  INSERT 那个请求里,以为剩下的只是个毫秒级窗口。实测不是:INSERT 要等别人的写事务时,那段
  等待**由对方的事务长度决定** —— 核对与落库之间等了约 1 秒,这期间另一路真走
  `translate._save → sync.export` 把那一篇换成新译文,收藏照旧 200、回看 0 个高亮。
- **同一个文件版本,两头的文本不是同一份 → 核得过、点回去照旧 0 个高亮。** 核对按面板的
  `mdHtml` 算(原始 HTML 成了元素、标签看不见),阅读页把原始 HTML 当**字面文字**显示。跨过
  一段 `<strong>` 的选区在面板上是连着的一句,在阅读页那一头中间插着四个尖括号字:版本号
  相等(文件真没动过)、核对也判「找得到」,当场一切正常,点回去才发现定位不到 —— 而这一类
  **没有退路可退**(原文就是 vault 里那一篇),悄悄存成功是最坏的一种收场。
- **核不过却把新读到的那一版带上 → 后端那道 409 永远判不出「面板旧了」。** 两件事被压成了
  一件:改稿把那句话删掉(该拒、该说刷新)和两头文本不是同一份(该存、该说定位不到)。实测
  改稿删句之后照旧 200 落库,提示说的是「可能定位不到」。
- **删掉原对话之后点那条问答收藏 → 永远停在「加载对话…」。** 这个接口对「会话不在了」回的是
  404 **带一份非空 JSON**,`r.json()` 于是正常解析出 `{detail: …}` —— 只判 `!d` 的那一版接着
  去 `d.messages.map`,当场 TypeError:屏幕停在「加载对话…」,待定位还挂着(下次打开另一个
  对话时它还在),而收藏那条记录本身好好的、引文一个字没丢。
- **「这一刻读不出来」被说成「还没进检索索引」。** 目标真在,只是那一次请求 5xx 或网络抛了,
  前端一律归成「确定没有」:用户得到的理由是错的(他会以为等索引跑完就好了),而 path 也被
  静默丢掉了。
- **按钮浮在不能收藏的地方。** 自测时真遇到过:`showSnipBtn` 原来不问 `describe()`,于是选中
  问答空态那三颗建议按钮、图鉴小节标题,按钮照旧浮出来,一点才换来一句「这一段现在收藏
  不了」。改法是弹之前就问,并**把那句 toast 删掉**(走不到的提示留着只会误导下一个人)。
- **多行代码存成一行 → 引文再也恢复不回去。** 选中四行带缩进的代码,按钮弹了、收藏成功了、
  回跳也定位得到;库里那条 `quote` 是接成一行的那一份,换行和缩进**没有任何地方还留着**。
  这一条的毒性在于它**不可恢复**:定位照旧好使,所以没有任何一处会报错,等发现的时候那段
  原文已经不在了。
- **盘上那篇是旧版 → 存之前目标文件里就没有这句话。** 译文刚写回、还没重导出的那几分钟里,
  面板上读到的是新译文、`path` 是真的、索引里也有行;收下来 `origin=doc`、HTTP 200,点回去
  是上一版正文、0 个高亮、一句「原文可能已更新」—— 而文件**不是收藏之后才改的**。
- **锚点只记 quote → 回跳落在另一处。** 同一句话在一份日报里出现两次时,`indexOf(quote)` 命中
  第一处,用户点回去看到的是另一段上下文里那句一模一样的话。屏幕上一切正常,高亮也在。
- **整锚点失配就挑第一处 → 同一个形态换了个入口。** 前后文记了、但「只 strip 引文」让
  `prefix+quote+suffix` 拼不回原文,于是每一次都走那条退路。**失配的原因可以是空白、可以
  是渲染器不同,表现完全一样:一个落在错地方的高亮。**
- **整段锚点本身就重复 → 两个定位器一起挑第一处。** 一字不差重复两次的整段,连它两头三十个
  字都一样,`p+q+s` 命中两次 —— 「有命中」于是不等于「定得了位」。app 那一侧和独立阅读页那
  一份内联实现**各错一次**,形态一样:高亮在、文字对、落在另一段上。
- **流式途中的问答收下来 → 刷新之后那段话压根不存在。** 追问时会话号早就有了,这一轮却要等
  NDJSON 收完才整轮落库。生成中的半截回答、「已停止(未保存)」、出错气泡、还没落库的那条
  提问,收下来都是「当场成功」:列表里有卡、有引文,点回去打开那个会话,里面没有这几条消息。
- **长链接把整条收藏拒成 422。** 订阅条目带一长串跟踪参数的原文地址原样往上传,后端那条
  `max_length` 一卡就是整条 POST 失败,屏幕上只有一句「收藏失败」—— 用户选完才发现存不下,
  而 404 那条退路只认「这篇还没进索引」,接不住它。
- **升级复用收藏编号 → 旧页面误删新收藏。** 保留一页旧收藏列表,在别处删掉编号最大的那条,
  升级后新存一条,再回旧页点删除 —— 删掉的是刚存的那条,HTTP 还是 204。PATCH(状态流转、
  改备注)和行动卡写回是同一个形态。
- **出处认「正在请求谁」→ 收藏记到另一天。** 切日那一刻屏幕上还是上一份正文,选中收藏存下来
  记的是新那一天;点回去打开新那一份,里面压根没有那句话。再往前一步是**失败提示本身被收成
  片段**:阅读区写着「读取失败」,那四个字照旧弹按钮、照旧存得下。
- **两头渲染器不同 → 存成功、却永远定位不到。** 订阅正文里带 `**` 的一句存成 `origin=doc`,
  HTTP 200、路径和引文都对;点回去阅读页上 0 个高亮,提示「原文可能已更新」,而文件一个字
  没改。
- **正文里有 emoji → emoji 附近那句普通文字收不下来。** 选中的那几个字里一个 emoji 都没有,
  可前后文窗口按 UTF-16 单元截、正好切在它中间;那半个字 UTF-8 编不出来,后端在 INSERT 那一句
  抛,**整条 POST 变成 500**,屏幕上只有一句「收藏失败」,收藏数还是 0。日报和独立阅读页同一
  个形态,标题裁口(300 字、问答那一问 60 字)是同一类。
- **两个哈希相等、盘上那篇已是另一份译文 → 存成 doc、点回去是另一句话。** 保留一页旧订阅
  正文不刷新,后台重译重导出:`exported_hash` 和 `content_hash` 仍然相等(它们是**原文**的
  哈希),旧判据照旧说「盘上那篇就是屏幕上这份」。收藏返回 200、落库 origin=doc,回看正文
  已经是另一份译文、高亮 0 个、一句「没找到这段收藏」。
- **两边的位置证据互相矛盾 → 又一个落在错地方的高亮。** 收藏第二处重复句之后正文改了稿,
  「只用前文」那一档唯一指向第一处、「只用后文」那一档唯一指向第二处;按档位顺序采信的那
  一档命中了,另一边明明还在、明明指着别处,谁都没去看。两份定位实现各错一次,屏幕上照旧
  是「有高亮、文字对」。
- **怎么都分不出来却不说 → 用户到点回去那一刻才发现。** 两处前后各两百字一模一样时,收藏
  存得下、点回去只能是一句「没找到」。app 那一侧早就在收藏那一刻说了,独立阅读页原来一律
  显示普通成功 —— **同一条收藏在两处得到两种交代**。
- **超长原文链接静默丢掉 → 回看只能回到来源面板。** 没有 path 的那一类(退回 feed 的订阅
  条目)靠这个链接回原文,超长就整条不送(半截 URL 点过去是另一个地方),而收藏当场是成功
  的、什么也没说。
- **分流漏掉 → `/doc/#kbq=…` 的死链。** 没有 path 的条目照旧按阅读页链接渲染,地址拼成
  `/doc/#kbq=…`,点下去 iframe 里是一张 404,而卡片看起来和能读的那条一模一样。

## 实测证据

- **非 WAL 的库被多个连接同时 `PRAGMA journal_mode = WAL` 会撞锁,而且不走 busy_timeout。**
  最小复现(12 连接 × 30 轮):非 WAL 起始失败 2 次,WAL 起始 0 次。真实的 v3 库是
  `store.connect()` 建的、一直是 WAL,所以这是**夹具必须照着真实起始态摆**的理由 ——
  照默认模式摆出来的话,那条并发用例测的其实是「转 WAL」,整份跑 60 轮红 3 轮,报
  `database is locked`,跟迁移一点关系没有。改完再跑 60 轮红 0 轮。
- **`ALTER TABLE … RENAME TO` 把索引一起带走,`CREATE INDEX IF NOT EXISTS` 随后按名字静默
  跳过。** 手工复现:改名后 `idx_favorites_path` 挂在 `favorites_v3` 上,新表上
  `CREATE INDEX IF NOT EXISTS` 不报错、也不建(`sqlite_master` 里 `tbl_name` 仍是
  `favorites_v3`),`DROP TABLE favorites_v3` 之后新表索引为空。**但这一条在本模块里兜不住
  任何后果**:重建里那句 CREATE INDEX 排在 DROP TABLE 之后、而 `connect()` 收尾还会无条件
  跑一次 DDL,两道带各自都够 —— 所以重建里那两句索引语句已经删掉了。
- **收藏列表同秒两条的先后在两次加载之间换过位置**(探针里点中的是重复句那条,而断言要的
  是另一条)。这是加 `f.id DESC` 的直接原因;探针那一侧同时改成按 origin **加引文**找按钮。
- **自增高水位在重建里丢掉是实测**(审查那份 `sequence_probe.py`,临时 v3 库 + 真实 API):
  修复前 `sequenceBefore: 10 → sequenceAfter: 9`、新收藏拿到 id 10、旧页面 DELETE 返回 204、
  新收藏消失;修复后 `sequenceAfter: 10`、新收藏 id 11、旧页面 DELETE 得到 404、新收藏还在。
  手工复现也确认了机制:`RENAME TO` 把 `sqlite_sequence` 那行一起改名,`INSERT … SELECT id`
  只把新表的 seq 抬到「插进去的最大 id」,`DROP TABLE` 把旧那行带走。
- **「有文档路径」被当成「逐字相同」是实测**:沙箱正文里写一句
  `请执行 **收藏定位的关键文本** 并核对结果。`,从订阅阅读器选中带星号那一段存下来 → 200、
  路径正确;打开阅读页 → 那一页只有不带星号的文字,高亮 0 个,提示「原文可能已更新」。
- **跨段落的前后文锚点**:同一段正文,订阅阅读器那头段落之间是两个换行、阅读页那头渲染成
  两个 `<p>`(串起来只剩一个换行)—— 不压平空白的话,凡是前后文跨过段落边界的锚点在另一头
  **必然**失配,于是全都走那条「退回只找引文」的路。这是压平比「只修重复句」更根本的理由。
- **「整锚点失配」的真因定点量出来过**:沙箱里那段重复正文,引文在订阅阅读器那条全文上落在
  135,在阅读页那条上落在 228;`q+s` 在阅读页上命中两次(重复整段的后文也一样)、`p+q+s` 则
  因为前文跨过一个 `## 又说了一遍`(阅读页那头渲染成 `<h2>`、井号没了)整段对不上,再加上
  正文末尾那个只在 `textContent` 里存在的换行 —— **三件事叠在一起,表现只有一个:0 个高亮**。
  这是「每一档都要唯一」「退一边那两档」「外侧空白剪掉」各修一件事、而不是互相替代的理由
  —— 其中「外侧空白」那一件**在现在的回归里打不红**,原因见下面 D3/D10/D17 那一段。
- **重复整段那一条在两个定位器上各复现一次**:同一条锚点,app 那一侧的高亮落在第一处、
  独立阅读页那一份内联实现也落在第一处。回归于是按**文本偏移**比对(不是比文字 —— 两处的
  文字都对),两份实现各有自己的红(见下面注入 D4/D5 和 D8/D9)。
- **问答那一条审查那边是按代码推断报的**(没有造流式服务,也没调模型),我们这边把三种状态
  真走了一遍:沙箱把 `chat_api.run_ask_stream` 换成一条不连网的假流(`_stub_stream`,带
  `HANG_MARK` 时就挂住),于是「生成中」「点了停止」「正常收完」是真状态,不是摆出来的 DOM;
  判据落在「这一刻收不收得下」和「把对话从库里重新读一遍,那段话在不在」上。
- **代理对被切开是实测,而且两头各一次**:浏览器真发出去的 POST 里
  `prefix="\ude00xxxxxxxxxxxxxxxxxxxxxxxxxxxxx"`(一个孤立的低位代理 + 29 个 `x`),日报和
  独立阅读页两次都回 **500**,第一次操作后收藏数仍是 0;把同一条请求喂给后端 `_anchor`,
  UTF-8 编码照旧 `UnicodeEncodeError: surrogates not allowed`。另一头:给带 `max_length` 的
  `origin_title` 塞半个字,pydantic 的 `RequestValidationError` **连 422 都发不出来** ——
  错误体里带着 `input` 原串,序列化它再抛一次编码错误(本轮自测复现)。
- **「两个哈希相等」证明不了译文版本是实测**:沙箱走真 `_save → sync.export → _index_pass`
  导出第一份译文,保持阅读器不刷新、以同一英文原文换第二份译文再走一遍同一条链;导出前后
  以及客户端缓存的两种哈希都是同一个值,旧判据 `sourceItemAtPath` 照旧为真,收藏返回 200、
  落库 origin=doc,回看高亮 0 个。
- **「两边证据矛盾」的偏移量过**:同一条锚点(前文 30 个 B、后文 30 个 D),改稿后完整锚点
  不存在、`prefix+quote` 唯一指向第一处、`quote+suffix` 唯一指向第二处 —— app 里实际高亮落在
  偏移 **509**、收藏那一处是 **606**;独立阅读页 **227 / 324**。两份实现各错一次。
- **「两侧候选不相交」的偏移量过**:三处一字不差的重复句(前两处前文相同、第三处后文换成
  收藏时存下的那一份),前文那一侧认第一、二处、后文那一侧唯一指向第三处 —— 日报三处偏移
  **809 / 912 / 1015**,收藏的是 912、旧代码高亮落在 1015;独立阅读页 **223 / 326 / 429**,
  收藏的是 326、落在 429。**两份实现各错一次**,现在两份各有自己的红(注入 F1/F2)。
- **「核对完到落库之间换了一版」在真时序上复现过**:沙箱把那一改挂在「那一次 `/api/doc` 的
  响应已经生成好、POST 还没发出」之间(`install_test_routes` 的 `swap-after-read`,**一个响应
  都不伪造** —— 核对读到的是那一刻盘上真有的那一份,随后文件真的变了)。缺版本号时收藏落
  `origin=doc` 返回 200、回看 0 个高亮;带上版本号之后 POST 得到 409、客户端退回
  `origin=feed` 并说「盘上那一篇刚换了一版正文」。
- **「读不出来」和「不在了」在真文件系统上分得开**:把那个路径换成一个同名目录(权限、网盘
  没挂上、IO 错是同一类 `OSError`,而目录这一种在任何用户下都稳定可复现 —— `chmod 000` 对
  root 无效),`/api/doc` 回 503、落库那一道也回 503;把文件删掉则两处都回 404。
- **「核验还在临界区里」是量出来的,不是读代码读出来的**:给 `_doc_version_now` 套一层只记录
  不改行为的壳,在它被调用的那一刻同时问两件事 —— 维护锁拿得到吗(`maintenance_lock(wait=0)`)、
  写锁拿得到吗(另一个连接 `BEGIN IMMEDIATE`)—— 两样都答「忙」。**反过来钉一边**:请求结束后
  再问同样两句,两样都答「闲」(锁和事务都收干净了,没有泄漏)。
- **「等写锁那一下别人换不进来」是让对手线程真去抢**:对手先 `BEGIN IMMEDIATE` 占住写锁,再
  轮询 `maintenance_lock(wait=0)` 直到它发现请求已经进了临界区,这时才去试那把维护锁
  (`wait=0.5`)—— 结果是 `blocked`,它只能回滚;请求照旧 200,盘上那一篇**逐字节未变**。
  对手真换成功的那一半另有一条:换完之后拿旧版本号存 → 409、0 行,拿新版本号存 → 200。
- **拿不到维护锁时是 503、一个字节没写**:让另一个线程把锁拿着、`_DOC_LOCK_WAIT` 调成 0.2 秒,
  绑文档那条收藏得到 503(话里有「没法核对」)、库里 0 行;锁放开之后同一条收 200。**反过来
  钉一边**:同一刻没有 path 的日报片段照旧 200 —— 一次维护不许把整个收藏入口堵住。
- **摘要行那一段浏览器自己就不交出来**:在 `<summary>` 里按压平坐标系设好 Range 之后
  `getSelection().toString()` 是空串(`isCollapsed` 却是 false),于是字数那道判据先把按钮
  按下去了。所以「正文之外的字不许收」这条判据的落点换成了那三颗链接按钮(选中「在阅读器
  打开」:修复前照旧弹按钮、照旧落库一行)。
- 浏览器那条链的判据跑在一个真沙箱上:真走 `put_items → export → index` 出一篇订阅译文
  (有 `documents` 行)、真写一份 `vault/daily/<日期>.md`(有文件、没有 `documents` 行)、真往
  `conversations`/`messages` 落一轮问答(连文件都没有)。一个模型调用都不花。
