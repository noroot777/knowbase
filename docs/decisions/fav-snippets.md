# 「收藏此段」长在所有能展示原文的地方(kb/static/js/snip.js、favorites 的 v4)

> **这一份整份都是这一块的记录:硬约束 + 事故形态、实测证据、回归清单和反向验证红数** ——
> 动这块代码之前先读它。CLAUDE.md 只留跨块的元规则和一张索引。

原来这个功能只长在 `/doc/…` 阅读页里(`kb/web/pages.py` 的 `_DOC_SNIP_JS`)。每日日报、
知识问答、我的订阅、图鉴条目各渲染一份正文,却都收藏不了。

## 硬约束

> 收藏表的建表 DDL 和它那几条迁移在 **`kb/store_migrate.py`**(连同 documents / entities 的补列)
> —— `store.py` 只剩建表与读写,两边唯一的入口仍是 `store.connect()`。

- **`favorites.path` 可空(v4),空值是 NULL、不是空串。** 日报写在 vault 的 `daily/` 下,
  **那个目录不在任何 `SOURCES.root` 底下**(`kb/config.py`),索引跑完它照旧不在 `documents`
  里;问答回答压根不是文件;订阅条目在导出之前只在 feeds.db 里。而 `path` 原来是
  `NOT NULL REFERENCES documents(path)`,外键在 `PRAGMA foreign_keys = ON` 下**对空串照查**
  (只有 NULL 豁免)—— 拿 `''` 占位的写法一条都存不进去,报 `FOREIGN KEY constraint failed`。
  **`path` 非空时外键和级联语义一个字没变**(只增不减)。
- **去掉 NOT NULL 只能重建整张表**(SQLite 没有 `ALTER COLUMN`),而重建是这条路上唯一会丢
  数据的一步。所以 `_rebuild_favorites_v4` 三条都得照办:
  - **按老表实际有的那几列拼 INSERT**(`_FAV_CARRIED` 过一遍 `PRAGMA table_info`)。v2 没有
    `action_json`,写死一份列名会让它在 `no such column` 上翻车。
  - **孤儿行的 path 落 NULL**(`CASE WHEN EXISTS (SELECT 1 FROM documents …)`)。外键是 ON 的,
    INSERT 回去逐行查 `documents` —— 历史上留下的、文档已经不在索引里的收藏(原来内连接下
    就看不见、却仍占着计数)会让那一句整条失败,于是 **`store.connect()` 本身再也成功不了**:
    页面 API、提取 worker、CLI 全挂,而迁移每次重试都会在同一行上失败。
  - **整段在一个写事务里,并在锁里重新读一次列集合**(口径同 `store_migrate.add_columns`)。常态(已经
    是 v4)在函数外那句 `PRAGMA table_info` 就返回了,一次锁都不取。
  - **把自增高水位一起搬过去**(`_carry_sequence`,排在 `DROP TABLE` 之前 —— 临时表一删,
    它那行 `sqlite_sequence` 就跟着没了)。`RENAME TO` 会把那一行一起改名,而新表那行是按
    「插进去的最大 id」重新算的:**编号最大的那条已经删掉时,新表的高水位比历史分配过的
    低,下一条新收藏就复用一个已经发出去过的编号。** 后果不是编号不好看 —— 收藏列表上
    那几颗按钮、`favorites_api` 的 PATCH/DELETE、`favbrain` 的行动卡写回全都只拿着 id,
    不复用时过期那一页最多得到 404,复用之后同一个请求会**成功作用在另一条收藏上**。
    v1 那条分支也过这个函数(它没有自增行,函数自己返回)—— **不变量待在一处,不是每条
    分支各记一遍**。
- **锚点那四列(`quote_unique` / `anchor_exact` / `origin_msg` / `doc_version`)只增不减,而且空值是「没记下」、不是 0 也不是空串。**
  老库里 favorites 已经在了,`CREATE TABLE IF NOT EXISTS` 不补列,只能 ALTER
  (`migrate_fav_anchor`,口径同 `migrate_promo`)。**判不准一律扣留**:`quote_unique`
  为 NULL 时回跳**不走**裸引文那一档(见下面「采集那一刻有几处」那条),`origin_msg` 为空时
  问答归属只核到会话一级,`doc_version` 为空时证明不了「要搜的这一篇就是采集时那一篇」、
  于是**弱档一律不采信**(见下面「弱档要先证明同一份语料」)。反过来把 NULL 当 0 / 空串用也
  错不到一处 —— 0 的意思是「当时就不只一处」,那是一个**结论**,而 NULL 是没有结论;
  `doc_version` 的空串会和「这一刻版本号读不出来」撞成一件事,前者是历史遗留、后者是此刻
  的故障。接口那一头同样不许 `COALESCE`(`_FAV_SELECT`)。
  **`anchor_exact` 的 NULL 往哪一边倒是反过来的**(放行,理由见下面那条)—— 可它同样只有
  「没记下」这一个意思,三态都得留住。
- **索引只由 `FAVORITES_DDL` 管一处。** `connect()` 在 `migrate_favorites` 之后无条件跑一次
  `executescript(FAVORITES_DDL)`,所以不论哪条迁移分支中间把它弄没了(索引跟着 `RENAME TO`
  挂到临时表上、临时表一删就跟着没),连接交出去之前都会被补回来。**迁移里不要再各自
  DROP/CREATE 一遍** —— 那是夹在两道带中间的死代码,见下面「反向验证」里注入 B2/B16。
- **列收藏用 LEFT JOIN,不是 JOIN**(`_FAV_SELECT`,`favbrain.extract_action` 和 `_inbox_rows`
  也是同一份)。内连接会让两类条目在列表里静默消失:没有 path 的(日报/问答片段),以及
  文档已经不在索引里的 —— 而**计数(`counts`)是全表数的**,于是标签上写着「待试 12」、列表
  里只有 9 条,剩下 3 条点不到也删不掉。
- **元数据有两个来源,顺序是「索引里那篇优先、收藏那一刻的快照兜底」**
  (`COALESCE(NULLIF(d.title, ''), f.origin_title)` 这一族)。`origin_title` / `origin_url` 是
  收藏那一刻存下的快照,**只在没有文档时顶上**:有文档时标题跟着索引走(重译、改标题之后
  列表里是新的那个)。
- **交给前端的 `path` 一律是空串,不是 null**(`item["path"] = item["path"] or ""`)。前端那套
  `docLink`/`obsLink` 直接拼,null 会拼出 `/doc/undefined`。
- **`doc_paths` 要排掉 NULL**(`WHERE quote='' AND path IS NOT NULL`)。整篇收藏只存在于 doc
  来源,但迁移置空过的孤儿行也满足 `quote=''` —— 不排掉就往这个数组里塞一个 null,而前端
  拿它当 Set 的成员去比对每张搜索卡片。
- **`path` 给了但不在索引里 → 404,后端不替调用方降级。** 把一条本该能定位回原文的收藏静默
  换成只有引文的那一类,是**调用方**该做的决定:它知道自己手里那篇有没有入库。订阅阅读器
  正是靠这一条退的(`sourceItemSnipSource` 的 `fallback`:md 落盘了、索引那一步还没跑的那几分钟
  里,`path` 是真的、`documents` 里却还没有行),退完还要如实告诉用户「这篇还没进检索索引,
  点回去会打开站外原文」。
- **绑了文档的收藏必须说清绑的是哪一版正文,落库前再核一次。** `POST /api/favorites` 带
  `doc_version`(缺了 400),后端按**盘上此刻**那一篇再算一次 `scanner.body_version`,不等就
  409。**核对和写入是两个请求**:调用方读 `/api/doc` 核对完、POST 还没到的那一下,重译写回
  (`translate._save`)、正文补抓(`fulltext`)照样会把那一篇换成另一版 —— 没有共同的事实,
  收藏照旧落成 `origin=doc` 返回 200,固化下来的是一条**点回去永远找不到那句话**的收藏,而
  当场一切正常。
  **「核验 → 写入 → 提交」整段待在同一个临界区里,不是「排得近一点」。** `doc_version` 是
  一次**取样**,临界区才是不变量:改那一篇的几条路(订阅同步导出末尾那句 `os.replace`、重译
  写回、正文补抓、展示层改写 `doc_rewrite`)**全都认同一把维护锁**(`kb/maintenance.py`),
  所以核验和 INSERT 一起圈进那把锁,它们就进不来;数据库那一头另有一道 —— `BEGIN IMMEDIATE`
  排在**读版本之前**,于是 INSERT 不会在「核完之后」再去排队等写锁。**只缩短间隔不算修**:
  INSERT 要等别人的写事务时,这个间隔由**对方**决定(实测核验与落库之间等了约 1 秒,期间另
  一路真走 `translate._save → sync.export` 把那一篇换成新译文,收藏照旧 200、回看 0 个高亮)。
  推论七条:
  - **版本号只认正文,不许用整份文件的哈希。** `body_version` 只哈希 `parse_frontmatter` 之后
    那一段;按 `file_hash`(也就是 `documents.content_hash`)算的话,提取回写那一刻的收藏会被
    **误拒** —— 那一步只往 frontmatter 里补 tags、写 extracted_at,正文一个字没变,收藏点回去
    照旧定位得到。和 `kb.extract_version.body_fingerprint` 算的是同一个数却各写一份:那一族判
    「模型结论针对的输入还是不是当前这份」,这一族判「收藏绑的目标还是不是用户看过的那份」。
  - **报版本号的三处和落库前再算一次的那一处,读法必须同一份**(`scanner.read_md_text`,解码
    一律 `errors="replace"`)。一处严格、一处 replace 的话,文件里有一个坏字节就会算出两个
    版本,把一条好收藏误拒成「原文已更新」。
  - **拒绝的三种形态各报各的:404 不在了 / 503 读不出来 / 409 已经是另一版**,口径同
    `/api/doc`(两头共用 `kb/web/common.py` 的 `read_doc_text`)。调用方按状态码决定退回哪一
    档、怎么跟用户说;合成一种的话,「这一刻读不出来」就被说成了「这篇还没进检索索引」,而
    后者是个**已经证明了的结论**(等索引跑完就好了),前者只是一次失败。
  - **三个绑文档的入口都得把版本号带上**:订阅阅读器从那次核对里带出来(`snipVerified` 把
    `doc_version` 挂到最终那个来源上)、图鉴条目从 `/api/projects/{norm}` 的 `version` 读
    (挂在每个 `.td-entry` 的 `data-snip-version` 上)、独立阅读页从渲染那一刻烤进 HTML
    (`DOC_VERSION`)。**有退路的那一个退一步**(409/503 退回 `origin=feed`,如实说退的是哪
    一种);**没有退路的那两个如实拒**,并且只许说「刷新页面再收藏」—— 同一个工具关掉重开
    抽屉用的是现成视图(`openToolDrawer` 的 `!changed && toolMeta`),版本号跟着那份视图一起
    还是旧的,说「重新打开这条记录」就是让用户再撞一次同一面墙。
  - **锁序是「先维护锁、再 `BEGIN IMMEDIATE`」,不许反**(反过来报的 `SQLITE_BUSY_SNAPSHOT`
    不受 `busy_timeout` 管),取维护锁之前**先把手里那个写事务落盘** —— 同
    `kb/extract.py` 的 `save_and_writeback`,口径在 `docs/decisions/maintenance-lock.md`。
  - **等不到那把锁按 503 收场、一个字节没写。** 这是「这一刻没法核对」,不是「那一篇不在了」
    (404)、也不是「已经是另一版」(409);等多久有上限(`_DOC_LOCK_WAIT`,比维护那一侧的
    900 秒短得多),等不到就出声,不许无限等、也不许跳过核验硬写。客户端那三条退路按状态码
    分(`RETRY_NOTE`)。
  - **只有绑文档的那一类取这把锁。** 日报、问答、订阅退回 feed 的那几类压根不读文件,把它们
    也串进去等于让一次维护把整个收藏入口堵住(回归反过来钉了这一边:维护锁被别人拿着时,
    没有 path 的日报片段照旧 200)。
- **`origin=doc` 成不成立,由「存之前去读那一篇、在里面找这条锚点」决定,不许用客户端手里的
  字段推断。** 判据只有一处(`snipVerified` + `snipDocText`):`describe()` 给一个
  `docText()`,它去读 `/api/doc?path=…`(**阅读页渲染的就是这个文件**,所以要照
  `doc_page` 同一条正则剥掉 frontmatter),**按阅读页那一头的规则**渲染、压平,再跑一遍
  `snipSeek`;找得到才存 `origin=doc`,否则落到 `fallback`(`origin=feed`,回跳走站外原文),
  **退的理由如实写进提示,而且「确定没有」和「不知道」要分开**(`absent` = 那一篇**确定**
  不在,只有 404 算;`unreadable` = 这一刻读不出来/不知道 —— 请求抛了、5xx、JSON 坏了、服务端
  没报版本号;`mismatch` = 读到了但这段话不在里面)。合成一种的话,一次暂时的失败会被说成
  「这篇还没进检索索引」,而那是个已经证明了的结论。
  这一道同时收掉三件**表现完全一样**的事 —— 收下来 HTTP 200、路径和引文都对,点回去 0 个
  高亮、一句「原文可能已更新」:
  - **盘上那篇可能不是「屏幕上这一份」正文。** `path` 是上一次导出留下的,而重译
    (`kb/feeds/translate.py` 的 `_save`)、正文补抓(`kb/feeds/fulltext.py`)都保留它。
  - **md 落盘了、索引那一步还没跑**:`/api/doc` 对它判 404 → `absent`。
  - **两头摊的不是同一种文本。** 订阅阅读器按 `textContent` 原样摊开正文(`**`、反引号、
    `[字](url)` 看得见),`/doc/…` 把同一份 md **按 markdown 渲染**(`marked.parse`),那些
    标记在那一头消失或变形。
  **原来这里拿 `exported_hash === content_hash` 推断「盘上那篇就是这份正文」(`sourceItemAtPath`),
  那个判据立不住,已经删掉。** 它是**原文**的哈希:`kb/feeds/sync.py` 导出成功那一句写的就是
  `exported_hash=content_hash`,而同一篇原文重译一遍、重导出一遍,这两个值一个字节都不变 ——
  「两个哈希相等」和「盘上那篇是哪一份译文」没有关系(审查实测:保留一页旧阅读器不刷新、
  后台重译重导出,两个哈希仍相等、旧判据照旧为真,收藏存成 doc 返回 200,点回去正文是另一份
  译文、0 个高亮)。**推断换成核对**:它不押在「谁改过正文」这件事上,下一个改正文的入口
  也不必来改这里。
  **核对要按「点回去那一页会看到的那份文本」算,不是按面板这一份算。** 两边差的是原始 HTML:
  面板的 `mdHtml` 把它交给 DOMPurify(标签成了元素、本身看不见),阅读页**把它当字面文字
  显示**(`_DOC_LITERAL_JS`,为的是 `List<T>`、`<dependency>` 这类示例在正文里看得见)。拿
  面板那套规则核的话,跨过一段 `<strong>` 的选区在面板上是连着的一句、核得过,点回去那一头
  中间却插着四个尖括号字、0 个高亮 —— 当场一切正常。所以共享层自己拿一份**独立的** marked
  实例照阅读页的规则渲染(`snipDocRenderer`,`new marked.Marked({renderer:{html}})`);
  **不许走 `marked.use()`** —— 那是全局的,图鉴、日报、问答、素材账本要的正是「标签当标签」
  (日报出处那一族还和它逐字节对齐)。这份规则**和阅读页那份是孪生的,改一处要改两处**
  (`kb/web/pages.py` 的 `_DOC_LITERAL_JS`,两处互指注释)。
  **核不过时怎么收场分两类:有退路的退回 feed;没有退路的照存、但当场说清。** 没有退路那
  几类(独立阅读页、图鉴条目)的原文就是 vault 里那一篇,退无可退 —— 悄悄存成功是最坏的一种
  (库里那条看着好好的,用户要到点回去那一刻才发现)。
  **核不过就把面板手里那一版原样送上去,不许把刚读到的新版本号带上。** 后端那道 409 于是
  正好替我们把两件事分开:两版**不等** = 面板旧了(改稿很可能正是把那句话换掉的那一下)
  → 409、一行不落、提示说「刷新再收藏」;**相等** = 文件没动过,核不过只是两头的文本不是
  同一份 → 照存、说清点回去可能定位不到。带上新版本号的话后面那道就永远判不出「面板旧了」,
  改稿把那句话删掉也照存。
  **`docText()` 读不到(404、请求失败、没报版本号)一律当「核不过」**,不许当成核过了:那会
  把一条永远定位不到的收藏固化下来,而退一步的代价只是回跳打开站外原文。
  **POST 被拒之后那三条退路留着,是第二道带子**(`RETRY_NOTE` 的 404/409/503):核对和 POST
  是两个请求,中间那一下索引行照样会没、正文照样会换一版、文件照样会读不出来;而不给
  `docText`、只给 `fallback` 的来源只有这一道。
  **这道核对是「类」约束:每个绑文档的入口都要过它,一个不许少。** 原先以为图鉴条目不需要
  (抽屉渲染的是 `mdHtml(e.body)`,`e.body` 就是那篇条目 md 去掉首行出处引用之后的正文,
  `kb/projects.py` 的 `get_tool` —— 看着是「同一个渲染器、同一份字符串」),可**阅读页那一头
  不是这个渲染器**:同一份字符串里那段原始 HTML 在抽屉里看不见、在阅读页上是四个字面字,
  同一个文件版本、两头的文本就不是同一份。所以图鉴条目也给 `docText`,和订阅阅读器、独立阅
  读页同一道。订阅阅读器只是额外多一座「纯文本 → markdown 文档」的桥(也是唯一有「盘上那篇
  停在旧版本」这个窗口的来源),那让它多一条退路,不是让它独占这道核对。
  **核对和保存契约各管一头,都不能省**:核对解决「两头摊的不是同一种文本」,契约解决「核对
  完到落库之间换了一版」(抽屉开着的这几分钟里那一篇被换掉,核对躲不过)。
  **这道判据待在订阅阅读器 + 共享采集层这一侧,不是 `favorites_api`**:后端认不得 markdown
  (渲染在浏览器里),也不许为了拿 `feed_items` 去 import `kb.feeds.*`(CLAUDE.md「仓库结构」)。
- **没有文档的收藏必须带 `origin_title` → 否则 400。** 列表、分诊、行动卡都靠它指代这一条,
  缺了就是一张无字卡片,而收藏当场是成功的。
- **快照字段的长度上限两头必须对齐:标题可以截,URL 只许整条丢。**
  `SNIP_MAX_TITLE = 300` / `SNIP_MAX_URL = 4096`(`snip.js`),和后端 `origin_title` /
  `origin_url` 的 `max_length` 是同一组数。这两个值是**内容自带的** —— 标题来自订阅条目和
  图鉴条目,URL 来自站外原文地址,带一长串跟踪参数的真实 URL 过 2048 是现实存在的,而各处
  `describe()` 都是原样往上传。两头对不上的后果是**整条 POST 被拒成 422**:用户选完才发现
  存不下,屏幕上只有一句「收藏失败」,而 404 那条退路接不住 422(它只认「这篇还没进索引」)。
  **URL 不许截**:半截 URL 点过去是另一个地方,比没有链接更坏 —— 超长就送空串。**而「送了
  空串」这件事,没有 path 的那一类要当场说**(「这条来源链接太长没能一起存下,点回去只能回到
  来源面板」):那时链接是回原文的唯一一条路。绑了文档的那一类回跳本来走阅读页,说它反而是
  噪音,所以那一句的判据是 `!eff.path && snipUrlDropped(eff)`,而 `eff` 是**最终真存下去的
  那个来源**(退过一步之后不是原来那个)。
- **`SNIP_ORIGINS`(前端)和 `_ORIGINS`(后端)是同一份名单**,加一种来源两边一起加;后端
  把不认识的 origin 拒成 400。
- **锚点坐标系必须和阅读页逐位对齐,而且只有一个:压平空白之后的全文。**
  `snipTextIndex` 用 TreeWalker 把容器里所有 text node 串成一条全文,**一段连续空白
  (空格、换行、制表、NBSP)一律当一个空格**,并记下每个字出自哪个节点的哪一位;前后文的
  截取、锚点的匹配、回跳的定位共用这一条全文。压平是必需的:同一份正文在两头的空白本来
  就不一样 —— 订阅阅读器摊的是 `textContent`(段落之间两个换行),阅读页把同一份 md 渲染
  成一串 `<p>`(串起来只剩一个换行),不压的话前后文锚点**一碰到段落边界就对不上**。
- **压平出来的那条全文只是「匹配表示」,不是收藏内容:`quote` 一律按原文逐字存。**
  采集那一刻拿 `snipOffsetRange` 把 `[a,b)` 换回 DOM Range、取它的 `String(range)`(端点
  落在元素边界那条退路取 `String(range)` 自己),只去两头空白;**压平留到读的时候才做**
  (`snipAnchor`、后端 `_anchor`)—— 对同一段话压一遍恰好等于 `idx.text.slice(a, b)`,所以
  匹配和保真同一个来源、不会差位。存压平版的后果是静默而且**不可恢复**:多行代码、带缩进
  的列表、分行的清单,存进库就成了接起来的一行,收藏面板、导出、行动卡上那段引文再也恢复
  不回去,而定位、回跳、高亮全都照旧好使 —— 没有任何一处会报错。推论三条:字数下限
  (`SNIP_MIN`)要判在**压平过的那一份**上(否则「冒号 + 四个空格 + 一个字母」算七个字),
  而且**弹按钮和存库同一份判据**(`showSnipBtn` 和 `saveSnip` 都过 `snipCollapse`)——
  两处分叉的话,这种选区会弹出按钮、点下去却静静收起,又是一颗点了什么也不会发生的按钮;
  后端 `_anchor` 只压 `prefix`/`suffix`,**不许把 `quote` 一起压**(那是同一个错换个地方犯)。
- **引文两头的空白在采集那一刻就挪出引文**(`snipSpec` 那两个 while 把 `[a,b)` 收到非空白
  上),读的时候再收一道(`snipAnchor` / 后端 `_anchor`:`q` 以空白开头就给 `p` 补一个空格、
  以空白结尾就给 `s` 补一个,接缝上只留一个)。不变量是 **压平之后 `prefix + quote + suffix`
  仍是正文里连着的一段**。只 `strip()` 引文是不行的:前后文照旧带着被剥掉的那几个空白,整段
  锚点就再也拼不回原文。两道带各自都够(见下面注入 C2/C6/C12)。
- **前后文最外侧的空白要剪掉**(`p` 去头、`s` 去尾,`snipAnchor` 和 `_anchor` 各一份)。接缝
  那一侧的空白**带着位置信息**(引文首尾那几个空白正是挪过来的),外侧那一侧**什么也不说
  明**,而且两种渲染给出来的还不一样:正文最后一段在订阅阅读器的 `textContent` 里后面跟着
  一个换行,渲染成 HTML 之后那儿什么都没有。不剪的话整段锚点差一个空格就失配,于是掉到更
  弱的档、或者干脆落到「没找到」—— 而路径、引文、HTTP 全是对的,页面上看不出哪儿错了。
- **定位按「候选集合」算,不按「档位顺序」挑;最后只剩一处才采信。**
  (`snipSeek` / 阅读页内联副本 `seek`,两头各一份、改一处要改两处。)
  - **每一侧都留全部候选,`snipAll`/`hitsOf` 回的是数组。** 前文那一侧(`p+q`)和后文那一侧
    (`q+s`)各有两种空法,**它们不是一回事**:0 个 = 这一侧的证据在这份文本里**用不上**;
    多个 = 这一侧**自己定不了位**,可它仍然把范围缩到了那几处。原来两种都回 `-1`
    (`snipOnly`/`only`),**后一件的证据就丢了** —— 前文明明说「只可能是第一处或第二处」,
    后文唯一指向第三处,丢掉前文那个集合之后只剩一个「唯一命中」,于是静默高亮一处前文已经
    明确排除掉的地方。
  - **两侧都还有候选就取交集**(交集正是整段 `p+q+s` 命中的那几处:`p+q` 在 x 处命中且
    `q+s` 在 x 处命中,等价于 `p+q+s` 在 `x-|p|` 处命中 —— 所以**不必再单列「整段」那一档**,
    它是这条规则的推论,不是另一道判据)。一侧用不上就只听另一侧,两侧都用不上才退到裸引文。
  - **最后一律要求只剩一处。** 剩两处是正文自己分不出的两处(一字不差重复的整段、模板说明、
    重复的代码块,连它两头三十个字都一样);剩零处是两侧的证据互相矛盾。**两种都如实说没
    找到** —— 锚点还在、位置说不清,比挑一处诚实:静默挑一处是把一句「没找到」换成一个落在
    错地方的高亮,而那几处的文字一模一样,用户从页面上看不出来。
  - **反过来钉一边:一侧有歧义不等于整条锚点作废。** 前文有两处候选、后文指着其中一处时,
    交集唯一 —— 那一条**照旧要落回那一处**。「一有歧义就全拒」也能让「不许高亮错地方」那几条
    全绿,而它把本来定得回去的收藏一起废掉(注入 F3/F4 各红 1 条就是这条反向判据)。
  - **「只听一侧」不是摆设。** 同一条锚点可能在另一种渲染里只对不上**一侧**:订阅阅读器摊的
    是 md 原文(`## 标题` 带着井号),`/doc/…` 把它渲染成 `<h2>`(井号没了)—— 前文跨过一个
    标题就失配,而后文那一侧分毫不差。少了这一支,带标记的正文里凡是前后文跨过标记的锚点
    **全都退到裸引文**,碰上重复文字就是一句「没找到」。这一格有自己的夹具(订阅那篇里靠
    小标题分隔的那对重复句),**两份实现各有自己的红**(注入 D4/D8)。
  - **数不完的那一侧也算说不清。** `snipAll` 数到 `SNIP_MAX_HITS`(64)就停,多出来那一个是
    「数不完」的信号,`snipSeek` 见到就回 null:截断过的集合拿去取交集会让交集**偏小**,而
    偏小正好是误采信的方向(交集恰好剩一处 → 采信一处位置可疑的高亮)。宁可多拒。
- **弱档(只听一侧、退到裸引文)要先证明「要搜的这份语料就是采集时那一份」。**
  (`snipSeek` 的 `spec.same` / 阅读页内联副本 `seek`,两头各一份、改一处要改两处。)
  一侧的**三种状态不许压成两种**:`null` = 这条锚点天生没有这一侧(引文顶在正文开头或末尾,
  采集那一刻就没取到前文/后文)—— 照旧只听另一侧;`[]` = **有这一侧、却在这份文本里一处也
  对不上**;非空 = 它认的那几处。中间那一种是分界:**它说明这份语料已经不是采集时那一份了**,
  那时另一侧的「唯一命中」证明不了它就是原处 —— 三处一字不差的重复句,收藏第二处、后来只把
  第二处的后文改掉,前文那一侧仍然唯一地指向第二处的**前一处**,于是静默高亮一处早该排除的
  地方(审查用生产函数实测:收藏偏移 912,改稿后回查 1015)。所以**除非证明得出是同一份
  语料,一侧失配就如实说位置说不清**。
  - 能证明的只有两种,别处一律按「不能」办:
    - **绑了文档的收藏**:`favorites.doc_version` 等于阅读页此刻那一篇的 `DOC_VERSION`
      = 文件没动过,那一侧失配只能是**两种渲染摊出来的文本不一样**(md 原文 `## 标题` vs
      渲染后的 `<h2>`)—— 弱档正是为这件事存在的。
    - **采集和回跳摊的是同一个单元**:问答那一条消息(落库之后不会再改,身份就是
      `favorites.origin_msg`;采集那一头的坐标系也正是那一条气泡,见下面「问答以消息为单元」)。
    - 日报正文、订阅正文**不在其中** —— 两头是同一个渲染器,一侧对不上就只能是正文自己变了,
      没有「两种渲染」这个借口。
  - **采集那一头 `same` 是事实而不是假设**:`snipContext`、`snipSpec`、`snipVerified` 手里那份
    文本就是此刻这一份,而 `snipVerified` 核过之后**把它那一版的版本号跟着收藏一起落库**。
    少了这一条,核对那头按宽档算出「定得到」、回跳那头按严档判,库里 `locatable` 写着定得到、
    点回去却是一句「没找到」。
  - **漏报顶多是一句如实的「没找到」,误报是静默跳到另一段话。** 这一道收紧之后,老收藏
    (没有 `doc_version`)和改过的文章都只认「两侧都对得上」的锚点 —— 那是宁可多拒的方向。
- **`doc_version` 要一路走到判它的那一头**:核对(`snipVerified` 读 `/api/doc`)→ 落库
  (`favorites.doc_version`,写入前后端按盘上此刻那一份又核过一次)→ 收藏面板拼 `#kbq=` 里的
  `v`(`favDocAHtml`)→ 阅读页和 `DOC_VERSION` 相比。**中间少一环,后果分两种**:落库或拼链接
  那一步丢了它 → 所有绑文档的收藏在**没改过**的文章上也退成「说不清」(漏报);阅读页忘了比
  → 改稿之后那一处同句照旧被当成原处高亮(误报)。`favJumpHtml` 那条路**不带** `v` —— 它只给
  没有 path 的收藏用(日报/问答/没导出的订阅条目),它们压根不绑文档。
- **裸引文那一档只有在「采集那一刻这段话就只有一处」时才算证据**
  (`favorites.quote_unique`,采集时真数一遍存下来)。两侧上下文都失配是常态(改稿、重译、
  正文补抓都会这样),这时只剩「按引文全文搜」这一档 —— 而**「现在只剩一处」证明不了「这一处
  就是当时那一处」**:当时有两处、收的是第二处,后来第二处被改掉,剩下的第一处按裸引文找正好
  唯一,采信它等于把另一处同句**冒充**成原位置(实测:收藏第二处、随后删掉第二段,回查命中第
  一段里的同句)。`u !== 1` 一律不走那一档,如实说没找到。
  - **`u === 1` 也只是必要条件**:这一档同样要上面那条 `same`。「两侧上下文全失配」本身就说明
    正文变过,那时连「当时唯一」也只在当时成立 —— 原句被改稿搬走、别处新写了一句一模一样的,
    裸引文照样唯一命中(审查用生产函数实测:收藏偏移 153,删掉原处之后回查到 45),于是一段
    用户从没收藏过的文字被当成他收藏的那一段高亮出来。
  - **NULL 是「不知道」,不是 0。** 老收藏没有这个数,那一档照旧不给用 —— 判不准一律扣留。
  - **这个数要一路走到判它的那一头。** 库 → 收藏面板 → 回跳,中间两条**不同的代码路径**各带
    一份:绑了文档的那一类是一条带 `#kbq=` 的阅读页链接(`favDocAHtml`),没有 path 的那几类
    是 `data-jump` 的回跳按钮(`favJumpHtml` → `jumpFavOrigin`)。少带一个 `u`,那一头只知道
    「不知道」,于是**采集那会儿确实只有一处的收藏也点不回去了**(屏幕上一句「没找到这段
    收藏」,而库里那条好好记着 1)。**两条路径各有自己的红**(注入 I9a / I9b)。
  - **采集和回跳两份实现各数一次**(`snipSpec` / 阅读页内联的 `uniqueIn`),改一处要改两处。
  - **核验(`snipVerified`)那一步的 `same` 按证明得出来的算,`u` 按屏幕那一份算,两个都不许
    写死。** 那一步问的是「这段话此刻在那一篇里还在不在」,可它一旦答「在」,收藏就**绑上
    盘上此刻那一版**落库返回 200 —— 后端那道 409 于是永远判不出「面板旧了」。
    - **`same` 的唯一证明是 `sameCorpus`:来源自己报得出它展示的是哪一版、而且那个数和刚读到
      的相等。** 两种「证明不了」都不许当成同一份:**版本号不等**是正面证据(这一篇在面板
      开着的这几分钟里换过一版);**说不出版本**是手里压根没有可被反驳的事实 —— 原来这一档
      按「两头渲染本来就不一样」默认同份,那是把**没有证据**当成了**证据**。
    - **`u: spec.unique ? 1 : 0`(不是写死 1)**:屏幕上就有两处时谁也说不出用户选的是第几
      处,而盘上只剩一处恰恰说明原处被删掉了。`partial` 的来源(列表卡、搜索卡只摊一截)
      `spec.unique` 本来就是 0,同口径一律不采信。
    - **证明不了时关掉的是两档弱档,不是整个核对**:裸引文(它还另要 `u === 1`)和「只听另一
      侧」都不采信,如实判 `mismatch`。三条实测事故各对一档 ——
      ① 两份语料里这句话**各只有一处**,而盘上那一处是改稿新写在另一节的(旧抽屉版本
      `eadb7fb8`、核对读到 `15f02774`):裸引文那一档。
      ② 两节里各写一遍、**连前文也一字不差**,旧抽屉上选的是第二节,盘上随后把第二节连后文
      一起换掉(旧页面 `351ade05`、盘上 `2c4ef0c0`,返回 200 / id=1,回看高亮第一节):
      前文那一侧唯一命中第一节 —— **「只听另一侧」那一档**。
      ③ 订阅阅读器那阵子**压根报不出版本号**,盘上那一篇把原处那一段换掉、另一节新写了一句
      一模一样的(阅读器那一份 `7f1aca69`、盘上 `8dc78146`):「说不出」被按「同一份」办。
    - **关掉的只是弱档,「两侧都对得上」那一档不问 `same`。** 那一档是整段锚点自己的位置证据
      (`p+q` 和 `q+s` 在盘上那一份里交出同一处),版本不等也该放行 —— 盘上末尾补了一段、
      原句连前后文都还在的那一条就靠它(`tests/snip_probe_bind.mjs` 第 4c 格:照存、绑新那
      一版、提示里不许出现「刷新」)。
- **摊了文档正文的来源,都得报出「我摊的这一截是按哪一版切的」(`doc_version`),而且这个数
  必须和它摊出来那份语料同源。** 这是上面那道 `sameCorpus` 唯一的输入,四处各有各的来路:
  - 图鉴条目接口**随正文一起给**(`kb/projects.py` 里 body 和 version 同出一次读);
  - 独立阅读页**烤在自己那份 HTML 里**(`DOC_VERSION`);
  - 订阅条目行摊的是 feeds.db 里那一行(`body`/`body_zh`),所以按**那一行内容**算出「它导出成
    md 之后正文该是什么指纹」(`kb/feeds/exported.py` 的 `item_body_md` → `scanner.body_version_of`,
    `/api/intake/{kind}/items` 接一次);
  - 搜索命中摊的是**建索引那一刻**切下来的 `best_chunk`,所以只在「建索引时那份文件和此刻盘上
    这一份逐字节相等」时才报(`kb/web/common.py` 的 `indexed_doc_version` 比
    `documents.content_hash`,`/api/search` 接一次)。
  前端 `source_reader.js` / `snip_cards.js` 原样挂到出处上,一个字都不许自己推。
  - **「响应那一刻读一遍盘」冒充不了它。** 那个数证明的是**刚读到的文件**,而这几处摊的往往是
    另一份语料,于是旧语料会带上新文件的版本号 —— 核对那一步两个数必然相等,弱档重新放行,
    收藏返回 200。两条真实路径各实测过一次:**先改稿、之后才打开搜索**(建索引时 `9b885a9a`、
    盘上 `8ae932ab`,返回的还是旧 `best_chunk`,点回去高亮改稿新写的那一节);**先改稿、之后才
    铺订阅列表**(阅读器那一份 `97aaf058`、盘上 `8b7eb4cb`,同样 200 / origin=doc)。
    「两份语料分了岔」在这两处都是**常态而不是竞态**:索引落后几分钟、条目译文写回还没重导出,
    天天发生。
  - **和 `/api/doc` 报的必须是同一个数**(都走 `scanner.body_version` 那一族)。各算一遍的话
    「相等」永远判不出来,而「相等」是那一头唯一的证明:订阅那一头因此要求「导出写进那一篇的
    正文」只有一份定义(`item_body_md`,导出真写下去的就是它)—— 差一个换行,两个数就永远不等,
    订阅正文的收藏整类退回站外原文(实测 N4)。
  - **读不出来回空串,不许抛、也不许编一个。** 一页列着几十条,其中一篇刚移走、还没重建索引
    是常态 —— 抛出去就是整页列不出来;而空串在那一头是「说不出版本」,照旧退到不采信弱档那
    一档。
  - **这个数是「展示那一刻」的事实**,所以订阅那两处报的是**铺这张列表时那一行内容**对应的那个
    数:面板开着的这几分钟里那一篇被重导出,它和刚读到的就不等了 —— 那正是要拦的窗口。
  - **别指望「核过之后落库的是刚读到的那一版、回跳那头自然有证明」替它。** 那句话只对**核得过
    的**那些成立,而这一道要判的恰恰是核不核得过;反过来用它当理由,等于让采集那一头的弱档
    一律免检。
- **「采集那一刻这条锚点定不定得住」要跟着收藏落库**(`favorites.anchor_exact`,
  `snip_text.js` 的 `snipSeek` 和阅读页内联副本 `seek` 各拦一道)。采集那一刻前后各两百字
  也一字不差的两处,谁也说不出用户选的是第几处(屏幕上当场说了一句「可能定位不到这一处」);
  后来原处被整节删掉,剩下那一处成了整段锚点的**唯一命中** —— 采信它就是高亮一处从没被收藏
  过的文字(审查用生产函数实测:采集偏移 740,删掉第二节之后回查到 244)。所以这件事是
  **采集那一刻的事实**,不是回跳那一刻能重算出来的:`e === 0` 的收藏**哪一档都不许定位**。
  - **三态同上:1 = 当时定得住、0 = 当时就定不住、NULL = 没记下。** NULL 一律**放行** ——
    这里和 `u`/`v` 反过来,因为拒掉它等于把存量收藏一次性废掉,而那些锚点并没有被证明定不住。
  - **这个数要一路走到判它的那一头**,两条路径各带一份:绑文档的走 `#kbq=` 里的 `e`
    (`favDocAHtml`),没有 path 的走 `data-jump` 的 `e`(`favJumpHtml` → `jumpFavOrigin`)。
    `v` 只走前一条(日报/问答压根不绑文档),**`e` 两条都要走** —— 「当时就定不住」是日报
    正文、问答回答自己也有的事实。采集那一头同样两份:app 的 `postSnip` 和阅读页内联那一份
    POST 各写一次,漏掉的那一头落库成 NULL,于是它收下来的收藏从此全不受这条约束管。
  - **落库那个数按核对的结果算(`fix.anchored`),不是按屏幕那一份算(`spec.locatable`)。**
    两件事分开记:`locatable` 是**屏幕上**那句提示的判据(「这一篇里有几处一模一样的文字」),
    `anchored` 是**库里**那个事实 —— 核对失配(`mismatch`)时屏幕上那句提示照旧按屏幕说,
    而落库那个数必须是 0:盘上那一份里这条锚点压根对不上。
  - **它还得活着走到「核对那一步」自己**(`snipVerified` 里那个 `stuck`)。采集阶段这件事挂在
    `locatable` 上、库里那一列叫 `anchor_exact`,而两头之间那个转换只认后者(`snipSpecOf`)
    —— 不在调用处补一下,核对拿到的锚点就**没有**这个事实,`snipSeek` 那道拒绝压根没机会
    生效:盘上把选中那一处整段换掉之后,剩下那一处成了整段锚点的唯一命中,于是「核过了」→
    按盘上那一份把 `unique/locatable/anchored` 全重算成 true、版本号也换成新那一版 → 落库
    `u=1/e=1/v=新`,屏幕上只有一句普通的「片段已收藏」,点回去高亮的是他从没选过的那一处。
    - **这一道在「同一份语料」上一分钱不要**:语料没变过时那两处都还在,两侧各命中两处、
      取交集还是两处,`snipSeek` 自己就判说不清 —— 真正被它拦住的只有「原处没了、剩下一处
      别处」。所以同版的正常全文核对、盘上末尾补了一段那一条(采集时本来就定得住)、以及
      上面那条裁定保留的双侧交集都照旧(逐格对比在「实测证据」那一节)。
    - **`partial` 的来源不算**(列表卡、搜索卡只摊那一篇的一截):切片里分不出两处可能只是
      前后文窗口被切片边界截断了,那是**未知**,不是「已证明分不出」—— 整篇那一份核过之后
      会按整篇重算一遍,那一份才作数。
- **回跳那一头的收紧到「整段锚点」为止,再往里收会把日报、订阅那两类收藏一次性废掉。**
  `v !== DOC_VERSION`(语料变过)时弱档已经全关,剩下的只有「两侧都对得上、交出同一处」那一
  档。它仍剩一种**构造得出来**的误报:原处被删掉,而另一处后来连两侧上下文都被改成一模一样
  (审查用生产函数实测 `u=0 / e=1` 那一组,两份实现都回同一处)。可**那正是日报正文里一字不差
  的两段必须照旧回得去的那个形状** —— 日报正文、问答之外的那几头两边是同一个渲染器,`same` 在
  那儿永远证明不出来(没有 path、没有版本号可比),于是「两侧都对得上」是它们唯一活着的一档。
  按那条构造去关它,代价是**任何改过一次的文章上所有收藏一起失效** —— 定点注入(交集那一档
  也要 `same`)实测**红 12 条**,红的全是常态:日报里那四行代码、一字不差重复两段的第一处和
  第二处、「前文两处候选、后文指着其中一处」、盘上末尾续写一段之后原句连前后文都还在那一格
  (bind 4c)、阅读页上那条跨段收藏。换来的是一个要「把另一段的前后文逐字改成相同」才摆得出来
  的误报;而采集那一头能拦的已经拦在采集那一头了(`anchor_exact`:那一刻就分不出两处的锚点,
  哪一档都不给用)。
- **反过来钉一边:「这份语料整份就是这段引文」是自证的同一性。** 两侧上下文天生都是空的
  (`!a.p && !a.s`)、而 `text.trim() === a.q` 时,这份语料里**没有别处可以冒认** ——
  这一档不要求 `same`、也不要求 `u`。少了它,日报整段正文收下来、一个字都没改,点回去却是
  一句「没找到」:采集那头按「这份 text 就是此刻这一份」算出「定得到」,回跳那头两侧都没有、
  又拿不出同一份语料的证明,于是**所有完整正文选区一律失效**(审查实测)。
  **它不是「放开裸引文那一档」**:语料只要比引文多一个字(日报重算过一轮、补了一段),
  这一档立刻失效,照旧回到上面那两条判据。
- **前后文长到「能唯一定位」为止,而且判据直接走回跳那个函数。** `snipContext` 按
  `SNIP_CTX_STEPS = [30, 80, 200]` 一档档加长,每档拿 `snipSeek` 在同一条全文上试一遍、
  **落回采集的那个偏移**才收;都做不到就回最短那档,并把 `locatable: false` 带到提示上
  (「这一篇里有几处一模一样的文字,点回去可能定位不到这一处」)。固定 30 字不够:一字不差
  重复的整段往往连两头三十个字都一样,那一刻存下的锚点**天生定位不到自己**,而收藏当场是
  成功的。**不许自己另写一遍「唯一吗」** —— 采集这头按一套规则算出「唯一」、回跳那头按另
  一套(候选集合 + 外侧空白)落在别处,是这条链上最难看出来的那种错:两处的文字一模一样。
  **独立阅读页那一份内联实现也要把这个标记传出来**(`contextOf` 回 `exact`,保存成功那句话
  按它分叉)—— 两份实现的**反馈契约**要对齐:那一页原来一律显示普通成功,于是同一条收藏在
  app 里会被告知「点回去可能定位不到」、在阅读页上什么也不说。
  反过来钉一边:**定得准的那一条不许乱提示**(「一律提示定位不到」把一句准话换成一句含糊话)。
- **每一处会进库的截断都不许切开一个字。** JS 的字符串按 UTF-16 存,emoji 一类字占两个单元
  (代理对),按单元 `slice` 会把它切成两半;**孤立的那一半 Python 的 str 装得下、UTF-8 编
  不出来** —— sqlite3 在 INSERT 绑参数那一句抛 `UnicodeEncodeError`,而那是 `try` 里的最后
  一步,于是整条 POST 变成一句 500。审查实测:正文里一个 emoji 后面隔着 29 个字母(正好让
  三十字那一档的前文窗口起点落在它的后一半上),选中再后面那句普通中文,**日报和独立阅读页
  都收藏失败、收藏数还是 0**,而用户选的那几个字里一个 emoji 都没有。
  口径只有一份(`snipWhole` / `snipClip`,阅读页那份内联副本里叫 `whole`),**截断处一律过
  它**:前后文窗口(`snipContext` / `contextOf`)、标题上限(`postSnip`、`chat.js` 的提问
  标题)。顺带把**选区端点**也收到整字上(端点落在代理对中间时往里收一格)—— 鼠标选不出这种
  端点,程序派的选区能。**只削掉边上那半个字,正文里合法的字一个不动**:替换合法原文动的是
  用户收下来的引文,那不是修法。
  后端还有一道,它拒而不改(`SnippetRequest._no_half_character`):**抛 `HTTPException(400)`
  而不是 `ValueError`,而且必须排在 `max_length` 前面**(`mode="before"`、字段写 `"*"`)——
  走 pydantic 的校验失败会变成 `RequestValidationError`,而那个错误体里带着 `input` 原串,
  序列化它又是一次 UTF-8 编码,于是「受控的 422」当场变成一个崩在错误处理里的 500(实测:
  带 `max_length` 的 `origin_title` 连 422 都发不出来)。这句 400 **不带原串**,所以一定
  编得出去。
- **`locateSnip` 读锚点时也过一遍规范化**(`snipAnchor`)。库里还有阅读页早先存下的、没压过
  空白的锚点;规范形态再压一次不变,所以两种都认。
- **弹按钮之前就得问清楚这一段收不收得下**(`showSnipBtn` 里那句 `snipSourceOf`)。一个注册
  过的容器里并不是每一处都是正文:问答空态那三颗建议按钮和回答同住 `#chat-msgs`、图鉴的
  小节标题和条目正文同住 `#td-entries`、会话还没落库时整块回答都没有落点。**一颗点了会失败
  的按钮比没有按钮更糟。**
- **高亮走 CSS Custom Highlight API,不许包 `<mark>`。** 包一层标记的话,那几个面板下一次
  重渲染就把标记连正文一起换掉,而且会打断 `dailyRefMap` 那类按节点结构找东西的代码。
- **回跳是「存一个待定位、再切面板,由面板自己消费」**(`dailyPendingSnip` / `chatPendingSnip`
  + `consumeSnipJump`,仿 `subsPendingKind`)。**不在 `jumpFavOrigin` 里 await 面板加载**:
  `switchTab` 会顺手起一轮 `loadDailyPanel` / `initChat`,那一轮自己也要决定「打开哪一份」,
  两边各发一次请求就是先发后到的旧回包盖掉新的(日报面板的 `dailyReadSeq` 为同一类竞态而
  存在)。
- **日报片段的出处写在正文容器自己的 `data-snip-ref` 上,由唯一写入口
  `setDailyBody`(kb/static/js/daily_body.js)和正文一起落下来。** 不许读 `dailyCurrent`:
  那是「列表里选中哪一天」,在请求发出之前就写好了,而这期间屏幕上还是上一份正文 ——
  拿它当出处,收下的就是一条**正文属于 A、出处记着 B** 的收藏,点回去永远找不到。
  绑在容器上同时收掉另外两种形态:正文已经被换掉时选区离开了文档树、`closest` 找不到
  容器,不收;读取失败/已删除那几个字(「读取失败」「已删除」)容器上压根没有出处,不收
  —— **那些字不是日报正文,一个字都不该收得下**。
- **问答那一侧的落点是**「这条消息的 id」,**不是一个「已保存」的布尔**(`SNIP_CID` /
  `SNIP_MID`:气泡上那两个 `data-snip-cid` / `data-snip-mid`)。一轮问答是**答完才整轮写进
  `messages`** 的(`_save_qa` 跑完后端才发 `done` 帧),所以:
  - **「会话在库里」不等于「这一轮在库里」。** 追问时会话号早就有了,而流式途中、点了「停止」
    之后、出错、以及**正常 EOF 却没有 `done` 帧**这几种状态屏幕上已经有整段回答。按会话号记
    出处的话,那条收藏指着一个压根没有这几条消息的会话,**刷新之后那段话不存在、回跳永远打
    不开**,而收藏当场是成功的。
  - **身份由后端给、客户端不自己造。** `done` 帧带回 `conversation_id` + `user_message_id` +
    `message_id`,`chatMarkSaved` 用它给这一轮两条气泡各写一份(同一轮的提问和回答是同一条
    `_save_qa` 写进去的);历史消息由 `renderMsg(m, {cid, mid})` 从库里那份读。`chatSnipSource`
    两个数都大于 0 才给落点 —— **一个布尔接不住这件事**:它只说「我以为存过了」,而出处要的是
    「存成了哪一条」。
  - **没有收据的那一轮要如实说一句**(「这一轮没有收到完成确认」),并且**不许把 `chatConvId`
    跟着设成 null** —— 那会把当前视图的会话归属一起抹掉,接着追问就新开了一个对话。不说的话
    用户只会以为「收藏此段坏了」。
    **那一句只许说到「没得到确认」为止,不许说成「没有落库」。** 后端是 `_save_qa` 之后才发
    `done`,所以那一帧**可能丢在存库之前(库里一个字没有),也可能丢在之后(已经存上了,只是
    回执没到)** —— 说成后者是拿一个没证明过的结论告诉用户,而它可能恰好是反的:历史里明明
    有这一轮,用户却按这句话又问了一遍。口径同 `snipVerified` 那三种退路各说各话
    (「这一刻读不出来」不许说成「确定不在」)。文案两份实现各一份(问答面板、图鉴抽屉)。
  - **后端自己再核一遍归属**(`_chat_message_id`:`SELECT 1 FROM messages WHERE id=? AND
    conversation_id=?`,核不过 400)。**两道都要**:这一道是存储层自己的口径,不押在页面状态
    上;核不过就如实拒掉,那条收藏存下来也只是一条点不回去的死收藏,而用户此刻还看着那段话、
    重问一次就能收。
  - **图鉴详情抽屉里那块问答是另一份收尾代码**(`gallery.js` 的 `doSendToolChat`),走同一条
    `/api/ask/stream`、同一个 `chatSnipSource`。**两份各有自己的红**:只修主问答的话抽屉这一头
    照旧把没有收据的那一轮标成已落库。
- **问答以「那一条消息」为单元:采集和回跳都收到它身上。**
  - **采集**:`chatSnipSource` 给出 `root: body`(那条气泡),所以坐标系、前后文和唯一性都只在
    这一条消息里算。摊整个消息区的话,引文顶在气泡开头时它的前文来自**上一条消息** —— 回跳在
    这一条里一辈子也对不上。
  - **回跳**:`chatSnipUnit` 按库里记着的 `origin_msg` 找到 `.msg[data-snip-mid=N]`,只在它的
    `.bubble` 里定位。在整个消息区里搜的话,同一个问题问两遍、回答一字不差时两处都对得上 →
    按「位置说不清」一个高亮也不给,**而要找的那一条明明记着**(审查复现);两条回答只有一半
    相同时更坏 —— 锚点在另一条上先命中,高亮落在别人身上。
  - **记着 id、可那条消息不在这个对话里了,不许退回整对话搜** —— 那正是「把另一条同句冒认成
    原处」的入口。如实说一句(「那条消息已经不在这个对话里了」)并把待定位收掉。
  - 两头收到同一个单元之后,这一头才敢按「同一份语料」采信弱档(消息落库之后不会再改,它的
    身份就是那个 id)。**没有 `origin_msg` 的老收藏**按整个对话搜,那时弱档一律不采信 ——
    它们的锚点本来就是按整对话采的,两侧都对得上才算。
- **那个落库标记挂在整条消息上,可不是这条消息里每个字都落了库:可收范围收到正文那一份上。**
  同一个 `.msg` 里还住着相对时间、模型名、「存为笔记」那颗按钮(`renderMsg` 拼的 `.msg-meta`),
  以及按 `refs` 现拼的「来源 N 篇 / Obsidian / 原文」那一块(`.refs`)—— 它们是**界面文字**,
  不是落了库的正文:相对时间过一会儿就变成「3 小时前」,照着它找只会找不到。所以
  `chatSnipSource` 要求选区落在 `.bubble` 之内(`body.contains(range.commonAncestorContainer)`)
  且不碰 `.refs`(`range.intersectsNode`)。两处问答(问答面板、图鉴抽屉)共用这一处判据。
- **「哪里算正文」这件事,采锚点的范围也得跟着收 —— 而且采集和回跳要同一个口径。** 共享层
  为此认 `describe()` 的两个字段:`root`(正文那个元素,采前后文只在它里面走)和 `skip`(容器
  里那几块界面文字的选择器,`snipTextIndex` 直接跳过整棵子树)。缺了的后果不是按钮弹错地方,
  是**那条收藏带着一段目标文档里压根不存在的上下文**:图鉴抽屉里采到的后文实测是
  `原文 Obsidian 在阅读器打开 就这个工具提问`(那三颗链接按钮和小节标题),问答那一侧采到的
  是模型名和「3 小时前」。**回跳那一头必须传同一个 `skip`**(`consumeSnipJump` → `locateSnip`),
  不然采集时算出来的唯一性在定位时就不成立了 —— 这一道是**冗余带**(现在的后果由
  `snipSeek` 按内容找接住了,定点注入打不红),留着是因为「两头同一个坐标系」是这条链的前提,
  理由写在 `locateSnip` 的注释里。
  **图鉴那一处还要反过来拦住正文之外的选区**(`.body.contains(range.commonAncestorContainer)`):
  一个 `<details>` 里并排住着摘要行、正文、三颗链接按钮,选中按钮文案也能存下一条点回去必定
  落空的收藏。摘要行那一段浏览器自己就不交出来(`<summary>` 里设好 Range 之后
  `getSelection().toString()` 是空串),所以回归那条判据落在**那三颗按钮**上。
- **收藏「提问本身」时标题取它自己那一问**(`chatQuestionOf` 头上那句)。往前找 `.user` 的
  话会取到**上一轮**的提问,于是列表里那条片段挂在一个跟它无关的问题下面。
- **回跳目标那一份日报已经不在了,要当场说清楚并把这次回跳丢掉**(`loadDailyReports`)。
  退回「打开第一份」的话,屏幕上是另一天的日报、没有任何提示,而待定位还挂着:用户以为
  跳到了,其实在读别的东西。
- **回跳目标整个编进 `data-jump`,不去全局列表缓存里按 id 捞** —— 这几颗按钮的寿命比那份缓存
  长(分诊结果渲染完、下一次 `loadFavPanel` 之前它一直在屏幕上)。
- **`feed` 这一类回跳走站外原文,不去订阅列表里重新定位那条。** 那条条目可能已经翻过好几页、
  或者被历史裁剪带走了;有 URL 就开站外原文,没有就切回那个面板并说一句。**退回面板那一步要
  先确认 `origin_ref` 的头一段是来源目录里认得的 id**(`subsCatalog`):`switchTab` 对不认识的
  名字是直接 return、页面一动不动,而紧跟着那句提示写着「已切到它所在的来源」—— 一句假话。
- **列表排序是 `created_at DESC, f.id DESC`,`id` 那一半不能少。** `created_at` 只到秒
  (`kb/web/common.py` 的 `now()`),而「收藏此段」让人在同一段正文上连着选好几句 —— 同一秒
  落库的那几条排序就成了未定义。
- **`_read_body` 对空 path 直接回空串。** 拿 `VAULT_ROOT / None` 去读是 TypeError,会把整条
  行动卡打掉(那是个后台线程,屏幕上只表现为「这一条永远只有引文」)。
- **出处那一行只替不是知识库文章的那几类说话**(`fav_view.js` 的 `favWhere`)。日报正文、问答
  回答、没导出的订阅条目在 `documents` 里压根没有一行,`d.source` 是 NULL —— 不替它们说,卡片上
  写的就是「其他来源」。反过来 **doc 不单独标**:它占绝大多数,标了就是每张卡上一句什么也没
  区分的话(同「图鉴类型色别撞重点色」那条理由)。卡片上那颗按钮的字同理分流(`favOpenLabel`:
  有文档的是「打开阅读」,没有的是「回到每日日报/知识问答/订阅内容」)。
- **收藏架那边的卡片是一条收藏一张,不按出处聚合**,所以判据落在「四类来源各有卡、各走对的
  那条路」,不落在卡片张数上(`tests/snip_probe.mjs` 第 4 格)。
- **`favDocA` 只是个转发,锚点口径不许在 `fav_view.js` 里再拼一遍。** 那一份要把 `u`/`e`/`v`/`m`
  一起带过去(见上面那几条),少带一个数,回跳那一头就只知道「说不清」、弱档一律不采信。
- **`kb/static/css/snip.css` 里那个 z-index 是 70**,夹在弹窗(60)和确认框(80)之间
  (要高过抽屉 30 和阅读器 41 —— 图鉴条目正文、订阅阅读器都在它们里面)。
  `kb/web/pages.py` 的 `_DOC_SNIP_JS` 自带一份内联副本(那是脱离 kb-web 也要能用浏览器直接
  打开的独立产物,口径同 CLAUDE.md「视觉语言」那节的三处产物),**色值、圆角、锚点口径改
  一处就要同步另一处**,两处都写了互指注释。两份一度在高亮文字色上对不上:
  内联那份写的是 `#17604F`(`--brand`),而高亮底色是 `--brand-soft`、按 base.css 的口径
  soft 底上的文字该用 `--brand-deep`(`#0E4A3B`)—— 已经按后者对齐。
- **图鉴详情抽屉里出处挂在每个 `.td-entry` 自己的 data 属性上**,按选区往上找宿主
  (`snipHostOf`)。那个容器里并排着一个工具的全部记录,各有各的 path;而小节标题
  (「记录时间线 · N 条」「就这个工具提问」)也住在里面 —— **找不到宿主要自己判空,
  不许靠访问 `dataset` 抛异常被 `snipSourceOf` 的 catch 吞掉**(行为上也对,但判据
  藏进 catch 里,读代码看不出这儿有个判断;见「反向验证」注入 A10)。
- **`quote` 是屏幕上那份文字,而显示文本的权威是浏览器自己。** `<br>`、段落 / 列表 / 表格
  边界在 DOM 文本节点里**一个字符都不占** —— `String(range)` 和文本节点串都会把分了行的两段
  接成一行,**收藏内容本身就丢了**,而面板上那条看起来一切正常。所以取原文**先问
  `Selection.toString()`**(元素边界算几个换行、`<pre>` 里的缩进怎么留,那套规则是 CSS 的),
  对不上(程序派的选区、滚动中选区没了)才退回 `snipFragText`(文本节点原文 + 元素边界补
  换行)。**退路不许用 `String(range)`。**
- **「能不能用浏览器那份」的判据是结构性的,不许拿文字比。** 判的是当前选区的两个**边界点**
  覆盖不覆盖这一段(`compareBoundaryPoints`);**拿我们自己拼出来的文本去跟选区比、不一样就
  改用自己那份,等于用一套认不出 CSS 的规范文本否决用户真正选中的原文。** 而且那个比法连
  「两份都对」的局面都挡不住:`snipFragText` 对块级元素**进出各算一处**换行(`<p>A</p><p>B</p>`
  → `A\n\nB`,和 Chrome 对得上),而同样两行装在两个 `display:block` 的 span 里时浏览器给的
  是一个换行 —— 文字比法在这儿判「对不上」,于是把浏览器那份正确答案扔掉,存下来的是多一个
  换行、两头还各带一个换行的那一份。
- **坐标系和取原文走同一份 `snipBreaksOf()`。** 这里咬着两条不变量:`quote` 是显示文本、
  「`quote` 压平一遍 = 坐标系里那一段」。只改保真那一头,`locatable` 当场变假、回跳落不回去
  (保真修对了、定位跟着坏,是这一处最容易留下的半成品)。一处显示分隔在坐标系里占一个空格
  位,但**「一段连续空白只占一位」那条不许破**(前面已经是空白就只标记、不另占位)。分隔位
  **没有自己的文本节点**,所以 `snipOffsetRange` 两头要往里收过它 —— `setStart(null, …)`
  当场抛。
- **空元素(`<br>`/`<hr>`)只算一处分隔**,有子节点的块级元素进出各算一处 —— 和 Chrome 对得上
  (`<p>A</p><p>B</p>` 在屏幕上是 `A\n\nB`)。
- **分隔由计算样式说了算,标签名那份名单只是离线那一头的退路。** 屏幕上哪儿换行是 CSS 的
  规则:`<span>` 标签名上是行内元素,`display:block` 一加就各占一行;用户样式、主题、将来
  某次 CSS 改动都长这样,**产品代码一个字不改**。所以活文档里按 `getComputedStyle(el).display`
  判(`inline` / `contents` / `ruby*` 和 `inline-*` 一族不换行,其余都换);`snipRenderedText`
  跑在 `DOMParser` 的文档上,没有布局、`display` 问不出来,那一头才退回标签名名单
  (`SNIP_BREAKS`,**刻意列得宽**:多一处分隔压平之后无害,少一处是永久丢一个换行)。
  **只改保真那一头、坐标系仍按标签名判的后果不是「引文错了」**,而是引文对、位置证据全废:
  坐标系里这两句之间没有分隔、引文里有,这一段在自己那篇里**一处也找不到**,于是存下来的按
  「说不清是第几处」记,当场还多一句「点回去可能定位不到」。
- **屏幕上看不见的那一棵子树,坐标系和取原文两头都要跳过**(`snipHidden`:`display:none`)。
  选区压根不交出它的字,一头收进去一头没有,`quote` 压平之后就对不上坐标系。
- **选区一旦碰到 `skip` 子树,浏览器那条路就不能用了。** 浏览器不认识 `skip`,给的那份文字里
  带着那几个界面字 —— 搜索卡和订阅列表在正文被截断处补的那个「…」就住在 `.snip-more` 里,
  存进引文的话点回去必然定位不到,而面板上那条看着好好的。这时退回 `snipRangeText`(逐节点
  走,跳得掉);丢掉的只是「CSS 造成的分隔」那一点精度,在界面文字旁边无关紧要。
- **保真优先于可定位。** 坐标系映射不出屏幕上那份文字时,**`locatable` 判假,不许反过来改
  引文去迁就坐标系** —— 引文是收藏的主要用处,点回去是附加值;改引文等于把用户选的那段话
  换成另一段,而屏幕上一切正常。
- **「选完了」这件事三种输入方式各报一次:mouseup / touchend / keyup。** 手机上长按选词没有
  mouseup,Shift+方向键选字从头到尾没有 mouseup/touchend —— 少一处,那一类用户压根看不到那颗
  按钮,而屏幕上什么异常都没有。`selectionchange` 只管**收起**(拖选途中一直在响,拿它弹按钮
  的话按钮会跟着每个字闪一下)。两份实现各一份。
- **每一次定位请求先把上一次的结果清掉**,早退那几条分支也算(没有 `kbq`、参数坏了、引文空、
  找不到、范围建不出来)。不清的话,同一页上从一条找得到的收藏换到一条找不到的,旧那一句照旧
  亮着、`load` 那一下还会把页面滚回它那儿 —— 用户看到的是「这条收藏指到那一句」,而那是上一条
  的位置。
- **最终那一步导航也过 `safeUrl`。** `origin_url` 是内容自带的(RSS 的 link),后端只管长度;
  同一份数据渲染成 `<a>` 时各处都过协议白名单,只有订阅那条回跳曾经直接 `window.open` ——
  口径两样就迟早有一天不一样。认不出协议时走「没有站外链接」那条退路(切回它所在的来源并
  说清为什么没直接定位),不是静静什么也不做。
- **坐标系那一族单独一份文件。** 压平、显示分隔、偏移映射、定位搜索在
  `kb/static/js/snip_text.js`,UI / 采集 / 核验 / 网络留在 `snip.js`(拆之前 676 行,过了
  CLAUDE.md 的 700 行上限);`index.html` 里**前者排在后者之前**。
- **列表上那几截也是真原文,一样得能收。** 需求是「只要能展示原文的地方都能收」,而
  「完整正文」那四个容器(阅读器、日报、问答、图鉴条目)之外还有两处列表:订阅列表卡片的
  `.source-excerpt` 直接摊正文开头 380 字(短社交观点往往整条都在里面)、搜索卡片的
  `.snippet` 直接摊命中 chunk 的前 160 字(`kb/search.py` 的 `best_chunk`,**那是文件正文里
  的一段真原文**,不是同一张卡上 `.summary` 那块模型写的摘要)。漏掉它们的形态是:用户在
  列表里读到一句想收,选中之后**什么都不发生**,而右侧同一句话收得下 —— 屏幕上看不出这是
  漏了一处还是功能坏了。两处合用一份注册器(`kb/static/js/snip_cards.js`),不是各抄一份。
  四条随之而来的硬约束:
  - **可收范围只到正文那一块**(`snipCardBody`:先定位卡片、再要求选区落在那一个正文块里)。
    标题、作者日期、页脚、`.summary`、实体按钮都不是原文,收了点回去一定找不到。
  - **容器只是那一篇的一截时必须声明 `partial: true`**,于是**唯一性一概不从它身上算**:
    「在卡片那 380 字里只有一处」证明不了整篇里只有一处,照切片存下去就是给裸引文那一档发
    一张它不配的通行证(回跳那一刻命中整篇里的另一处)。绑得上文档的那一类随后由
    `snipVerified` 按**盘上那一篇**重算(`fix`),那一份算的语料正是回跳那头会看到的;
    核不过、退回 `origin=feed` 的那一类没有重算的机会,**只能按「说不清」存**。
  - **正文被截断处那个「…」是界面文字**,走 `skip`(`.snip-more`)排掉 —— 它在那一篇里压根
    不存在。
  - **拖选不是点击。** 订阅列表卡片整块可点(点开右侧阅读器),而浏览器在一次拖选松手时
    **既派 mouseup 也派 click**,不挡住(`snipSelectionIn`)的话那一下会把阅读器切走、选区和
    刚浮出来的按钮跟着一起没,窄屏上还会把列表整块藏起来。
  - **搜索卡那一类不自带 `doc_version`,也不给 `fallback`:它只能说出「刚读到的那一版」。**
    检索语料是入库时切的块(`kb/chunker.py` 为了让检索词对得上剥掉了 `*`、却留着 `~~` 之类),
    卡片又只摊命中的那一截 —— 所以那段话在卡片上和那一页上**本来就不是同一份文本**,核对
    必然有核不过的时候。它没有版本可带、也没有一档不说谎的退路(退 `origin=feed` 是假话:
    这是库里的文章;`origin=doc` 配空 path 后端按 400 拒)。于是定两条:
    - **`snipVerified` 核不过、又没有退路可退时,来源自己说不出版本的,就记下刚读到的那一版**
      (那是它唯一能说的版本);**来源自带版本号的一律不许替换** —— 图鉴条目带的是面板上那一
      份的版本,它和盘上此刻**不等**正是「面板旧了」的唯一信号,后端那道 409 全靠它,替成新的
      之后改稿删掉那句话也照存。于是搜索卡那一头照旧绑那一篇(点回去打开的至少是对的那一篇
      文章),并当场说清「点回去可能定位不到这一处」。
    - **`saveSnip` 一道通用的带:绑了文档、却拿不出核对过的版本号时,一行都不送**,并且说出
      真正的原因(这一篇已经不在索引里 / 这一刻读不出来)。后端那道必答校验本身是对的,可一条
      POST 撞上它,用户看到的是「收藏失败:绑文档的收藏必须带 doc_version」—— 一句他无法处置
      的话,而真正的原因一个字都没说。**也不许反过来把 path 丢掉偷偷存成一条只有引文的收藏**:
      那是把「能回到原文」静默降级,只有用户能做这个决定(同后端那段契约:它故意不替调用方
      降级)。新接上来的入口忘了带版本号时,坏的也是这一句话,而不是一个必填字段错误。

## 事故形态

- **`path` 非空 → 日报/问答片段一条都存不下。** 前端那颗按钮、toast、列表渲染全都写好了,
  POST 回来是 500,`FOREIGN KEY constraint failed`。拿 `''` 当「没有文档」的占位同样被拒 ——
  空串不是 NULL。
- **孤儿行把整次迁移带崩 → 库再也打不开。** 这一条最毒:迁移是在 `store.connect()` 里跑的,
  失败之后不是「收藏面板坏了」,是**所有要连库的入口一起失败**,而且每次重试都在同一行上
  失败,自己好不了。
- **内连接 → 计数和列表分叉。** 「待试 12」而列表里 9 条;剩下那 3 条**既点不到也删不掉**。
  行动卡那一侧是另一个形态:日报片段永远只是一段引文,没有卡,而**指纹是按 `_inbox_rows()`
  那批行算的** —— 漏掉等于新收一条日报片段之后分诊缓存仍判「新鲜」,整轮分诊不重跑。
- **位置证据只听了一半 → 高亮落在一处另一侧已经排除掉的地方。** 三处一字不差的重复句,
  收藏第二处;改稿只动后文之后,前文那一侧认得出第一、二处(两处候选)、后文那一侧唯一指向
  第三处。把「有两处」和「没有」压成同一个值的话,前文那个集合就丢了,只剩后文那个「唯一
  命中」—— 于是点回去高亮的是第三处,**而三处的文字一模一样,页面上看不出来**。
- **核对完到落库之间正文换了一版 → 固化一条永远找不到的收藏。** 订阅正文上点收藏,「收藏中」
  那一下同一篇完成重译并重导出;核对(读 `/api/doc`)读到的是旧那一版、这段话真在里面,而
  INSERT 落的是「绑着那个 path」—— HTTP 200、提示收藏成功,立刻回看是新译文、原句不存在、
  高亮 0 个。**这一件和「屏幕上这份不是盘上那篇」不是同一件**:后者核对拦得住,前者发生在
  核对之后,只有共同的版本号拦得住。
- **核对在临界区之外 → 间隔由对方决定,固化一条永远找不到的收藏。** 上一版把核对挪进了
  INSERT 那个请求里,以为剩下的只是个毫秒级窗口。实测不是:INSERT 要等别人的写事务时,那段
  等待**由对方的事务长度决定** —— 核对与落库之间等了约 1 秒,这期间另一路真走
  `translate._save → sync.export` 把那一篇换成新译文,收藏照旧 200、回看 0 个高亮。
- **同一个文件版本,两头的文本不是同一份 → 核得过、点回去照旧 0 个高亮。** 核对按面板的
  `mdHtml` 算(原始 HTML 成了元素、标签看不见),阅读页把原始 HTML 当**字面文字**显示。跨过
  一段 `<strong>` 的选区在面板上是连着的一句,在阅读页那一头中间插着四个尖括号字:版本号
  相等(文件真没动过)、核对也判「找得到」,当场一切正常,点回去才发现定位不到 —— 而这一类
  **没有退路可退**(原文就是 vault 里那一篇),悄悄存成功是最坏的一种收场。
- **核不过却把新读到的那一版带上 → 后端那道 409 永远判不出「面板旧了」。** 两件事被压成了
  一件:改稿把那句话删掉(该拒、该说刷新)和两头文本不是同一份(该存、该说定位不到)。实测
  改稿删句之后照旧 200 落库,提示说的是「可能定位不到」。
- **删掉原对话之后点那条问答收藏 → 永远停在「加载对话…」。** 这个接口对「会话不在了」回的是
  404 **带一份非空 JSON**,`r.json()` 于是正常解析出 `{detail: …}` —— 只判 `!d` 的那一版接着
  去 `d.messages.map`,当场 TypeError:屏幕停在「加载对话…」,待定位还挂着(下次打开另一个
  对话时它还在),而收藏那条记录本身好好的、引文一个字没丢。
- **「这一刻读不出来」被说成「还没进检索索引」。** 目标真在,只是那一次请求 5xx 或网络抛了,
  前端一律归成「确定没有」:用户得到的理由是错的(他会以为等索引跑完就好了),而 path 也被
  静默丢掉了。
- **按钮浮在不能收藏的地方。** 自测时真遇到过:`showSnipBtn` 原来不问 `describe()`,于是选中
  问答空态那三颗建议按钮、图鉴小节标题,按钮照旧浮出来,一点才换来一句「这一段现在收藏
  不了」。改法是弹之前就问,并**把那句 toast 删掉**(走不到的提示留着只会误导下一个人)。
- **多行代码存成一行 → 引文再也恢复不回去。** 选中四行带缩进的代码,按钮弹了、收藏成功了、
  回跳也定位得到;库里那条 `quote` 是接成一行的那一份,换行和缩进**没有任何地方还留着**。
  这一条的毒性在于它**不可恢复**:定位照旧好使,所以没有任何一处会报错,等发现的时候那段
  原文已经不在了。
- **盘上那篇是旧版 → 存之前目标文件里就没有这句话。** 译文刚写回、还没重导出的那几分钟里,
  面板上读到的是新译文、`path` 是真的、索引里也有行;收下来 `origin=doc`、HTTP 200,点回去
  是上一版正文、0 个高亮、一句「原文可能已更新」—— 而文件**不是收藏之后才改的**。
- **锚点只记 quote → 回跳落在另一处。** 同一句话在一份日报里出现两次时,`indexOf(quote)` 命中
  第一处,用户点回去看到的是另一段上下文里那句一模一样的话。屏幕上一切正常,高亮也在。
- **整锚点失配就挑第一处 → 同一个形态换了个入口。** 前后文记了、但「只 strip 引文」让
  `prefix+quote+suffix` 拼不回原文,于是每一次都走那条退路。**失配的原因可以是空白、可以
  是渲染器不同,表现完全一样:一个落在错地方的高亮。**
- **整段锚点本身就重复 → 两个定位器一起挑第一处。** 一字不差重复两次的整段,连它两头三十个
  字都一样,`p+q+s` 命中两次 —— 「有命中」于是不等于「定得了位」。app 那一侧和独立阅读页那
  一份内联实现**各错一次**,形态一样:高亮在、文字对、落在另一段上。
- **流式途中的问答收下来 → 刷新之后那段话压根不存在。** 追问时会话号早就有了,这一轮却要等
  NDJSON 收完才整轮落库。生成中的半截回答、「已停止(未保存)」、出错气泡、还没落库的那条
  提问,收下来都是「当场成功」:列表里有卡、有引文,点回去打开那个会话,里面没有这几条消息。
- **长链接把整条收藏拒成 422。** 订阅条目带一长串跟踪参数的原文地址原样往上传,后端那条
  `max_length` 一卡就是整条 POST 失败,屏幕上只有一句「收藏失败」—— 用户选完才发现存不下,
  而 404 那条退路只认「这篇还没进索引」,接不住它。
- **升级复用收藏编号 → 旧页面误删新收藏。** 保留一页旧收藏列表,在别处删掉编号最大的那条,
  升级后新存一条,再回旧页点删除 —— 删掉的是刚存的那条,HTTP 还是 204。PATCH(状态流转、
  改备注)和行动卡写回是同一个形态。
- **出处认「正在请求谁」→ 收藏记到另一天。** 切日那一刻屏幕上还是上一份正文,选中收藏存下来
  记的是新那一天;点回去打开新那一份,里面压根没有那句话。再往前一步是**失败提示本身被收成
  片段**:阅读区写着「读取失败」,那四个字照旧弹按钮、照旧存得下。
- **两头渲染器不同 → 存成功、却永远定位不到。** 订阅正文里带 `**` 的一句存成 `origin=doc`,
  HTTP 200、路径和引文都对;点回去阅读页上 0 个高亮,提示「原文可能已更新」,而文件一个字
  没改。
- **正文里有 emoji → emoji 附近那句普通文字收不下来。** 选中的那几个字里一个 emoji 都没有,
  可前后文窗口按 UTF-16 单元截、正好切在它中间;那半个字 UTF-8 编不出来,后端在 INSERT 那一句
  抛,**整条 POST 变成 500**,屏幕上只有一句「收藏失败」,收藏数还是 0。日报和独立阅读页同一
  个形态,标题裁口(300 字、问答那一问 60 字)是同一类。
- **两个哈希相等、盘上那篇已是另一份译文 → 存成 doc、点回去是另一句话。** 保留一页旧订阅
  正文不刷新,后台重译重导出:`exported_hash` 和 `content_hash` 仍然相等(它们是**原文**的
  哈希),旧判据照旧说「盘上那篇就是屏幕上这份」。收藏返回 200、落库 origin=doc,回看正文
  已经是另一份译文、高亮 0 个、一句「没找到这段收藏」。
- **两边的位置证据互相矛盾 → 又一个落在错地方的高亮。** 收藏第二处重复句之后正文改了稿,
  「只用前文」那一档唯一指向第一处、「只用后文」那一档唯一指向第二处;按档位顺序采信的那
  一档命中了,另一边明明还在、明明指着别处,谁都没去看。两份定位实现各错一次,屏幕上照旧
  是「有高亮、文字对」。
- **怎么都分不出来却不说 → 用户到点回去那一刻才发现。** 两处前后各两百字一模一样时,收藏
  存得下、点回去只能是一句「没找到」。app 那一侧早就在收藏那一刻说了,独立阅读页原来一律
  显示普通成功 —— **同一条收藏在两处得到两种交代**。
- **超长原文链接静默丢掉 → 回看只能回到来源面板。** 没有 path 的那一类(退回 feed 的订阅
  条目)靠这个链接回原文,超长就整条不送(半截 URL 点过去是另一个地方),而收藏当场是成功
  的、什么也没说。
- **分流漏掉 → `/doc/#kbq=…` 的死链。** 没有 path 的条目照旧按阅读页链接渲染,地址拼成
  `/doc/#kbq=…`,点下去 iframe 里是一张 404,而卡片看起来和能读的那条一模一样。

- **屏幕上分了两行,库里是接成一行的那一份。** 这一条最毒的地方是它**当场看着全对**:按钮弹
  了、提示说已收藏、面板上那条也在、点回去还落得对 —— 只有把引文粘出来才看得见那个换行没了
  (多行代码那一条更直接:粘出来不是能跑的代码了)。
- **保真改对了、定位跟着坏。** 只在取原文那一头补上显示分隔、坐标系没跟着补,`quote` 压平一遍
  就不再等于坐标系里那一段:收藏那一刻 `locatable` 判成假,面板上多一句「可能定位不到」,
  点回去真的找不到。
- **段落之间多出一个换行。** marked 在 `</p>` 和 `<p>` 之间留着一个空白文本节点 —— 渲染里看
  不见、文本节点串里在。自己照标签名算的那一份于是给三个换行,而屏幕上是两个。
- **只用键盘选字的人压根看不到那颗按钮。** Shift+方向键选字全程不触发 mouseup/touchend,
  手机上长按选词也没有 mouseup;而屏幕上没有任何异常,看起来就是「这个功能不存在」。
- **换一条找不到的锚点,上一条的高亮还亮着。** 提示说「没找到这段收藏」,屏幕上却有一句亮着
  —— 用户读到的是「这条收藏指到那一句」。
- **`javascript:` 的链接被交给 `window.open`。** `origin_url` 是内容自带的,后端只管长度;
  真交出去就是在当前源上跑一段脚本(登录态、库里全部内容都在手边)。
- **一套认不出 CSS 的规范文本**否决**了用户真正选中的原文。** 两段装在 `display:block` 的
  span 里的话,屏幕上、剪贴板里、`Selection.toString()` 都是两行,而拿自己拼的那份去比、
  不一样就改用自己那份 —— 落库的成了接成一行(或者多一个换行、两头各带一个换行)的那一份。
  坏的是**收藏内容本身**,而面板上那条看着一切正常。
- **装饰用的那个「…」被存进了引文。** 搜索卡和订阅列表在正文被截断处补的那个省略号在那一篇
  里压根不存在,跨过它选一段,存下来的引文点回去必然定位不到 —— 而当场一切正常。
- **正常 EOF 却没有 `done` 帧 → 一条指着从来没有这句话的会话的收藏。** HTTP 200、delta 帧
  完整、屏幕上整段回答都在,只差最后那一帧(代理掐断、进程被杀、响应被截都长这样)。按
  「当前是哪个对话」记出处的话,旁边那一轮正常保存给出的真实会话号会被安到这段话头上,
  刷新之后那段话不存在、回跳永远打不开。
- **「现在只剩一处」被当成「这一处就是当时那一处」。** 采集那会儿有两处、收的是第二处,
  后来第二处被改掉 —— 剩下的第一处按裸引文找正好唯一,于是静默高亮一处采集时就明确不是的
  地方,而那两处的文字一模一样,用户从页面上看不出来。
- **按「卡片那一截」算出来的唯一性。** 列表卡片只摊正文开头 380 字,一句话在那一截里唯一、
  在整篇里有两处 —— 照切片存下去就是给裸引文那一档发一张它不配的通行证。
- **用户在列表里读到一句想收,选中之后什么都不发生。** 而右侧阅读器里同一句话收得下 ——
  屏幕上看不出这是漏了一处入口还是功能坏了。
- **一侧失配时采信另一侧 → 高亮落在改稿前就已经排除掉的那一处。** 「只听还说得上话的那一侧」
  本来是为「两种渲染摊出来的文本不一样」存在的,可它分不出另一种情形:**正文真的改过**。
  三处一字不差的重复句,收藏第二处、改稿只动它的后文 —— 后文那一侧于是 0 个候选,前文那一侧
  唯一地指向另一处,静默高亮过去。页面上一切正常(有高亮、文字对),用户看不出来。
- **原句被改稿搬走、别处新写了一句一模一样的 → 裸引文把它冒认成原处。** 「采集那会儿只有
  一处」在当时是真的,改稿之后它什么也不证明:两侧上下文全失配恰恰说明这段话周围的正文已经
  不是采集时那样了。于是一段**用户从没收藏过的文字**被当成他收藏的那一段高亮出来。
- **同一个问题问两遍、回答一字不差 → 一句「没找到」,而库里明明记着是哪一条消息。**
  回跳在整个消息区里搜,两条回答都对得上 → 按「位置说不清」一个高亮也不给。收藏行里那个
  后端核验过的 `origin_msg` 白记了。两条回答只有一半相同时更坏:锚点在另一条上先命中,
  高亮落在别人身上。
- **搜索卡上带删除线的一句 → 一句「收藏失败:绑文档的收藏必须带 doc_version」。** 检索语料
  剥了 `*` 却留着 `~~`,所以那段话在卡片上和那一页上不是同一份文本、核对必然不过;而这一类
  既不自带版本号也没有退路,于是一条本来存得下的收藏被一个**必填字段错误**挡掉,用户拿那句话
  什么也做不了。
- **「没收到完成确认」被说成「没有落库」。** 那一帧可能丢在 `_save_qa` 之前,也可能丢在之后
  —— 后一种时历史里明明有这一轮,而用户按那句话又问了一遍。
- **核对那一步按「别处一句一模一样的话」算过了 → 收藏绑上新那一版、HTTP 200,点回去高亮的是
  他从没选过的那一处。** 抽屉/面板开着的那几分钟里盘上那一篇改了稿:选中那一处连前后文一起
  被换掉,另一处同句还在。两侧上下文全失配恰恰说明「他选的那一处的邻域没了」,而按裸引文一问
  正好只剩一处 —— 于是那次核对不但没拦住,还把版本号换成了盘上这一版,后端那道「面板上这份
  旧了」的 409 从此永远说不出口。
- **采集那一刻就定不住的锚点,后来成了唯一命中。** 前后各两百多字也一字不差的两处,采集那一刻
  谁也说不出用户选的是第几处(屏幕上当场说了一句「可能定位不到」);后来原处被整节删掉,剩下
  那一处成了整段锚点的唯一命中 —— 采信它就是静默高亮一处**从没被收藏过**的文字。而「当时定不
  定得住」这件事只有采集那一刻知道,回跳那一头无论怎么算都算不出来。
- **整份正文收下来、一个字都没改,点回去却是一句「没找到」。** 日报正文整段就是那句引文时,
  两侧上下文天生都是空的,而面板那一头永远证明不出「要搜的这份语料就是采集时那一份」——
  于是为防冒认而设的那几道闸把**所有完整正文选区**一起判死了,而采集那一刻屏幕上说的是
  「定得住」。两头判据矛盾时,错的那一半在屏幕上看不出来。
- **两份语料里这句话各只有一处,而盘上那一处是改稿新写在别处的。** 面板开着的那几分钟里,
  盘上那一篇把这句话所在那一节整段换掉、另一节新写了一句一模一样的(前后文全不一样)——
  按数量看两头都「唯一」,按文字匹配核对正好命中,于是版本号被换成新那一版、后端那道 409
  再也判不出「面板旧了」、落库返回 200,点回去高亮的是**他从没选过的那一节**,而屏幕上那句
  提示只说「片段已收藏」。
- **旧面板上一侧的「唯一命中」被当成原处 → 收藏绑上新那一版、HTTP 200,点回去高亮的是他从没
  选过的那一节。** 两节里各写着一句一模一样的,连前文也一字不差;旧抽屉上选的是第二节,盘上
  随后把第二节连后文一起换掉 —— 前文那一侧于是唯一命中第一节,后文那一侧一处也对不上。
  「一侧对不上」在核对这一步本来是常态(两头的渲染不一样),**可常态证明不了「这两份是同一份
  语料」**(审查实测:旧页面 `351ade05`、盘上 `2c4ef0c0`,返回 200 / id=1,回看高亮第一节)。
- **来源报不出版本号 → 「渲染不一样」被当成「同一份语料」,裸引文那一档照旧放行。** 订阅阅读
  器那阵子什么都不报,于是「两侧全失配」被按常态解释放过:盘上那一篇把原处那一段换掉、另一节
  新写了一句一模一样的,收藏返回 200 / origin=doc、提示只说「片段已收藏」,点回去高亮的是改稿
  新写的那一节(审查实测:阅读器那一份 `7f1aca69`、盘上 `8dc78146`)。**没有可反驳的事实不是
  证明** —— 这一类的默认值只能是「证明不了」。
- **版本号是「响应那一刻读一遍盘」算出来的 → 旧语料带着新文件那个数,核对必然判「相等」。**
  那个数证明的是刚读到的文件,而这两处摊的是另一份语料:搜索卡摊的是**建索引那一刻**切下来的
  `best_chunk`,订阅条目行摊的是 feeds.db 里那一行。于是**改稿发生在打开页面之前**那个时序整个
  失守 —— 先在盘上把原处那一段换掉、另一节新写一句同句,**之后**才打开搜索(建索引时
  `9b885a9a`、盘上 `8ae932ab`)或铺订阅列表(阅读器那一份 `97aaf058`、盘上 `8b7eb4cb`):返回的
  还是旧那一截,带着新文件的版本号,弱档重新放行,收藏返回 200 / origin=doc / `u=1,e=1`,点回去
  高亮改稿新写的那一节。**「屏幕上这一份」的版本号只能由摊它出来的那一头算**,而且在这两处都
  **不是竞态而是常态**(索引落后、译文写回还没重导出,天天发生)。

## 实测证据

- **采集那一刻算出来的「这条锚点定不住」在进入核对之前丢掉过,后果是一条指着他从没选过那一
  处的收藏。** 真实 UI 复现:图鉴条目末尾摆两节、各写着同一句引文、两侧各 220 字一字不差
  (超过最大窗口 200),抽屉打开时屏幕上确实是两处、展示版本 `18930e6c6f990dc3`;页面不刷新、
  盘上把第二节整节删掉(`810108132c3ecce0`),再在旧抽屉上选中第二节那一处收藏 —— 屏幕上只
  有一句普通的「片段已收藏」,`/api/favorites` 里新增一行 `quote_unique=1`、`anchor_exact=1`、
  `doc_version=810108132c3ecce0`,点面板上那条阅读页链接,高亮落在 `Review A` 那一节(用户
  选的是 `Review B`,而那一节已经不在了)。生产函数那一头同一条锚点:带着采集期事实回 `null`、
  不带就回 `[230, 254]`。修复后同一条路径得到的是 409「面板上这份正文旧了,刷新再收藏」、
  一行都没落库。
- **非 WAL 的库被多个连接同时 `PRAGMA journal_mode = WAL` 会撞锁,而且不走 busy_timeout。**
  最小复现(12 连接 × 30 轮):非 WAL 起始失败 2 次,WAL 起始 0 次。真实的 v3 库是
  `store.connect()` 建的、一直是 WAL,所以这是**夹具必须照着真实起始态摆**的理由 ——
  照默认模式摆出来的话,那条并发用例测的其实是「转 WAL」,整份跑 60 轮红 3 轮,报
  `database is locked`,跟迁移一点关系没有。改完再跑 60 轮红 0 轮。
- **`ALTER TABLE … RENAME TO` 把索引一起带走,`CREATE INDEX IF NOT EXISTS` 随后按名字静默
  跳过。** 手工复现:改名后 `idx_favorites_path` 挂在 `favorites_v3` 上,新表上
  `CREATE INDEX IF NOT EXISTS` 不报错、也不建(`sqlite_master` 里 `tbl_name` 仍是
  `favorites_v3`),`DROP TABLE favorites_v3` 之后新表索引为空。**但这一条在本模块里兜不住
  任何后果**:重建里那句 CREATE INDEX 排在 DROP TABLE 之后、而 `connect()` 收尾还会无条件
  跑一次 DDL,两道带各自都够 —— 所以重建里那两句索引语句已经删掉了。
- **收藏列表同秒两条的先后在两次加载之间换过位置**(探针里点中的是重复句那条,而断言要的
  是另一条)。这是加 `f.id DESC` 的直接原因;探针那一侧同时改成按 origin **加引文**找按钮。
- **自增高水位在重建里丢掉是实测**(审查那份 `sequence_probe.py`,临时 v3 库 + 真实 API):
  修复前 `sequenceBefore: 10 → sequenceAfter: 9`、新收藏拿到 id 10、旧页面 DELETE 返回 204、
  新收藏消失;修复后 `sequenceAfter: 10`、新收藏 id 11、旧页面 DELETE 得到 404、新收藏还在。
  手工复现也确认了机制:`RENAME TO` 把 `sqlite_sequence` 那行一起改名,`INSERT … SELECT id`
  只把新表的 seq 抬到「插进去的最大 id」,`DROP TABLE` 把旧那行带走。
- **「有文档路径」被当成「逐字相同」是实测**:沙箱正文里写一句
  `请执行 **收藏定位的关键文本** 并核对结果。`,从订阅阅读器选中带星号那一段存下来 → 200、
  路径正确;打开阅读页 → 那一页只有不带星号的文字,高亮 0 个,提示「原文可能已更新」。
- **跨段落的前后文锚点**:同一段正文,订阅阅读器那头段落之间是两个换行、阅读页那头渲染成
  两个 `<p>`(串起来只剩一个换行)—— 不压平空白的话,凡是前后文跨过段落边界的锚点在另一头
  **必然**失配,于是全都走那条「退回只找引文」的路。这是压平比「只修重复句」更根本的理由。
- **「整锚点失配」的真因定点量出来过**:沙箱里那段重复正文,引文在订阅阅读器那条全文上落在
  135,在阅读页那条上落在 228;`q+s` 在阅读页上命中两次(重复整段的后文也一样)、`p+q+s` 则

  钉一边**:同一刻没有 path 的日报片段照旧 200 —— 一次维护不许把整个收藏入口堵住。

  打开」:修复前照旧弹按钮、照旧落库一行)。

    **反过来钉一边:第一处收下来也要落回第一处** —— 第一处是不对称的那一面,整段锚点在
    它身上 `indexOf` 恰好等于采集偏移,「命中且位置对」会把一条并不唯一的锚点判成「能
    定位」,前后文于是不再加长,而回跳那头按唯一性一问就是一句「没找到」。
  - **译文刚写回、还没重导出的那一条退回 `origin=feed`**(`path` 落空、URL 是站外那个),
    **反向钉住**:导出是最新的那一条照旧绑文档。
  - **锚点只有一边被另一种渲染扰动的那一格**:同一篇里另有一对**靠小标题分隔**的重复句,
    订阅阅读器摊的是 md 原文(`## 乙一节` 带着井号)、阅读页渲染成 `<h2>` —— 整段和「只用
    前文」两档在那一头都失配、裸引文又重复两次,**只剩「只用后文」那一档**。判据是后果:
    存之前那道核对认它定位得到(没退回 feed)、点回去真落在第二处。
  - **流式途中 / 点了停止 / 同一轮还没落库的提问都不许收**,`done` 帧回来之后那一刻起收得
    下,**把对话从库里重新读一遍**那段话真的在,回跳也定位得到。
  - **压平之后不满 4 字的选区不弹按钮**(反向:「冒号 + 四个空格 + 一个字母」原样数七个
    字符、压平只剩三个 —— 引文按原文存之后这两个数才第一次分叉)。
  - **内容自带的长标题长链接不会把整条收藏拒成 422**,两头各钉一条:真实长度(3000 字)的
    链接**原样存下来**(后端上限这一半)、超过约定上限的链接**整条丢掉而不是截一半**
    (采集层这一半),标题一律截到后端认的长度;外加**裁口正好落在一个字中间**那一格
    (第 300 位是 emoji 的前一半)。
  - **正文里有 emoji 的那一段收得下、库里那条前后文是整字**(日报和独立阅读页各一次),
    后端对半个字**如实拒成 400**;反过来钉一边:**定得准的那一条不许乱提示**。
  - **两个哈希相等、盘上那篇已是另一份译文的那一条退回 `origin=feed`**,先钉住夹具真是
    「两个哈希相等」那一种(否则这条判据可能是靠别的理由过的),再钉退的理由写进了提示。
  - **两边的位置证据互相矛盾时一处也不许高亮、如实说没找到**(app 和独立阅读页各一次)。
  - **三档前后文都分不出来的那一段:存得下,而且收藏那一刻就说了「点回去可能定位不到」**
    (app 和独立阅读页各一次 —— 两份实现的反馈契约)。
  - **原文链接超过上限时整条没存,而且当场说了**(没有 path 的那一类靠它回原文)。
  - **「存为笔记」那行界面文字和按 refs 现拼的引用块都不算可收正文**(同一条消息的正文照旧
    收得下 —— 反过来钉一边),以及**提问第 60 个字是 emoji 的那一轮也收得下、标题裁得干净**。

  - **原对话已经删掉之后点那条收藏的回跳**:屏幕上说清「不在了」(不许停在「加载对话…」)、
    提示里说清**收藏里那段原文还在**、这次待定位被丢掉(不会挂到下一个打开的对话上)。

    拒」也能让上面两条全绿。
  - **独立阅读页手里那份正文旧了之后,收藏如实被拒、一行不落库、提示说清刷新再收**;

    「原文」的话窗口压根够不到后面两颗,这条判据就跟采集范围无关了);反过来钉一边,选中
    那三颗按钮的文案**不弹按钮、0 行**(判据不落在摘要行上:那一段浏览器自己不交出来)。
  - **核对那一步不许动全局那套渲染**:核过一次之后原地重渲染这一条,正文里那段 HTML 照旧是
    粗体 —— 拿 `marked.use()` 换规则的话图鉴、日报、问答就都跟着变了。
  - **弱档那几格:同一篇正文、同一句话、同样失配的两侧,每一格只差一个数。**
    ① **日报那一头一律不采信**:`u=1` 和 `u=0` 两条都该是「没找到」且不许高亮 ——
    采集和回跳是同一个渲染器,没有「两种渲染」这个借口,`u` 不是放行条件。两侧**天生都没有**
    的那一条(裸锚点)也在这一头照旧不采信:那句话在正文里确实只有一处,可那不是证据。
    ② **一侧有证据、却在这份文本里一处也对不上**(中间那一格,最容易蒙过去的一格):前文给
    一句正文里压根不存在的话、后文指得出**第二处**,而同样的话正文里有两处 —— 一个高亮都不
    许给,因为采信的后果是亮起一句用户没收过的话。**反过来钉一边:天生没有那一侧的锚点照旧
    只听另一侧**(引文顶在开头、md 与渲染差一个标题那类),落回它指的那一处 —— 一侧的三种
    状态(天生没有 / 有证据但全失配 / 有候选)压成两种的话,这一条会跟着一起被拒。
