# 来源面板的条目卡片(kb/static/js/sources.js 的 renderSourceItems)

> **这一份整份都是这一块的记录:硬约束 + 事故形态、实测证据、回归清单和反向验证红数** ——
> 动这块代码之前先读它。CLAUDE.md 只留跨块的元规则和一张索引。

- **大V观点那一档不显示标题,别再加回来。** 推文没有「标题」这回事:采集器把正文的
  前 500 字符原样当成 title(`x_browser._entry` / `x_feedgrab._entry`;桥接那条走
  `fetching.parse_feed`,源没给标题时回退成正文首行)—— 于是卡片上那行大标题和紧跟
  着的正文是**同一句话连着显示两遍**,而标题那个 `<button>` 继承了 base.css 的
  `white-space: nowrap`,一条长推文一行到底、**直接撑出卡片右边界 971px**(2026-10-09
  用户截图,探针里逐字复现)。阅读弹窗同理不显示它:那是正文的前 500 字符,摆在正文
  正上方就是同一段话读两遍;作者和时间留在 meta 行上,这一条是谁什么时候发的不会丢。
- **判据是条目自己的 `content_kind === 'post'`**,不是「当前视图是不是 social」:
  要回答的是"这一条内容有没有标题",那是内容自己的属性。**如实记一笔**:今天
  `sourceKind === 'social'` 和它逐条等价(social 来源的每一条都是 post,而弹窗是模态
  的、开着时切不了视图),定点注入换成按视图判一条都不红 —— 选它不是因为防住了某个
  事故,是因为另一个问句(现在在看哪个来源)恰好同解,而同解是会变的。页脚那句
  「社交观点 / 订阅正文」问的才是来源,所以它照旧按视图走。
- **去掉标题之后正文从 muted 的"摘要"提成次要正文**(`.source-excerpt.is-post`,
  `--ink-2` + 15px):它成了卡片上唯一的内容,继续按辅助信息显示的话整列卡片看起来
  全是次要信息、没有主体。反过来钉一边:RSS 那一档照旧是 muted 摘要。
- **等翻译那一档照旧显示那行状态文案**(`.source-entry-name` 的「外文内容，正在等
  翻译」)。它回答的是"这张卡片为什么没有内容",不是"这条内容叫什么" —— 和上面去掉
  的那个标题不是一回事;去掉它只剩一行小字,和一条正常推文在页面上几乎分不出来。
- **展开阅读原来有标题和页脚两个入口,现在只剩页脚那个**,够用(页脚那颗按钮上写着
  「展开阅读」四个字,比"标题可点"这件看不出来的事更明确)。
- **顺带修的 `.source-entry-title { white-space: normal }` 对三类来源都成立**:
  base.css 给所有 button 设了 nowrap(按钮文字本来就不该折行),而这个"按钮"是一整行
  标题 —— 旁边那句 `overflow-wrap:anywhere` 在 nowrap 之下压根不起作用,中文标题又
  一个空格都没有,于是长标题照样撑出卡片(RSS 那一侧实测 227px)。大V观点这一档已经
  没有标题了,这条是给另外两类兜底的。
- 回归在 `tests/test_source_post_title.py`(4 条:两条 X 采集器和桥接给的
  `content_kind` —— 前端那道判断的前提在采集器那头,它变了页面上看起来只是"标题又
  回来了")+ `tests/source_post_probe.mjs`(真页面 + 无头 Chrome,自带 mock 后端,
  18 项)。探针的断言**先验后果**:「有没有东西画到卡片外面」「正文一个字没少」
  「正文的第一句只出现一遍」排在「DOM 里还有没有那个元素」前面 —— 只验元素在不在的
  话,一个把标题藏起来却仍然撑开卡片的实现(visibility/opacity)也能全绿。反向验证
  定点注入过五版:整个改动退回(修之前的真实状态)红 7 条,其中第一条正是用户截图那份
  证据(`{"px":971,"who":"source-entry-title"}`);只退标题那一处红 4 条(**溢出那条
  不红** —— `white-space:normal` 已经让它折行了,所以这两条判据各管各的);只去掉
  `white-space:normal` 红 2 条(都在 RSS 那一侧);去掉 `is-post` 样式红 1 条;
  判据换成按视图判 0 条红(上面那条"如实记一笔"就是这么来的)。
