# X 长文(Article)的正文补全(kb/feeds/x_article.py)

> **这一份的第一节就是这一块的硬约束(不许怎样)—— 动这块代码之前先读它**,后面是完整的事故形态、
> 实测证据、回归清单和反向验证红数。CLAUDE.md 只留跨块的元规则和一张索引。
> 硬约束和下面的展开**说的是同一条口径,要改规则两边一起改**。

## 硬约束(原 CLAUDE.md「X 长文(Article)的正文补全(kb/feeds/x_article.py)」)

- **长文推文在时间线上一个字都没有**(`text` 就是一条指向 `x.com/i/article/<id>` 的短链),两条通道入库的都是
  空正文。**主路是 FxTwitter 的公开接口**(`tweet.article.content` 是 Draft.js 块);**后路**是在
  `browser`/`attach` 的登录态浏览器里按 DOM 读(`browser_fetch`,由 `x_browser.harvest` 把还活着的会话传下
  去),它不当主路的理由是只对两条通道成立 + X 改版就要跟一次。`feedgrab` 没有浏览器,照旧「补不到就
  不入库、不推进水位」。
- **文章页地址 = 推文地址把 `/status/` 换成 `/article/`,不需要 `article_id`**(后者只出现在接口回包里,而后路
  恰恰在接口不可用时才跑)。
- **「这条推文没有长文」的判据是 X 自己的路由行为**:纯图推文的 `/article/<id>` 会 302 回 `/status/<id>`。这一
  档返回 `None`(照旧入库、**不冻水位**)。**判不准的时候一律抛,不许返回 `None`**(登录墙、空壳、渲染超时、
  CDP 报错全部抛)。CDP 报错只抛 `ArticleUnavailable`,不冒到「浏览器会话中断」上去。
- **后路落地之后要核对「这一页到底是不是我们要的那一篇」,这一道承重**(`seen[1] != want` 一律抛)—— 导航**可能
  不生效而页面停在原处**。配套三条:`Session.goto` **返回** navigate 回包而不抛(时间线那两处各自按 `_STATE_JS`
  判);回包里的 `errorText` 是**早一道**、不能靠它;**`back` 那一档也要求身份相符**。
- **这一步要带整轮的时间预算和停止开关**(`fill(..., deadline=, should_stop=)`,**两条通道各挂一次** ——
  `x_browser.harvest` 和 `x_feedgrab.harvest` 的调用点都传):它跑在时间线读完**之后**,外面那两道闸都够不着
  它,而 `_GIVE_UP_AFTER` 只数**连续**失败。拦下的按扣留办。**接口切后路之前再问一次停止。**
- **块内按子节点顺序拼,`<img>` 分两种,判据是 alt 的内容**:至少含一个表情码点**且**整串只由表情相关码点组成
  的是行内表情(按 alt 还原),其余一律是真·配图(`![alt](src)`)。「有 img 就只要图片」丢整段文字,「非空 alt
  就是表情」丢图片地址,`innerText` 不含 alt。
- **预格式化块里的空白是内容,一个都不许折叠**(两道任一成立:计算样式的 `white-space` 以 `pre` 开头,或标签本
  身是 `pre`/`code`/`samp`/`kbd`;折叠挪到文本节点那一层)。**反过来钉一边**:只存在于 HTML 源码里的换行缩进照
  旧折叠。
- **零宽字符只清 ZWSP 和 BOM,`\u200c`/`\u200d` 一个都不许动**(组合表情的一部分)。
- **代码块里一个字节都不改**(零宽清理和 nbsp 归一只对普通段落做),两条路对同一篇文章必须给出同一份代码。
  **占位清理整个挪去组边界**(`codeBody` 的 `blankRow`)—— 在逐块那一支做的话,组**中间**那一行零宽字符也被当占
  位符清掉。
- **代码块要写成 markdown 代码围栏 —— 读对那串字符只是半截**(两条路各一处:主路认 Draft.js 的 `code-block`,后路认标
  签)。写 `<pre>` 没用(阅读页按契约把剩下的标签一律当字面文字),改阅读页 CSS 会动全站且 vault 里躺的仍是裸代码。配套
  四条:①**相邻的代码块合并成一个围栏**;②**围栏里每一行都原样,一个字节都不改**(行首缩进和**行尾空白**都是内容,
  **收尾不许用 `.strip()`/`.trim()`**;占位空块只在**整组边界**削**完全空**的行,纯空格的一个都不削,两侧各一份实现
  `_code_body` / `codeBody`、**各有自己的回归**);③**围栏长度要避开代码里已有的反引号串**(`max(3, 最长串+1)`);
  ④**后路那道判据只认标签,不许用计算样式**(Draft.js 默认给**每一个块**都加了 `white-space: pre-wrap`)。`preish`
  (保住空白)和 `codeish`(写围栏)是两道**不同**的判据。
- **补完正文不许把转推上下文丢掉** —— 入库正文是三段按原顺序拼:转推上下文(`> …`)→ 推文自己写的介绍 → 文章正
  文(`quote_lines` / `lead_text` 各摘各的)。
- **接口答「有标题、没正文」时一律当成没取到**(回包被截断那个形状原来返回成功,而空正文一旦落库就改不回来)。
- **第三方回包的结构异常一律留在接口边界内,两道各有射程。** ①**承重的是每一层明确判类型**(`_rows` + `_media_urls` /
  `_entity_image` / `_entities` / `render` 各一遍 `isinstance`),认得出的结构异常**就地降级**(那张图跳过、那一块跳过)。
  **不许拿 `or {}` / `or []` 当类型检查**(它只认假值,而撒谎的回包给的是**非空**的错类型);**判一层不够,得每一层都
  判**,没有「这一层不会出问题」这种例外。②**兜底是 `fetch` 把 `render` 的数据形状异常一起翻成 `ArticleUnavailable`**
  (`AttributeError`/`TypeError`/`KeyError`/`IndexError`/`ValueError`),只圈这几类,不写 `except Exception`。
  `json.loads` 那道 except 要带上 **`RecursionError`**(它是 `RuntimeError` 的子类;但**绝不能写成
  `except RuntimeError`**)。
- **必需的结构认不出来一律抛,`str()` 强转和 `continue` 都是在给错内容盖「成功」的章**(`_must_text` / `_must_block`)
  —— 强转和丢成员都得到**非空**结果,于是「正文为空就抛」和异常兜底**都没有机会介入**(残缺不是空)。必需 = 块的
  `text`/`type` 和块列表的**成员**;可选(图片地址、标题)认不出来跳过那一块,**但同样不许强转**。**空值跳过、非空错
  类型一律抛**:真的空块是 `{}`,走正常路径留一个空行;而**非空的错类型 `article` 不是「确定没有长文」**,缺失、
  `null`、空对象、空列表、空串才照旧返回 `None`。**后路那一侧是同一条缺陷的两个位置**,各有自己的回归。
- **`render` 只按块级转 markdown,块内 inline 样式一概不动**(`inlineStyleRanges` 的偏移是 **UTF-16 码元**)。另
  两处形状坑:`entityMap` 是**列表不是字典**(键一律按字符串比);图片要 `mediaItems[].mediaId` →
  `media_entities[].media_id` → `original_img_url` 三跳,**查不到就跳过、不许编一个**。**正文里不写标题**
  (`sync.export` 自己会写)。
- **`needs_article` 三条判据**:①正文里**明写着**一条文章地址(**两种路径形式都算**);②**时间线上看见了那张长文
  卡片**(`x_article.HINT`,从 DOM 里读,排掉引用推容器里的那张,**只补不清**);③推文自己一个字都没说。**不拿
  「正文里有 t.co 短链」当信号。** 那个信号键**不进 `feed_items`**(`_strip_hint`,`fill` 每个出口都过它)——
  `put_items` 把整份条目哈希成 `content_hash`。
  (原来还有一个 `links_only=True` 的省钱档只认判据①,给桥接那条路用。桥接删掉之后它没有调用方了,
  连同 `fill_bridge` 一起删。)
- **①那条判据要认 X 的两种文章路径形式**(`/i/article/<article_id>` 是 t.co 展开出来的,
  `/<handle>/article/<tweet_id>` 是 X 自己 302 到的**规范形式**),**而且和 `lead_text` 共用同一条正则**
  (`_ARTICLE_LINK`)—— 少认一种 = 那条链接本身当成正文入库、永久固定。**两处都要跟着改**:判据① 决定「要不要去
  问」,`lead_text` 决定「问到之后正文开头留什么」。handle 的字符类不许放宽(`[A-Za-z0-9_]{1,20}`)。
- **地址识别那一族判据,动之前必须读 `docs/decisions/x-article.md`:每一条收窄都对应一类真实写法,合并或放宽任意一
  条都会静默丢数据。** 两个消费方方向正好相反 —— 判据① 是 `search`(漏认 = 空正文永久固定),`lead_text` 是 `sub`
  (多删 = 作者写的字永久消失),所以**地址主体认宽、尾巴和起点一律收窄**。
- 不许动的那几道:`_URL_TAIL`(**只摘地址本身**,紧挨的标点和文字一个都不许跟着走;**不许写 `\S` 或 `\w`** —— 前者
  含汉字,而 str 模式下 `\w` 也是 Unicode 的;结尾必须落在「不像句读」那一档);**起点按候选带不带 scheme 分两档**
  (合成一档必然漏认一头);`_nested` 三步、**两种嵌套证据各管一类入口缺一不可**;`_URL_RUN` 按 RFC 3986 取**全
  集**(含 gen-delims)、**不许和裸域名那档的禁止集共用一份**(少认一个字符,外层起点就追不回来);`](` 是**起手标
  记不是终止符**,`_text_closed` 连显示文字一起收、**扫描范围是本行**;`_inert` + `_code_spans` 按 CommonMark 判哪些
  方括号是字面(**找闭合反引号串按字面、不认反斜杠转义**,而跨度外那个转义分支照旧留着)。
- 已知两道缝,知情且接受:非 ASCII 的外层路径、跨软换行的显示文字。
- ~~**`bridge` 这条通道也接上了,钩子是 `x_channels.fill_bridge`**~~ —— 桥接那一档整条删掉之后这个钩子
  也拆了(走 HTTP 的只剩填了专用订阅链接的订阅,它们从来不走这个钩子)。
- **补不到的那几条本轮不入库,而且这一轮算「没读完」**(水位留在原处,面板显示「部分同步」)。
- **两个开关各管一条路**:`KB_X_ARTICLE_API=''` 关掉接口(这正是「不想把推文 URL 发给第三方」要的那一档);
  `KB_X_ARTICLE_BROWSER=0` 关掉后路。**后路成功要把 `_GIVE_UP_AFTER` 的计数清零。**
- **失败文案只取 `fetching` 那句话分号前的那一半**(后半截在长文语境里是胡话)。
- **存量回填是 `scripts/x_article_backfill.py`(scan / run --yes)** —— 采集那侧修好只对**新**长文生效。它只改
  feeds.db 的 `title`/`body`/`content_hash` 并清 `exported_hash`,不写 kb.db、不写 vault。**`lang` 要一并清成空串**
  (空正文那会儿按占位标题判成了中文,而 `lang='zh'` 永远进不了翻译队列);不想花翻译钱就把 `translate_tries` 设成
  `translate.MAX_TRIES`,**别改成 `lang='zh'`**(那是谎报语言)。写回按元规则带条件。
- 读文章页的 JS 在 `x_article_js.py`、回包结构判定和块级零件在 `x_article_shape.py`、地址识别在
  `x_article_links.py`(起点判据再往下拆进 `x_article_nest.py`),**只因为行数**。
  `API`/`PAGE_WAIT`/`BROWSER_FALLBACK`/`MAX_CHARS` 一个都没搬(它们被 `patch.object` 改过);搬过去的名字一律原样再
  导出。
- 详细见 `docs/decisions/x-article.md`。

## 事故形态与实测证据

- **长文推文在时间线上一个字都没有。** 推文自己的 `text` 就是一条指向
  `x.com/i/article/<id>` 的 t.co 短链,而 X 把它藏起来、改渲染成一张「X 文章」卡片
  —— 于是浏览器通道那边 `[data-testid="tweetText"]` 压根不存在、feedgrab 那边产物
  正文就是那条链接本身。两条通道入库的都是空正文:标题回落成「某某 的动态」、
  vault 里那篇 md 没有内容、提取阶段每轮把它报成「正文为空,需回填」。
  2026-10-09 在生产库上实测:近三周 social 的 342 条里 11 条空正文,**其中 9 条
  是长文**(1305~31864 字),另两条是一条纯图推文和一条已被作者删掉的推文。
- **取法是 FxTwitter 的公开接口**(`https://api.fxtwitter.com/<handle>/status/<id>`,
  回包里 `tweet.article.content` 是 Draft.js 块)。**另外四条路各自不成立**:
  ①`/i/article/<id>` **不登录打不开** —— 裸 curl 只拿到 SPA 外壳,不登录的无头
    浏览器实测显示「该页面不存在」+ 登录框。**但别把这句写成"开个浏览器点进去也
    不行"**:`attach` 通道连的是用户自己那个登录着的浏览器,那里打得开 —— 实测
    同一篇在它里面渲染出 2986 字可读文本、没有登录墙(2026-10-09)。那条路算下面
    的 ④,不算这一条;②X 自己的 syndication 接口(`cdn.syndication.twimg.com/tweet-result`)
    不要登录,但只给 `article.title` 和约 120 字的 `preview_text`,**没有正文**;
    ③**feedgrab 也不行** —— 它走的是 X 内部 GraphQL + `x-client-transaction-id`
    签名,而那套签名的 manifest 只下发给**登录态**页面(它自己的文档写着要先
    `feedgrab login twitter`),所以"不登录就能抓长文"在它那条路上同样不成立;
    ④在登录态浏览器里按 DOM 读 —— 这条**技术上成立**(上面那次实测就是它),
    **它现在就是后路**(见下面那几条)。不拿它当主路的理由不是"读不到",是两条
    代价:它只对 `browser`/`attach` 两条通道成立(`feedgrab` 用不上,
    而主路要三条通道通用)、**X 改版就要跟一次**,正是这个项目明确不收的那种
    维护量(同「不要把 feedgrab 抄进 kb」那条)。**原来还记着第三条「拿到的是
    混着导航栏和作者简介的 innerText」,那条已经不成立了** —— 后路按 Draft.js
    的块读(见下面),拿到的是纯正文。
  **选它换来的是:不要登录、不要浏览器、三条通道通用、一次 HTTP 往返拿结构化
  JSON。** 代价两条,都如实记着:多一个第三方依赖;推文 URL 会离开本机(内容
  本身是公开的)。超时 `KB_X_ARTICLE_TIMEOUT`(默认 20 秒)。
- **FxTwitter 是一个第三方服务(开源 FixTweet 跑的公共实例),所以它关了要有
  后路:`browser`/`attach` 两条通道手里正好有一个已经登录的浏览器**
  (`x_article.browser_fetch`,由 `x_browser.harvest` 把那个还活着的会话作为
  `fill(entries, session=page)` 传下去)。`feedgrab` 没有浏览器,那一条
  照旧按「补不到就不入库、不推进水位」办,下一轮重试 —— 所以后路是**加**出来的
  一条路,不改任何既有行为。导航是安全的:这个账号的时间线已经读完了,下一个
  账号的 `_harvest_one` 第一句就 goto 回它自己的 profile。
- **文章页的地址 = 推文地址把 `/status/` 换成 `/article/`,不需要 `article_id`。**
  这是 X 自己的规范形式,不是我们凑的:`/i/article/<article_id>` 实测 302 到
  `/<handle>/article/<tweet_id>`(2026-10-09)。**这一点是后路成立的前提** ——
  `article_id` 只出现在 FxTwitter 的回包里,而后路恰恰要在那个接口**已经不可用**
  的时候跑,手里只有推文 URL;要是非得先知道 `article_id`,这条路压根立不起来。
- **「这条推文没有长文」的判据是 X 自己的路由行为,不押任何 CSS 选择器**:实测
  一条纯图推文的 `/article/<id>` 会被 X **302 回 `/status/<id>`**,而有长文的那条
  老老实实停在 `/article/` 上(2026-10-09 两条各实测一次,都走的是用户自己那个
  登录着的浏览器)。这一档返回 `None` —— 照旧入库、**不冻水位**,口径同主路那条
  「确定它没有长文是另一回事」;不分开的话一条纯图推文能把这个号的水位永久冻住。
- **判不准的时候一律抛,不许返回 `None`。** 两个方向的代价差着一个量级:把
  「有长文」说成「没有」会让一条空正文落库,而 `put_items` 是 `DO NOTHING` ——
  那一篇从此永久是空的、下一轮重试也救不回来;反过来把「没有长文」说成「问不到」
  只是让水位留在原处、下一轮重叠重抓一次(`put_items` 按 URL 去重)。所以只有
  上面那一种 302 才算「没有」,**登录墙、空壳、渲染超时、CDP 报错全部抛出去**。
  其中 CDP 报错只抛 `ArticleUnavailable`(这一条没取到),不冒到 `harvest` 外面
  那道「浏览器会话中断」上去 —— 单篇读不动不该把剩下的账号一起带掉。
- **块内按子节点顺序拼,`<img>` 分两种,判据是 alt 的内容:alt 整串都是表情
  字符的是行内表情(X 把 emoji 渲染成 twemoji 图片,alt 就是那个字符),按 alt
  还原;其余一律是真·配图,写成 `![alt](src)`。** 原来是「这一块里有 `img` 就只要
  图片」,而**段落里插一个表情图是极常见的形态** —— 那一版把**整段文字丢掉**只留
  一张小图,而且照样报成功(2026-10-09 审查用真无头浏览器渲染 Draft.js 形状的页面
  实测:页面上那句「第一步，保存你真正想读的资料。然后安排每天二十分钟完成练习，
  别只收藏不行动。」出来只剩 `![](data:image/svg+xml,…)`)。**也不能用 `innerText`**:
  它压根不包含 img 的 alt,表情会静默消失。
  **但「非空 alt 就是表情」同样不成立** —— 给配图配一句描述是无障碍的常规做法
  (`alt="系统架构示意图"`),那一版把**图片地址整个丢掉**只留那句描述,而剩下的
  文字让正文看着非空:`browser_fetch` 那道「正文空不空」的判据发现不了图没了,
  一篇缺图的正文照样落库、`DO NOTHING` 之下永久改不回来(2026-10-09 第 2 轮审查
  用真浏览器实测:`<figure><img alt="系统架构示意图" src="…">` 出来只剩那五个字)。
  所以判据换成两道:**至少含一个表情码点** + **整串只由表情相关码点组成**

- **接口答「这条没有长文」时不走后路。** 那是一个确定的答复,再开一张标签页只是
  白等。只有接口**问不到**(500、超时、回包读不懂)才轮到后路。
- **后路成功要把 `_GIVE_UP_AFTER` 的计数清零。** 那个计数防的是「接口整个挂了而
  这一轮还有几十条要问,每条各等满一次超时」;而接口全挂、后路全好时每一条都补
  得到,在第 3 条上放弃等于白扔掉后面那些。两条路都坏了才照旧放弃。
- **两个开关各管一条路**:`KB_X_ARTICLE_API=''` 关掉接口 —— **手里有浏览器时就

  关掉后路;两个都关 = 整条退回这一步出现之前(`fill` 原样返回这一批)。

  那篇长文从用户自己那个登录着的浏览器读出 2791 字 / 40 段 + 真标题,`note` 是空的
  (这一轮算读全了、水位照常推进);同一次把纯图推文交给 `browser_fetch`,它答
  `None`、`note` 照旧是空的。
- **补不到的那几条本轮不入库,而且这一轮算「没读完」。** 理由只有一个:
  `put_items` 是 `ON CONFLICT(key) DO NOTHING` —— 空正文一旦落库就**再也更新不了**,
  下一轮重叠重抓也救不回来。所以 `fill` 把它们从这一批里摘掉、返回一句原因,两条
  通道各把它并进自己那个 `incomplete`/`note`,于是**水位留在原处**(口径同
  「没读到上次的位置,水位一步都不许动」),下一轮重试;面板上显示成「部分同步」。
  **「确定它没有长文」是另一回事**(`fetch` 返回 `None`,纯图/纯视频推文):那条
  照旧入库、**不冻水位** —— 不分开的话一条纯图推文能把这个号的水位永久冻住。
- **坏掉的端点不许问五十次**(`_GIVE_UP_AFTER`=3):连着三条都问不到就不再问这一轮
  剩下的,但它们照样记进那句原因(没取到就是没取到,不能因为放弃得早就当成读完了)。
  成功一次就把计数清零。
- **`needs_article` 三条判据**:①正文里**明写着**一条文章地址(feedgrab 那条路的
  形态,哪怕作者还写了别的话;**两种路径形式都算**,见下一条);②**时间线上看见了那张长文
  卡片**(`x_article.HINT`);③推文自己一个字都没说(同样是卡片那条路,只是作者
  没写介绍)。**不拿「正文里有 t.co 短链」当信号** —— 那可能是图片、引用推、任意
  外链,按它发请求等于给一大半推文各买一次调用,换回来的多半是"它没有长文"。
- **②那条信号是从时间线 DOM 里读出来的,原来整个没有,于是「写了一句介绍 + 一张
  长文卡片」的推文永久只收那句介绍**(`x_browser._COLLECT_JS` 里那个
  `a[href*="/article/"]`)。X 把链接藏起来改渲染成卡片之后,这种推文的正文**非空**
  —— ①③两条都不命中,整篇文章就这么漏掉了,面板上一切正常(2026-10-09 审查用真
  无头浏览器实测:长文接口一次都没被调用,库里正文是那句「我写了一篇新文章」)。
  **它只是信号,地址不用它**:文章页地址由推文自己的 URL 推出来(见
  `article_page`),"有没有长文"的结论由接口/页面那一侧给 —— 所以信号误判的代价
  只是一次白跑的询问(答复正好是"它没有长文"、照旧入库),绝不会把别人的文章记
  到这条推文头上。配套两条:**排掉引用推容器(`div[role="link"]`)里的那张卡片**
  (那是别人的文章;排错了只是回到漏掉的现状,收错了是污染 —— 这个方向上宁可多
  排),以及**卡片只补不清**(某一次滚动它没渲染出来时沿用认过的那一个)。
- **那个信号键不进 `feed_items`**(`x_article._strip_hint`,`fill` 的每个出口都过
  它):`put_items` 把**整份条目**哈希成 `content_hash`,留着它会让同一条推文在两
  条通道上算出不同的哈希。
- **①那条判据要认 X 的两种文章路径形式,而且和 `lead_text` 共用同一条正则**
  (`_ARTICLE_LINK`:`/i/article/<article_id>` 是 t.co 展开出来的那种,
  `/<handle>/article/<tweet_id>` 是 X 自己 302 到的**规范形式** —— 后者正是本实现
  `article_page()` 生成的那个地址,不是一种我们不支持的 URL 规范)。原来只认前一种,
  而展开成哪一种由上游和 X 说了算、我们看不见也管不着,于是后一种在**三条通道**上
  各有一种末态(2026-10-09 实测,每一种各有一条回归):**feedgrab** 上三条判据一条
  都不命中(①看不见这个形式,③因为"正文里有字"而不命中,②的卡片信号只有浏览器通道
  才有)—— 那条链接本身当成正文入库,`added=1`、`errors=[]`、`partial=[]`、水位照常
  推进、标题回落成「某某 的动态」,而 `DO NOTHING` 之下**下一轮重抓也更新不了它**;
  **浏览器/attach 没读到卡片**时(某次滚动没渲染出来、或者被引用推容器那道排除规则
  挡掉)末态逐字相同 —— 所以①本来就该是独立于卡片信号的第二道;**读到了卡片**那一档
  正文补上了,可 `lead_text` 同样认不出这个形式,那条地址原样留在库里那篇正文的开头。
  **两个方向的代价差着一个量级,所以宁可认宽**:漏认一种形式 = 空正文永久固定,多认
  一种 = 最坏一次白跑的询问(答复正好是"它没有长文",照旧入库、不冻水位),口径同上面
  那条信号。**但 handle 的字符类不许放宽**(`[A-Za-z0-9_]{1,20}`,同 `_STATUS` /
  `_ARTICLE_PATH`;`/i/` 的 `i` 本来就落在里面)—— 这条正则在 `lead_text` 里是拿去
  `sub(' ')` 的,放成任意一段就会把推文里真实的字删掉。**两处都要跟着改**:判据①
  决定"这一条要不要去问",`lead_text` 决定"问到之后正文开头留什么",只改前一处时
  端到端那两条照旧红(定点注入实测红 4 条)。
- **摘掉的只能是那条地址本身,紧挨着它的标点和文字一个都不许跟着走**(尾巴的口径
  在 `_URL_TAIL`,`_ARTICLE_LINK` 和 `_TCO` 共用)。两条正则的尾巴原来都是「吃到
  下一个空白为止」(`\S*` / Unicode 的 `\w+`),**而中文不带空格** —— 于是
  「我写了一篇新文章:<地址>,重点看第三节。」里那句说明被整段当成地址删掉,
  `added=1`、`errors=[]`、`partial=[]`、水位照常推进、一行提示都没有,而
  `put_items` 的 `DO NOTHING` 让这一篇**永久**只剩前半句 —— 重复同步也补不回来
  (2026-10-09 审查实测,证据里连导出的 md 一起核过)。中文括号/方括号包住、
  `?s=20` 或 `#sec3` 之后紧跟中文、英文的 `. ` 与 `) ` 收尾,六种形态逐字同样;
  **两种路径形式和 t.co 那条都有这个病**,后者在 `lead_text` 的下一行、是同一次
  「把链接从正文里摘掉」的动作。
  **两道各挡一类,缺一不可**:①**字符类只收 URL 的 ASCII 合法字符**,中文(逗号、
  括号、以及作者正文本身)天然落在外面 —— **不许写 `\S` 或 `\w`**:前者是「任意
  非空白」,汉字就在里面;而 Python 的 str 模式下 **`\w` 也是 Unicode 的**
  (`re.match(r'\w+', '中文')` 当场命中),换成它一样挡不住,`_TCO` 原来就是这么
  漏的(定点注入这一版照旧红)。②**结尾必须落在「不像句读」的那一档**(窄集比宽集
  少了 `.` `,` `;` `:` `!` `?` 和闭括号):这些字符在 URL 中间合法(`?t=a.b`),贴在
  查询串尾巴上的那一个却是作者的标点 —— 中文标点压根不在字符类里,所以这一道只在
  **英文**句读上才看得出射程,它自己那条用例因此是 `?s=20. ` / `?t=a.b&s=09, `
  (只摆中文样本的话去掉这一道只红 1 条,补上之后红 2 条)。另外 `[/?#]` 后面要求
  至少一个字符(尾斜杠那一支单列),否则 `Did you read <地址>?` 句末那个问号会被当
  成一个空查询串吞掉。
  **「认宽」只对地址主体成立,尾巴反过来要收窄** —— 两个消费方的方向正好相反:
  判据① 是 `search`,宁可认宽(漏认 = 空正文永久固定);`lead_text` 是 `sub`,宁可
  少删(多删 = 作者的字永久消失)。收窄尾巴恰好只动后者:地址主体已经足够回答
  「有没有一条文章地址」,尾巴匹配到哪儿对 `search` 的真假一点影响都没有。所以
  **两头都要钉**:只验「那句说明还在」的话,一个压根不摘地址的实现也能全绿(反过来
  那两条:判据① 对带查询串/片段/尾斜杠的地址照旧为真、带尾巴的地址要摘得干干净净,
  定点注入「尾巴整个不认」实测红 6 条)。
- **左边同理:地址必须从一条 URL 的起点算起**(`_URL_HOST`,两条正则共用)。两条正则里
  的 `x.com` / `twitter.com` / `t.co` 都只是一段字符,**压根不要求它是主机名** ——
  于是一条**合法的外部地址**只要内部出现这一段就被当成起点、后半截被 `sub` 掉,
  而 `DO NOTHING` 让这种删除**永久固定**。实测被改坏的五种(2026-10-09,每一种都
  是真实写法):`https://fxtwitter.com/Example/article/10001` → `https://fx`
  (镜像站,`fx` 后面那一段逐字就是 `twitter.com/<handle>/article/<id>`)、
  `https://notx.com/…` → `https://not`(域名后缀)、`https://help.x.com/…` →
  `https://help.`(子域名)、`https://example.org/docs/x.com/…` →
  `https://example.org/docs/`(真实主机名是 `example.org`,`x.com` 只在它的路径里)、
  `https://evil.example/?u=http://t.co/aBcD12&next=1`(查询参数被删掉一截)。
  末态和尾巴那条逐字相同:`added=1`、`errors=[]`、`partial=[]`、水位照常推进,
  库里和导出的 md 里都只剩那半截,一行提示都没有;同一道缺口还让判据① 把这些推文
  一律误判成「要去问一次长文」,每条白跑一次调用。
  **判据按候选自己带不带 scheme 分成两档,因为这两档要排掉的东西根本不是一回事。**
  **①自带 scheme 的候选**(起点在正则里**一个字符都不限**,全部交给 `_nested` 按
  上下文判):`https://` 本身就宣告「一条新 URL 从这里开始」,域名后缀那一类从定义上
  不可能,要排的只有「它嵌在另一条 URL 里」—— 而**「嵌没嵌」不是紧贴那一个字符回答
  得了的**,见下面 `_nested` 那三步。
  **②裸域名的候选**(`_BARE_HEAD`,`x.com/<handle>/article/<id>` 不带
  scheme):起点就是主机名第一个字符,域名后缀和路径嵌套都要排,禁止集是「URL 内部
  字符」那一整套(字母数字 `.` `-` `_` `~` `%` `+` `/` `=` `&` `?` `#` `@`)——
  **它和分档之前那道闸逐字相同**,分档只是给①松了绑。
  **合成一档的后果实测过,而且它是「漏认」那个方向**:`.` 和 `~` 有两个互相冲突的
  身份 —— 在 `help.x.com` / `my-x.com` 里是**域名的一部分**,在 `新文章...<地址>`
  里是**作者的标点**,单看紧贴的那一个字符分不开。一律禁掉的话,省略号或波浪号紧贴
  的**真**地址被拒,`needs_article` 三条判据一条都不命中,于是那条链接本身当成正文
  入库:`added=1`、`errors=[]`、`partial=[]`、水位照常推进、标题回落成「某某 的
  动态」,而 `DO NOTHING` 之下重复同步也补不回来(2026-10-09 第 3 轮审查实测
  `我写了一篇新文章...https://x.com/Example/article/10001` 与 `新文章~…`,两种路径
  形式各一次,浏览器通道没读到卡片信号时逐字同样;英文的 `Check it out...` 同理 ——
  那时连左边那个字母一起落在同一段里)。分档之后压根不用分辨那个字符是什么身份。
  **而①那一档里「按紧贴的那一个字符判」栽过两次,两次都是漏认,所以这个判据整个
  不许写成一张分隔符名单。** 那五个字符在正文里**全都另有身份**:
  ①**第 4 轮:`?` `#` 同时是作者的句读。** `Have you read this?<地址>` 和
    `读过这篇吗?<地址>`(中文不带空格,半角问号紧贴是常见写法)里那条**真**地址被
    自己的句末问号挡住,`needs_article` 三条判据一条都不命中,末态是:`added=1`、
    `errors=[]`、`partial=[]`、水位照常推进、标题回落成「某某 的动态」,而
    `DO NOTHING` 之下重复同步也补不回来(2026-10-09 实测;`What#<地址>` 同形,
    两种路径形式、两条通道逐字一样)。

    「定宽后视里只剩 `=` `&` `/`,它们在正文里压根不是标点,没有第二个身份」——
    **那句话是错的**,真实写法一测就推翻:`全文=<地址>`(`=` 当赋值号/冒号用)、
    `阅读地址/<地址>`(`/` 当并列号)、`Read &<地址>`(`&` 当连词)。末态和上一条
    **逐字相同**,而那一轮的 133 条长文回归**全绿** —— 因为那组直测里有一条
    无条件要求这三个前缀失败,把错误假设写成了预期(2026-10-10 自由工作流第 1 轮
    审查实测,规范形式与旧式形式各一次、浏览器通道没读到卡片信号时同样)。
  **反过来直接把这五个字符一律放行也不行**:`https://example.org/#<地址>` 和
  `?u=<地址>` 这种整条嵌在别人查询串/片段里的写法照旧要一个字不动,那条地址是

  block(空行)放宽是因为段内落单的 `[` 之后 CommonMark 的结论和这条判据未必一致
  (`见 [注\nhttps://example.org/a](b)#<别人的地址>` 渲染出的链接目标是 `b`,那条
  X 地址压根不在链接里),于是第 6 轮那一档会从"head 为空"扩散成"段内有没有落单的
  `[`"。两头都是永久损坏,线划在"一条链接写在一行内"上 —— 可解释,而且是 markdown
  产物与推文正文的事实。**两头各有一条回归钉着这个取舍,改方向时要一起改。**
  **范围放宽没有带来可观测的代价**:左边那一半改成从右往左扫 + `'[' not in head`
  短路,实测「25000 字符说明文字 + 显示文字是网址」0.0008 秒、第 6 轮那条测时样本
  0.0004 秒(回归里那条给的余量是 0.1 秒)。
  **而范围里哪些 `[` 算 markdown 结构字符,又是第 8 轮的根因**(2026-10-10 自由工作流
  第 8 轮审查)。扩到本行是对的,可那一半只会"数括号":

  ```text
  我的长文 https://x.com/Example/article/10001
  分享参考 \[<https://example.org/share?text=read](https://x.com/Other/article/20002)>]
  ```

  `\[` 是**字面**的方括号(CommonMark 的 backslash escape),尖括号包着的是一整条
  `example.org` 参考地址、内部那条 X 地址是它的查询内容。新范围一路扫过 `<` 取到那个
  转义的 `[`,`head` 是 `分享参考 \[<` —— 左边那道闸据此宣布"外层地址已经结束",
  `_drop` 把内部候选摘成 `…?text=read]( )`:`added=1`、`errors=[]`、`partial=[]`、
  水位照常推进、**自己的长文照旧补到了**、一行提示都没有,而 `DO NOTHING` 让它
  **永久**固定 —— 把 URL 里那个 `]` 换成等价的 `%5D` 再同步,正确的参考地址和全文都
  已经传到真实 `put_items`,`added` 仍是 **0**,库里和导出的 md 里逐字还是第一次那份
  坏正文(审查实测,连真 `/doc/` 阅读页一起核过)。六种形态逐字相同:转义、转义 + 中文
  说明、**行内代码 `` `[` ``**、片段容器、旧式文章路径、t.co;顺带这些推文还各白买
  一次长文询问。
  **分界线是"那个 `[` 到底开不开启 link text",而它有真 `marked` 的实证**:上面六种
  **各渲染成恰好一条完整的外部链接**(`href` 经 `unquote` 之后逐字等于输入那条地址),
  而**未转义**的 `[<…read](<X 地址>)>]` 被 `marked` 解释成**一条独立的 X 链接** ——
  它真的是链接起手,摘掉它是对的,所以审查者把它排除在问题之外。**同一行里一个落单的
  未转义 `[` 也是这一档**(`注：[ <…>`),照旧摘。
  **所以左边那一半扫描时跳过「不是结构字符」的 `[` / `]`**(`_inert` + `_code_spans`,
  判据逐字取自 CommonMark):①被**奇数个**连续反斜杠转义的(`\[` 是字面,`\\[` 是字面
  反斜杠加一个真的起手);②落在一段**闭合的**行内代码跨度里的(一串 N 个反引号由
  **恰好 N 个**的串闭合;找不到那样的串时这串反引号就是字面文本、不构成跨度 ——
  把未闭合的也当成"开到行尾"会让它后面那个真的 `[` 变成字面字符,第 7 轮那一族当场
  回退)。顺带认 `` \` ``(转义过的反引号不开启跨度),而跨度**里面**的反斜杠是字面。
  **而「跨度里面的反斜杠是字面」管的不只是内容,也管闭合串怎么找 —— 第 8 轮只兑现了
  前一半,那是第 9 轮的根因**(2026-10-10 自由工作流第 9 轮审查)。当时找闭合串的那个
  循环照抄了跨度**外**的转义规则(遇 `\` 就跳过下一个字符),于是:

  ```text
  `note\` [Visit `caption` www.example.org](https://example.org/?q=foo)[article](<真地址>)
  ```

  `` `note\` `` 是一段**闭合**的代码(内容 `note\`),可那个收尾反引号被当成"被 `\`
  转义了"跳过去,跨度一路吃到**第二段**代码的起手 —— 报告那份轨迹逐字写着
  `_code_spans` 给出 `(0, 16)`,而实际区间是 `(0, 7)` 和 `(15, 24)`。**两个方向同时
  坏**:①两段代码**之间**那个真正属于显示文字的 `[` 被判成字面,这条推文**自己的**
  文章地址被当成「嵌在别人查询值里」,`needs_article` 返回 False —— `added=1`、
  `errors=[]`、`partial=[]`、**接口调用 0 次**、水位照常推进、标题回落成「某某 的
  动态」,而 `DO NOTHING` 让它**永久**固定(删掉那个反斜杠再同步 `added=0`,库里和
  导出的 md 里仍然只有那几条链接);②`` `[\` `` 那一档跳过收尾反引号之后压根找不到
  等长串、返回**空区间**,于是那个字面 `[` 又被当成链接起手,后面那条完整的参考地址被
  `_drop` 摘成 `…?text=read]( )` —— **这一档第 8 轮也坏**,是同根因的变体、不是新坏的。
  四种 A 形态(查询值容器 / 片段容器 / 旧式文章路径 / 双反引号前缀)和两种 B 形态逐字
  相同(2026-10-10 第 9 轮审查实测,连真阅读页和导出的 md 一起核过)。
  **分界线有真 `marked` 的实证**:CommonMark 自己那个例子 `` `foo\`bar` `` 渲染成
  `<code>foo\</code>bar` 加一个字面反引号 —— 跨度里的反斜杠是内容,闭合照旧发生;
  而跨度**外**的 `` \`x` `` 渲染成纯文本(转义的反引号真的不开启跨度)。所以**外层那个
  转义分支照旧留着,内层那个不许有**:两处的范围不同(一个在自由文本里找**起手**,一个
  在跨度内容里找**收尾**),判据也就不同 —— 口径同下面那条「右半边不问这一道」。
  **右半边(`tail`)不问这一道,而那不是漏掉的**:它整段落在 `run` 里,而 `_URL_RUN`
  是 RFC 3986 的字符表、**既没有反斜杠也没有反引号** —— `tail` 里的 `[` / `]` 在结构
  上不可能被转义或在代码里,`_target_closed` 同理。两边的范围不同,判据也就不同:
  `head` 是本行的**自由文本**,`tail` 是一段 URL 字符。回归里有一条**契约**钉住这个
  不变量本身(往 `_URL_RUN` 里加这两个字符时它会红,而不是等某次同步把地址剪断)。
  **跨度查询用二分,不是逐段扫**:`_inert` 被「每个候选 × 每个起手式 × 本行每个方括号」
  各调一次,逐段扫是 `O(方括号数 × 跨度数)` —— 实测一行 20000 字符的 `` `[` `` 要
  **0.93 秒**(10000 字符 0.23 秒,正好四倍),二分之后 **0.007 秒**。那不是真实写法,
  但推文正文对 premium 用户能写到两万字,口径同第 6 轮把往左扫描从 `re.search` 换成
  逐字走那次;回归里那条测时给了近两个数量级余量。
  **已知留着的另一道缝**:跨**软换行**的行内代码跨度看不见(开头在上一行、`[` 在本行
  时它被当成结构字符)。那是「本行」这个范围固有的那道缝的另一面,和跨行显示文字同族,
  线划在同一处 —— "一条链接、一段代码写在一行内"。
  `_nested` 那两处实现细节各有理由:**往左只吃 URL 合法字符,不是「数到最近的空白」**
  —— 外层起手式必须和它自己那条 URL 的 authority/path 连成一段,而正文里的汉字天然
  落在字符集外面;数到空白的话 `https://example.org/doc,<地址>`(两条地址用逗号紧连)这种
  **真**地址会被误拒(有直测样本钉着,注入「数到空白」实测红 1 条)。
  **而「URL 合法字符」这个集合必须按 RFC 3986 的字符表取全集,而且不许和②档那个
  禁止集共用一份**(`_URL_RUN`,四类:unreserved `A-Za-z0-9-._~`、pct-encoded 的
  `%`、sub-delims `!$&'()*+,;=`、**gen-delims `:/?#[]@`**)。两者回答的根本不是
  同一个问题:②档那一份是「紧贴真地址前面的那一个字符算不算 URL 内部」,加宽它
  等于把「英文逗号/括号 + 裸域名」也拒掉、扩大②档已记的取舍;这一份是「往左追外层
  URL 的起点时能跨过哪些字符」,**少认一个,外层起点就追不回来** —— `_nested` 误答
  「不是嵌套」,于是别人家片段/查询里那条 X 文章地址被当成这条推文自己的,`_drop`
  把它删掉,而 `DO NOTHING` 让这种删除**永久固定**;同一道缺口还让判据① 把这些
  推文一律误判成「要去问一次长文」,每条白买一次调用。
  **「见一个样本补一个」栽过两次,所以这里取标准全集、并由一条回归钉住它就是全集**
  (`tests/test_x_article_urlrun.py`:和 RFC 3986 的字符表逐字相等,而且不含空白与
  非 ASCII)。两次的末态逐字相同,缺的字符各在一个部件上:
  ①**第 5 轮:sub-delims(路径字符)**。原来复用 `_URL_CHARS` 再补一个 `:`,于是
    `(` `)` `;` `$` `'` `,` `!` `*` 八个合法路径字符一个都不认 —— 实测
    `参考：https://example.org/docs(v2)#https://x.com/Other/article/20002` 在库里和
    **导出的 md** 里都只剩 `…/docs(v2)#`,而 `added=1`、`errors=[]`、`partial=[]`、
    水位照常推进、一行提示都没有(`/path;v=2?…` 和 `/$docs#…` 逐字同样)。
  ②**第 6 轮:gen-delims 的 `[` `]`(authority 里的 IPv6 字面量)**。**这道扫描
    一路往左跨过路径、authority 乃至 scheme,不是只处理路径** —— 所以补完路径字符
    还不够:`https://[2001:db8::1]/docs#<别人的文章地址>` 在 `]` 处断掉,留下的尾部
    只有 `/docs`、再也找不到 `https://`,库里和导出的 md 里都只剩
    `https://[2001:db8::1]/docs#`(`https://[2001:db8::1]:8443/docs?…` 同样 ——
    端口那个 `:` 本来就认得,断的是方括号),末态和①逐字相同:`added=1`、
    `errors=[]`、`partial=[]`、水位照常推进(2026-10-10 第 6 轮审查;真无头浏览器
    读回这两条的 hostname 就是 `[2001:db8::1]`、后面那段属于 hash/search,压根不是
    第二条独立链接)。
  **判据得可解释** —— 一个字符在不在 URL 里有标准答案,不靠猜;而**补齐 gen-delims
  之后这张表就满了**,不会再有「下一个漏掉的字符」,这正是取标准全集而不是逐个补
  样本换来的唯一好处。
  **往左的那一段是从右往左逐字走的,不是在左半边做一次 `re.search`。** 两种写法取
  的是同一段(末尾那段连续的 URL 字符),但后者让正则引擎从左半边的**每一个位置**
  各试一次 `[…]*$`,于是正文越长越慢:实测一条「长英文正文 + 空格 + 句末问号 +
  文章地址」的推文,`needs_article` 在 1000 字符上 0.002 秒、10000 字符 0.202 秒、
  25000 字符 1.256 秒(第 6 轮审查测时,本地复现到 1.2523 秒),而从右往左只扫实际
  那一段、同一条样本 0.0005 秒 —— 推文正文对 premium 用户能写到两万字以上。这条
  是报告的**不拦项**,改的是必修那条同一行代码,语义逐字不变;回归给足两个数量级
  的余量(25000 字符上 0.1 秒),所以它不是一条看机器快慢的 flaky。
  **加宽也不许加过头,这一头同样是漏认**:往这个集合里塞一个**正文里也会出现**的
  字符(汉字、空白)就会把句读紧贴的真地址一起判成嵌套。于是**非 ASCII 的外层路径
  留成一道已知的缝**:`…/文档#<地址>` 那条照旧会被摘掉,因为它和放行样本
  `参考https://example.org/说明?<地址>` **完全同形**(都是「往左吃到一个汉字就
  断」)—— 两个方向都是永久损坏,不是「哪个对」的问题。线划在 ASCII 上的理由是它
  可解释:非 ASCII 不是 URL 的原生形态(浏览器要先百分号编码),而编码之后的写法
  (`/%E6%96%87%E6%A1%A3#…`)由 `%` 和十六进制字符覆盖,本来就判得对。**这道缝两头
  各有一条用例钉着,改方向时要一起改**,只改一条就是把另一头静默打开。
  路径里的 `:` 要认(`…/a:b#<地址>` 照旧挡得住,注入去掉它红 6 条),它只是不进
  `_BARE_HEAD` 的禁止集,两件事。**起手式只认 `https?://` 和 `www.`**(口径同
  `daily_refs._autolinked`),而且**必须大小写不敏感** —— 漏掉 `re.I` 时
  `WWW.example.org/a#<地址>` 会被当成句读放行、别人那条地址从中间剪断(注入红
  1 条,口径同 `_autolinked` 那条大小写坑)。于是「裸域名 + `?` + 嵌一条完整 X
  地址」(`example.org?<地址>`)这道缝留着 —— 那不是任何真实写法。
  ①那一档**已知留着的另一道缝**:外层 URL 的路径里用一个**内容字符**(`.` `,` `;`
  之类)紧接一个完整 scheme、而那条外层 URL 自己又不带 `?#`
  (`…/path.https://x.com/…`)照旧会被放行 —— 那不是任何真实写法,而上面那两种证据
  覆盖了全部真实嵌套入口(查询值、片段、路径段)。②那一档的代价是**「标点 + 裸域名」
  一律被拒**(`...x.com/…`、`读过这篇吗?x.com/…`、`第三节#x.com/…`,**包括
  `_nested` 救得回来的那五个分隔符 —— 这一档不走它**),取舍是故意的:裸写法不是 X
  展开出来的形态(t.co 展开必带 scheme,feedgrab 的产物也是完整 URL),而域名后缀
  误认会把**别人的文章**记成这条推文的内容,这个方向上宁可多排(口径同 `HINT` 那条
  「排掉引用推容器里的卡片」)。给这一档也开口子得在那里再拆一份字符集(`_URL_RUN`
  那一份管的是另一件事,见上),多一份要对齐的口径换一种没有真实触发路径的写法,
  不值(注入「②档跟着放宽」红 41 条,全在「外部地址一个字不许动」那一批上)。
  放行空白、行首、中文字(含中文标点)和英文的开括号/引号/逗号 —— 真地址只会出现在
  这些后面。**禁止集必须逐个列出 ASCII,不许写
  `\w`**:str 模式下它是 Unicode 的,于是「我写了一篇新文章:<地址>」里那条**真**
  地址会被自己前面那个汉字挡住 —— 那是漏认,比多删还重一个量级(口径同尾巴那条
  ①;`_TCO` 原来就是这么漏的。注入 `\w` 实测红 4 个方法,而**两条端到端保持绿** ——
  它们的前导是镜像站域名里的 `x`,`\w` 正好挡得住,所以那条**直测**判据的用例非有
  不可,口径同 `daily_refs` 那对 `_autolinked` / TLD 名单)。
  **`:` 两档都不在禁止集里**:`参考:<地址>` 这种英文冒号紧贴的写法里那条地址是真的,
  禁掉它就摘不下来;代价是某条外部地址正好在 `:` 后面嵌一个 X 文章地址时照旧会被
  摘,那比漏认轻(它自己那条用例钉着这个取舍,注入「把 `:` 加进去」红 2 条)。
  **没有改成「先切出 URL 再 `urlsplit` 校验主机名」**(审查建议的那条路):正文是
  自由文本,「从哪儿到哪儿是一条 URL」本来就是这条正则在回答的问题,再加一层解析
  只是把同一个边界问题挪到切分那一步,还多一份要对齐的口径;`_nested` 那三步直接
  回答「这个起点是不是一条 URL 的起点」,判据和匹配待在同一条规则里。
  **第 4、5 轮审查各建议过同一条路**(「以完整候选地址校验主机名和路径」/「依据
  完整外部 URL 的上下文判断嵌套」),答复同上:真正要判的是那个 `?` 处在普通句子
  还是外层 URL 里,而那是**切分**问题、不是**校验**问题 —— 候选切出来之后它的
  主机名本来就是 `x.com`,`urlsplit` 一律说合法。第 5 轮那条缺陷的根因也不在「要不
  要解析」上,而在**那个字符集少了八个合法路径字符**,补齐它正是「覆盖合法路径
  字符」这个要求本身。**第 6 轮也一样**:缺的是 authority 里的那两个方括号,而
  `urlsplit` 对切出来的候选照旧只会说「主机名是 `x.com`,合法」。
  **自由工作流第 1 轮那条不一样,它那一半照改了**:报告说的是「依据外层 URL 的
  实际上下文区分嵌套地址和普通正文标点」,而那一轮的缺陷根因确实在**判据的形状**
  上 —— 「紧贴那一个字符」根本回答不了这个问题(上面那两条实测)。所以起点判据从
  正则里的定宽后视整个挪进 `_nested` 的三步上下文判,两个消费方共用。**仍然没有
  引入 `urlsplit`**,理由同上:切分问题不是校验问题,而 `_nested` 回答的正是
  「这个起点是不是一条 URL 的起点」。
  **地址识别这一整套已经搬进 `kb/feeds/x_article_links.py`**(第 6 轮改到它时
  `x_article.py` 已经 686 行、再加注释就越过 700 上限,而这一块本来就是最独立的
  那一块):两条正则、`_URL_TAIL`/`_URL_HOST`/`_URL_RUN`、`_nested`/`_first`/`_drop`、
  `lead_text` 连同它的对偶 `quote_lines`、`HINT`/`_strip_hint`/`needs_article`、
  `_ARTICLE_PATH`/`article_page` 全在那边,`x_article.py` 只剩「取一次长文正文」
  (接口、浏览器后路、Draft.js 渲染)。**和 `x_article_js` / `x_article_shape` 是
