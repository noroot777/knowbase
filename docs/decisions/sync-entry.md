# 起跑弹窗:一次同步跑哪几段、跑完出不出日报

## 硬约束

- **页面上勾得动的东西,后端必须真的按它跑;后端不收的东西,页面上就不许让人勾。**
  这一块所有约束都是这一条的分支。违反之后的形态是**勾选被静默忽略** —— 用户按
  自己勾的那一份理解了这一轮的结果,而实际跑的是另一套,面板上一个字都不说。
- **「跑完出日报」不是第七个步骤,它换的是另一条起跑通道**(`/api/daily/run`)。
  那一轮的步骤由 `daily_run` 自己排(每个来源各跑一遍 `FETCH_STAGES`、再统一跑一次
  `DIGEST_STAGES`),出完报还接着 `daily_library.library_round`(整理图鉴 + 更新
  Wiki)。所以勾上它之后:
  - **步骤那一组固定成 `PIPE_DAILY_STAGES` 并禁掉**。留着能改 = 用户取消了「提取要
    点」、后端照旧提取。
  - **时间范围和订阅那两块禁掉**(`#pipe-scope-fields`)。`daily_api.RunRequest` 收的
    是 `since/until/sync/channels` 加一份覆盖批准,而 `since/until` 说的是**哪些素材
    进这份日报**,不是抓哪几天;订阅名单它压根不收。
  - **起跑之前要问一声会不会盖掉当天那份日报,而且要把那份批准跟着请求发下去**
    (`confirmDailyOverwrite` → `overwrite_day` / `overwrite_version`)。确认框和日报
    页那颗按钮共用一份;这条路不带区间,目标就是今天。**后端在落盘之前还会按这份
    批准核对一次**(`kb/daily_overwrite.py`,口径在 `daily.md` 第一节):那一道管
    「问的是不是真正要写的那一份」(这一轮要先跑几小时同步,跨零点就不是今天了),
    这一道管「问没问过」—— 漏掉这一道的后果是点一次「跑完出日报」就静悄悄盖掉。
  - **汇总那一句里不许念订阅数和日期段** —— 念了就是一句假话。
  - **出完报那两段也要念出来,而且顺序是「出报插在中间」**(`PIPE_DAILY_TAIL`,
    真顺序在 `daily_run` 收尾那个 finally 里)。少念了,用户就会被一段几十分钟的
    慢活偷袭(「几十分钟」那枚标记和「含 N 段全库的慢活」那句话都是按它数的);
    按步骤表一路念下去,又会把「先整理、后出报」念成事实。
  - **它跟着定时设置里那个勾走,不许一律承诺**(`pipeDailyLibrary()`:关着的时候
    `daily_library.library_round` 压根不跑,图鉴和三张图谱就是不更新)。**三档各
    说各的,「读不到」不许当成开着或关着** —— 说「接着整理」而它关着,是替后端许
    诺一件不会发生的事。**所以弹窗一打开就去读一次定时事实**(同步中心平时不读
    它,读它的是「我的订阅」和日报页),回包落地时就地重画那几句。
- **「哪几步认来源」只有一份口径,而且抓取和导出都认**(前端 `PIPE_SOURCE_STAGES`、
  后端 `pipeline_stages.run_scopes` 与 `pipeline_api._SOURCE_STAGES`,判据都是
  `{crawl, export} ∩ 这一轮的步骤`)。所以分三档,**不许按「有没有勾抓取」一刀切**:
  - 抓取**或**导出只要有一个在跑 ⇒ **来源那块照旧能点,请求里必须带 `channels`**。
    导出也是按来源跑的(`_run_export` 走 `_per_channel`),只勾「导出文章」时把来源
    一起禁掉、连字段都不带的后果是:后端收到一个没有来源的来源敏感请求,
    `crawl_channels` 给回一个空通道、`active_collector('')` **回落到默认采集器** ——
    用户选的是订阅源,实际导出的是公众号,而面板上一个字都不说。
  - **订阅名单和日期段只有抓取收**(`FetchScope` 收它们,`materialize()` 压根不收),
    所以不抓取时**只禁 `#pipe-scope-fields`**,并且请求里那个来源的 `accounts` 留空
    —— 空 accounts 就是「这个来源整条导出一遍」,正是导出实际覆盖的范围。
    这一档也**不许拿「一个订阅都没勾」把起跑拦住**(拦住了就没有任何办法只补导出)。
  - 只剩全库那几步(索引/提取/整理/Wiki)⇒ 来源、时间范围、订阅三块一起禁掉,
    **请求里一个来源字段都不带**。带上去的话留档上那一轮看着像是按来源跑过。
- **后端不许把「点名了来源敏感步骤、却没给来源」的请求默默解释成另一个来源**
  (`pipeline_api._SOURCE_STAGES` 那道:拒成 400)。什么都没点名的老契约照旧
  (整库同步走默认来源,`tests/test_sync_channels.py` 钉着)—— 区别在于请求有没有
  **显式**写明要跑抓取/导出。判不准一律拒(元规则那条):多一次报错顶多再点一下,
  静默跑错来源救不回来。
- **弹窗正文的滚动盒必须是一个真能裁剪的 `div`,不许让 `fieldset` 兼任**(`.pipe-setup-body`
  包着 `#pipe-fields`)。`<fieldset>` 当滚动容器在 Chrome 上裁不住自己的内容:`overflow-y: auto`
  不生效、`scrollTop` 也设不上。弹窗加了「跑哪些步骤」这一块之后内容超过了 `max-height: 90dvh`,
  于是那几行照旧往下绘 —— 实测 1452×806 下正文可视区到 656px,而「抓取内容 / 导出文章」那两行绘在
  737~802、正好压在操作条(656~764)底下点不动,「重建索引」往后几行干脆跑到弹窗(底 765)外面去了。
  fieldset 只留一个职责:**起跑中整组禁用**。
- **「这一次起不起得了跑」只判一处**(`pipeStartBlocked()`)。那颗按钮的 `disabled`
  和脚下那句汇总都读它。两处各判一遍的结果是「汇总说可以跑、按钮按不下去」。
- **步骤顺序按 `PIPE_STAGE_DEFS` 定死,不按勾选先后**。后端 `start_pipeline` 也是按
  `STAGES` 过滤的,两边念出来的顺序得是同一个。
- **取消「跑完出日报」要把用户自己那一份还回去**(`pipeStageKept`),不是重置成全选 ——
  重置等于悄悄把那两段慢活又勾上了。

### 所有同步都走这个弹窗,「我的订阅」里的锁在当前那一页

- **「我的订阅」里那几颗同步按钮打开的是同一个弹窗,而不是直接起跑**
  (`sources.js` 的 `syncSource` / `syncWechatSubs` → `openPipeModal({channel, accounts, stages})`)。
  改之前三颗按钮各走各的路、跑哪几步谁也说不出来,而且两边还不一样:订阅源那一侧
  固定四段;公众号那一侧 `POST /api/pipeline/run` **不带步骤清单**,被 `start_pipeline`
  兜底成 `STAGES` 全跑 —— 点一下「同步全部」就顺手跑一遍全库条目化和更新 Wiki
  (几十分钟),而页面上一个字都不说。
- **锁定要在通道目录落地之后才落**(`applyPipeLock()` 排在 `await loadPipeChannels()`
  之后)。`applyChannelData` 头一回会按 localStorage 里的草稿重建 `pipeRunSel` ——
  在它之前上锁会被它盖掉:实测点公众号那一页的「同步全部」,提交的是「公众号 + RSS」
  两个来源(`retired_channel_probe` 那几条)。
- **锁定那一次用的是它自己的一份配置:开窗整份存下来、关窗整份还回去**
  (`stashPipeOwn` / `releasePipeLock`)。**不许逐字段挑着存** —— 只存「来源 +
  步骤」的那一版漏掉了日报开关和 `pipeSel`,两处都实测出了后果:
  - 残留的 `pipeSel` 会在**下一次打开普通弹窗**时被 `loadPipeAccounts` 开头那句
    `savePipeDraft()` 存进 `pipeDrafts`(那时锁已经解了,`if (pipeLock) return`
    挡不住)。实测:同步中心勾好「博客甲、乙」,去订阅页点一下「博客丙」的同步
    再取消,回同步中心只剩博客丙,点开始发出去的也只有博客丙。
  - 日报开关原来在释放时被无条件置 false:勾着「跑完出日报」去订阅页打开看一眼
    再关掉,那个勾就没了,连 `pipeStageKept` 里用户自选的那几段也一起清掉。
  所以**判据要落在「再打开一次之后那一份是什么」和「点开始真正发出去的是什么」**,
  不是关窗那一刻内存里几个字段对不对。
- **缓存和选择要成对存、成对还**(`pipeSel` 连同 `pipeAccounts` 那份 ready 缓存)。
  只还选择、把缓存留在原地的后果是**冷态**那一档:`savePipeDraft()` 用「ready 却
  一条都没选」表示「用户明确清空过」,而释放之后内存里恰好就是这个样子 —— 于是它把
  一份空草稿存了下来,下一次打开普通弹窗照着那份空草稿读回三条订阅、一条都不勾,
  「开始同步」按不动(实页形态:刷新后先去订阅页点「同步全部」再「暂不执行」,
  回同步中心「已选 0 / 3」)。
  **这三种状态必须始终分得出来**:未初始化(还没读过订阅)/ 明确选空(人自己清掉的)
  / 已选名单。拿「ready」去推断「人已经选过」就是把第一种错当成第二种。
  **`loading` 那一格不还**:它等的那次读取在关窗时已经被中止,还回去就永远结束不了。
- **锁定一个字都不许往草稿里写**(`kb-sync-channels` 是同步中心那一份多来源选择)。
  写了的话,从「我的订阅」点一次,下次新建同步就少了几个来源,而没人说一声。
  同理**整组 `input` 都 disabled**,连锁定的那一个也不许取消 —— 取消它会走
  `saveRunChannels()` 把草稿清掉。
- **锁定「整条来源」那一档(accounts 空)也不许看草稿。** 它说的就是全部;读草稿
  会让订阅页那颗「同步全部」实际只跑同步中心上次收窄过的那几个,而按钮上写着
  「全部」(同一轮审查 R1 的另一半)。
- **锁到具体几条订阅时,请求里发的是「明确点名编号」**(`id:12` 这种形态;产出方
  `pipeStableTargets`,入口那一侧 `sources.js` 传 `{id, name}`)。后端那道范围匹配
  是「id 相等**或** name 相等」(`reg.in_scope`),而名字**不唯一**(唯一约束是
  `(kind,url)`)—— 两条地址不同、名字相同的 RSS,点第一条的「同步」实测两条都被抓。
  这颗按钮改走弹窗之前传的是 `source_ids`(精确),所以那是改动带进来的回归。
  **但光换成裸 id 不够**:那串数字同时也可能是**另一条订阅的名字**。实测
  `accounts=["11"]`(编号 11 那条叫「博客甲」、另一条订阅名字就叫「11」),真去抓的是
  `[11, 12]` 两条 —— 请求里明明只点了一条。所以目标空间要**带类型**:
  - **身份口径只有一份**:`kb/feeds/targets.py`。前缀只在 `id_target()` 里拼、只在
    `target_source_id()` 里解,别处不许各写一遍(前端那份字面量
    `PIPE_ID_TARGET` 由 `tests/test_feed_targets.py` 钉着跟后端常量一致 —— 两种语言
    各写一次的东西是最容易悄悄岔开的)。
  - **三个同源消费方和真正的抓取必定走同一道**(就绪检查、稳定身份归一、重试收窄,
    加 `sync.collect` 的选源)。不许在某颗按钮或某个来源上额外加条件。
  - **裸形态照旧认 id 和名字两种**:存量历史轮次和日账名单里存的就是裸 id,判成
    不匹配就是静默漏抓。
  - **账本那一侧只留裸 id**(`stable_targets` 是边界,进去带前缀、出来剥掉):
    `still_failing` 按 `str(source['id'])` 比,带前缀存进去等于换了个键,那一格的
    欠账永远清不掉。
  - **真有订阅名字就叫 `id:9` 时两边都算**(安全那一侧):多抓一条顶多重抓一次,
    漏抓是静默丢数据。按「撞上就优先认编号」反而把错误方向翻到漏抓那边。
  **显示仍用名字**(勾选框、折起来那一行都按名字渲染),只有发出去的那一份带类型。
  两头各有自己的红:前端 `pipe_entry_probe`(发的是 `id:<n>`;**真去抓哪几条**那一面
  在后端钉,它的后端是夹具)、后端 `test_feed_targets`(整条链)与
  `test_channel_attribution`(**反过来钉一边**:按名字发的照旧是「所有叫这个名字的」,
  那是面板筛选和公众号那条路在用的口径,不许为这一条收掉)。
  同步中心那份多来源名单仍按名字走(`/api/pipeline/accounts` 只给名字),那是基线
  口径,这次不动它。
- **锁着的时候要说清为什么、也要给出路**(`#pipe-channel-hint`:「这一次只同步
  「X」,因为你是从它那一页点进来的。要同时跑别的来源,去同步中心新建一次。」)。
  一片灰色不说话,用户只会以为坏了。
- **入口定默认步骤,但默认不许漏进同步中心**(`pipeStageOwn`)。从「我的订阅」进来
  默认跑入库那四段(不带整理工具和更新 Wiki);同步中心那一份是用户自己挑的,被入口
  顶掉时先存起来、关窗时原样还回去。**默认归默认,弹窗里照旧改得动。**
- **手动收录不进这个弹窗**(`pollable === false`):它没有可轮询的源,抓取那一步对它
  空转,弹窗里的来源/时间范围/订阅三块对它全是空的 —— 它跑的是后半条链(把已经收下、
  还没落 vault 的那几条写进知识库),照旧直接 `POST /api/intake/inbox/sync`。
- **人按的那一轮跳过来源退避,而「是不是人按的」判据只有一份**
  (`kb/run_trigger.py`:`hand_pressed` / `apply_force`)。一条订阅抓失败会记一个
  `retry_at`(最短 1800 秒),那道闸是给**自动轮次**用的;不跳过的后果是退避中的
  那几条被**静默跳过**(只记一笔 `deferred`),而页面说「同步已开始」—— 「失败之后
  手动点一次同步」这条唯一出路要绕开的正是那道闸。
  - **入口只声明、不判**:四个入口(「重试失败项」、「我的订阅」页那颗同步、弹窗走
    管道那条、弹窗勾了「跑完出日报」那条)都把触发方式交给那一处盖。前三个曾各自
    写死一句「这一轮带 force」、第四个压根没人写,于是同一颗「开始同步」按钮,
    **勾不勾「跑完出日报」是两种行为**:不勾抓得到刚失败的那条订阅,勾上就抓不到。
    这条缺口此前是**一个入口一个入口**补的,每次都只补了自己看得见的那一处 ——
    元规则「口径只有一份」说的正是这种形态。
  - **判据写成「不是定时就算手动」**,方向是不对称的那一侧:误判成手动顶多多抓一次,
    误判成定时是静默不同步。所以将来哪个调用方忘了声明,落在重抓那一侧。定时那一条
    (`kb.daily_run.tick`)压根不走 HTTP,所以 HTTP 侧**什么都不声明也算人按的**。
  - **页面发的是 `trigger: 'manual'`,不是 `force: true`** —— 后者那个字段现在没人读;
    浏览器里缓存着的老页面照旧发它,而默认已经是手动,所以得到的是同一种轮次。
  - 红:`tests/test_run_trigger.py`(方向两头 + 「整个 `kb/` 下只有一处盖 force」的
    结构红)、`tests/test_sync_channels.py`(管道那条)、`tests/test_daily_two_stage.py`
    (日报那条:手动带、定时不带)、`tests/test_retry_scope.py`(「重试失败项」真抓到
    退避里那条)、`tests/test_feed_sources.py`(「我的订阅」那颗)。再往下
    (`pipeline_stages._fetch` → `FetchScope.force`)另有自己的红。
- **起不了跑也要说一声**(`openPipeModal` 开头那句 toast)。同步中心那颗按钮在跑着时
  是禁用的,所以原来静默 return 走不到;而「我的订阅」那几颗要等下一次轮询才知道
  「正在同步」—— 中间那段时间按下去什么也不发生,看着就像坏了。

### 两栏:一屏放得下整个弹窗

- **弹窗是两栏(880 宽):左边「这次抓什么」,右边「跑哪几步」。** 一栏排下来正文内容
  1240px,而可视区在 900/800/720 三种窗口高下只有 566/476/404 —— 要滚 674~836px 才看得
  全,**「跑哪些步骤」那一组永远在屏幕外**。可点对比稿 `docs/demo/sync-space.html`
  (页面底下那行读数是它自己量 `scrollHeight - clientHeight` 得来的)。
- **来源那一组是紧凑行,不带整段说明**(`pipe_channels.js`:`c.hint` 退到 `title`)。
  那段话是 `source_types.py` 的 `note` —— 「我的订阅」页上解释**这类来源是什么**的文案
  (邮件简报那段六行),在「这次跑哪几个」的选择器里是纯占地:六张带说明的卡片实测
  450px,比弹窗可视区还高。
- **步骤那一组在右栏里排两列**(`#pipe-stage-list`)。竖着一列六张卡实测 558px,右栏
  整个 562 —— 它一个人就比 720 高窗口的可视区(475)还高,两栏也救不回来。
- **订阅名单默认折起来,但收窄过的选择不许折**(`pipeAcctFoldable()`)。摊开的搜索框
  加列表占 280px,而九成情况这里就是「全部」;折起来会把「这次只跑其中几个」藏了,
  用户按「全部」理解这一轮。**有来源读失败时也必须摊开** —— 「重新读取订阅」那颗
  按钮在列表里面,折着就没有出路。
- **操作条只念这一次的事实,不复述跑哪几段**(`pipeEstText`)。步骤就在右栏勾着,同一份
  信息念两遍正是操作条占掉三行的由来。两处例外,都不是复述:**日报那一档照旧整句念**
  (它的顺序是「出报插在中间」,右栏那一组是平铺的,表达不了插在哪儿),以及**「含 N
  段全库的慢活」那句一档都不许省**(慢活标记在每个格子上,但"一共几段"只有这里数得出来)。
- **方位词不许写死**(「上面的来源」改成「来源」):两栏时它在左边,窄屏回落成一列时
  它又真的在上面,写死哪一边都有一半是错的。

## 为什么会有这一块

改之前两个入口各自固定:「新建同步」跑六段不出日报,「同步全部并生成」跑四段出日报,
**名字上一个字都看不出区别**;而那两段全库的慢活(整理工具、更新 Wiki)一跑几十分钟,
从哪个入口进来都没人说一声。可点 demo 在 `docs/demo/sync-entry.html`。

与 demo 的两处差别,都是「后端收不收」逼出来的:

- demo 里「跑完出日报」和步骤勾选互不影响。实际后端没有「跑任意几段再出日报」这条
  通道,所以这里改成由它接管步骤并禁掉(理由见上)。
- demo 里步骤那一组排在来源之后、时间范围之前。实际弹窗里时间范围和订阅都是**来源的
  细化**,拆开更难读,所以步骤排在最后一块。

## 回归

`tests/pipe_stages_probe.mjs`(自带只读 mock 后端:两个来源各带订阅,状态恒空闲;
起跑请求原样留下来比对)。**判据落在「后端收到的是什么」**,不落在页面上的勾选快照 ——
前者才是这一块唯一会出事的地方。三档各有自己一局(只导出、只剩全库那几步、正常全跑),
**反过来钉一边**那一局验的是「来源真的不参与时才不带来源字段」。

后端那道在 `tests/test_sync_channels.py`:来源敏感请求缺来源拒成 400,而什么都没点名的
老契约照旧默认本机库 —— **两边各有自己的红**。

**那份 mock 后端必须把定时设置也摆上**(`/api/daily/settings`,GET 外面套一层
`{settings, ...}`):不摆就落在「读不到」那一档,而那一档一绿,「开着」和「关着」两档
就都没验过。关掉那个勾走的是共享层那道门(`schedulesSaved` —— 别处保存成功就是这么
交过来的),所以同一局里还顺带钉住了「设置变了页面就地改口」。

**遮挡那一局的判据是「真按一次鼠标,这一行有没有反应」,外加「这一行在不在正文那个滚动盒里」。**
后一维不能省:溢出到操作条底下、甚至弹窗外面的那几行,在页面上反倒"点得到"(命中测试命中它自己),
光做命中测试会漏;而程序化 `click()` 无视遮挡,证明不了事件链。滚动也不许自己先 `scrollIntoView`
到视口中间 —— 那一下恰好把问题滚开了。

反向验证定点注入过 7 处各红 1–2 条:不带 `stages`、不勾抓取也带来源字段、勾了出日报
还走管道通道、取消出日报重置成全选、勾了出日报步骤还改得动、一步都没勾也放它起跑、
不勾抓取时那三块不禁。

入口那一半在 `tests/pipe_entry_probe.mjs`(自带只读 mock 后端:三类来源,其中一类
`pollable: false`;**有 python 包装 `test_pipe_entry_probe.py`,所以它进全量**)。
判据同样落在「后端收到的是什么」。定点注入过 5 处各红 1–4 条:起跑声明成定时轮次、锁定时
别的来源不灰、入口不给步骤清单(回落成六段)、入口默认漏进同步中心、手动收录也被拽进
弹窗。**反过来钉一边**那一局验的是同步中心那颗「新建同步」没被入口改掉(三个来源都
点得动、步骤照旧六段)。

**冷态那一局必须真刷新**(`Page.reload`):`Page.navigate` 到**同一个地址**只改
hash,文档压根不重载,于是 `pipeAccounts` / `pipeDrafts` 那几张内存表原样留着 ——
刷新前后两份现场逐字节相同,定点拆掉修复也照旧全绿(本轮实测过这一版)。所以那一局
先埋一个换页标记(`window.__coldMark`)、等它消失才算真换过文档,而刷新后那几句
`until` 里每个表达式都要 `typeof` 兜一道:旧上下文会先答一次,而 `until` 会把
`evalJs` 的异常原样抛出来。

「锁定不许被草稿盖掉、也不许改写草稿」那两条在 `tests/retired_channel_probe.mjs`
(它本来就摆着存量 `kb-sync-channel` / `kb-sync-channels`,是唯一摆得出这一局的地方)。

同步中心那几份探针(`pipe_layout` / `pipe_history` / `pipe_pending` / `pipe_latest` /
`pipe_drop` / `retired_channel`,共 243 条)在这一版上全绿 —— 它们按 id 操作,新加的
两层 `fieldset` 不影响。
