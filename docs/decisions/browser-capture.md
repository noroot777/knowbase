# 从已打开的浏览器标签补正文

人已经在浏览器里打开了那篇文章,由他在那个标签上点一下扩展,正文补回原条目。
这一侧的界面是主页面**左侧滑出的采集抽屉**(外壳 `capture_drawer.js`、状态机
`browser_capture.js`);怎么装、怎么用写在 `docs/browser-capture.md`。

**入口有三处,都是逐条的,而且叫同一个名字**:
- 「我的订阅」展开来源文章列表后、条目页脚上那个小文字链「从浏览器采集」
  (`source_reader.js`,只在 `body_from_link` 为真时露面);
- 「问题与待办」详情动作区里那颗**「从浏览器采集」**(正文那三档,排在「手动补正文」
  **前面**且是那两者里的主项)—— 理由见下面那条硬约束;
- 同步面板失败明细里那一条右边的「从浏览器采集」(`pipe_view.js` 的 `pipeFailureRow`),
  **只跟着后端给的 `capture` 走**(只有正文补抓失败才带,见 `fulltext.md`),排在「不再抓取」
  前面 —— 能补回来的先补,删是认了没有正文之后的事。
抽屉**只能从这三处开**(没有自己的地址了);原来那个独立页 `/browser-capture?item=<key>`
连同它的路由一起退役,理由见下面那条硬约束。

## 硬约束

- **`here()` 要先兑现人明确发起过的那个待办,再去问库里那一行的 url。**
  「这一页是哪一条」有两个答案源:`feed_items.url`,和人自己指过的最终网址。只问
  前者的话,「发起浏览器采集」「改用这一页的地址」「重新采集正文」这三条路发出的
  待办在扩展那一侧**一次都不会被认到** —— 而它们存在的全部理由恰恰是「这一页的
  地址和库里那一行不一样」或者「正文已经齐了、但我手上这份是错的」。
  实测两种形态:①按语言跳转的站点上发起(或 adopt)之后再问一次,答 `absent`,
  主按钮于是走 `/api/grab`,**同一篇被收成第二行**(各有各的 key、各导出一篇 md);
  ②正文齐了的那一条点过「重新采集正文」并发起,答 `complete` / `intent=null`,弹窗
  一颗按钮都不给 —— 而撤掉预览之后那是唯一的事后纠错出口,抽屉那边还写着「等待
  浏览器采集」,两块屏幕互相打脸。
  **兑现不等于放行**:挑待办只许走 `_pending()`(来源许可、排除、CAS 都在它的
  `_refresh_status` 里),自己另写一遍就会把一个已经作废的待办当成人发起过的兑现。
  **`elsewhere` 排掉的是这一答用掉的那一个,不是「所有指着这一页的」**:两个不同
  条目的待办同时指着这一页时(地址粘错),只认最早那个而把另一个一起吞掉,这一页
  到底算哪一篇在界面上就无从改,而写进去不可逆。回归
  `tests/test_browser_capture_here.py`。

- **「这个浏览器配过扩展没有」只有扩展自己答得出来,不许拿服务端的历史回执代替。**
  首次引导摆在哪(顶上摊开 / 底部折叠)问的是**此刻这个浏览器**的配对状态;而
  `browser_capture_audit` 答的是**全库共享的历史**「有没有人采成过一次」。两者不是同一
  个范畴,错位出来的两种形态都真会发生:①另一个浏览器(或重装之前的这一个)采成过一次,
  于是还没配对的这一个也看不到引导,他只会点下「发起采集」然后等一个永远不来的采集;
  ②只用「改用这一页的正文」收录新链接的人一直有配对,那条路却只写 `body_provenance`、
  从不插审计表,引导就**永远**摊在他眼前。服务端手上根本没有前一个事实 —— 配对密钥是
  整机一把、存在扩展的本地存储里,它只知道密钥存在、有人拿着密钥来过,换浏览器、重装
  扩展它一个字都看不出来;**能想到的服务端代理量一样不准**,所以不是换个字段的事。
  出路是让扩展自己说:内容脚本 `present.js` 在回环地址的页面上标一个
  `data-knowbase-capture`(值是版本号),抽屉读那一个,`/setup` 只剩「装哪个目录」。
  - **`matches` 只能写到回环地址那一级**(Chrome 的匹配式里写不了端口,而服务地址的端口
    是人自己配的),所以**收窄那一道落在脚本自己身上**:存着的 `server` 和这一页不是同一
    个 origin 就什么都不标。没有这一道的话,「端口配错了」会被当成「配好了」—— 而那恰恰
    是最需要看到引导的人。它**只碰那一个属性**,页面内容一个字都不读(README 的「权限与
    边界」按这个写着)。
  - **跟着 `storage.onChanged` 变**:密钥就是从知识库那一页复制的,配对几乎总发生在它开着
    的时候;只在注入时读一次的话,引导要等人刷新才收起来。反过来一边同样钉住 —— 密钥被
    清掉就当场撤掉标记。
  - **抽屉那一侧也要消费这个变化**(`build()` 挂一个只盯 `data-knowbase-capture` 的
    `MutationObserver`,`closeCaptureDrawer()` 断开)。标记会变而引导只在打开时算一次的话,
    人在扩展弹窗里配好、回到这一页,**引导还整块摊在顶上** —— 他刚做完的事在界面上没有
    任何回应,得关掉再打开才看得出来。断开那一下和停轮询同等重要:不断的话,一个已经
    remove 掉的抽屉还会在每次标记变化时跑一遍 `renderSetup`(白打一次 `/setup`、往作废的
    DOM 里写),开过几次就是几个。回归 `tests/capture_drawer_shell.mjs` ⑤c⑤d。
  - **位置在 `/setup` 答之前就定下来**(判据本来就是本地事实)。这一条是上面那些的结构面:
    谁再把位置挂回某个服务端字段,`tests/capture_drawer_shell.mjs` ⑤b 当场红。回归另见
    `tests/capture_present_mark.mjs`、`test_setup_answers_where_to_install_and_nothing_about_pairing`
    (**按整个键集比**,不只问「有没有 `used_before`」—— 换个名字再捎同一个事实回去是同一
    个错)。

- **人点中的那一篇就是写进去的那一篇:那个身份从「改用它」一路带到落库,中途谁都不许
  重选。** `/here/adopt` 把建好的待办交回扩展,扩展存住它的 `id`,之后每一问
  (`/here`、人点「重新确认」那一下)都带上,`precheck` / `upload` 用的就是那一答里的
  `intent`。**实测事故**:两个条目填了同一个最终网址,人点了后一篇那行的「改用它」、
  界面也说「已改用」,可扩展扔掉了交回来的身份、转头只按网址再问一次 —— 服务端于是在
  同页那几个待办里按 `created_at` 代选了最早那个,「采集」把**后一篇的正文写进了前一
  篇**:前者 `content_rev` 0→1、正文是后者的,而后者仍然缺正文,写完那一问还把后一篇
  显示成主目标,把刚刚改错的那一行遮住。
  **准入那几道门一道没拦住它,而且本来就拦不住**:来源许可、排除、过期、版本和那条
  UPDATE 自己 WHERE 里的 CAS 证明的是「这一条写得了」,**证明不了「人刚才选的就是这一
  条」**。身份连续性是另一件事,得自己钉。
  - **选不出来就不代选**(`situation='undecided'`,不带 `intent`,`PLANS` 里也是 `null`,
    所以扩展一颗采集按钮都不给)。两种情形:同一页上不止一个条目在等而人没点过;他点过
    的那个已经失效了(过期 / 被顶掉 / 条目变了 / 另一端取消了)。按创建时间挑一个是在
    赌,赌错那一下是正文被另一篇覆盖、**不可恢复**;而问一句的代价只是他在候选列表里点
    一下。**反过来钉一边**:只有一个在等时照旧直接答 `fill`,这道闸不许把正常那一条也
    扣住。
  - **第二种情形的判据不许挂在「这一页还剩几个待办」上 —— 带了显式身份却兑现不了,
    一律到此为止。** 写成 `bool(bound)` 的那一版只在「还有别的在等」时拒绝代选,一个
    不剩时照旧回落到按网址查找、再给命中的那一篇新建一个合法待办。**实测形态**:两篇
    都在等同一页,他选了后一篇,另一端(知识库界面)把两个待办都取消掉之后他点「重新
    确认」—— 前一篇被摆成主目标并给出「采集」,点下去两次 precheck 和 upload 全过,
    前一篇 `content_rev` 0→1、正文是这一页的,后一篇仍旧缺正文。那几道门验的是「这个
    新待办写得了」,**没有一道在验「它还是人刚才选的那一篇」**。
    同一支还有另外几种面目,一并被这一条封住:`_prune()` 到期清光、服务重启丢掉内存里
    那几个、条目变化被 `_pending()` 滤掉;以及这一页在库里没有对应行时答 `absent`
    (把「你选的那个没了」说成「这一页还不在知识库里」,把人引去收录出第二行同一篇)、
    对应那行正文已齐时答 `complete`(把失效直接遮掉)。
  - **身份只对他点的那一页有效**(`popup.js` 的 `chosenFor`)。标签这期间自己跳走了
    (站内重定向、推送式改地址)还带着它去问,上面那条会答「你选的那个失效了」—— 其实
    什么都没失效,他只是站到了另一页上,而那时摆出来的候选属于上一页,点下去是把这一页
    认给了另一篇。换页就当他没点过。
  - **「这一档有没有主动作」只由 `PLANS` 答一处**(`popup.js` 的 `actionable()`,三个按钮
    的处理器都过它)。藏起来不等于按不到(程序化点击、辅助技术、以后某次改动忘了藏),而
    `complete` / `refused` / `undecided` / `saved` 这几档按下去会落进 `absent` 那一支 —— 那是拿
    `/api/grab` 把同一篇**收成第二行**,正是候选列表存在要防的事。钉在
    `tests/grab_from_page_gate.mjs` ⑧:`undecided` 那一档按三颗按钮,**一个请求都不许发**。
  - **这条管到这一次操作做完为止:写成功之后身份不许放掉**(`popup.js` 的 `read()` 不
    动 `chosen`),服务端认那张回执(`situation='saved'`,`PLANS` 里也是 `null`)。
    **实测形态**:两篇都指着这一页,保存完他选的那一篇、不做任何重新选择再按一下
    「采集」,正文就写进了**另一篇**(那一篇 `content_rev` 0→1、正文是这一页的),而
    屏幕上只是标题换了一行 —— 放掉身份之后,下一问只能按网址和「还剩哪几个待办」重
    判,同一颗按钮于是被另一篇接管了。
    `saved` 的回执由 `saved()` 从 `browser_capture_audit` 读,**不是内存里那一份**:
    服务重启、上传那一答在路上丢了,带着同一个身份再问照旧认得,而不是把已经写进去
    的说成「你选的那个失效了」。保存之后正文又被别人改过时 `saved()` 抛 ValueError,
    这里转成 `refused` 原样说那句话(口径仍只有它一份)。要换另一篇得他自己在候选
    列表里点一下 —— 那正是这颗按钮不该替他决定的事。
  - **但那张回执只证明「上一次写成功了」,证明不了「这一篇此刻没有更晚的欠账」。**
    同一条目上又有一个待办在等着(人在采集抽屉里点过「重新采集正文」)时,`here()`
    不许再答 `saved` —— 那一答进了扩展的 `SETTLED` 白名单,等于替这一页签下「没事
    了」,而「关掉这一页」认的正是它。**实测形态**:显式点过「改用它」、采完,随后
    同一条目再发起一次采集,回弹窗点「重新确认」,上面写着「已经写进这一条了」、下面
    同时列着同一篇在等采集,按下去真把那一页关掉了(后端查:新请求仍 `pending`、
    回执为空,只有旧那张)。改答 `undecided`,把那句历史成功和「这一篇又有一次采集在
    等着」一起说出来,那个新待办只作为候选摆着。
    **判据按条目问,不按页问**:一个条目同时只挂一个待办(`_create` 把其余的顶成
    `superseded`),而这一次保存已经把它自己那个用掉了 —— 所以「它名下还挂着一个
    pending」就等于「那一个比这张回执晚」,不必另存一个代次。
    **不代选、也不自动执行那个新待办**(同「兑现不等于放行」)。**反过来钉两边**:
    ①别的条目在等这一页照旧答 `saved`(那是他没做过的事,不是他刚做完的那一项又回到
    未完成);②那一次重采被取消之后,同一个身份再问又回到 `saved`。
  - **那张回执也只为它那一页说话。** 换一页问(同一个身份),答的是那一页自己的情形
    (`done['page_url'] == page` 这一道)。漏了的话扩展那一侧读到 `saved` 会**按当前
    这一页再授权一次**(`grant(here, here.url, true)`),许可就发给了人此刻在读的那
    一页 —— 扩展那边的桩照这一条摆(`tests/popup_host.mjs` 的 `hereAnswer`,桩里不分
    的时候 (d) 那条反向钉当场变红)。
  - 回归 `tests/test_browser_capture_here.py` 的
    `test_the_item_a_person_picked_is_the_item_that_gets_written`(**判据落在库里哪一行
    变了**,不是某个标志位)、`..._is_not_decided_by_sort_order`、
    `..._does_not_quietly_hand_over_another_item`、`..._with_nothing_left_is_not_answered_by_url`
    (零待办那一头,**连同 `absent` 那种面目**)、
    `..._keeps_answering_for_the_item_it_wrote`(写完那一头,外加清掉内存里那几个
    再问一次、以及**换一页问那一头**)、
    `..._stops_speaking_once_the_item_waits_again`(同一条目又有一次采集在等着时不许
    再答 `saved`,**反过来钉两边**:取消之后回到 `saved`,别的条目在等照旧 `saved`),
    以及 `tests/grab_from_page_gate.mjs` ⑧。

- **`elsewhere` 有几条就摆几条,每行自带那颗「改用它」。**
  服务端一直交回全部,弹窗原先只画 `elsewhere[0]`、adopt 也只认 `[0]`。两个条目的待办同时
  指着别处时(人把最终网址粘错了),他正站着的这一页偏偏可能是**第二条** —— 那就一颗按钮
  都对不上,只能回采集抽屉里一条条改地址,而扩展这一侧存在的理由恰恰是不必回去。
  **界面形状要跟数据形状一致**:是列表就画列表,而不是「挑一个更聪明的 `[0]`」。
  每行那颗按钮在重画时当场绑上(那些行每次都是新元素,按 id 绑一次的写法重画之后点下去
  什么都不会发生);标题和网址一律 `textContent` —— 它们来自订阅源,拿 innerHTML 拼等于把
  源站的字当标记送进弹窗这个有 `chrome.*` 的上下文。`setBusy` 也从那张列表上现读按钮,不
  另记一份名单。回归 `tests/grab_from_page_gate.mjs` ⑦(**点的是第二行那一颗**)。

- **抽屉每次打开是一代,异步写动作回来之前先问自己「我还是不是这一代」。**
  `stopCapture()` 里那个 `++loadVersion` 只作废得了在途的 `refresh`;「发起 / 取消 /
  改址 / 继续处理」这些写动作 `await` 完回来还要读 `itemKey`、写 `actionError`、调
  `render()`、再 `refresh()` 排下一轮轮询 —— 而那时人可能已经关掉抽屉、甚至打开了
  另一篇。实测两种形态:①发起后立刻关掉,几秒后冒出 `GET /target/null`,**本该停掉
  的轮询被一个已经关掉的抽屉重新点着**;②A 的网址填错、发起后立刻关掉并打开 B,
  A 那个迟到的 409 把 B 顶上改成红字「请使用完整文章网址」,而 B 的网址是对的,还被
  `actionError` 留着不走。外壳那几个续体同一道闸:只问「现在有没有
  抽屉」不够,关掉再打开之后那是**另一个**抽屉。
  - **剪贴板那两处也算写动作**(复制路径、复制密钥)。它那一问可以迟迟不决(权限弹窗、
    系统忙),人这时关掉抽屉、打开下一篇,旧的那句「已复制」就冒在新抽屉上;失败那一支
    更进一步 —— 它还会 `select()` 一个早就 remove 掉的输入框,而屏幕上那句「请复制选中的
    配对密钥」指着一处什么都没选中的地方。**成功和失败是两条分支,各自守一次。**
  - **这个号码认的是「现在摆在屏幕上的那一套引导 DOM」,不是「这一次抽屉」。**
    只认抽屉那一层会漏掉中间一种:抽屉**一次都没关过**,而标记一变 `renderSetup()` 就把
    那一块整个重建(`innerHTML` / `replaceChildren`)—— 他在扩展弹窗里把配对做完,引导收
    进折叠块,上一次渲染里那次复制的迟到失败照旧 `select()` 那个早就 remove 掉的输入框。
    所以凡是让那套 DOM 失效的事都推一格:开抽屉、标记变了重绘、关抽屉。
  - **反过来钉一边:标记被重写成同一个值不算重绘**(`present.js` 每次重读都写一遍版本
    号)。当成重绘的话位置根本没变,却把摊开的密钥收回去、把正在等的那次复制一起作废
    (`laid` 记着「现在这一套是按哪一种配对状态摆的」,关抽屉时复位)。
  回归 `tests/capture_drawer_shell.mjs` ⑥⑦⑧⑧b。

- **按钮「露不露面」和它「叫什么」是两件事,不许合成一个字段。**
  `PLANS` 里 `absent` 那一档曾经用 `selection: ''` 同时表示这两样:`renderSituation()`
  把名字写成空串,而自动抓取失败那条路上只改 `hidden` —— 屏幕上放出来的是一颗
  26×36 的空白小方块,`extract.js` 回的那句「请选好全文再读一次」正指着它。
  名字一律在 `renderSituation()` 里先写上,不管这一刻露不露面;`popup.html` 的模板
  里也带着默认文字。回归 `tests/grab_from_page_gate.mjs` ①③。

- **弹窗那一排按钮共一行、按单颗换行,而「一颗采集按钮都不给」那道闸仍然挂在
  `#here-actions` 整组上。** 这两件事看着像一件,其实互相拉扯:`#act` / `#act-page` /
  `#act-selection` 要和「重新确认」排在同一行(原先是两个 `.actions`,「重新确认」
  永远独占第二行、而且和「采集」一样粗 —— 三颗等重的按钮摞成两排,看不出这一页
  该点的是哪一颗);可 `complete` / `undecided` / `saved` / `refused` 那四档是**整组
  不给**,判据只有 `PLANS` 一处、落点就是 `element('here-actions').hidden`
  (`tests/grab_from_page_gate.mjs` ⑦ 和 ⑧ 按它断言)。
  所以那一组留着自己的元素、只把 `display` 换成 `contents`,让三颗直接参与外层
  flex;`[hidden]` 的 `display:none !important` 盖得过它,整组照旧藏得掉。
  **谁要把这一组拆平进 `.actions`,那道闸就得自己逐颗去关** —— 而「按钮藏起来了
  不等于按不到」正是 `actionable()` 存在的理由(见下面那条)。
  「重新确认」降成无框文字(`.quiet`):它不对这一页做任何事,只是再问服务端一次。
  「关掉这一页」排在那一组和它之间,**但不在那一组里面** —— 理由见下一条。

- **「关掉这一页」认的是「这一次真采成了」,不是「服务端说这一条齐了」;而它故意站在
  `#here-actions` 外面。**
  - **许可只有一张凭据:`doneFor`**,内容是「哪个标签的哪一页」(`{id, url}`)。**它只有
    一个来源:这一次真写进去的那一份身份**(三条采集路都算 —— 补回原条目、服务端自己
    抓、用这一页的正文收录),在真采成那一刻显式落进去。反过来一边要紧:**只认服务端
    那句「这一条齐了」就是把一颗默认接焦点的关页按钮摆给一个只是路过旧文章的人** ——
    一个回车关掉他正在读的东西,不可撤销。
  - **只读查询不建许可、也不移交许可 —— 它只能撤销。** 原先服务端那一答 `saved` 是
    「第二个来源」:`loadHere()` 读到它就就地 `grant(here, here.url, true)`,理由是回执
    存在审计表里,服务重启、上传那一答在路上丢了都还认得。**那条路撤掉了**,因为回执里
    只有文章和操作的身份、**没有 Chrome 标签身份**:它说得出「这一篇的正文写进去了」,
    说不出「写进去的那一次发生在你眼前这个标签里」。于是那一下把许可**挪到了人此刻在读
    的那个标签**上,随后 `granted()` 拿标签 id 去比的是它自己刚写进去的值,等于没比。
    **真机实测形态**:在 71 号标签上采成(点过「改用它」,所以服务端答得出 `saved`),
    弹窗不关、当前标签变成同一地址的另一个 72 号(同一篇开了两个标签,或者采完那一个
    已经被他关了、眼前这个是后开的)—— 按下去关掉的是 72,而 72 压根没参与这一次采集。
    **代价摆在明处**:上传那一答真丢了的时候屏幕上照旧写着「已经写进这一条了」,但不给
    关页出口,人自己关掉那个标签。漏一个出口是多按一下,关错一个标签不可撤销。
    (`saved` 仍然留在 `SETTLED` 白名单里 —— 那是另一维:它答的是「这一页此刻没有待做
    的采集」,给**已经存在的**凭据放行,不是创建凭据。)
    回归 `tests/popup_close_tab_gate.mjs` (d)(d2)。
  - **凭据只能由「这一次真写进去的那一份身份」建立 —— 三条路都过同一处(`grant()`)。**
    - `url` 取**这一次真交给服务端的那个地址**:两条读页的路是 `extract.js` 在页面里现
      报的 `location.href`(也正是 precheck / upload / from-page 收下的那一个),服务端
      自己去抓那一路是 `/here` 那一答针对的地址。
    - `tab` 取**这一次操作开头现读到的那一个标签**(`currentTab()`),提取目标也用它。
    - **实测形态(两头都错)**:在 A 上采失败、站点同源换到 B、点「改用这一页的正文」
      —— 提取、预检、收录的全是 B(服务端那边 B `known:true`、A `known:false`),凭据
      却记成了 A。于是**真采成的 B 没有出口**,而人回到 A 点一次「重新确认」,服务端照旧
      说「这一页还不在知识库里」,那颗按钮反倒露着面、还接走了焦点 —— 一个回车关掉的是
      那篇**还没采的** A。拿展示快照里那个 `id` 去提取还会读到**另一个标签**的正文,
      把别人那一篇收成这一篇。
    - **「请求和凭据取的是同一份展示快照」不等于对**:两者一致只说明它们同源,不说明
      那一份就是真写进去的那一页。
    - **许可还要服务端那一句「这一次正文真写进去了」(`stored_body`)—— HTTP 200 不是
      那个事实。** 两个新条目入口(`/api/grab`、`/api/grab/from-page`)共用同一份写入
      响应契约,而那份契约里重复那一档的**每条出口都是 200**:写语句撞上 `DO NOTHING`、
      库里只有一段订阅同步先落下的 RSS 摘要、重抓明确失败、整条链早就走完的幂等答复。
      **实测形态**:打开扩展时这条还没收录,后台同步先收下它那段摘要,再点「采集」——
      服务端回 200 / `added:0` / `duplicate:true` / `content_ok:true`,一个字的正文都没
      采到,随后那一问照旧说「正文还缺着」,而「关掉这一页」露着面、还接走了焦点,一个
      回车关掉的就是那篇**还没采的**原文。
    - **这一问只能由服务端答,扩展一个字都不自己判**(`grab_api` 一处算、两个入口共用)。
      别的键一个都推不出它:`added` 在重复那一档恒 0(重抓真换掉了也是 0),`content_ok`
      说的是**库里那一份**的质量(那段摘要也为真),`done` 说的是后半条链走完没有(正文
      刚写进去时恒假,而那时已经算采成)。**缺省方向定成否是构造上的**:以后这一档多一条
      出口,它自动不授予许可 —— 漏给只是少一个出口,多给不可撤销。
    - 反过来钉一边:**该给的也要给**。问过 `/here` 之后他切到另一个开着同一篇的标签、
      在那儿点「采集」—— 凭据的标签身份取他眼前这一个,取上一次问到的那个,采完了反倒
      一颗出口都没有。
    - **许可还要「人没换过操作」和「服务端此刻没说这一页还欠着事」—— 一次真的成功,
      不许给后来另一项还没完成的操作授权。** 三道一起由 `granted(tab)` 一处答,渲染和
      按下去共用它(只是参照不同:渲染问展示快照,按下去问那一刻现读到的标签)。
      - **实测形态(两支)**:①A 采成了,而服务端那边 B 的待办也指着这一页;人点 B 那
        一行的「这一页就是这一篇,改用它」—— 屏幕上同时写着 B 的「正文还缺着」和一颗
        「关掉这一页」,一次采集都没再发生,按下去关掉的就是 B **还没采的**那一页(后端
        独立查:B 仍 `pending`、回执为空、正文还是原来那 11 个字)。②同一条目上点一次
        「重新采集正文」再回弹窗「重新确认」:服务端这一答变回「正文还缺着」,旧按钮
        照旧摆着、还接着焦点。
      - **两道各管一侧,缺一不可。** 「人换过操作」看的是 `doneFor.intent === chosen`
        (他在候选列表里点的那一条,采成之后不会自己变)—— 这一维**不经过网络**,所以
        改选之后哪怕 `/here` 正好失败,旧许可也当场作废。「还欠着事」只有服务端答得了
        (`SETTLED` 白名单:`complete` / `saved`)—— 第 ②支里他一个候选都没点,身份那
        一维两头都是空串,只有这一道拦得住。
      - **白名单不是黑名单**:以后多一档、或者某一档的含义变了,它自动不算做完。不能
        复用 `PLANS[s] === null`——那张表答的是「这一档摆不摆主动作」,而 `refused` /
        `undecided` 同样没有主动作,却恰恰是「这一页还有事没定下来」。
      - **「问不着」在展示和在按下去那一刻不是一回事,所以 `granted(tab, unknownOk)` 那
        一维由调用方明说。** `situation` 为 `null` 只说明这一问没成(503、断网、超时),
        **摆那颗按钮时算放行**(`captureLanded()` 传 `true`)—— 不许把一次有效的成功丢在
        一次网络抖动上,否则采完之后网络一抖出口就没了,而那一页正是采集抽屉刚为它开出来
        的;摆着它也关不掉任何东西,按下去还要再问一次。**按下去那一刻不算**(传 `false`):
        见下面那颗按钮自己那一条。
      - **服务端明确说「这一页还有事没做完」时,那一下否决要落在凭据上,不是只落在那一
        答里。** 否决只活在 `situation` 里的话,**下一问失败就把它抹掉了**:`situation`
        退回 `null`,而上一条正要求「未知」沿用凭据 —— 于是已经收回去的按钮重新露面、
        还接走焦点,一个回车真发出了 `tabs.remove`(实测:那个新请求仍 `pending`、回执
        为空,只有上一次操作那张旧回执)。所以读到任何一档不在白名单里的情形,就**当场
        把凭据作废**(`loadHere()` 里那一句 `doneFor = null`),此后只有新的一次成功才
        能再授权(`grant()` 那几条路),刷新一万次、服务端下一答又说「齐了」都换不回来。
        **反过来钉一边:这一下只在服务端真答上来时才算数。** 那一问失败时 `api()` 抛
        出去、压根走不到那一行,凭据原样留着;「没问着」和「问着了、答的是还欠着事」是
        两件事,混起来判就把上一条推翻了。把失败也当否决的写法(在 `catch` 里撤)变红
        的是**按下去**那一条而不是显示那一条 —— 抛出去时那次重画也没发生,屏幕上那颗
        照旧摆着,正是「先断言后果」那条元规则的射程。`situation &&` 那一臂管的是另一
        种:答上来了、却是一份空答复。
      - **那两句拒绝的话要分得清。** 「这一页已经不是刚才采的那一篇了」只能在凭据还在、
        而标签身份对不上时说;凭据已经作废时说的是「这一页还有一件没采完的事」。所以
        那一问要在 `loadHere()` **之前**算(它会改 `chosen` 和 `situation`),写成
        `!doneFor || …` 的话,撤销之后人看到的是一句对不上号的解释。
  - **`situation` 和 `here` 都是可变的展示状态,谁也不许当凭据用。** 前者每问一次就换
    一份、问失败时是 `null`;后者是「最近一次查到的当前标签」,人换一页它就跟着换。
    **实测的事故**:刷新这件事是「清掉上一答 → 把身份换成当前标签 → 问服务端」,中间
    那一步换完了身份、那一问却失败(503/断网/超时/401),于是 `tab` 和 `here` 一起是
    那个**还没采的新页面**、两两相等、校验通过。形态是第一下说「没有关掉它」(那句话
    顺手又刷了一次,把参照也换成了新页),**第二下就把新页面关掉了**;人自己先点一次
    「重新确认」而那一问失败,同样一下就能关掉。凭据反过来只在真采成那一刻写下来,
    屏幕上后来发生什么都不改它。
  - **两个维度缺一不可**:只认地址时,同一篇他开了两个标签就会把另一个认成这一个;
    只认标签时,站内 SPA 路由换了一篇照旧算「采过」。
  - **许可跟着身份走,所以身份换好了才渲染。** `loadHere()` 原来先清空 `situation` 渲染
    一次、再去问当前标签 —— 那一次用的是**上一页**的身份,于是按上一页的许可继续摆着,
    下面那一问失败时它就停在那儿。顺序改成「先换身份、立刻重画、再问服务端」:那一问
    成不成都不影响,许可那一刻已经按新身份算过了。显示侧与动作侧**同一张凭据**,所以
    不会出现「按钮露着却按不动」或者反过来。
  - **位置**:它不在 `#here-actions` 里,因为那一组在 `complete` / `saved` / `undecided` /
    `refused` 四档是**整组不给**(上一条),而采完之后正好落在前两档 —— 放进去等于
    永远不露面。
  - **「默认选中」= 露面那一次接走焦点**,而且**只在 `hidden` 真的翻过来时接**:这一块
    每问一次就整个重画一次,每次都抢的话,人刚把焦点挪到「重新确认」上就被拽回来。
  - **焦点要等按钮真的能接才送得出去**(`wantFocus` + `flushFocus()`,`setBusy()` 收尾
    时冲刷)。三条成功路径都是先 `setBusy(true)`、再在渲染里让按钮露面并要焦点、最后
    `finally` 里 `setBusy(false)`:**那一刻按钮还 disabled,真实 Chromium 不收焦点**,
    `activeElement` 停在 body、回车什么也不做。实测形态是「按钮在、看着也该是默认的、
    按回车没反应」。冲刷时要再看一眼它有没有又藏回去(这中间可能刷到了别的情形)。
    **这条当初是测桩自己瞎的**:假 DOM 的 `focus()` 不管 disabled/hidden 一律记
    `focused = true`,于是断言恒绿 —— 桩现在照 DOM 规矩拒掉。
  - **按下去那一刻现问一次当前标签、跟凭据对,对不上就不关。** 露不露面是**上一次
    渲染**时算的,而关标签不可撤销 —— 两者之间标签完全可能已经不是那一页了(站内 SPA
    路由、站点采完自动翻下一篇、刷新那一问失败而按钮残留)。实测形态:弹窗 DOM 上还
    写着采过的那一页,宿主交回的当前页已是下一篇,点下去传给关闭接口的是**新那一页**
    的标签。所以现问一次 `currentTab()`,和**凭据**的 `{id, url}` 逐一对过(不是和
    `here`,理由见上面那条);对不上就改为重新问一次服务端(那一下会把这颗按钮自己
    收回去)并说明为什么没关。**判据是原样字符串相等,不做任何规范化** —— 这里只决定
    「关不关」,宁可多留一个标签,也不能关错一个。把这道核验挂在**唯一那个关页动作
    边界**上,不要去给某一种跳转加监听:会踩到的跳转不止一种,而「刷新通常会成功」和
    「按钮刚才还在」都不是「这一页采成了」。
  - **按下去那一刻也现问一次服务端,问完再决定。** 凭据证明的是「那一次写成功了」,
    证明不了「这一页此刻没有更晚的欠账」:采完之后他去采集抽屉里点一次「重新采集
    正文」再回来按这颗按钮,屏幕上那一份答复早就停在采成那一刻了 —— 只在「重新确认」
    那一下更新的话,这中间这一下关掉的就是一页**正等着被重采的原文**(真机实测:
    服务端那一侧修好之后,只差这一道照旧关得掉)。服务端那一侧另有自己的一道(上面
    那条「旧回执不为新欠账背书」),**两份实现各有自己的回归** —— 这里这一道管的是
    「他压根没再问过」那一段窗口。
    **挑话用的是撤销前那一份凭据**(`const held = doneFor`):`loadHere()` 读到「还有
    事没做完」会把它清掉,拿清完之后那一份挑话,说出来的是「这一页已经不是刚才采的
    那一篇了」—— 而他压根没换页,下一步指错了方向。**标签读得越晚越好**(这一问是
    一次网络往返,中间站点完全可能自己翻了下一篇)。
    **而「问不着」在这一下是否决(`granted(tab, false)`)。** 服务端那道否决正是靠这一问
    送过来的,503 / 断网 / 超时把它一并吞掉:弹窗这边「什么都没变、只是断网」和「已经又
    发起了一次重采、偏巧也断网」长得一模一样。**真机实测形态**:采完一篇后再为它发起
    重采,不点「重新确认」直接按这颗按钮而这一问 503 —— 那一页正等着被重采,却被关掉了
    (后端独立查:新请求仍 `pending`、回执为空)。分不清就不许关:拒了是人自己关一下那个
    标签,关错了是那个待办再也兑现不了(它只有人站在那一页上才采得成)。**保留的是回执和
    那句「已经写进这一条了」,收回的只是这一下的许可。**
    **这一问还得有界**(`AbortSignal.timeout(ASK_MS)`,4 秒)。服务端接了连接却一直不答
    (卡在维护锁上、磁盘满)时 `fetch` 自己不会醒,而这一下已经把按钮按住了(`busy`):
    没有截止时间的话人等到的是一颗永远按不动的按钮,连「再试一次」都点不了。到点按
    「问不着」处理 —— 那是拒绝,不是放行。**别把它改成 `call()` 的全局超时**:上传一篇长
    正文、服务端自己去抓一页都可能正当地慢过它。
    拒了之后那句话分三种(换页了 / 问不着 / 还有一件没采完),**判据仍然只有 `granted()`
    一处**,`situation` 和 `held` 只用来挑话说。
    回归 `tests/popup_close_tab_gate.mjs` (g3)(g3b)(g3c)。
  - **关的永远是当前这一个标签**:现问一次 `currentTab()`,不拿上面记着的那个 id。
    `chrome.tabs.remove` **不需要任何额外权限**(`tabs` 那一条只管 `url`/`title` 这几个
    敏感字段),清单一个字没加 —— README 的「权限与边界」按这个写着。标签一关弹窗多半
    跟着就没了,`window.close()` 管它没走的那一种。
    回归 `tests/browser_capture_gate.mjs` ⑤、`tests/popup_close_tab_gate.mjs`;
    「写进去了没有」那一问**服务端那一侧另有自己的回归**(`tests/test_grab_write_contract.py`,
    元规则「两份实现各有自己的回归」)。

- **这几块界面不加次级标题,也不描述屏幕上看得见的东西。** 抽屉和扩展弹窗原先每块都
  顶着一行标题(「这次补哪一篇」「这篇文章正在等待的采集」),每个输入框下面还跟一句
  说明它行为的小字(「默认匹配原网址」—— 那一栏本来就是预填好的),建议里还逐颗复述
  下面排着的按钮(「用『从浏览器采集』最省事,否则试『换链接』」)。**留下来的只有屏幕
  上看不出来的那些**:15 分钟的有效期、「继续导出与索引」那一下的真实射程、再试一轮
  会不会还是同一个结果、这一下要不要花模型的钱,以及「继续」**不必逐篇点**(射程本来
  就是整类来源加全库索引,逐篇点只是把固定开销付 N 遍、后几下还会撞上「管道正忙」;
  不点的话,下一轮带上这类来源的同步也会处理)。这一句不写死定时时刻 —— 日报定时可以
  关、范围可以不含这一类,写死就会在那些人面前说假话。
  **两处例外不许删**:①「继续导出与索引」那段射程必须和确认框、回执三处对得上
  (`tests/test_browser_capture.py` 钉着 `条目化提取不在这一步`);②「从浏览器采集」
  旁边那句前提(文章开着 + 扩展装好)—— 那是点下去之前唯一能知道它为什么不动的地方
  (`tests/intake_diag_probe.mjs` 钉着 `开着` / `扩展` / `手动补正文` 三个词)。

- **「从浏览器采集」和「手动补正文」是一道闸上的一对,不许一颗开一颗关。** 它们写的是
  同一列、过的是同一份准入(`_admit_body`),所以「问题与待办」里这两颗按钮共用后端那
  一个答案(`intake_diag_api.item` 的 `can_paste` = `permits_link_body`,「换链接」也在
  同一道闸上)。开着的那一颗点下去只会在服务端被拒,而**屏幕上看不出是为什么** ——
  那正是这块面板最该答出来的事。禁掉时那句理由也只有一份
  (`source_types.link_body_refusal`,**空串 ⇔ 许可**,前端一个字都不自己编),而且
  **既进 `title` 也就地显示一行**:`title` 在触屏上压根出不来,「按钮灰着、旁边什么都
  不说」正是人会反复点它的形态。人手敲 `/browser-capture?item=<key>` 绕过界面时,
  `target()` 那句拒绝也带着同一句理由。
  **顺序和主次是约定,不是排版**(`lanes.Lane.exits` 的顺序就是屏幕上的顺序):会落到
  正文那三档的多半是「页面上没有识别出正文,可能需要登录或由脚本渲染」「这一页要求先
  完成验证或登录」「HTTP 403」—— 那些页人**已经在浏览器里开着、登录态也在**,从那个
  标签抓比手工全选复制粘贴顺得多,也不容易粘坏。读不出主次,人就会先去点那颗兜底的。
  **批量栏里不给这一颗**:一个浏览器标签就是一篇文章,勾 20 条采不了 20 篇。
- **交接只带 key,「是不是这一世」由这条路自己认。** 面板上那颗按钮只拼
  `/browser-capture?item=<真实 feed_items.key>`(和 `/body`、`/requeue` 发出去的是同一个
  值,不是展示编号),**刻意不捎一份 `life` 过去** —— 身份这件事由 `_same_life`
  (`fetched_at` + `content_rev`)一处回答,而面板自己那几个写入口按 `feed_items.life` 认
  (`kb.intake_diag.warrant`)。两份判据的洞不一样(见下面 `_same_life` 那条和
  `intake-diagnostics.md` 的「还没做的」),**在交接处再判一遍只会多出第三份口径**;
  判错的方向两边都是安全那一侧(认不出来一律当「没有回执」)。详情抽屉把
  `fetched_at` 和 `content_rev` 两个值如实摆在详情末尾那块灰框里,人对着它就能看出
  「这一世变没变」。
- **准入判据只有一份,在服务端。** 「这一次写不写得了」由 `kb/browser_capture` 的
  `_admit_body`(正文够不够)、`_admit_page`(是不是指定的那一页、来源允不允许、请求
  还在不在)、`_admit_item`(条目还是绑定的那一版吗)回答;`precheck` 和 `save` 调的是
  **同一组**。**扩展一处都不判** —— 它只负责展示结论。
  事故形态(实测三种):扩展自己 `new URL()` 比网址、自己数原始字符数、信上一次刷新
  下拉时缓存的那份清单,于是「服务端会拒」的三类都要等人**把整篇文章读完、点下
  提交**才被 409 拒 —— 白读一整页。其中网址带中文那一类是
  **每一次都失败**,怎么重来都一样。往扩展里补一张规范化表、再抄一遍去重算法只会
  开出第四第五个实例,所以判据整个退回服务端。
- **`page_url()` 是文章网址的唯一规范形**(连同 `_page_aliases()` 住在
  `kb/browser_capture_url.py`,由 `browser_capture` 原样再导出一次 —— 纯函数层分出去
  是因为那个文件撞了 700 行上限,**判据仍然只有一份**)。 口径跟着浏览器的 `new URL().href`:
  scheme / 主机小写、非 ASCII 主机转 punycode、默认端口去掉、非 ASCII 与不安全字符
  百分号编码、**已有转义原样透过**、点段折叠、片段丢掉。空 query(末尾那个 `?`)两边
  都丢 —— 比浏览器宽一格,宽的那头只会多认一个同页地址。**不许在别处再写一份,也
  不许拿原始字符串比**。`%2e` 这种编码过的点段不折叠(浏览器会),后果止于「人自己
  填了个点段地址」→ 读之前就被告知网址不同,可改可重发。
- **拒绝那一刻手上的真实网址不许丢 —— 出路开在待办那一行里。** `_admit_page` 判出
  「不是这一页」时把浏览器交回来的规范网址记进 `intent['seen_url']`(`_seen_elsewhere`,
  **只在 pending 的那个上记**),采集抽屉把它摆出来并给一颗「改用这个地址」—— 点下去走的
  是同一个 `create`(旧待办由服务端顶掉),不是先取消再发起。
  事故形态:站点按浏览器语言跳转(`openai.com/index/x` 在中文浏览器里落到
  `/zh-Hans-CN/index/x`),这一类订阅**每一次**都被拒,而人只看到一句「网址不同」;
  原来那句拒绝语指向的操作(「回知识库核对最终网址并重新发起」)在页面上**当场做不到**
  —— 有待办时那一栏和「发起」都是禁用的(上面那条约束要的就是这个),得先在下面取消
  待办。**记下来不等于放行**:原请求照旧只写得了它绑定的那一页,改用要人点,所以
  「扩展不会用另一篇文章静默覆盖」一个字都没松。
  **不许顺手剥掉语言前缀来「认成同一页」**:那是站点自己的约定,`/zh-Hans-CN` 在别的
  站完全可能是路径的真身,剥错一次就是把**另一篇**的正文写进这一条 —— 而 `page_url`
  那份口径的底线正是「宽的那头只会多认一个同页地址,不会把另一篇认成这一篇」。
- **`precheck` 一个字都不落库,也不顶替事务内那一道。** 真正的互斥待在 `save` 那条
  UPDATE 自己的 WHERE 里(key / 来源 / 原网址 / 正文指纹 / 修订号 / 非 X 观点 / 未排除,
  `rowcount != 1` 即拒);`precheck` 和 `save` 开头那次 `_refresh_status` 都只是**早一道**。
- **采集抽屉那一栏网址:人动过就不许被轮询填回去。** 自动填入只认「框里还是上一次
  自动填进去的那一份」(`autofillUrl`);已有请求时强制显示服务端记下的那一份并禁用。
  事故形态:本页每 2 秒重画一次,原来的判据是「框是空的就当还没填过」—— 人清空、
  切出去复制浏览器里真正的地址、切回来一粘贴,贴的那一截接在被填回的原网址后面,
  拼成一个谁也打不开的地址(实测 2.6 秒后变回原值),之后扩展只会一直说「当前标签
  网址与指定文章不同」。**两个触发点**:平常那一次,和点过「重新采集正文」进草稿态
  之后 —— 这道闸不能只挡首次渲染。
- **「同时在新标签打开这一篇」默认勾上,而那个默认写在两处、必须说同一句话。** 模板里
  那个 `checked`(`capture_drawer.js`)是读代码的人看到的那一个;真正落到屏幕上的是
  `startCapture()` 里那一次复位 —— 每次打开都 `build()` 一套新 DOM、随后立刻跑它,
  所以只改模板的话这一行会不声不响把它顶回来,模板从此是一句假话(反过来同理)。
  默认勾着是因为这颗按钮发出的待办**只有人站到那一页上、在那儿点扩展才兑现得了**:
  不开那一页,按下去什么都不会发生。`window.open` 仍然要留在那次点击的同步调用栈里
  (离开就不算用户手势,被弹窗拦截挡掉)。**反过来钉一边**:人取消掉之后,面板每 2 秒
  那次重画不许把它勾回去。回归 `tests/capture_drawer_shell.mjs` ⑨⑨b⑨c(两边都钉:
  勾着就真的开、而且是同步开;取消了一个都不开)。

- **抽屉关掉的时候要回头告诉开它的那一方,而那是两件事、两个口子**:
  `openCaptureDrawer(key, {onClose, onSettled})`。开它的那两处(「问题与待办」面板、
  「我的订阅」)**在空闲时都不自己刷新** —— 不回这一声的话,正文已经补上、那一条已经
  换了档位,屏幕上还写着「重试已停止」,人唯一的出路是刷新整页。
  - `onClose()` **无条件、同步**叫一次。底下那一页正确与否全靠它,所以**不许押在
    网络上**,也不许排在下面那一问之后 —— 服务端慢一秒,那一行就多旧一秒。
  - `onSettled(note)` 只在「这一次真采成了」时叫,而**那件事的答案在服务端,不在
    关掉前那次轮询快照里**:轮询 2 秒一轮,人在扩展弹窗里点完回来随手就关 —— 回执
    服务端已经写下了,这边一轮都还没看见。所以 `window.captureSettled()` 先用轮询
    已经看见的那一半,没看见就**拿打开那一刻的基线再问一次 `/target`**,只有「现在有
    一张、且不是进来时那一张」才算。空串(没变 / 问不着)**一次都不叫**,这条判在抽屉
    里,不留给每个面板各写一遍。
  **几边都要钉**:凭「抽屉关了」就报一句喜是在骗人;「打开那一刻就已经在那儿」的回执
  **不算这一次采的** —— 算的话,每打开一条早就补过正文的条目、随手关掉都会报一次「正文
  已补入原条目」,而这块面板上点进来的条目相当一部分正是已经补过的(`browser_capture.js`
  的 `baselined` / `sawReceipt` 就是这一道基线,**轮询那一路和关掉现问那一路共用它一
  份**);没拿到基线(第一轮轮询还在途就关了)和问不着(网络红)**都不报喜,也不猜**
  —— 漏一句提示的代价是人自己再看一眼那一行,认错的代价是指着一条根本没补上的文章说
  「正文已补入原条目」。那一问的头几行**必须同步读模块状态**(结论、基线、`itemKey`):
  外壳拿到 Promise 之后紧接着就 `stopCapture()`、人甚至已经开了下一篇;顺带钉住了顺序
  —— 真排到 `stopCapture()` 之后去,`itemKey` 已经是 null,它只会闭嘴。**没人听就不问**
  (没挂 `onSettled` 的调用方、Esc 关掉的那些不该为此多打一次接口)。回调跟着「这一次
  打开」走,**换一条打开时上一次那一声当场结清**,不许欠着串到下一篇头上(同
  `generation` 那条约束一个道理)。
  面板那一侧收到之后做什么,见 `intake-diagnostics.md`。
  回归 `tests/capture_drawer_shell.mjs` ②⑩a–⑩g(**一律比次数**:「每次都叫、参数是空
  串」和「该叫时才叫」在只问「叫没叫」的用例里长得一模一样)。
- **回执按文章恢复,不靠标签的 `sessionStorage`。** 服务端按文章 key 返回当前待办和
  最近一条有效审计回执(`browser_capture_audit`),关页、换标签、超过 15 分钟、服务
  重启之后都找得回来。已保存请求无论命中内存还是从审计恢复,都走 `saved()` 同一套
  校验(来源、排除状态、修订号、正文摘要);旧回执失效时隐藏成功区、禁用继续按钮
  并给出原因。
- **回执记的是「哪一世」的那篇文章,认不出来就当「没有回执」。** `item_key` 按网址
  算:存量清理(`scripts/feed_trim_history.py`)删掉一条、下一轮又从同一个链接收回来,
  key 一个字都没变,而库里那是另一行、另一份正文。判据只有 `_same_life` 一份 ——
  `item_fetched_at`(只在 INSERT 时写,换内容的几个写入方一个都不碰它)+ `content_rev`
  不许倒退(一行的生命里只增,新插进来的从 0 起),两条各补对方的洞:同一秒里删掉又
  收回来时 `fetched_at` 会撞上(它只记到秒),那一下由倒退的 `content_rev` 认出来。
  **认不出来一律当「没有回执」,不是「正文被改过」**:后者会在那篇文章的采集抽屉上
  常驻一句假红字,还连带藏掉回执区、禁掉继续处理那颗按钮,而重抓一次也去不掉(审计
  那一行记的是上一世,怎么比都不等)。老库里没记身份的回执行同样按「没有回执」办。
  新回执落库时顺带收掉这个 key 上前一世的审计行,判据**特意比 `_same_life` 窄**(只
  认身份那一半),这样删掉的一定是认领不了的行。
- **同一文章只留一个 pending。** 在锁内比正文版本、来源、原网址和指定最终网址:
  匹配就复用原请求和有效期,不匹配把旧的标 `superseded` 再建新的。额度只算 pending
  (`MAX_PENDING`),保存 / 取消 / 陈旧不占。不同文章各自排队。
- **额度撞满的那一下不拒人,顶掉最老的那个。** 取消的出口只开在**各自那篇文章的
  采集抽屉**上,而额度是全局的:拒了就得让人挨个翻完那 100 篇才发得出第 101 次。等待
  中的请求手上没有任何产物(正文还没读),顶掉最老的(它也最接近过期)只值一次重新
  点击,扩展那边收到的话正是「被新的采集请求替代」。**已保存的回执压根不在池子里**,
  顶不掉。
- **进入「重新采集」不撤销已保存的正文和回执**,退出也不清审计;只有再次预览确认
  提交才替换。
- **「继续导出与索引」那颗按钮的射程只有 `CONTINUE_STAGES`,而且页面、确认框、回执
  三处的话必须跟它对得上。** `extract`(条目化提取)**不在里面**:它的队列
  (`kb.extract.pending_docs`)压根没有来源参数,按全库取数 —— 一颗开在某一篇文章页上
  的按钮不该顺手买下全库那一轮模型调用(原来的话写着「该来源其他待办」,而实际射程
  是全库)。`export` 这一段认 `crawl_filter`(只有这一类来源),`index` 是整个 vault 的
  增量比对、不调模型,这两件事页面上明写着。要提取就到同步中心起跑弹窗里勾;这一篇的
  `extract_stale=1` 还在,下一轮同步自己会重新提一遍。
- **`fulltext_at` 一写上,这条就退出自动补抓队列**(`fulltext.queued_sql()` 要求它为空)。
  好处是刚补的正文不会被自动补抓再盖一遍;代价是万一采到的是一张过得了去重门槛的
  会员说明页,出路只剩人工「重新采集正文」。
- **`api.js` 住在扩展目录**(`kb/static/browser-extension/knowbase-capture/api.js`),因为
  下发的 ZIP 要带上它、扩展取不到 `kb/static/js/` 下的文件。页面在 `ui.js` **之前**加载
  它;全站十来个脚本的 `apiFail` / `toastIfFail` 都是它那一份。
- **扩展的 `popup.css` 另抄一份色板**(扩展装在浏览器里,取不到 `kb/static/css/base.css`)。
  改 `base.css` 的 `:root` 色值要连它一起改 —— 两份文件各写了一行互指注释(`base.css`
  那行就在 `:root` 上面)。CLAUDE.md 的「视觉语言」里数的那**三处**是脱离 kb-web 的
  独立产物,各抄色值 + 箭头几何;popup 只抄色板、没有箭头,所以单记在这一份里。
- **`plainUrl()`(两处,各三行)只是显示** —— 把百分号编码过的中文地址显示成人能对着
  地址栏核对的样子。它不是判据,回填给服务端时会被重新规范化成同一份。

- **「我站着这一页,此刻能做什么」只有 `here()` 一份口径,popup 里也只有一块。**
  扩展开起来就问这一次(`POST /api/browser-capture/here`),服务端答四档
  (`fill` / `absent` / `complete` / `refused`)连同那句给人看的话;popup 那张
  `PLANS` 表只把它摆成按钮,**一个字都不自己编、一处都不自己判**。
  原先这里是两块:一块问 `/api/grab/state`「这一页在不在库里」,另一块是「补回哪个
  待办」的下拉框。**两块必须并成一问,理由不是好看**:两边查条目的方式不一样
  (`grab.normalize` 一份规范形 vs `here` 两份),于是同一页能同时得到「不在库里,
  收录吧」和「在库里」两个答案 —— 屏幕上互相打脸,而点下收录就是库里多一行。
  - **下拉框连同「从清单里挑一个待办」整套退场。** 「这一页是哪一条」地址栏里就
    写着,让人再答一遍的代价是跨三个界面走七步(知识库面板 → 补抓页复制密钥 →
    核对最终网址 → 发起待办 → 回文章标签 → 挑出刚才那个 → 读取)。而那个下拉框
    信的是上一次刷新时缓存的清单 —— 那正是 `precheck` 当初要补的事故形态。
  - **待办没被取消,它退到了幕后。** `fill` 那一档由 `here()` 自己 `_create`,于是
    `precheck` / `save` 那一整套准入、CAS、回执与审计**一个字都没改**;新增的只有
    「谁来建待办」。`_create` 是从 `create` 里拆出来的**同一段**(复用、顶替、额度
    那三段),两个发起方共用 —— 各写一遍的话「同一篇文章会不会同时挂两个待办」就有
    两个答案。
  - **只在正文还欠着的时候自动建**(`_OWED` = `fulltext._eligible()` 原样转手 +
    `fulltext_at=''`,正是三档正文待办的共同前缀,不是第四份口径)。正文已经齐的那
    一条照旧要人在采集抽屉上明说「重新采集正文」:那是另一件事(「我手上这份是错的」),
    它自带警示和回执,挤成同一颗按钮会让人分不出点的是哪件。顺带也挡住一类浪费 ——
    随手逛过的页面如果也建待办,全局额度(`MAX_PENDING`)会被它们占满,而它们手上
    没有任何产物,真要补正文的那一条反倒被顶掉。
  - **按两份规范形找那一行**(`_page_aliases`:`page_url` 和 `grab.normalize`)。库里
    那一行的 `url` 是**收它的那条路**存下来的 —— 订阅类原样存 feed 给的地址,手动收录
    存的是去掉 `utm_*` 之后那一份。只按一份问,另一条路收的那一半永远答「不在库里」,
    而那一句的下一步是收录。**这不是模糊匹配**:两个候选都是这一页自己的规范形,一个
    字符都不猜;**绝不剥语言前缀、也不读网页自报的 canonical**(剥错一次就是把另一篇
    的正文写进这一条)。
  - **`elsewhere` 是承重的,不是提示。** 它交回「等着的、但指着另一个地址的那些待办」。
    事故形态:站点按浏览器语言跳转(`openai.com/index/x` → `/zh-Hans-CN/index/x`),
    人从采集抽屉发起的待办指着前者、浏览器停在后者,按地址一问这一页**确实**不在库里 ——
    只凭这一句请他收录,库里立刻多出第二行同一篇文章,两行各有各的 key、各导出一篇 md。
    把那个待办摆在他眼前、给一颗「改用这一页的地址」(`/here/adopt`,和采集抽屉上那颗
    「改用这个地址」同一个 `create`),他一眼就看出是同一篇。**要在建完待办之后才算它**
    (`answered()` 里那一句):`_create` 会把同一条目上指着别处的旧待办标成
    `superseded`,先算就会把刚作废的那个摆出来请人改用,而点下去只会被拒。
    `elsewhere` 过的是 `_pending()`(和 `/pending` **同一段**),所以条目在这期间被改过、
    被排除、被删掉的照旧当「没有待办」—— 自己再过一遍 `_intents` 就会漏掉那一道。
  - 共用的还有两样:那条连接和配对密钥(`call()`)、在标签上读一次正文(`extractFrom`)。
    原先还有第三样 —— 预览区和那道「我已核对」,由 `collecting` 标记决定提交走 `/upload`
    还是 `/from-page`;那块界面撤掉之后(见下面那条),**分路改由 `situation` 自己答**
    (`fill` → `read`/`/upload`,`absent` → `collect`/`/from-page`),少一个要和服务端那
    一答保持同步的本地标记。收录那一头自己的硬约束在 `link-grab.md`,端点是 `/api/grab*`。
  - **配对密钥用一次不依赖当前标签的调用验**(`/pending`)。拿 `/here` 验不行:人在扩展
    管理页或知识库页面上配对时 `currentTab()` 先拒,于是密钥对不对一个字都没验、还因为
    没抛出而被当成连上了,密钥照旧存进本地。`/pending` 因此不是死端点 —— 它是那道
    连接自检。
  - **提示语指向的按钮必须真的在**(`extract.js` 那两句)。按钮改名时它要跟着改 ——
    改名之前那两句写着「读取所选文字」,而弹窗上已经没有这颗了。

- **补抓页退役成抽屉,而抽屉关掉要真的停、重开要能用。**
  原来那个独立页从「我的订阅」或「问题与待办」点进去要跳出当前页面,补完正文还得自己
  找回刚才看的那一条。现在它贴在左边,底下那一页原样留着。搬家牵出三件**回退之后界面
  上一点都看不出来**的事,各有一条红(`tests/capture_drawer_shell.mjs`):
  - **关掉要把轮询一起停了**(`stopCapture`:清 timer **并且** `loadVersion += 1`)。
    独立页关掉标签就什么都没了;抽屉关掉之后底下那一页还活着,`setTimeout` 链不停就会
    一直每 2 秒打一次 `/target/<key>`,开过几次之后变成几条并行的链。只清 timer 不够 ——
    已经发出去的那一次会在自己的 `finally` 里再排下一轮。
  - **建了就 append、关了就 remove,不是切 `display`。** `workspace.js` 的
    MutationObserver 只盯**页面初始那批**浮层的 style 变化,后来挂上去的那个改 display
    它看不见;而 body 的 childList 它盯着(先例是 `egress.js`)。焦点陷阱、inert、Esc
    关闭链全靠 `syncOverlays`,所以 `#cap-drawer` 也进了它的收集口径,并在打开时注册
    `overlayClosers['cap-drawer']`。**Esc 不自己再挂一个 keydown**:两处都关的话,叠在
    抽屉之上的确认框按一次 Esc 会连抽屉一起带走。
  - **因此每次打开拿到的是一套全新元素,事件必须重绑。** 那个「只绑一次」的标志会让第
    二次打开起每一颗按钮都没有监听器:界面完整、数据也在、点下去什么都不发生。同理
    **模块级状态要跟着条目换** —— `urlAuto` 留着上一篇的网址时,这一次 `autofillUrl`
    会被自己那道「人动过就不填」的闸挡掉(新框是空的,和基准对不上),网址栏**空着**,
    人点发起就是拿一个空地址去发。
  - **DOM 由 JS 建,不写进 `index.html`**(那份已经顶着 700 行上限),**每个 id 带
    `cap-` 前缀** —— 独立页那会儿用的是 `title`、`message`、`create`、`pending` 这类
    裸名字,搬进主界面就会跟别人撞上,而 `getElementById` 撞车不报错,只是安静地拿到
    另一个元素。样式同理**整份锁在 `#cap-drawer` 里**:那份 CSS 原先写的是裸标签
    (main / header / h1 / button / input / details / summary),搬进来会命中全站。
  - **首次使用那一块要摆在看得见的地方。** 没采成过时它在最上面且摊开,采成过之后收进
    底部折叠块 —— **位置和折叠状态一起变**。只把 `<details>` 默认打开的话它还是在整屏
    最下面,而扩展没装、密钥没配的人恰恰最需要先看到它:那一栏网址和「发起采集」对他
    毫无意义,他只会点下发起,然后等一个永远不来的采集。判据见下面那条硬约束 ——
    **是扩展自己在页面上留的标记,不是服务端那张审计表**。
  - **装扩展给的是仓库里那个目录的绝对路径,不是只给一个 ZIP。** 它是「加载已解压的
    扩展程序」装的,而仓库里本来就躺着那份 —— 下载再解压等于把同一份代码在磁盘上放两
    处,之后改了代码,装着的还是解压出来那一份,**而人不会知道自己装的是旧的**。指到
    仓库里这一份,改完点一次「重新加载」就生效。ZIP 留着,给「浏览器不在这台机器上」
    那种情形。

- **预览区和那道「我已核对」撤了:读完直接写进去。**(产品决定。)人就站在那一页上,
  他比屏幕清楚自己要的是哪一篇,再把同一份正文塞进 450px 宽的弹窗里请他重读一遍,
  **拦不住任何服务端拦不住的东西**。
  - **撤掉的只有事前那一问,准入一道都没少**:长度(`_admit_body`,按行去重之后的
    字数)、是不是指定的那一页(`_admit_page`)、条目还是绑定的那一版吗
    (`_admit_item`),连同 `save` 那条 UPDATE 自己 WHERE 里的 CAS,全在服务端原样判。
    `precheck` 也留着 —— 它还答出那个字数,写完要摆给人看。
  - **`/upload` 的 `confirmed_complete` 跟着撤。** 界面不再问人,却照旧报一句「人已经
    核对过了」,那是**扩展签给自己的证词**;何况它从来挡不住非界面调用,随手填个 `true`
    就过。回归钉住「把它加回来会被 422 拒掉,而不是被当真」
    (`test_a_self_signed_confirmation_field_is_refused_not_believed`)。
  - **`body_provenance.confirmed` 改成如实记。** 它记的是「有没有人逐字看过这份正文」:
    扩展那两条路(`browser_article` / `browser_selection` / `browser_grab`)现在记
    `False`,**只有「手动补正文」那条还记 `True`** —— 那一段是人自己粘进来的,断言它
    属于这篇文章的就是他。两者在知识库里要分得出来,这就是分得出来的地方
    (红:`test_who_vouched_for_this_body_is_recorded_as_it_actually_happened`,正反都钉)。
  - **代价是真的,知情留下**:登录墙、摘要页只要过得了那道去重 400 字符就会被写进去,
    原先指望那道勾挡一手。出路是事后的 —— 写完就把标题和字数摆出来,不对就到知识库里
    那一条上「重新采集正文」。`fulltext_at` 一写上这条就退出自动补抓队列,所以**那是
    唯一的出路**。
  - **发起采集时可以顺带打开那一页**(抽屉上那个勾)。`window.open` **先开再发起** ——
    一旦离开这次点击的同步调用栈就不再算用户手势,会被弹窗拦截挡掉。发起失败时多开一个
    标签不要紧:勾它的意思本来就是「我这就要去那一页」。
  - **改了扩展就升 `manifest.json` 的版本号**,并且**版本号摆在弹窗头部**。这个扩展是
    「加载已解压的扩展程序」装的,改了代码要人去扩展管理页点一次「重新加载」——
    装的是哪一版只有那里看得出来,没有它,「我到底重载过没有」只能靠猜。

## 知情的代价

- 抽屉开着时固定 2 秒轮询,切到后台也不停(关掉就停);每轮 `item_state()` 开三次数据库连接。
- `save()` 持 `_lock` 期间执行 `BEGIN IMMEDIATE`,库被别的进程占着时 `item_state` /
  `pending` 一起等。TTL 内最多 100 个 pending,影响有界。
- `precheck` 让每次读页多两次本机往返,换的是「不让人白读一整页」。
- 请求队列在单个 web 进程的内存里,不支持多 worker;重启丢未完请求,不丢已保存
  正文和审计回执。
- `save()` 不取维护锁,与手动收录 `grab_store.replace()` 对称 —— 判据待在 UPDATE
  自己的 WHERE 里,见元规则「并发与数据安全」。
- 审计表每成功补抓一次长一行(一次人的动作),前一世那些在下一次补抓时收掉,没有
  按时间的留存策略。**同一秒里删掉又收回来、而且两世的修订号正好对齐**的那一档,
  旧回执仍可能按它自己的请求 id 读出来 —— 那时两份正文的摘要也相同,所以它说的话
  不假;那一页上显示的始终是这一世最后那张。
- 「继续导出与索引」不买提取,所以**图鉴条目要等下一轮同步**(或人自己到同步中心勾
  一次)。换来的是:这颗按钮的射程和钱都可预测。

## 还没做的(知情留下,不是忘了)

- **采集抽屉没有一个正经的导航入口。** 它只能从上面那两个逐条入口开(页面退役之后连
  地址都没有了)。给侧栏加一个页签牵扯导航结构,**那是仓库主人拍板的事**,不在这一轮里
  自己加。
- **`_same_life` 还在用旧那两列认「这一世」**(`item_fetched_at` + `content_rev`),没有换
  到 `feed_items.life` 上 —— 理由和它判错的方向写在上面那条约束里,要并到一份口径上是这
  一块自己的一轮。
- **补抓成功之后,「问题与待办」上给不出第二次机会**:这一条落在 `ingest_queued`,而那一档
  的出口里既没有 `body` 也没有 `capture`(「已定的正文可以被再改一次」是个产品决定,见
  `intake-diagnostics.md` 的「还没做的」)。要重采得回到这篇文章的采集抽屉点「重新采集正文」。
- **扩展那边保存完成,没有一条跨页面通知。** 抽屉是靠自己两秒一轮的轮询看见那张回执
  的,交接那一刻另问一次服务端(上面那条约束)补上了「关得比一轮快」那个空窗 —— 但
  抽屉**开着**的那段时间里,屏幕上那一屏仍然最多旧两秒。要抹掉那两秒就得让「保存完成」
  有一条主动的跨页面通知(SSE / `BroadcastChannel`),那是另一条机制,不在这一轮里。
