# 从已打开的浏览器标签补正文

人已经在浏览器里打开了那篇文章,由他在那个标签上点扩展、预览确认,正文补回原条目。
入口在「我的订阅」的文章条目上(RSS / 网页专栏 / 手动收录),页面是
`/browser-capture?item=<key>`。怎么装、怎么用写在 `docs/browser-capture.md`。

## 硬约束

- **准入判据只有一份,在服务端。** 「这一次写不写得了」由 `kb/browser_capture` 的
  `_admit_body`(正文够不够)、`_admit_page`(是不是指定的那一页、来源允不允许、请求
  还在不在)、`_admit_item`(条目还是绑定的那一版吗)回答;`precheck` 和 `save` 调的是
  **同一组**。**扩展一处都不判** —— 它只负责展示结论。
  事故形态(实测三种):扩展自己 `new URL()` 比网址、自己数原始字符数、信上一次刷新
  下拉时缓存的那份清单,于是「服务端会拒」的三类都要等人**把整篇文章读完、核对完
  预览、勾完确认、点下提交**才被 409 拒 —— 白读一整页。其中网址带中文那一类是
  **每一次都失败**,怎么重来都一样。往扩展里补一张规范化表、再抄一遍去重算法只会
  开出第四第五个实例,所以判据整个退回服务端。
- **`page_url()` 是文章网址的唯一规范形。** 口径跟着浏览器的 `new URL().href`:
  scheme / 主机小写、非 ASCII 主机转 punycode、默认端口去掉、非 ASCII 与不安全字符
  百分号编码、**已有转义原样透过**、点段折叠、片段丢掉。空 query(末尾那个 `?`)两边
  都丢 —— 比浏览器宽一格,宽的那头只会多认一个同页地址。**不许在别处再写一份,也
  不许拿原始字符串比**。`%2e` 这种编码过的点段不折叠(浏览器会),后果止于「人自己
  填了个点段地址」→ 读之前就被告知网址不同,可改可重发。
- **`precheck` 一个字都不落库,也不顶替事务内那一道。** 真正的互斥待在 `save` 那条
  UPDATE 自己的 WHERE 里(key / 来源 / 原网址 / 正文指纹 / 修订号 / 非 X 观点 / 未排除,
  `rowcount != 1` 即拒);`precheck` 和 `save` 开头那次 `_refresh_status` 都只是**早一道**。
- **补抓页那一栏网址:人动过就不许被轮询填回去。** 自动填入只认「框里还是上一次
  自动填进去的那一份」(`autofillUrl`);已有请求时强制显示服务端记下的那一份并禁用。
  事故形态:本页每 2 秒重画一次,原来的判据是「框是空的就当还没填过」—— 人清空、
  切出去复制浏览器里真正的地址、切回来一粘贴,贴的那一截接在被填回的原网址后面,
  拼成一个谁也打不开的地址(实测 2.6 秒后变回原值),之后扩展只会一直说「当前标签
  网址与指定文章不同」。**两个触发点**:平常那一次,和点过「重新采集正文」进草稿态
  之后 —— 这道闸不能只挡首次渲染。
- **回执按文章恢复,不靠标签的 `sessionStorage`。** 服务端按文章 key 返回当前待办和
  最近一条有效审计回执(`browser_capture_audit`),关页、换标签、超过 15 分钟、服务
  重启之后都找得回来。已保存请求无论命中内存还是从审计恢复,都走 `saved()` 同一套
  校验(来源、排除状态、修订号、正文摘要);旧回执失效时隐藏成功区、禁用继续按钮
  并给出原因。
- **同一文章只留一个 pending。** 在锁内比正文版本、来源、原网址和指定最终网址:
  匹配就复用原请求和有效期,不匹配把旧的标 `superseded` 再建新的。额度只算 pending
  (100 个),保存 / 取消 / 陈旧不占。不同文章各自排队。
- **进入「重新采集」不撤销已保存的正文和回执**,退出也不清审计;只有再次预览确认
  提交才替换。
- **`fulltext_at` 一写上,这条就退出自动补抓队列**(`fulltext.queued_sql()` 要求它为空)。
  好处是刚补的正文不会被自动补抓再盖一遍;代价是万一采到的是一张过得了去重门槛的
  会员说明页,出路只剩人工「重新采集正文」。
- **`api.js` 住在扩展目录**(`kb/static/browser-extension/knowbase-capture/api.js`),因为
  下发的 ZIP 要带上它、扩展取不到 `kb/static/js/` 下的文件。页面在 `ui.js` **之前**加载
  它;全站十来个脚本的 `apiFail` / `toastIfFail` 都是它那一份。
- **`plainUrl()`(两处,各三行)只是显示** —— 把百分号编码过的中文地址显示成人能对着
  地址栏核对的样子。它不是判据,回填给服务端时会被重新规范化成同一份。

## 回归

- `tests/test_browser_capture.py` —— 事务、版本保护、审计恢复、鉴权,外加「浏览器交
  回来的那一份网址规范化之后是同一页」和「`precheck` 的结论与 `save` 逐字一致、且
  不落库」。
- `tests/browser_capture_gate.mjs` —— 扩展侧:读页**之前**先问服务端(不通过就一个字
  都不读)、正文那一问没过不渲染预览、预览上的字数用服务端那一份,外加一条结构红
  (扩展和提取器里不许再出现第二份判据)。
- `tests/browser_capture_url_field.mjs` —— 网址那一栏的两个触发点,反过来钉一边:
  没人动过的空框照旧填默认值。
- `tests/browser_capture_feedback.mjs`、`browser_capture_notices.mjs` —— 共用错误解析、
  一次性反馈不被轮询盖掉。四条 node 探针都挂在
  `tests/test_browser_capture_feedback.py` 上(纯 `vm`,不起浏览器,留在快速层)。
- 反向验证靠**定点注入**:把「框是空的就当没填过」那两行换回去 / 在扩展里恢复一次
  `new URL()` 比对 / 在提取器里恢复 400 那道门槛 —— 三处各让对应的那一条红。

## 知情的代价

- 补抓页固定 2 秒轮询,切到后台也不停;每轮 `item_state()` 开三次数据库连接。
- `save()` 持 `_lock` 期间执行 `BEGIN IMMEDIATE`,库被别的进程占着时 `item_state` /
  `pending` 一起等。TTL 内最多 100 个 pending,影响有界。
- `precheck` 让每次读页多两次本机往返,换的是「不让人白读一整页」。
- 请求队列在单个 web 进程的内存里,不支持多 worker;重启丢未完请求,不丢已保存
  正文和审计回执。
- `save()` 不取维护锁,与手动收录 `grab_store.update_known()` 对称 —— 判据待在 UPDATE
  自己的 WHERE 里,见元规则「并发与数据安全」。

## 不在这一块里

旧的**自动**补抓资格查询(`kb/feeds/fulltext.py` 的 `_eligible`)和订阅编辑里那个补抓
勾选框是基线既有的另一条执行路径,已转独立任务 `oYebSouTUqu6`。**不要在这一块里
顺手改它们** —— 两处各改一版的后果比晚修一轮严重。
