# 订阅正文转纯文本(kb/feeds/fetching.py 的 plain)

> 从 CLAUDE.md 外移的决策记录。CLAUDE.md 只留硬约束和一行指针,
> 这里是完整的事故形态、实测证据、回归清单和反向验证红数。原文逐字搬运。

- **只有块级元素换行,行内元素一个分隔符都不插。** 别退回
  `soup.get_text('\n', strip=True)`:那个分隔符对**每一个文本节点**各插一次换行,
  而 `<a>`/`<em>`/`<code>` 正是把一句话切成多个文本节点的东西 —— 一句
  「As `<a>`promised`</a>`, Anthropic released ...」出来就是三行,每个链接文字独占
  一行。更糟的是**段落边界跟着一起塌掉**:`<p>` 之间本该是空行,`strip=True` 之下
  也只剩一个 `\n`,和句中被切开的那些换行再也分不出来(2026-10-08 实测:库里 738 条
  RSS 条目有 677 条带换行,带空行的只有 3 条 —— 段落信息在入库那一刻就没了)。
- **后果是三重的,而且只有第一重看得见。** ①面板的阅读视图按
  `white-space: pre-wrap` 一行行照显,就是用户截图里那个样子;②导出的 vault md
  整篇没有一个空行,markdown 渲染时整篇糊成一段;③翻译那边 `translate._split`
  按 `'\n\n'` 切块,于是**整篇算一个段落**、超过 `CHUNK`(3000)就从句子中间硬切,
  而 prompt 里写着「保持原有的段落与换行结构」—— 模型忠实照做,把碎行逐行译了
  一遍。所以「翻译后排版乱」里翻译是无辜的:点「看英文原文」同样乱。
- **边界分三档,各插一个标记,相邻标记合并成最强的那一档**(`\x02` 块级 >
  `\x03` 换行 > 空格)。前后各插一个而不是只插一个,是为了不依赖兄弟节点的顺序;
  合并规则兜住「两个块挨着时留下双倍空行」。分档的理由各自不同:`<br>` 和 `<tr>`
  只断行(一张表被空行撑成几十段没法读),`<td>`/`<th>` 同一行里用空格分开(一格
  一行就把行列结构彻底拍平),`<li>` 归块级(vault md 里单换行会被 markdown 合并,
  几项挤成一行)。
- **`<pre>` 先整块摘出去、最后再放回来**(NUL 占位符)。它的缩进和内部空行是内容,
  而主流程那一道 HTML 空白折叠会把代码块压成一行。放回必须排在行清理之后,否则
  缩进被当成源码缩进吃掉。入口先把 `\x00`/`\x02`/`\x03` 从 html 里清掉 —— 正文
  里伪造出占位符形状就能把别处的 `<pre>` 内容搬过来。
  **摘的时候换掉的是内容,不是整个标签**(`tag.string = 占位符`,不是
  `tag.replace_with(...)`)。整个 replace 成一段裸文本的话,`pre` 虽然在 `_BLOCK` 里,
  后面那趟 `find_all` 已经找不到这个标签了 —— 它自己那道块级边界跟着一起没:两个
  相邻代码块首尾相接成一个(`first()\n    more_first()second()`),代码和两侧正文
  之间也不分段(`Beforecode\n    indentAfter`),照着复制的命令当场是错的。
  **原来那条 `<pre>` 回归恰好被 `<p>` 遮住了** —— 样本写成 `<p>Try:</p><pre>…</pre><p>Done.</p>`,
  `<p>` 替它补上了边界,于是这个缺口一条测试都没红(2026-10-08 审查发现)。
- **空白折叠要赶在插标记之前做**,否则连自己插的换行一起折叠掉;逐个文本节点替换
  时判 `type(x) is NavigableString` 而不是 `isinstance` —— `Comment`/`CData`/
  `Doctype` 都是它的子类,照样替换会把注释内容搬进正文。
- **先问正文是什么类型,再决定怎么解析**(`body_text(value, kind)` 是唯一入口,
  `entry_body` 负责把每份值和它自己那份类型一起取出来)。上面整套说的都是 HTML;
  把它套到纯文本正文上是同一个病的反面 —— **纯文本里的换行就是内容**,而
  `_WS.sub(' ', …)` 那道 HTML 空白折叠会把它全抹平:一篇 Atom `type="text"` 的
  文章原本好好分着段,解析完成了一整段,译文、vault md 和阅读页一路继承
  (2026-10-08 审查实测 `'First paragraph.\n\nSecond paragraph.\nThird line.'` →
  `'First paragraph. Second paragraph. Third line.'`)。纯文本只做最轻的归一
  (`_plain_lines`:统一行尾、去行末空白、三个以上连续换行并成一个空行)。
  **类型要跟着值一起取**:`content` 用 `content[i].type`、`summary` 用
  `summary_detail.type`,各有一份,不能只认一个。
- **分流只问类型,不看内容长什么样。** 别再往 `_is_plain` 里加「内容里有标签就
  按 HTML 处理」那种嗅探 —— **「这段文字能被解析成标签」证明不了作者标错了类型**。
  技术文章里的 `List<T>`、尖括号写的链接、一段字面 HTML 示例全是这个形态,而它们
  正是作者声明 `type="text"` 要原样显示的东西:嗅探会把 `<T>` 当标签删掉、真实
  段落再按 HTML 规则折叠掉(`'Use List<T> for the new generic API.\n\nThe second…'`
  → `'Use List for the new generic API. The second…'`),字面 `<b>` 同理消失;一篇
  正文只有 `<script>alert(1)</script>` 示例的文章更会被 `plain()` 的脚本清理整个
  掏空,`parse_feed` 当场跳过条目抛 `FeedError`,**文章有正常标题和链接却收录不
  进来**(2026-10-08 第 2 轮审查三种形态各实测一次)。它是待显示的示例文字,不是
  要执行的脚本 —— 阅读页本来就用 `textContent` 显示正文。
  **当初加那道嗅探的理由本身是错的**:它写着「feedparser 把 RSS 的裸 `<title>`
  一律标成 `text/plain`」,而实测 RSS 的裸标题和 `<description>` 拿到的都是
  `text/html`(复判那一轮重测确认);`text/plain` 只出现在 Atom 显式 `type="text"`
  和 Atom 不写 type 时 —— 两种都是作者的明确声明,不是错标。
  **类型取不到就按 HTML 走**,并且容忍 `None`:content 与 summary 并存时
  feedparser 给的 `summary_detail.type` 就是 `None`(那条路 content 先返回,走不到,
  但别让它崩)。
- **标题和作者走 `oneline`**(plain 之后把换行压成空格):它们是单行字段,`<br>`
  在正文里该换行,在标题里只该是一个空格。**它也要带上类型** —— 纯文本标题同样
  不该被当 HTML 解析。
- **实现里不许有递归**:`find_all` 和 `get_text` 都是迭代的,畸形 HTML 嵌套几千层
  也只是慢,不会 `RecursionError` 把整个订阅源的解析带崩。
- **存量不会自动修复**:`registry.put_items` 是 `ON CONFLICT(key) DO NOTHING`,
  已入库的条目再抓到也不更新。改这里只对新条目生效。要修存量只能重新抓(而 feed
  里早已滚出去的条目救不回来),且 body 一变 `content_hash` 就变,会连带触发重译
  和重新导出 —— 那是一笔要单独决定的模型开销。
- 回归在 `tests/test_feed_plain.py`(24 条):截图那条真实形态的句子不许被链接切开、
  段落之间真的有空行、注释和 script 不进正文、源码缩进照 HTML 规则折叠、`<br>`
  只断一行、表格行列各归各位、`<pre>` 的缩进和内部空行原样、**相邻两个 `<pre>` 不
  粘连**、**`<pre>` 和紧挨着它的正文之间也分段**(这两条不许再借 `<p>` 补边界)、
  正文里伪造占位符偷不走 `<pre>` 内容、`parse_feed` 出来的 body 带段落边界、标题不
  含换行、**Atom `type="text"` 的正文与 summary 端到端保留段落和单换行**、
  **声明成纯文本的 `List<T>` 和字面 `<b>` 一个字都不许少**、**正文只有 `<script>`
  示例的那篇照样收录得进来**、**类型说是 HTML 就照样剥标签**(反过来钉住别把分流
  判反)、**类型缺失或为 `None` 时按 HTML 走且不崩**、纯文本字段照样压成一行、
  行末空白与连续空行归一,以及**翻译按段落切而不是从句中硬切**(判据是
  `'\n\n'.join(_split(body)) == body` —— 硬切时当场不成立)。反向验证定点注入过
  五版:整个 `plain` 退回旧版红 11 条(其中就有翻译硬切那条)、三档边界合并成一档
  红 2 条、去掉 `<pre>` 保护红 1 条、`<pre>` 退回 `replace_with` 整个标签红 2 条、
  正文类型一律忽略红 6 条、**把 bs4 嗅探加回去红 3 条**(`<T>` 被吃掉 / 字面 `<b>`
  被吃掉 / `<script>` 那篇抛 `FeedError`)。
