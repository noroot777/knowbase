# 域名解析与出口(`kb/feeds/resolve.py`、`fetching.public_addresses`、`scripts/web_env.sh`)

> **这一份的第一节就是这一块的硬约束(不许怎样)—— 动这块代码之前先读它**,后面是事故形态、
> 实测证据、回归清单和反向验证的注入点。CLAUDE.md 只留跨块的元规则和一张索引。
> 硬约束和下面的展开**说的是同一条口径,要改规则两边一起改**。

## 硬约束

- **本机解析可以是假的,而症状会伪装成对方的问题。** 抓不到的那一句「订阅连接超时,请稍后
  重试或修改链接」把人指向「改链接」,而链接一点毛病没有 —— 真正发生的是解析被污染、钉出去
  的 IP 是别人家的地址,TLS 握手原地超时。**所以「连接超时」这句话不许当成结论**:同一台机器
  上人工 `curl` 打得开的站点,服务抓不到,先怀疑解析。
- **换解析器只换「地址从哪来」这一步,后面那几道一个字都不动**:`is_global` 过滤、空集拒绝、
  `dict.fromkeys` 去重与顺序、调用方钉数字 IP + `Host` + `sni_hostname`。SSRF 防护因此一分
  不少 —— 实测「经代理 + 钉真实 IP + SNI」同样返回 200,**代理和钉 IP 不冲突**;而污染指向
  内网时(`127.0.0.1`)那一道正是把它拒掉的东西,不许以「反正要换解析器了」为由拆掉。
- **这一层默认关**(`KB_FEED_DOH` 空):关着时一次 DoH 请求都不发、解析逐字走
  `socket.getaddrinfo`。既有的传输层不变量(钉 IP、逐跳重校验、重定向丢验证器、连不上换下
  一个地址)原样有效,`tests/test_feed_transport.py` 一个字都没改 —— **那一份是这一层的反向
  边界,改它之前先问为什么**。
- **不做「哪些域名走 DoH」的名单。** 污染随时变、形态也不止一种(同一个库里同时存在「指向
  别人家的公网地址」和「指向 127.0.0.1」两种),名单正是会静默过期的那类东西 —— 漏一个域,
  症状就又变回一句看不出原因的超时。
- **DoH 这一跳刻意不过 `public_addresses`**:用主机名 + `trust_env=True` 让代理去解析
  (CONNECT 带的是主机名),所以端点域名自己被污染也不受影响。放弃的那道 IP 校验在这里没有
  威胁模型可言 —— 端点是用户在环境变量里写死的一个常量,不是订阅内容带进来的地址。
  **反过来钉一边:订阅 URL 本身绝不许绕过 `public_addresses`。**
- **DoH 的答案当不可信输入解析,判不准一律抛,不许返回「确定没有」**(元规则)。
  - `Status` 只认 0 和 3;`Answer` 必须是列表,**不是列表就是答得不对**(`{"Status":0,
    "Answer":"nonsense"}` 被 `for` 当字符串逐字迭代、每个字符都不是记录、于是一条不剩,
    末态报成「无法解析订阅服务器地址」—— 那是在替对方断言一件我们并不知道的事)。
  - `Answer` 里**只取 type 1/28**,CNAME 等一律忽略而不是当地址。**这一道要独立于「data 解析
    不动」成立**:拿 CNAME 的域名串做料时,它会被下一道 `ipaddress.ip_address` 的 ValueError
    兜住,于是类型过滤在那份料上压根不可见(去掉它一条红都没有)。回归喂的是「非 A/AAAA 的
    记录、data 却是个合法 IP 串」。
  - 每条 `data` 必过一遍 `ipaddress.ip_address`,**畸形的那一条跳过**而不是带掉整轮。
- **两种「答不上」要分开说,面板文案各只有一个出处。**
  - `Unavailable`(端点连不上、超时、代理没配、SERVFAIL、答案不是 DNS JSON)→ 面板说
    **「域名解析服务不可用,请检查 KB_FEED_DOH 与代理设置」**:这是**我们这一侧**没出口,人要
    去看的是配置,不是改订阅链接。
  - `Unknown`(对方明确答了:NXDOMAIN、或只有 CNAME 没有地址)→ 面板说 `_UNRESOLVED`
    (「无法解析订阅服务器地址」),**和系统解析器报错共用同一句、同一个常量**。
  - 合成一档就是把「我这边坏了」说成「你的链接写错了」。**「没时间问了」归前者**:预算耗尽
    时报「这个域名没有地址」同样是在替对方断言(这一条不经 `request` 才测得到 —— 那条路上
    `remaining()` 会先抛,resolve 自己那个分支一条红都没有)。
- **一族查不动、另一族答上了,就按答上的算。** 部分成功不丢:A 挂了而 AAAA 给了地址,照旧
  拿去连(`request` 本来就是按顺序试、连不上才换下一个)。**A 排在 AAAA 前面**,IPv4 可用面更大。
- **预算由调用方给,这一层不自带一份**(`seconds`)。只有 `fetching` 那边的 `remaining()` 知道
  这一次还剩多少、整轮采集的 `collect_deadline` 有没有更紧 —— 自带一份的后果是单源那 20 秒
  之外又挂上最多 6 × 2 次 HTTP 往返,而面板上只显示「慢」。`collect_deadline` 照旧管得住它
  (超了抛 `CollectionBudgetExceeded`,不被包成一次订阅失败)。
- **缓存不是优化,是正确性**:`request` 一次最多 6 跳、每跳解析一次,`fulltext` 一轮 20 条跑在
  3 个线程里。**按域名缓存,不许按 URL** —— 按 URL 会让「每跳都重新解析」这条不变量当场失效
  (那正是挡住 DNS rebinding 的东西)。TTL 取答案自己给的,夹在 `TTL_MIN`/`TTL_MAX` 之间;
  **失败一律不进缓存**,一次网络抖动不该粘住十分钟。锁只锁查和写两下、不锁 HTTP 等待(同一
  域名撞上最多多问一次,锁着网络等待会把三个工作线程串成一条)。
- **起服务那条命令必须把「出口」这一族环境变量透传进去**(`scripts/web_env.sh` 的
  `build_web_env`,由 `kb.sh` source —— **拆出去是因为 `kb.sh` 顶到了 700 行那条线**,
  而「服务进程的环境怎么拼」本来就有自己的名单、理由和回归),
  **但别把理由记成「否则就没有出口」**。
  - `KB_FEED_DOH` 是**硬需求**:不透传的话服务里永远读不到它,上面那一层等于没有开关。
  - 代理那几个是**让出口变显式**。`env -i` 在 **macOS 上并不会**让抓取失去代理:httpx 的
    `trust_env` 走 `urllib.request.getproxies()`,它在 macOS 上读的是系统代理设置
    (SystemConfiguration)—— 环境变量清光了照旧拿得到。**Linux / 容器 / CI 上
    `getproxies()` 只看环境变量,那里 `env -i` 才真的把出口断掉**,而那正是开源交付要走
    的那条路。
  - **名单只有一份。** 形态是同一件事在两处各判一遍、只补了一处:装依赖那一步
    (`web_prepare_env`)一直在透传这一族、注释里还写明「这台机器上 pypi 常常得走代理」,
    而起服务那一行用的是裸 `CLEAN_ENV`。谁再手写第二遍循环就会复发。
  - **只透传出口这一族,不是整份 `KB_` 开头的变量。** `KB_DATA_DIR` 不透传是现状:把它放进来
    会静默换掉服务读的那个库,那是另一件事。
  - **空值不许透传**(`NO_PROXY=''` 和「没设」不是一回事;httpx 读到空代理会当成配了一个)。
  - `WEB_ENV` 那段刻意不用 `mapfile`:macOS 自带的是 bash 3.2。
  - **配了 `KB_FEED_DOH` 却一个代理变量都没有时打一行提示,提示而不代劳**(口径同 `code_stale`
    / `graph_stale`)—— 那种配法下端点多半也连不上,而后果是每条订阅都报「解析服务不可用」。

## 事故形态与实测证据

一条 HN Buzzing 带出来的 `https://mistral.ai/news/voxtral-3/` 在面板上显示「订阅连接超时」、
`fulltext_tries=2`,正文是 feed 给的 45 字节壳(标题 + 域名 + HN 得分)。

用项目自己的通道(`fetching.request` → `fulltext.fetch_one`)复现并逐层拆开,下面这组数字是
**2026-10-22 那一刻的快照**(污染答案会变,别拿它当常量):

| 测法 | 结果 |
|---|---|
| `fetching.request(url, fulltext._HEADERS)` | `FeedError: 订阅连接超时`,12.1s |
| 逐 IP 看卡在哪 | 两个地址都是 `ConnectTimeout: handshake timed out`,各 6.0s(TLS 握手,不是 TCP) |
| `getaddrinfo` 给的地址 | `199.16.156.75`(Twitter 段)、`2a03:2880:f11c:…`(Meta 段) |
| 换解析器 | 系统/Tailscale → `108.160.173.207`(Dropbox);`@8.8.8.8` → `162.125.32.6`;`@223.5.5.5` → `31.13.94.41` —— 四个解析器四个假答案 |
| 真实地址(Cloudflare DoH,经代理) | `162.159.142.207`、`172.66.2.203`(Cloudflare) |
| 直连真实 IP + SNI,不走代理 | `ConnectError: Connection reset by peer`,1.2s / 0.3s(SNI 阻断) |
| 经代理 + 主机名 | **HTTP 200,585 227 字节** |
| 经代理 + 钉真实 IP + SNI(项目原样那套写法) | **HTTP 200** ← 钉 IP 的设计本身没问题 |
| 经代理 + 钉**污染** IP | 失败 ← **只给服务配代理不够,解析必须同时是干净的** |
| 跑着的 kb-web 整份环境(`ps eww`) | 8 个变量:`HOME PATH PORT UV UV_RUN_RECURSION_DEPTH VIRTUAL_ENV __CF_USER_TEXT_ENCODING __PYVENV_LAUNCHER__` —— 代理变量一个都没有(**但见下面「归因里曾经错的那一条」:这台机器上它照旧有代理**) |
| 两半都补上之后跑 `fulltext.fetch_one` | 正文 10 168 字、`why=''`、`grab_page.admit` 八道全过;`markup_size` 565 542 < `readable.MAX_HTML` |

**污染的第二种形态**:`buy-european.net` 被解析成 `127.0.0.1`,于是 SSRF 那道**正确地**把它
拒了,面板上报的是「订阅域名未解析到公网地址,已拒绝连接」。两句不同的提示,同一个病根 ——
这也是「换解析器不许顺手拆掉 `is_global`」的理由:它在污染之下仍然是对的。

**范围**:同一个库里 13 条「连接超时」几乎全是被墙域名。两半都补上之后复测,**6 条变成
HTTP 200**,余下 7 条变成有信息的真失败(付费墙 401、拒代理 IP 的 403、关卡页、404)——
这一层把「静默超时」换成「说得出原因」,**不治**付费墙、关卡和拒绝代理 IP 的站点。

## 归因里曾经错的那一条

第一版归因写的是「服务被 `env -i` 洗掉了代理,所以只会直连」。**那一半是错的**,而它会把
下一个人引到错的修法上(只补 `kb.sh`、不碰解析,然后以为修好了)。

决定性实验:`env -i HOME=… PATH=… python -c "import urllib.request; print(urllib.request.getproxies())"`
→ `{'http': 'http://127.0.0.1:7897', 'https': 'http://127.0.0.1:7897'}`。httpx 的 `trust_env`
用的就是 `getproxies()`,而它在 macOS 上读 SystemConfiguration 里的系统代理 —— 所以
**kb-web 一直是有代理的**。

于是真正的病根只剩一条:**钉出去的那个 IP 是假的**。而「经代理去连一个假 IP」能不能通,
取决于代理软件要不要按 TLS SNI 嗅探重路由、以及那个假 IP 落到哪条规则上 —— **所以它随机**。
同一轮实测里把四种组合各跑 6 次,四种全 6/6 通(含「无代理变量 + 污染 IP」);而同一个假 IP
在 `trust_env=False`(真直连)下是 6 秒握手超时、真实 IP 直连是 RST。库里的痕迹对得上这个
随机性:**同一个 `mistral.ai/news/` 下,`mistral-large-4` 那条补抓成功过(14 606 字节正文),
`voxtral-3` 这条连失败两次**。

**这也是为什么「连接超时」这句话不许当结论**:它既不说明对方拦着你,也不说明你没有出口 ——
它可能只说明你敲错了门,而那扇门是解析告诉你的。

**所以两半的分量不一样,别记反**:可信解析(`KB_FEED_DOH`)是真正把成败从「押在代理的嗅探
行为上」变成确定的那一半;`kb.sh` 的透传在 macOS 上对代理而言基本是冗余的(但对
`KB_FEED_DOH` 是硬需求),它的价值在没有系统代理概念的机器上 —— 容器和 CI。

## 知情的取舍

- **`Unavailable` 照旧扣 `fulltext_tries`。** 更对的做法是不扣(「我这边的解析器坏了」不该消耗
  「对方拦着你」那份预算),但那要给 `fulltext._fail` 加一档、牵动 `queued_sql` 的 ③④ 那组
  硬约束 —— 那是另一块的事,不捎带着改。眼下的兜底是上面那条「提示而不代劳」:配了 DoH 却
  没有代理时起服务会说一句。
- **端点走环境变量,还没有面板入口。** 开源要能交付(反复要做的步骤该做进页面),但那是结构性
  的界面改动,按约定先给可点的 demo 再定夺。现在的出路是 shell 里 export + `./kb.sh web restart`。

  话、发了几次 DoH 请求。污染注入用真实形态(**公网**假地址和 `127.0.0.1` 分成两条红)。

  实测到过);subTest 换料走 `arm()`。

  一起改)跑一遍 `build_web_env`,顺带验 bash 3.2 兼容;外加两道文本守卫:起服务那一行用的是
  `WEB_ENV`、名单在 `kb.sh` 加 `web_env.sh` 两份里合起来只出现一次。行为测试起不了真服务,

- 定点注入(各自该打中的那一条):这一层没接上 / CNAME 当地址 / 两种答不上合成一档 /

  预算耗尽也照样问 / 起服务退回裸 `CLEAN_ENV` / 空值也透传 / 把 `KB_DATA_DIR` 放进名单 /
