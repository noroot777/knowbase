# 域名解析与出口(`kb/feeds/egress.py`、`resolve.py`、`fetching.public_addresses`、`scripts/web_env.sh`、设置里的「出口与解析」面板)

> **这一份的第一节就是这一块的硬约束(不许怎样)—— 动这块代码之前先读它**,后面是事故形态、
> 实测证据、回归清单和反向验证的注入点。CLAUDE.md 只留跨块的元规则和一张索引。
> 硬约束和下面的展开**说的是同一条口径,要改规则两边一起改**。

## 硬约束

- **本机解析可以是假的,而症状会伪装成对方的问题。** 抓不到的那一句「订阅连接超时,请稍后
  重试或修改链接」把人指向「改链接」,而链接一点毛病没有 —— 真正发生的是解析被污染、钉出去
  的 IP 是别人家的地址,TLS 握手原地超时。**所以「连接超时」这句话不许当成结论**:同一台机器
  上人工 `curl` 打得开的站点,服务抓不到,先怀疑解析。
- **换解析器只换「地址从哪来」这一步,后面那几道一个字都不动**:`is_global` 过滤、空集拒绝、
  `dict.fromkeys` 去重与顺序、调用方钉数字 IP + `Host` + `sni_hostname`。SSRF 防护因此一分
  不少 —— 实测「经代理 + 钉真实 IP + SNI」同样返回 200,**代理和钉 IP 不冲突**;而污染指向
  内网时(`127.0.0.1`)那一道正是把它拒掉的东西,不许以「反正要换解析器了」为由拆掉。
- **这一层默认关**(`KB_FEED_DOH` 空):关着时一次 DoH 请求都不发、解析逐字走
  `socket.getaddrinfo`。既有的传输层不变量(钉 IP、逐跳重校验、重定向丢验证器、连不上换下
  一个地址)原样有效,`tests/test_feed_transport.py` 一个字都没改 —— **那一份是这一层的反向
  边界,改它之前先问为什么**。
- **不做「哪些域名走 DoH」的名单。** 污染随时变、形态也不止一种(同一个库里同时存在「指向
  别人家的公网地址」和「指向 127.0.0.1」两种),名单正是会静默过期的那类东西 —— 漏一个域,
  症状就又变回一句看不出原因的超时。
- **DoH 这一跳刻意不过 `public_addresses`**:用主机名 + `trust_env=True` 让代理去解析
  (CONNECT 带的是主机名),所以端点域名自己被污染也不受影响。放弃的那道 IP 校验在这里没有
  威胁模型可言 —— 端点是用户在环境变量里写死的一个常量,不是订阅内容带进来的地址。
  **反过来钉一边:订阅 URL 本身绝不许绕过 `public_addresses`。**
- **DoH 的答案当不可信输入解析,判不准一律抛,不许返回「确定没有」**(元规则)。
  - `Status` 只认 0 和 3;`Answer` 必须是列表,**不是列表就是答得不对**(`{"Status":0,
    "Answer":"nonsense"}` 被 `for` 当字符串逐字迭代、每个字符都不是记录、于是一条不剩,
    末态报成「无法解析订阅服务器地址」—— 那是在替对方断言一件我们并不知道的事)。
  - `Answer` 里**只取 type 1/28**,CNAME 等一律忽略而不是当地址。**这一道要独立于「data 解析
    不动」成立**:拿 CNAME 的域名串做料时,它会被下一道 `ipaddress.ip_address` 的 ValueError
    兜住,于是类型过滤在那份料上压根不可见(去掉它一条红都没有)。回归喂的是「非 A/AAAA 的
    记录、data 却是个合法 IP 串」。
  - 每条 `data` 必过一遍 `ipaddress.ip_address`,**畸形的那一条跳过**而不是带掉整轮。
- **两种「答不上」要分开说,面板文案各只有一个出处。**
  - `Unavailable`(端点连不上、超时、代理没配、SERVFAIL、答案不是 DNS JSON)→ 面板说
    **「域名解析服务不可用,请到设置里的「出口与解析」检查端点与代理」**:这是**我们这一侧**没出口,人要
    去看的是配置,不是改订阅链接。
  - `Unknown`(对方明确答了:NXDOMAIN、或只有 CNAME 没有地址)→ 面板说 `_UNRESOLVED`
    (「无法解析订阅服务器地址」),**和系统解析器报错共用同一句、同一个常量**。
  - 合成一档就是把「我这边坏了」说成「你的链接写错了」。**「没时间问了」归前者**:预算耗尽
    时报「这个域名没有地址」同样是在替对方断言(这一条不经 `request` 才测得到 —— 那条路上
    `remaining()` 会先抛,resolve 自己那个分支一条红都没有)。
- **一族查不动、另一族答上了,就按答上的算。** 部分成功不丢:A 挂了而 AAAA 给了地址,照旧
  拿去连(`request` 本来就是按顺序试、连不上才换下一个)。**A 排在 AAAA 前面**,IPv4 可用面更大。
- **预算由调用方给,这一层不自带一份**(`seconds`)。只有 `fetching` 那边的 `remaining()` 知道
  这一次还剩多少、整轮采集的 `collect_deadline` 有没有更紧 —— 自带一份的后果是单源那 20 秒
  之外又挂上最多 6 × 2 次 HTTP 往返,而面板上只显示「慢」。`collect_deadline` 照旧管得住它
  (超了抛 `CollectionBudgetExceeded`,不被包成一次订阅失败)。
- **缓存不是优化,是正确性**:`request` 一次最多 6 跳、每跳解析一次,`fulltext` 一轮 20 条跑在
  3 个线程里。**按域名缓存,不许按 URL** —— 按 URL 会让「每跳都重新解析」这条不变量当场失效
  (那正是挡住 DNS rebinding 的东西)。TTL 取答案自己给的,夹在 `TTL_MIN`/`TTL_MAX` 之间;
  **失败一律不进缓存**,一次网络抖动不该粘住十分钟。锁只锁查和写两下、不锁 HTTP 等待(同一
  域名撞上最多多问一次,锁着网络等待会把三个工作线程串成一条)。
- **起服务那条命令必须把「出口」这一族环境变量透传进去**(`scripts/web_env.sh` 的
  `build_web_env`,由 `kb.sh` source —— **拆出去是因为 `kb.sh` 顶到了 700 行那条线**,
  而「服务进程的环境怎么拼」本来就有自己的名单、理由和回归),
  **但别把理由记成「否则就没有出口」**。
  - `KB_FEED_DOH` 是**硬需求**:不透传的话服务里永远读不到它,上面那一层等于没有开关。
  - 代理那几个是**让出口变显式**。`env -i` 在 **macOS 上并不会**让抓取失去代理:httpx 的
    `trust_env` 走 `urllib.request.getproxies()`,它在 macOS 上读的是系统代理设置
    (SystemConfiguration)—— 环境变量清光了照旧拿得到。**Linux / 容器 / CI 上
    `getproxies()` 只看环境变量,那里 `env -i` 才真的把出口断掉**,而那正是开源交付要走
    的那条路。
  - **名单只有一份。** 形态是同一件事在两处各判一遍、只补了一处:装依赖那一步
    (`web_prepare_env`)一直在透传这一族、注释里还写明「这台机器上 pypi 常常得走代理」,
    而起服务那一行用的是裸 `CLEAN_ENV`。谁再手写第二遍循环就会复发。
  - **只透传出口这一族,不是整份 `KB_` 开头的变量。** `KB_DATA_DIR` 不透传是现状:把它放进来
    会静默换掉服务读的那个库,那是另一件事。
  - **空值不许透传。** 理由**不是**「httpx 会把空值当成配了一个代理」—— 那一条实测**不成立**
    (`urllib.request.getproxies_environment()` 跳过空值);理由是服务进程的环境该只有真正
    配过的东西,空壳变量会让「到底配没配」这个问题在排查时多一层噪声。
  - `WEB_ENV` 那段刻意不用 `mapfile`:macOS 自带的是 bash 3.2。
  - **配了端点却一个代理都探不到时打一行提示,提示而不代劳**(口径同 `code_stale`
    / `graph_stale`)—— 那种配法下端点多半也连不上,而后果是每条订阅都报「解析服务不可用」。
    **这一行的内容全在 Python 里**(`egress.summary()`),shell 只负责把它打出来,见下一节。

### 出口配置的入口:页面为主、环境变量兜底

方向是仓库主人在 demo(`docs/demo/resolver-settings.html`)上定的 **B / C / F**:只存设置、
保存即生效、代理也可配。下面这几条是它的硬约束。

- **设置优先,环境变量退成兜底**(`kb/feeds/egress.py`)。**注意这和 `kb.llm` 的 key /
  base_url 方向相反** —— 那边环境变量压过文件。两处不同是知情的:key 常由运维注入、不该被
  一份文件悄悄改掉;而出口这几项是人在页面上按网络状况随手调的东西,**页面说了不算就等于
  这个入口是假的**。两个方向**各要有一条回归**:只钉「设置压过环境」的话,把读取写成
  「只读设置」也全绿,而那会让容器和 CI 那条路直接失效。
- **口径只有一份,所有消费方都过 `egress`。** 已经踩过的两处:
  - shell 再自己判一遍 `[ -n "$KB_FEED_DOH" ]` 的话,「设置里填了、环境变量没填」会打
    「关」,而服务其实开着 —— 所以 `scripts/web_env.sh` 只负责把 `egress.summary()` 打出来,
    一个字都不自己判(`tests/test_egress_env.py` 用词边界数了一遍:那两份 shell 的**代码行**
    里每个变量名只许出现一次)。
  - 前端自己写一份环境变量名的话,代理那一族有四个候选,猜不出是哪个在兜底 —— 所以
    `view()` 把**出处整句**(`where`)给出去,`egress.js` 只负责显示。
- **每次取值都读一遍盘,不在进程里固化**:这是「保存即生效」的全部实现。**保存那一侧还要
  顺手清解析缓存**(`invalidate()`)—— 不清的话旧答案最多还粘 10 分钟(TTL 上限),人会以为
  新端点没生效。
- **代理只脱敏密码位,主机端口照旧回传。** 整条藏起来的话,人改一次端口就得把密码重输一遍。
  回传 `user:***@host:port`,写回来时带着 `***` 就按「这一位没改」处理 ——
  **`save()` 必须先 `merge_proxy()` 再 `check()`**,顺序反了或漏了那一下,存进盘的密码真的
  就变成 `***`,而人要等下一次抓取失败才发现(实测红过一条)。
- **「测一下」用还没保存的值,靠一层 ContextVar 覆盖**(`using()`)。**不许用模块级变量**:
  那会让人点一次测试就把正在跑的那一轮采集换掉,而面板上看不出来。覆盖**进出各清一次缓存**
  (缓存键里只有端点和域名,代理不在里面)。**这颗按钮不写盘**。
- **探测走 `fetching.public_addresses`,不另写一份。** 另写一份的后果是「测得通、抓不到」
  成为常态,而这颗按钮存在的理由正好是回答「到底哪一步给错了」。**端点留空也值得测**:
  那一下走系统解析,正好把本机被污染这件事摆出来。
- **坏值在保存之前拒掉,并带上是哪一项**(`BadValue.field`)。400 的 **`detail` 必须还是
  一句话** —— `ui.js` 的 `apiFail` 只认字符串,给它一个对象那句话会被静默换成「保存失败」;
  字段名单独一个 `field`。前端按它就地红字(项目约定:字段级校验不用 toast)。
  **反过来钉一边**:后端没说是哪一项的失败照旧走 toast,否则那句话谁也看不见。
- **前端读 400 的 body 要先 `clone()` 再交给 `apiFail`。** `apiFail` 里那一下 `r.text()` 把
  body 消费掉了,之后再 clone 拿到的是个读不出东西的壳 —— 后果是 `field` 永远为空、红字一条
  也落不到框下面(真页面探针红过这一条,单测看不见)。
- **弹窗标记由 `kb/static/js/egress.js` 现建**(`index.html` 顶着 700 行上限),所以它得自己
  往 `overlayClosers` 里报名:漏了报名不是「Esc 没反应」,是焦点被陷在弹窗里出不来。
  另外 `workspace.js` 的 MutationObserver 只盯**页面初始那批** `.modal-mask` 的 style 变化,
  所以这个弹窗只能**建了就 append、关了就 remove**,不能靠切 `display`。

### 本轮(审查第 1 轮)补进来的硬约束

- **主机名规范化在进查询之前一次做完**(`fetching.host_for_lookup`),两条路共用那一份。
  **地址字面量一个解析器都不许问**(DoH 会答 NXDOMAIN)。**名字的编码问 httpx 要**
  (`httpx.URL(...).raw_host`),不自己编 —— 详见下一节。判据是**翻开关不改变结果** ——
  从「能」变成「不能」是回归。字面量照旧过 `is_global`,SSRF 一分不少。
- **「答得不对」绝不许说成「确定没有」。** 这几种一律 `Unavailable`:`Answer` 不是列表、
  有地址记录但每条 data 都解析不动、任一族预算没跑完、任一族答不上。
  **只有「两个族都拿到明确答案、里面确实没有地址」才是 `Unknown`。** 顺序是**先看有没有
  拿到地址**:拿到了就用(哪怕只问到一个族),一个都没有时才谈够不够格说「没有」。
  反过来钉一边:**只有 CNAME 没有 A/AAAA 是正常答案**,不是故障。
- **缓存的是调用方留下来的那些,不是端点给的原样**(`keep`)。顺序反过来实测过:先答
  `127.0.0.1`(被 SSRF 正确拒掉)、再改答公网地址,第二次照旧报「未解析到公网地址」——
  被拒的答案进了缓存,把域名钉死最少 60 秒(TTL 上限 600)。
- **具体原因要带回面板。** HTTP 400 / HTTP 301(端点写成了 http://)/ 响应超限 / 超时 /
  预算用尽长同一句话的话,指不到该改什么。响应体有 `MAX_BYTES` 闸。
- **`KB_FEED_DOH_SECONDS` 配错在用到它的时候报,不在 import 的时候崩。** 写成模块级
  `float(os.environ.get(...))` 的后果:`=abc` 让 `import kb.feeds.fetching` 直接抛
  ValueError,开关压根没开也进不去。
- **测试进程里继承来的功能开关要在 `tests/__init__.py` 清掉**(`FEATURE_ENV`),不是只在
  `tests.tiers`:`python -m unittest tests.xxx` 那条路不经过 tiers。不清的后果实测是
  101 条既有传输/预算/准入用例红 27 条,红的全是跟 DNS 无关的东西 ——
  **看起来像这一版把整条抓取链改坏了**。名单显式,`KB_DATA_DIR` 必须留着。
- **出口告警的判据是真探测**(`urllib.request.getproxies()`,httpx 的 trust_env 走的那一份),
  不是「环境变量里有没有」:后者在 macOS 上是误报。
- **`code_stale` 要把被 source 的 `.sh` 也算进去。** 「`scripts/` 每次都是新起的子进程」
  那条只对 `.py` 成立 —— 被 source 的 shell 文件决定服务进程拿到哪一份环境。
- **容器那条路不经过 `kb.sh`**(`docker/entrypoint.py` 直接起 `kb-web`),所以透传在那里
  等于没有:出口变量要写进 `compose.yaml` 的 `environment`。

### 审查第 1 轮(自由工作流)打回来之后补的硬约束

- **问地址用的名字,必须就是连接时敲的那个名字。** `host_for_lookup` 现在问
  `httpx.URL(f'https://{host}/').raw_host` 要,不自己 `str.encode('idna')`:后者是老的
  IDNA2003,把德语 ß 映射成 ss,而 httpx 走 UTS46/IDNA2008 —— 实测 `faß.de` 一边编成
  `fass.de`、一边编成 `xn--fa-hia.de`,**那是两个不同的域名,可以属于不同的人**。这一层的
  全部设计是「解析出数字 IP,再钉着它 + 原主机名的 Host/SNI 去连」,两个名字错开就是
  **查 A 家的地址、敲 B 家的门**:证书对不上,面板上报「无法连接订阅服务」,而域名没毛病。
  **既有的两条不变量照旧**(实测):IP 字面量在上一档就返回了;纯 ASCII 不被收紧
  (httpx 只在非 ASCII 时才调 idna,63 字符以上的标签、`_dmarc` 这种都原样放过)。
- **面板上的预设端点名单归协议那一侧**(`resolve.JSON_API_PRESETS`,就在 `_read` 旁边),
  页面通过 `view()['presets']` 拿,**`egress.js` 里一个地址都不许写死**(回归按正则数)。
  判据不是「这家有没有 DoH」,是**它认不认 `_read` 发的那一种请求**:`?name=&type=` 加
  `accept: application/dns-json`。DoH 还有另一种协议(RFC8484 wireformat,`?dns=<base64>`),
  走同一个 `/dns-query` 路径、长得一模一样。实测:前端照着「这家有 DoH」列进去的
  `https://doh.opendns.com/dns-query` 只认 wireformat,点一下保存、下一次抓取当场 HTTP 400,
  面板上只剩一句「域名解析服务不可用」,人会以为是自己网络的事。
- **地址的形态判据只有一份**(`egress.check_url`),端点和代理共用,只有协议名单不同。
  分开写的那一版谁都没判端口:`http://h:99999` 一路存进 `secrets.json`,下一次抓取在
  `httpx.Client(proxy=...)` 那一行抛 `httpx.InvalidURL` —— **它不是 `httpx.HTTPError` 的
  子类**,`fetching.request` 那两道 except 一个都接不住,整轮同步 500、面板上一个字的原因
  都没有。注意 `urlsplit` 的两处坑:方括号没闭合时**当场**抛,端口越界要等读 `.port`
  (一个 property)才抛。所以**判对错走 `check_url`(抛 `BadValue`,面板就地红字),
  显示路径一律走宽松的 `_split`,一个字都不许抛** —— 存量里就是会有坏值,而人打开这个
  面板正是为了把它改掉。另外 `fetching.open_client` 把建 client 那一行的 `InvalidURL` /
  `ValueError` 翻译成 `FeedError`,给存量值兜底。
- **「谁说了算」的口径只有一份**(`egress._effective`):取值、来源分类、出处文案、交给
  httpx、合并密码位,五处全问它。各自判一遍实测出过两种后果 —— 出处判错(代理被说成
  `KB_FEED_DOH` 在兜底),以及**丢密码**:代理来自环境变量时 `merge_proxy` 只看设置里那份
  (空的),于是页面原样回传的 `http://me:***@h:1` 被当成「没有旧值可沿用」,密码位被抹成
  空串写进 `secrets.json`,把本来好用的出口顶掉。
- **页面回传的兜底值不落盘。** 页面显示的是**生效值**,人只改一格、把其余原样交回来是常态;
  照单全收的话环境变量那份就被复制进 `secrets.json` 固化下来,**运维再改环境变量不生效**,
  而面板上的值一模一样,看不出发生过什么。**真的没有旧密码可沿用时拒**(`BadValue`),
  不许把 `***` 猜成空串。
- **`mask_endpoint` 从 `hostname[:port]` 拼,不拿 `netloc`** —— netloc 里带着 `user:pass@`,
  而这个函数存在的全部理由就是别把凭证写进日志。**没写协议头的地址也要剪**(剪到第一个
  `/`,再去掉 userinfo):`urlsplit` 认不出那种地址的主机名,原样返回等于最该剪的一类一个字
  都没剪。
- **起服务/看状态那几行报的是「跑着的那个进程在用什么」**,不是当前 shell
  (`scripts/web_env.sh` 的 `service_env`,拿 `ps eww -p <pid>` 读)。服务可能是几天前、在
  另一个终端里起的,按当前 shell 算出来的答案会**精确地反掉**:你刚 export 了一个代理,
  状态里就写「出口代理:…」,而真正在抓取的那个进程里一个都没有。**读不到那个进程的环境
  时不许退回当前 shell**,打一行「只按设置文件算」。**不带 pid 调 = 刚用 `WEB_ENV` 把它起
  起来的那一下**,那份环境按构造就是服务的。
- **`Answer` 只有「根本没出现」才算合法的空答案。** 写成 `answer.get('Answer') or []` 的话,
  `{}`、`""`、`0` 这些**出现了、但不是列表**的假值会在那一行就变成空列表,绕过下面那道
  `isinstance` 判断 —— 实测四种畸形答案全报成「无法解析订阅服务器地址」,人被指去改一条
  没毛病的链接。**列表里混着不是记录的东西**(`["x"]`)同理是答得不对,不许逐条跳过。
  反过来钉一边:**缺这一栏 / 它是 null / 只有 CNAME,照旧是正常的空答案**。

## 事故形态与实测证据

一条 HN Buzzing 带出来的 `https://mistral.ai/news/voxtral-3/` 在面板上显示「订阅连接超时」、
`fulltext_tries=2`,正文是 feed 给的 45 字节壳(标题 + 域名 + HN 得分)。

用项目自己的通道(`fetching.request` → `fulltext.fetch_one`)复现并逐层拆开,下面这组数字是
**2026-10-22 那一刻的快照**(污染答案会变,别拿它当常量):

| 测法 | 结果 |
|---|---|
| `fetching.request(url, fulltext._HEADERS)` | `FeedError: 订阅连接超时`,12.1s |
| 逐 IP 看卡在哪 | 两个地址都是 `ConnectTimeout: handshake timed out`,各 6.0s(TLS 握手,不是 TCP) |
| `getaddrinfo` 给的地址 | `199.16.156.75`(Twitter 段)、`2a03:2880:f11c:…`(Meta 段) |
| 换解析器 | 系统/Tailscale → `108.160.173.207`(Dropbox);`@8.8.8.8` → `162.125.32.6`;`@223.5.5.5` → `31.13.94.41` —— 四个解析器四个假答案 |
| 真实地址(Cloudflare DoH,经代理) | `162.159.142.207`、`172.66.2.203`(Cloudflare) |
| 直连真实 IP + SNI,不走代理 | `ConnectError: Connection reset by peer`,1.2s / 0.3s(SNI 阻断) |
| 经代理 + 主机名 | **HTTP 200,585 227 字节** |
| 经代理 + 钉真实 IP + SNI(项目原样那套写法) | **HTTP 200** ← 钉 IP 的设计本身没问题 |
| 经代理 + 钉**污染** IP | 失败 ← **只给服务配代理不够,解析必须同时是干净的** |
| 跑着的 kb-web 整份环境(`ps eww`) | 8 个变量:`HOME PATH PORT UV UV_RUN_RECURSION_DEPTH VIRTUAL_ENV __CF_USER_TEXT_ENCODING __PYVENV_LAUNCHER__` —— 代理变量一个都没有(**但见下面「归因里曾经错的那一条」:这台机器上它照旧有代理**) |
| 两半都补上之后跑 `fulltext.fetch_one` | 正文 10 168 字、`why=''`、`grab_page.admit` 八道全过;`markup_size` 565 542 < `readable.MAX_HTML` |

**污染的第二种形态**:`buy-european.net` 被解析成 `127.0.0.1`,于是 SSRF 那道**正确地**把它
拒了,面板上报的是「订阅域名未解析到公网地址,已拒绝连接」。两句不同的提示,同一个病根 ——
这也是「换解析器不许顺手拆掉 `is_global`」的理由:它在污染之下仍然是对的。

**范围**:同一个库里 13 条「连接超时」几乎全是被墙域名。两半都补上之后复测,**6 条变成
HTTP 200**,余下 7 条变成有信息的真失败(付费墙 401、拒代理 IP 的 403、关卡页、404)——
这一层把「静默超时」换成「说得出原因」,**不治**付费墙、关卡和拒绝代理 IP 的站点。

## 归因里曾经错的那一条

第一版归因写的是「服务被 `env -i` 洗掉了代理,所以只会直连」。**那一半是错的**,而它会把
下一个人引到错的修法上(只补 `kb.sh`、不碰解析,然后以为修好了)。

决定性实验:`env -i HOME=… PATH=… python -c "import urllib.request; print(urllib.request.getproxies())"`
→ `{'http': 'http://127.0.0.1:7897', 'https': 'http://127.0.0.1:7897'}`。httpx 的 `trust_env`
用的就是 `getproxies()`,而它在 macOS 上读 SystemConfiguration 里的系统代理 —— 所以
**kb-web 一直是有代理的**。

于是真正的病根只剩一条:**钉出去的那个 IP 是假的**。而「经代理去连一个假 IP」能不能通,
取决于代理软件要不要按 TLS SNI 嗅探重路由、以及那个假 IP 落到哪条规则上 —— **所以它随机**。
同一轮实测里把四种组合各跑 6 次,四种全 6/6 通(含「无代理变量 + 污染 IP」);而同一个假 IP
在 `trust_env=False`(真直连)下是 6 秒握手超时、真实 IP 直连是 RST。库里的痕迹对得上这个
随机性:**同一个 `mistral.ai/news/` 下,`mistral-large-4` 那条补抓成功过(14 606 字节正文),
`voxtral-3` 这条连失败两次**。

**这也是为什么「连接超时」这句话不许当结论**:它既不说明对方拦着你,也不说明你没有出口 ——
它可能只说明你敲错了门,而那扇门是解析告诉你的。

**所以两半的分量不一样,别记反**:可信解析(`KB_FEED_DOH`)是真正把成败从「押在代理的嗅探
行为上」变成确定的那一半;`kb.sh` 的透传在 macOS 上对代理而言基本是冗余的(但对
`KB_FEED_DOH` 是硬需求),它的价值在没有系统代理概念的机器上 —— 容器和 CI。

### 第二条曾经写错的理由

第一版在 `web_env.sh` 和它的回归里写过「空值不透传,因为 httpx 读到空字符串的 proxy 会
当成配了一个空代理」。**实测不成立**:urllib 的 `getproxies_environment()` 跳过空值
(`HTTPS_PROXY=''` → `{}`)。不透传空值这个做法留着,但理由换成真的那一条 —— 服务进程的
环境里只该有配过的东西,空壳变量让「到底配没配」在排查时多一层噪声。

## 知情的取舍

- **`Unavailable` 照旧扣 `fulltext_tries`。** 更对的做法是不扣(「我这边的解析器坏了」不该消耗
  「对方拦着你」那份预算),但那要给 `fulltext._fail` 加一档、牵动 `queued_sql` 的 ③④ 那组
  硬约束 —— 那是另一块的事,不捎带着改。眼下的兜底是上面那条「提示而不代劳」:配了 DoH 却
  没有代理时起服务会说一句。
- **端点走环境变量,还没有面板入口。** 开源要能交付(反复要做的步骤该做进页面),但那是结构性
  的界面改动,按约定先给可点的 demo 再定夺。现在的出路是 shell 里 export + `./kb.sh web restart`。
