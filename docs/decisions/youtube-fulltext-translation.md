# YouTube：全文直译，不做字幕配音式对齐

2026-11-03 起，知识库需要的是完整、可读、可检索的中文资料，而不是与视频逐句同步的配音稿。
本决策替代此前的细段 JSON 对应、逐细段语言硬校验和三次失败后混合降级发布；
不改变发现窗口、视频数量和时长预算、字幕获取、原字幕时间覆盖检查、发布、导出或索引规则。

## 正常处理

1. 获取并校验完整原字幕。已有中文正文直接保留，不调用翻译模型。
2. 通常把全文一次交给 `translate` 阶段模型，直接返回中文正文，不要求 JSON 或逐句对齐。
3. 为控制已有请求的输入／输出体量，超过 12,000 字符时按自然句段切成少量大块。
   这是保守的字符上限，不是模型能力探测或精确 token 计算；现有输出上限和正常结束检查继续生效。
4. 标题单独翻译，失败可以保留原题。标题和正文共用原有全进程三席限流、超时、取消和熔断机制。
5. 按原文顺序拼接译文，并保留原文对照、字幕来源及未做人工事实核查的提示，不另行摘要或合稿。

## 检查和失败处理

- 模型请求必须正常结束；截断、拒绝、非正文或空响应仍被拒绝。
- 正文仅做基础异常检查：非空、有中文、不是原文照抄；源文至少 200 个字母／汉字时，
  译文字母／汉字不足源文的 10% 视为异常短结果，等待重试。
- 不再按细段条数、中文比例或英文单词数否决译文，允许正常技术术语和英文引用。
- 这些是异常检查，不是逐句语义审校，不能保证没有漏译、误译或事实错误。
- 一个请求失败不再拆成 450 字符小段继续请求；保留已完成大块缓存，由原候选失败／退避机制重试。
- 不再生成新的 `mixed-fallback`、`original-fallback` 或 `translation-fallback` 正式成品。
  未完成的正文保留原字幕和缓存，候选显示失败待重试，不伪装为完整中文成功。

## 缓存与已有数据

新正文和标题分别使用 `translate-fulltext-v1`、`translate-fulltext-title-v1` 缓存标识，
按原文、模型和版本隔离；不把旧 JSON 缓存直接当作普通文本使用。
旧完整大块在原校验通过、且能完整覆盖新块时可以只读复用；不从部分中文与未译原文拼出新成品。
旧细段缓存、语言失败计数文件和原字幕均不删除，也不再因旧三次计数触发降级。

已有正式条目不自动重翻、不批量重写；此前 74 篇完整译文和已标记的 1 篇混合降级版保持原样。
历史混合版仍是未解决项，只有明确重试并成功生成中文正文后，才可更新同一正式条目。

## 实现与覆盖

- `kb/youtube/fulltext.py`：全文提示词、请求体量上限与基础异常检查。
- `kb/youtube/notes.py`：缓存迁移、并发翻译、拼接；旧结构化翻译工具仅用于兼容既有缓存及历史调用。
- 改动测试覆盖全文单请求、容量分块、缓存复用、英文术语／引用、失败不降级、正常发布恢复，
  以及原并发、取消、超时和熔断行为。只执行本轮改动的测试文件；全套回归留待验收。
