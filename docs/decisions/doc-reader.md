# 文章阅读页的正文渲染(kb/web/pages.py 的 /doc/)

> **这一份整份都是这一块的记录:硬约束 + 事故形态、实测证据、回归清单和反向验证红数** ——
> 动这块代码之前先读它。CLAUDE.md 只留跨块的元规则和一张索引。

- **副标题那个外链一律写「原文」,不许写来源的名字。** 这页最早只有公众号文章,文案就写死成了
  「绿泡泡原文」—— 而 vault 里现在有九个原始来源,于是一条 GitHub Trending 的 RSS 条目在阅读页
  上也写着「绿泡泡原文」,点过去是 github.com(2026-10-17 实测,用户在日报的译文抽屉里撞见)。
  **也不许改成按来源分支写几套文案**:那是在这一页**再立一份来源名口径**(人话标签那份在
  `kb.daily._SOURCE_LABEL`),下一个新来源照样会漏;而站内另外两个入口本来就只写「原文」
  (`index.html` 的 `reader-src`、订阅阅读器的「打开原文」),这里跟上就行。
  回归 `tests/test_reading_literal.py` 的 `DocPageOriginLinkTests`,**两种来源各一条** ——
  只验 RSS 那一条的话,"按来源分支"的实现照样全绿(定点注入:写回「绿泡泡原文」红 2 条;
  只给公众号写「绿泡泡原文」红 1 条)。
- **vault 里文章正文按契约已经是纯文本,所以正文里剩下的尖括号一律按字面文字显示**
  (`_DOC_LITERAL_JS`:`marked.use` 把 html token 转义掉)。RSS 走
  `kb/feeds/fetching.py` 的 `plain`/`body_text`、公众号走它自己的转换器,两边都把标签
  剥干净了 —— 于是正文里剩下的 `List<T>`、`<dependency>`、`<system-reminder>` 全是作者
  写在文章里的示例文字,没有一处是要渲染的标记(实测 2.58 万篇 vault md 里 39 篇正文
  带着**代码围栏之外**的这种示例:38 篇公众号 + 1 篇 RSS;围栏里的 marked 本来就当代码
  显示,wiki/daily/index 一篇裸 HTML 都没有)。
- **原来这些字在阅读页上直接消失,而同一篇在订阅面板上是完整的。** marked 默认把它们
  当原始 HTML 交给 DOMPurify:`Use List<T>` 显示成 `Use List`(`<T>` 当未知标签被吃
  掉)、整段只有 `<script>alert(1)</script>` 的那篇**正文一片空白**(净化器删得对,只是
  那本来不是脚本)。订阅面板的展开阅读用 `textContent`(`sources.js` 的
  `renderSourceReader`),同一份正文在那边一个字不少 —— **换个阅读入口内容就少一截**
  (2026-10-08 第 3 轮审查两种样本各实测一次)。
- **不是关掉净化,DOMPurify 照旧过一遍。** 改的只是「原始 HTML 怎么渲染」:html token
  转义成字面文字,于是压根没有原始 HTML 送到净化器面前,比原来更严。代价是正文里真有
  一段想渲染的 HTML 时也只显示文字 —— 那正是要的:上面那条契约说它不该存在,而「示例
  文字静默消失」比「示例文字照显示」坏得多。
- **不许改成「渲染前把整份 md 里的尖括号先转义掉」。** 那一刀落在 markdown 解析之前,
  **代码围栏里的内容是字面量**:`&lt;script&gt;` 会原样显示成这五个字符,照着复制的命令
  当场是错的(回归里那条围栏用例就是钉这个,注入这版当场红)。转义必须发生在 token
  层,只对「被认成原始 HTML」的那一段生效。
- **不许改成在导出那一侧转义**(`sync.export` 写 md 时)。md 是事实来源:索引/FTS 读的
  就是它,写成 `List&lt;T&gt;` 之后全文检索 `List<T>` 再也命中不了;而且那只覆盖 RSS
  一个导出器,公众号那 38 篇照旧坏着。阅读页这一侧改一次,存量和未来、两个管道一起好,
  不动一个字节的 md、不碰 `content_hash`、不触发重译重导出。
- **只改这一页。** `kb/static/js/core.js` 的 `mdHtml` 渲染的是模型写的 markdown(问答
  回答、日报正文)和条目正文,不是剥过标签的文章原文;而且日报出处链接那套裁决器
  (`kb/daily_refs.py`)的方言是按它逐位对齐的(`html=True`),动它等于让那份对齐失效。
- `renderer.html` 的入参 marked v12 给的是字符串、v13 起给 token 对象,两种都接住 ——
  拿错了是抛异常、正文整个空白。
- **正文是嵌进页面内联 `<script>` 的,所以那份 JSON 里的 `<` 一律编码成 `\u003c`**
  (`_script_json`,`md_json` 和 `path_json` 共用它),**不是只防 `</script>` 那一种写法**。
  HTML 的脚本数据状态里,`<!--` 之后再出现 `<script` 会把分词器推进「双重转义」:那之后
  的 `</script>` 只把状态退回一层、**不结束这个 script 元素**,于是页面末尾的
  `</script></body></html>` 全被当成脚本内容吞掉 —— **整段脚本一行都没执行**:`MD` 没
  定义、上面那个字面 renderer 没注册、正文渲染、纯文本降级和片段收藏全都没发生,阅读页
  **只剩标题**。实测一篇正文写着 `示例开头写 <!-- <script>。` 的纯文本文章,连它后面那个
  普通段落一起看不见,而同一篇在订阅面板上是完整的(2026-10-08 第 4 轮审查)。
  **放进 markdown 代码围栏里不管用** —— 故障发生在 markdown 解析**之前**(HTML 文档的
  内嵌 JSON 那一层),围栏保护不了它:一篇 `html` 围栏里只写 `<!--` 换行 `<script>` 的
  文章同样整篇空白,代码块后面的普通段落一起没了。`<` 全编码掉之后分词器再也离不开
  脚本数据状态,原来那条 `</` 特判被它涵盖;`\u003c` 是合法的 JSON 转义,`JSON.parse`
  回来还是同一个字符串,md 一个字节不变。
  **同形状但本轮没动的是两张图谱页**(`scripts/wiki/catgraph_page.py` 只防 `</`、
  `scripts/wiki/build_graph_html.py` 一个字都没防),它们内联的数据里也有文章标题和项目
  简介这类外部文本 —— 不在本任务的正文保真链路上,而且改完要重建产物才看得出来
  (`./kb.sh graph`,从 worktree 跑会拿空库覆盖好页面),所以留着没碰。
- **判据不能只是「md 文件里能找到这串字符」**:那一关原来就是过的,丢字发生在渲染。
  回归在 `tests/test_reading_literal.py`(真起一个沙箱 kb-web + 无头浏览器,27 项):
  三条正文带字面标签的条目真走 `put_items → sync.export → kb index`
  (`tests/serve_reading.py`),然后在订阅面板展开阅读、再打开同一篇的 `/doc/` 页,比的是
  **两边的可读内容逐行相同**(空白规则本来就不同,比的是有没有少字);外加段落结构没塌、
  正文里没有可执行的 script 节点、innerHTML 里没有裸标签、**整段内联脚本真的跑到底了**
  (`typeof MD === 'string'` 且 `#snipbtn` 挂上了 —— 它排在渲染之后,脚本被吞掉时第一个
  消失的就是它)、**围栏里写着脚本开头的那篇照旧按代码显示且后面的段落还在**,以及反向
  那六条**正常 markdown 照旧渲染成元素**(标题/列表/外链/行内代码/围栏/表格)。另有一条
  不要浏览器的早期信号(`EmbeddedJsonTests`:序列化出来不许留裸 `<`、`json.loads` round-trip
  不变)。反向验证定点注入过三版:整条字面策略退回旧版红 4 条(红的正是第 3 轮审查报告里
  那两份证据 —— `新 API 使用 List。` 和正文 `"\n\n"`)、换成「整份 md 预转义」红 1 条
  (围栏里的示例变成 `&lt;script&gt;`)、**内联 JSON 退回只防 `</` 红 11 条**(6 条浏览器
  行为 + 5 条序列化,红的正是第 4 轮那两份证据 —— `#content` 是空串、`typeof MD` 是
  `undefined`)。
