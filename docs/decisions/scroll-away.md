# 读正文时让出位置:往下滚就把上面那条工具栏收起来

> **这一份的第一节就是这一块的硬约束(不许怎样)—— 动这块代码之前先读它**,
> 后面是落点的取舍、事故形态、实测证据和回归清单。CLAUDE.md 只留跨块的元规则和
> 一张索引。硬约束和下面的展开**说的是同一条口径,要改规则两边一起改**。
>
> 代码:`kb/static/js/scrollaway.js`(机制)、`kb/static/css/base.css` 的
> `.scroll-away` 与 `.away-exit`(过渡、收起态、常驻退出控件)。四处接入各一行:
> `source_reader.js` 末尾(订阅页)、`core.js` 的 `bindReaderScrollAway()`(文章
> 阅读器)、`gallery.js` 的 `openToolDrawer()`(工具详情抽屉)、`fav_view.js` 的
> `renderFavInspector()`(收藏详情);对账挂在 `sources.js` 的
> `applySubsReadingLayout()` 和 `updateSourceNotices()` 上。

## 硬约束

- **收起只认用户自己滚的那一下**(滚轮 / 触摸 / 键盘 / 拖滚动条),程序改
  `scrollTop` 不算。违反之后的形态是**按钮点不中**:这一页到处在改 `scrollTop`
  (换一篇写回 0、从「订阅管理」切回阅读时恢复上次停在哪儿),后一种会被当成
  「他正在往下读」,工具栏当场收起,而用户手都没动过、紧跟着要点的那颗按钮恰好
  就在收起的那块里。
- **这道门认的是「手还按着没松」,不是「最近若干毫秒有过动静」。** 按住原生滚动
  条慢慢往下拖,这一分钟里手一直在上面;按时间窗算的话过了窗口就判成「程序在
  滚」,工具栏**再也收不起来**(实测:按住 1000ms 再拖 120px,正文从 500 长到
  1744px 而工具栏纹丝不动;同样距离快速拖就正常收起)。所以 `pointerdown` 置
  `holding`、`pointerup`/`pointercancel` 收敛,时间窗只留着接松手之后的惯性,
  松手事件要挂顶层(拖着滚动条甩出元素外也得收得到)。
- **放出来不设这道门** —— 那个方向永远安全,换文章时正该靠它自动展开。所以手势
  判据**只能写在收起那一支上**,不许写成 tick 开头的提前 return:那样写等于连
  「超过窗口的向上展开」一起挡掉了。
- **收起之后必须还滚得回来。** 收起让滚动容器变高、可滚距离跟着变短;短到比收起
  的那一块还少时,浏览器会把 `scrollTop` 钳回去,那一下是**一次向上的滚动事件**,
  于是展开、容器变矮、又能往下滚 —— 来回抖。所以收之前问两句:整条轴够不够长
  (`AWAY_ROOM`)、此刻离底还有没有收起那么多(`AWAY_FLOOR`)。**两问缺一不可**:
  前者管「这篇太短、收了也没意义」,后者管「已经读到底了」。
- **方向要累计着看**(`AWAY_STEP`)。触控板和惯性滚动一帧里正负都有,单看一次
  delta 会在边界上反复横跳,看着像页面在抖。
- **只绑正文那一条滚动轴。** 内容列表(`#source-list-pane`)自己滚的时候不收 ——
  那不是在读。
- **收起态要留着 `overflow:hidden`,展开之后那条 inline `overflow` 必须撤掉。**
  来源工具栏里挂着一块绝对定位的状态浮层(`.source-notices-body`,`top:100%`),
  不裁的话它会从一条高度为 0 的工具栏底下冒出来;而常驻 hidden 又会把**展开态**
  的浮层也裁掉,那才是真丢信息。
- **收起态要跟着收掉 padding、上下边线和 min-height**,不能只把 `height` 压到 0。
  `box-sizing` 是 border-box,只压 height 的话内边距和那条底边线仍占着十几二十
  像素;而各面板自己给工具栏定的 `min-height`(`.subs-mode .source-heading` 是
  60px)会直接把 `height:0` 顶回去。`base.css` 里那条选择器**要带上 `body`**:
  面板规则跟 `.scroll-away.is-away` 同特异性、而且排在 base 后面,不抬一级压不住。
- **收起的东西要 `inert`。** 里面是按钮和输入框,高度为 0 不等于走不进去 ——
  Tab 照样停在看不见的控件上。
- **阅读区不在页面上时一律瞬时复位,不走动画** —— 不然那条工具栏停在
  `height:0 + inert` 上,切回正文视图它还是那样,整条谁都点不着。
  **这条不许押在「某个按钮记得调一下复位」**:「只看列表」(`expandSourceList`)和
  窄屏「返回列表」(`backToSourceList`)只切 class、根本不经过布局函数,挨个打补丁
  必然漏。不变量落在元素自己身上 —— 每条轴绑的时候挂一个 `ResizeObserver` 盯着
  自己,被 `display:none` 时尺寸归零就当场复位。隐藏元素量不出高度,动画只会留下
  一个半截的 inline 高度跟着跑到别的视图上。
- **要人处理的告警不许被收走。** 订阅页收起的那块里装着「读取失败 + 重新读取」
  (`#source-error`,`role="alert"`):落进 `inert` 子树就等于这条消息没送到人跟前。
  所以有 `role="alert"` 摆着时**既不许收、已经收了的要放出来**,闸在
  `scrollAwayBlocked()` 里判一次,由 `updateSourceNotices()`(所有提示状态的汇合
  点)拨。**反过来钉一边**:同一块浮层里的进度和待配置是 `role="status"`,那两类
  不该把工具栏钉死在展开态。
- **收起不许把退出这一处的唯一入口一起收走。** 文章阅读器、工具详情抽屉、收藏
  详情的那条头里就只有标题和关闭/返回。收起时在 `opts.host` 上打
  `has-scroll-away`,右上角那颗 `.away-exit` 顶上 —— 判据是**点它真能退出去**,
  不是「它的 display 不是 none」(收起态那块是 `inert` + `opacity:0`,只看样式
  分不出来)。收藏那一颗**不许带 `fv-icon-button`**:`#favpanel .fv-icon-button`
  特异性 (1,1,0) 压得过 `.away-exit`,带上它收起之前那颗按钮就一直摆在那儿。
- **自己改的那点高度不算用户在滚。** 收起/展开会改变滚动容器里的内容布局,浏览器
  为了让视口里那段文字别乱跑会补偿 `scrollTop`(scroll anchoring),补偿方向正好跟
  收起相反。**这一档只有收起目标落在它自己那条轴里面时才出得来** —— 四处接入里
  只有收藏详情是这样,另外三处的目标都在轴外,所以「它们能通过」证明不了收藏也
  能通过。两件事都要做,缺一个都还在抖:
  - **换一把不受自身收起状态影响的尺子**,所有位置判据用它:`scrollAwayPosition()
    = scrollTop + 此刻被自己收掉的轴内高度`。只吞事件不够:收起 57px 的头,补偿
    正好把 `scrollTop` 从 120 压到 63 —— **低于 `AWAY_ENTER`**,平息期一结束,
    「回到顶部一律放出来」当场触发,展开又反向补偿回 120,这是一组**双稳态**,吞
    多久都会在那一下炸开。加回收掉的那份高度之后这个数在收起前后恒定(120 → 63,
    加 57 还是 120),方向累计和「回到顶部」两条判据从此有共同的参照。
  - **平息期**:改完高度之后那一小段(`AWAY_MS`)只跟着记位置、不改判 —— 动画
    **跑的过程中**高度是渐变的,而收掉的高度按整份算,那几帧仍然对不齐。平息期
    一完按真实位置补判一次:期间的事件都吞了,用户要是在那会儿停在了开头、或者
    换了一篇,不补判就没有下一次 scroll 事件来把这条头放出来。
  **别去猜「这一截位移是不是补偿」。** 按方向 + 时间窗 + 幅度上限估一个「自身补偿
  量」看着也能把震荡压住,但那三样都证明不了因果:平息期里用户真的反向滚了、换一
  篇把 `scrollTop` 写回 0,统统满足同一组条件,于是被当成自身补偿攒进去 —— 而且
  **一趟趟累积**(收藏往返三次:57 → 104 → 161,可那条头一共才 57px)。攒过
  `AWAY_ENTER` 那条线之后,快速滚回开头、或者紧接着点下一篇,整条工具栏就再也回
  不来了。
  事故形态:单次 120px 滚轮之后停手,1049ms 内方向反转 9 次,那条头在 29.7~57px
  之间抖,最后一点没收起来。
- **只有轴内的目标算进那把尺子,轴外恒为 0**(绑定时 `axis.holds(el)` 量一次)。
  轴外的那块收起时根本不动 `scrollTop`,把它那份高度也加进去,位置就凭空多一截。
  这一档在当前几何下**构造不出可观测的差别**:轴外收起不改 `scrollTop`,所以「回到
  开头」一定伴随一次大的反向位移,方向判据先于位置判据把头放出来 —— 定点注入
  「一律按轴内算」红 0 条,想过了,是场景不可达,不是用例不敏感。留着是因为这把
  尺子的定义本身要求如此,头再高一点、或者 `AWAY_ENTER` 调小就会显形。
- **轴要跟着断点选。** 收藏详情 760px 以下是 `max-height:none; overflow:visible`,
  用户滚的是整页;还照桌面那条轴绑的话它的 `scrollTop` 和可滚距离都是 0,一下都
  收不起来,而那条 sticky 的头会一直占着屏幕上方一行。所以绑的时候按
  `matchMedia` 选 window 还是元素,**断点一变重绑一次**;可见性参照一律给
  `.fv-detail` 自己(window 永远「在」)。窄屏那颗常驻返回按钮也要跟着改成
  `position:fixed` —— 整页滚动时 absolute 会跟着内容滚出视口。
- **「要人处理」由状态自己声明,闸只认一种角色。** 手动收录那条持久提示
  (`#grab-hint`)平时是普通说明,落到 `failed` / `pending` 才标上 `role="alert"`
  (在 `updateGrabControls()` 这个唯一汇合点),然后对一次账。**进行中和成功态不标**
  —— 那几档不该把投递栏永久钉在展开态。违反之后的形态:投了一条、接着往下读,
  慢回包返回 400,短暂 toast 过几秒就没了,而那句「这条没存下来」躺在
  `height:0 + inert` 的投递栏里,一个字都到不了人跟前。
- **「这条告警在不在页面上」要自己量盒子,不能只问它的 `hidden`。** 投递栏是跟着
  来源整条 `display:none` 的,而里面那句上一轮的失败提示自己并没有 `hidden`、角色
  也还挂着 —— 只看 `hidden` 的话,收录失败过一次之后,大V观点 / RSS / 简报 /
  网页专栏读长文时工具栏**全都收不起来**(四处实测)。判据是
  `getClientRects().length > 0`:它**包含**了原来那道 `hidden`(`hidden` 就是
  `display:none`,盒子为空),而**被收起的那一块照旧量得出盒子**(`height:0 +
  overflow:hidden` 不改布局盒),所以「收起之后新来的告警要放出来」一字没变。
- **「对账」和「一刀切复位」是两回事,别混用。** `applySubsReadingLayout()` 后台
  同步完一轮也会走到,在那儿一刀切复位就是「读着读着工具栏自己弹回来」(实测收起
  约 4.6s 后恢复,正文从 886 缩回 826)。那里要调 `syncScrollAway()`:阅读区还在、
  也没有告警要处理时,收起态原样留着。`resetScrollAway()` 只留给「量过的高度整批
  作废」那一类场合(窗口尺寸变了)。
- **高度只能由 JS 量了写进 inline。** `height:auto` 做不了过渡,得给具体的起点和
  终点;展开动画跑完要把 inline 那几条撤干净,元素回到自然布局 —— 之后窗口折行、
  提示文字变长变短都不用谁来同步。窗口尺寸一变直接复位(重新量不如复位稳,用户
  接着往下滚一下就又收起来了)。

## 装在哪四处,为什么是这四处

判据是**正文自己占一条滚动轴、而轴上面那条头固定不动**。整页滚动的面板(每日
日报、全文检索、同步中心、工具图鉴列表)页头本来就跟着整页滚走,一个字都不用改。

| 阅读区 | 滚动轴 | 收起的那块 | 退出入口 |
|---|---|---|---|
| 「我的订阅」阅读区 | `#source-reader-scroll` | `#source-head` + `#grab-bar` | 列表就在旁边,不用常驻 |
| 文章阅读器 | `#reader-frame` 的 `contentWindow` | `#reader-head` | `#reader-exit` |
| 工具详情抽屉 | `#td-scroll` | `.td-head` | `#td-exit` |
| 收藏详情 | 桌面 `.fv-detail` / 窄屏 `window` | `.fv-detail > .fv-aside-heading` | `.fv-detail-exit` |

- 订阅页是收益最大的一处:阅读区高度锁在可用视口上(`body.subs-reading`,来由见
  [`subs-layout.md`](subs-layout.md)),页头每多一行正文就少一行,而它上面顶着
  来源工具栏(60px)加手动收录那一类的投递栏(95px),一共 155px,滚不动也挤不走。
  六类来源(公众号 / 大V观点 / RSS / 简报 / 网页专栏 / 手动收录)共用
  `#subs-feeds > #source-head`,装一处就全覆盖;专注阅读和窄屏单栏阅读走同一条
  轴,自动生效。**这一处不加常驻退出控件** —— 内容列表一直在旁边,工具栏不是
  退出的唯一入口。
- **文章阅读器那一条轴在 iframe 里**(同源的 `/doc/`)。所以绑的是
  `contentWindow`、手势听它那份 `document`,而「这块还在不在页面上」得看 iframe
  元素自己 —— 跨文档量不着。iframe 每换一次 `src` 都要重绑,`closeReader()` 解绑。
- **收藏详情每次重绘都是新 DOM**(`renderFavInspector()` 整块重写 innerHTML),
  绑定跟着渲染走,渲染前先 `release()` 上一份,否则监听和 `ResizeObserver` 会越
  积越多。
- **收藏详情是唯一「要收的那条头在它自己轴里面」的一处**,滚动锚定那一档只在这里
  出得来(见硬约束);它也是唯一在断点上换轴的一处(桌面内部滚、窄屏整页滚)。
- 后三处的头里就只有标题和关闭/返回,所以收起的同时必须把退出控件留下(见硬约束
  那一条)。

## 实测形态

- 1440×1000、手动收录那一类:收起前正文滚动区 728px,收起后 886px —— 让出来的
  158px 全给了正文,一屏多出四五行。
- **「程序滚动也当成他在读」那一档不是推演出来的**:手势门还没装的时候,整趟订阅
  页探针当场断在既有检查 `subs_usability_checks` 的第 41 行 —— 它前一步把
  `$('source-reader-scroll').scrollTop` 恢复到 180(模拟「从管理切回阅读」),工具栏
  跟着收起,紧接着那次 `click('#source-view-manage')` 落在了高度为 0 的元素上,
  视图没切过去,后面一串检查连环超时。把那句门加回去,整趟恢复全绿。
- 失败点会飘:同一处缺陷两次运行分别断在 usability 和 editor-views 两段,**不要
  按「这次断在哪」归因**,拿基线 worktree 跑同一组对照。

## 回归

三份,都接在 `tests/subs_layout_probe.mjs` 上(入口 `tests.test_subs_layout`;这
四处在同一个单页应用里,切 tab 就到):`subs_reader_checks.mjs`(收起本身)、
`subs_reader_guard_checks.mjs`(退出路径 / 告警出口 / 手势门 / 后台重绘)、
`reader_scroll_away_checks.mjs`(另外三处阅读区)。判据一律钉在**后果**上:阅读区
实际多拿到多少高度、放回来之后是不是真回到原样、该拦的那几档拦没拦住 ——
不验「类名加上没有」。
收起和展开走**真滚轮**(`Input.dispatchMouseEvent` 的 `mouseWheel`),证明真实手势
走得到;两道「滚得回来」判据的位置靠程序摆、再补一次小幅真手势触发判断,因为那两
档的射程全在精确的 room 和 top 上。

- **夹具自己也要钉一句。** 那两档要把可滚距离摆到 200 / 600,而摆的办法**不能是
  「把正文压成 0 再量 `scrollHeight`」** —— 内容比视口矮时 `scrollHeight` 会被
  `clientHeight` 兜底,量到的是视口高度不是内容高度,照它算出来的 room 全错(要
  600 实际拿到 20),于是那一档变成一条**不敏感的绿**。改成先撑到一定滚得动的高度、
  量出此刻的 room、再按差额回调,并把「摆到位了没有」单独 check 一次。
- **反向各钉一边**:滚内容列表不收、程序恢复阅读位置不收、太短不收、贴底不收,
  配一条「同一篇在中段照收不误」压着,别为了防抖把正常收起也吃掉。
- 投递框的焦点环那条也在这一份里(`checkGrabInputFocus`):
  `tests/redesign_probe.mjs` 第 8 节钉的是检索页和图鉴页那几个框,够不着订阅页里
  这一个 —— 它正是漏在外面、长出「双眼皮」的那一处,口径见
  [`link-grab.md`](link-grab.md) 硬约束一节。

- **撑高夹具不能用空白盒子。** 滚动锚定要有**文本节点**要保位置才会去补偿,拿一个
  `height:2400px` 的空 div 占位,「自身布局反馈」那一档就是一条不敏感的绿 ——
  连滚六次最终状态碰巧对了,而单次滚动停手时它一直在抖。收藏那一处的夹具用真实
  段落,判据是**一次滚轮之后停手、隔开一秒多采两次**:抖的话不可能两次都正好是 0。
- **窄屏那一支的滚轮坐标要取元素跟视口的交集中心。** `.fv-detail` 在窄屏比视口高
  出好几屏,它自己的中心落在视口外,滚轮一下都发不进去。
- **「看得见」不能用 `getClientRects()` 判。** 收起态是
  `height:0 + overflow:hidden + opacity:0 + pointer-events:none`,而
  `getClientRects()` 对这几样一概照旧非空 —— 拿它当判据的话,「报错被收走了」
  也是一条绿(撤掉告警闸的注入下一条都不红)。换成命中测试:那颗按钮在它自己
  中心点上是不是最顶层的东西。
- **一条轴上连着做几组,每组之前要复位。** 「判位置的尺子带了状态」这一类缺陷,
  前一组攒下的东西会让后一组从收起态起跑,于是后一组变成一条不敏感的绿 —— 实测
  同样两条检查,换个先后次序红的就换了一条。派一次 `resize`(那条路会把这条轴整个
  复位)再补一句「前提 —— 这一组从摊开态起跑」。
- **判「会不会累积」要做两趟。** 攒出来的量单趟顶多一整条头(57px),还差一点到
  `AWAY_ENTER`(64px),只做一趟就是一条过不了线的绿。
- **探针里的 `wait` 等不到会抛,整趟当场结束。** 那样注入验证看到的是「一条都没
  红」,跟「用例不敏感」分不开 —— 要验的那一步用定长等待,把结论交给 `check`。
- **滚轮坐标现算,不许写死。** 这一组里有一段把视口压到 720 宽验窄屏,写死的
  x=1150 落在视口外,滚轮一下都发不进去,而后面那几条照样跑完。
