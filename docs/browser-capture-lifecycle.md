# 补抓条目状态与多标签恢复

## 生命周期约束

- 服务端按文章 key 返回当前待办和最近一条有效审计回执。页面不再以 `sessionStorage` 中的请求 id 作为唯一把手，关页、换标签及重新采集后改主意都不丢回执。
- 单进程内同一文章只保留一个 pending；在锁内比较正文版本、来源、原网址及指定最终网址。匹配则复用原请求和有效期，不匹配则将旧请求标为 `superseded` 后创建新请求。不同文章仍独立排队，100 个 pending 的总限额不变。
- 应用端可看到本篇待办的发起时间、到期时间和网址，并通过已有同源取消接口处理。扩展下拉也显示发起时间；没有把扩展的全局待办接口开放给普通网站。
- 已保存请求无论命中内存还是从审计恢复，均使用 `saved()` 校验当前条目状态、来源、修订号和正文摘要。页面每两秒重新查询条目状态；旧回执失效时隐藏成功区域、禁用继续按钮并给出原因。
- 进入重新采集模式不撤销正文或回执，退出该模式也不清审计。重新采集过程中旧正文仍有效；新请求等待时先完成或取消它，再继续该来源后续处理。
