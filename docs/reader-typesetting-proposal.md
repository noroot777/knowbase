# 阅读区精排方向（方案，尚未实现）

本轮已实现 Markdown 优先采集与翻译代码块保真。本页只记录其他文章的后续设计方向，不表示页面已改版。
取得 Markdown 不等于复刻来源网站的全部效果：内嵌 HTML 仍沿用字面显示的安全规则，相对资源地址与 Mermaid 等扩展需要后续单独适配。

## 推荐：按内容精排，而非统一换皮

普通文章采用安静的长文阅读版，README / 教程采用文档版；短动态继续保持原始换行。
二者共用正文块、字阶、颜色和安全渲染规则，不给用户增加一排必须手动选择的模式开关。

| 内容 | 呈现重点 | 避免 |
|---|---|---|
| 长文章、博客、公众号 | 单一标题、紧凑元信息、克制的工具栏；约 32–38 个汉字的行长、舒适行距与段间距；图注和引用形成轻层级 | 每段套卡片、过多分割线、所有内容同一种字号 |
| README、教程、技术文档 | 有层级的目录、代码语言与复制、宽表格独立滚动、等宽字符图、图片完整展示 | 代码自动折行破坏图形、将表格拍扁成多段文字 |
| 短动态 | 原换行、引用与链接；弱化重复标题和元信息 | 套用长文的巨大标题与段间距 |

## 先有结构，再做排版

1. 有 Markdown 取 Markdown。普通网页提取正文时保留标题、段落、列表、引用、代码、表格、图片与图注的语义块，
   再安全地转成 Markdown 或统一正文块；不能只保存 `get_text()` 后的字符串。
2. 正文块是原文与译文共用的结构，翻译只替换可译文字。代码、链接目的地和图像位置不交给模型自由重排。
3. 历史纯文本缺少结构时保守显示，不凭粗体、短行或关键字强行猜标题。可明确重抓恢复，不能靠 CSS 补回已经丢失的语义。
4. 源文不覆盖：原文/译文仍可切换。若增加 AI 导读或整理版，单独标注并按需生成，不冒充忠实译文，也不影响引用定位。

## 与替代方案的取舍

- **仅调整 CSS**：最便宜、立即改善密度，但无法补回已丢失的标题、列表和表格，不适合作为唯一方案。
- **保留原网页样式**：忠实度高但会带入来源网站的杂乱样式，并增加隔离与净化成本，不作为默认阅读体验。
- **AI 重新组织全文**：扫读方便，但增加费用且可能改写原意；适合可选导读，不适合默认正文。
- **结构化精排（推荐）**：采集层保结构，阅读层统一呈现；改动稍多，但保真、清晰和跨来源一致性更均衡。

后续应先选普通长文、复杂 README 和图文教程各一篇验证结构提取与阅读效果，再逐步扩展来源。
