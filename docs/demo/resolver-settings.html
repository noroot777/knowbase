二、存在哪里

要你定夺

这一处定了之后不好改:它决定「环境变量」和「页面上填的」谁说话算数。

A · 存进设置,环境变量仍然优先

页面上填的存进 secrets.json 一类的地方,服务每次解析时读它; 但 KB_FEED_DOH 设了就压过页面 —— 容器和 CI 只有环境变量一条路, 那边不该被一份文件悄悄改掉。页面上会显示「这一项当前由环境变量接管」。

改动:加一个配置项 + 读取口径一份 + 页面提示一处

B · 只存设置,环境变量退成兜底

页面是唯一的正经入口,环境变量只在设置里没填时起作用。好处是「看得见的就是生效的」; 代价是容器里改配置要进页面点一次,compose.yaml 那套透传就只剩兜底意义。

改动:同上,外加 compose / README 的说法要跟着改

三、改完要不要重启

要你定夺

现在是「必须重启」(开关从进程环境读)。存进设置之后可以不重启 —— 但那会多一条热读的路。

C · 保存即生效

每次解析时读当前配置,改完下一条抓取就用新端点。顺带清一次解析缓存 (不清的话旧答案最多还粘 10 分钟)。

改动:解析那一层多读一次配置 + 保存时清缓存

D · 存下来,提示去重启

和现在的 code_stale 一个调子:保存成功后页面上说一句「重启后生效」。 路最短,但「填了没生效」这件事会再出现一次。

改动:只加提示

四、要不要连代理一起放进来

要你定夺

DoH 端点在墙外时要代理才连得上。现在代理只能来自起服务那个 shell。

E · 不放。只在这里显示探到了什么

代理归环境管(shell、compose、系统设置),页面只读地显示「服务那份环境里探到 http://127.0.0.1:7897」或者「探不到」。

改动:一个只读状态接口

F · 放。代理也做成可配置

页面上能填代理地址,存进设置、注入给抓取用的那个客户端。好处是开源交付后 不用懂 shell;代价是这台机器上的代理从此有两个来源。

改动:抓取那一层要接受外部代理配置,影响面比上面三项大
