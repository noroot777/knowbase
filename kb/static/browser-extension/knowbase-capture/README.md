# Knowbase · 采集此页

用于把浏览器里已经打开的那一篇文章收进本机 Knowbase，不是自动浏览器爬虫。

**只有一问：你站着的这一页，此刻能做什么。** 扩展把地址交给本机服务，服务回答它是哪一条、写不写得了，弹窗照着给按钮——**哪一种情形由服务端判，扩展一处都不自己判**。

## 安装与配对

1. 在本机 Knowbase 的订阅文章上或「问题与待办」里点「从浏览器采集」，左侧滑出采集抽屉。**这个浏览器**还没配过扩展时，「首次使用：装扩展并配对」就摊在它顶上；配好之后它自己收进底部的折叠块（扩展会在知识库页面上留一个标记，抽屉读那一个）。
2. 在 Chrome 的扩展管理页启用开发者模式，点击「加载已解压的扩展程序」，选择**本目录**——抽屉里直接给出它的绝对路径，不用下载解压。安装由用户自行操作。
3. 在抽屉里显示并复制本机配对密钥。在扩展中填写服务地址（默认 `http://127.0.0.1:8787`）与密钥，保存连接。只需配对一次。
4. 以后改了扩展代码，在扩展管理页点一次「重新加载」即可。**弹窗头部那个版本号就是用来确认这一下点过没有的**（`manifest.json` 每次改动都会升）。

## 用法

在那篇文章的标签上点扩展（或 `Command+Shift+Y` / `Ctrl+Shift+Y`）。按它给出的那句话走：

- **「知识库里有这一条，但正文还缺着」** → 点「采集」。**不必先去知识库发起什么** ——
  待办由服务端自己建好了。自动识别不准时改点「改用所选文字」，先在文章里选好全文。
- **「这一页还不在知识库里」** → 点「采集」。**只把地址交给服务端，它自己去抓**：那样能走完整的
  准入检查，还能取到标题、作者和日期。抓不到时（登录墙、人机验证、整页由脚本渲染）才露出「改用这一页的
  正文」和「改用所选文字」。**不按失败原因分流** —— 无论哪一种，你的下一步都一样，而你正看着这篇文章。
- **「还在等采集的条目」** → 站点常按浏览器语言跳转（`openai.com/index/x` 在中文浏览器里落到
  `/zh-Hans-CN/index/x`），于是这一页按地址查「不在库里」。那一块会把知识库里记的那些摆出来，**有几条
  就摆几条、各自一颗「这一页就是这一篇，改用它」**；你正看的是哪一篇就点那一行。**换不换由你决定**，
  核对那是同一篇文章再点。点下去那一下就是答案——它会跟着后面每一问走，不会被按时间顺序换成另一篇。
- **「有 N 个条目都在等这一页的正文，点一下你要补的那一篇」** → 同一页上不止一个条目在等，而你还没点过。
  这一档**一颗采集按钮都不给**：替你挑一个是在赌，赌错那一下是正文被另一篇覆盖、救不回来。
  在下面那张列表里点你要补的那一行，按钮就回来了。
- **「正文也齐了」** → 没有可做的事。要换掉现有正文得回采集抽屉点「重新采集正文」：那是另一件事
  （「我手上这份是错的」），它自带警示和回执。

**点下去就写进知识库了，没有预览、也没有「我已核对」那道勾。** 你就站在那一页上，比屏幕清楚自己要的是
哪一篇。撤掉的只是事前那一问：长度、网址、条目版本那几道准入全由本机服务原样判，读完会先问一次再写，
写完把标题和字数摆给你看。不对就到知识库里那一条上点「重新采集正文」。

抽屉里那颗「发起浏览器采集」**不是必经的第一步**，它留给一种情况：你要让某一条去认一个和它自己网址
不同的最终网址。

收进来的条目记着 `browser_grab` 这个来历，和服务端自己抓的那些分得出来。X 的单条推文不走这条路，直接「收录这条链接」即可。

## 权限与边界

- `activeTab`：只有用户主动调用扩展，才读取当前文章标签。不枚举、扫描、导航、刷新、滚动或关闭其他标签。
- `scripting`：在隔离世界读取文章 DOM 或用户选中文字；清洗在克隆节点上进行，不改原页面。
- `storage`：在扩展本地保存服务地址和配对密钥，不使用同步存储。
- 回环地址上的 `present.js`：**只做一件事** —— 在你配过的那个本机服务的页面上留一个 data 属性，告诉采集抽屉「这个浏览器配过扩展」，它据此决定首次引导摊开还是收起。不读页面内容，不碰别的 DOM；Chrome 的匹配式写不了端口，所以脚本自己比对 origin，和你配的服务地址不是同一个就什么都不标。
- 回环地址 host 权限：只连接本机 Knowbase。Chrome 的 host 匹配无法限定端口，代码进一步限制为用户配置的本机 origin，并拒绝重定向。
- 不申请 Cookie、历史记录、全站读取权限；不上传整页 HTML、Cookie、表单、密码或浏览器登录凭据。首次配对时只与本机服务交换待办信息。正文在写进知识库之前会先交给**本机**服务做准入判断（够不够一篇正文、这条收没收过），这一步不出本机。**点「采集」那一下就是决定**——没有第二道确认。
- 正文仅保存到用户绑定的原条目；网址须是同一页（按浏览器同一套规范化后比对，忽略片段），不信任网页自报的 canonical 地址。服务端版本比较防止覆盖已经变更或排除的条目。
- **这些判断都在本机服务里做**：扩展读取页面之前先问一次「这一页现在还写得了吗」，不通过就一个字都不读；读完之后、写进去之前再问一次。扩展自己不判网址、字符数和条目版本，所以不会让你读完整篇才被拒。
- 使用已有的正文非重复字符门槛（400，由本机服务判）；补回原条目最多 20 万字符，收录新链接最多 6 万字符。两条路都是**超限直接拒，不偷偷截断**，拒绝时会说清超了多少。写完那句话里的字符数就是落了库的那一份。**DOM 提取无法证明全文加载完毕**——登录后可见但还没加载出来的部分，采到的就是缺的那一份，所以收进来的正文记 `confirmed=false`（只有「手动补正文」那条路记 true：那一段是你自己粘的）。
- 只允许知识库明确支持的 RSS、网页专栏和手动收录文章；简报摘要的外链指向第三方文章，不能用来替换摘要。暂不支持 PDF、浏览器内部页面、X 观点、时间线、跨域 iframe 和独立公众号采集器文档；登录后可见但尚未加载的全文不会被绕过。
- 待采集请求 15 分钟过期，服务重启会清除未完成请求。已保存正文和审计回执按文章持久恢复，关掉抽屉、另开标签、过期或重启后仍可查看并继续后续处理；退出重新采集不会丢失原回执。原条目更新、删除或排除后旧回执失效，抽屉开着时定期核对。
- 最多同时等待 100 个采集请求；已保存、已取消或陈旧请求不占等待名额。
- ZIP 中的 `api.js` 与知识库页面共用错误解析；更新时请替换整个扩展文件夹并在扩展管理页重新加载，不要只复制 `popup.js`。直接加载仓库目录的话，点一次「重新加载」就行。
- 扩展未上传浏览器商店，需要用户手动安装；代码不会自动安装扩展或接管用户现有标签。
- 收录新链接时正文由你这一页提供，所以那两个端点（`/api/grab/from-page` 及其预检）要配对密钥，和补正文同一把。只交地址的那一个不需要——内容由服务端自己去抓。
