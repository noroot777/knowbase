# kb-grab:把链接收进知识库

knowbase 的「手动收录」是第六类来源 `inbox`:给一条链接 → 抓正文 → 入库 → 写成
vault 里那一篇 → 进全文索引。本 skill 是它的**非网页入口**,和面板上那颗
「存入知识库」按钮**打同一个接口、同一套判断**。

唯一的命令(下称 `$G`,它自己会找到仓库、必要时起服务):

```bash
bash ~/.claude/skills/kb-grab/scripts/grab.sh --json <链接>...
```

skill 若随仓库走,路径是 `<仓库>/.claude/skills/kb-grab/scripts/grab.sh`;
找不到检出时设 `KB_HOME`。

## 怎么做

### 1. 把链接拿出来

用户可能给的是:一条裸地址、一句话里夹着地址、一堆地址、一个文件、剪贴板。

```bash
bash $G --json "https://example.com/post"            # 一条或多条,空格隔开
pbpaste | bash $G --json -                           # 剪贴板那段文字里的链接
bash $G --json - < links.txt                         # 文件里的链接(一行一条也行)
```

`-` 表示从标准输入读:**它会从那段文字里挑出所有 http(s) 地址并去重**,所以把
整段话喂进去就行,不用先清洗。地址合不合法由后端判,别自己先过滤掉可疑的。

### 2. 读那一行 JSON,按 `status` 汇报

`--json` 下一条链接一行 JSON。**只许按 `status` 说话**:

| `status` | 事实 | 怎么跟用户说 / 下一步 |
|---|---|---|
| `saved` | 已写成 vault 里那一篇、进了全文索引 | 「已写入知识库,检索里搜得到了」+ 标题 |
| `duplicate` | 这条早就收过而且走完整条链了 | 「早就在知识库里了」,不必再做什么 |
| `pending` | **内容已存下,但还没写进知识库** | 照 `detail` 说(它自带「欠哪一步 + 去哪儿点一次」)。**不是失败,别重投** |
| `bad_content` | 收下的那一份看不出是正文(多半撞上了登录/验证墙) | 说清楚,并问用户要不要 `--refetch` 重抓 |
| `failed` | 没收下,一个字节都没写 | 原样转述 `detail`(它就是原因 + 下一步) |
| `absent` | (`--state`)这条还没收进来 | 如实说没有 |
| `unknown` | 投出去了,但结果没核到 | 说「结果不确定」,建议稍后 `--state` 查一次 |

**三条红线:**

1. **只有 `saved` 才能说「已写入知识库」。** `pending` 是「存下了、还搜不到」——
   把它说成已完成,用户去检索里找不到,而再投一次只会得到同一句话。
2. **`failed` / `bad_content` 时不要自己换个方式再抓一遍**(别用 WebFetch 取正文
   再塞进去):抓不到正文一律不入库是硬约束,空正文一旦落库就**永久改不回来**。
3. **不要 import `kb.feeds.grab` 自己抓,也不要直连数据库。** 判断只有服务端那
   一份;进程外写进去的内容还得靠管道才写得进知识库,而管道跑在 kb-web 进程内。

### 3. 用户说「刚存那篇不对」

```bash
bash $G --json --refetch "<同一条链接>"
```

它会重抓一次,**确认得了才替换**库里那一份。这是错存的唯一出路(普通重投会被按
URL 去重挡住,一个字节都不会动)。因为它会覆盖已收下的内容,**先跟用户确认一句**
再跑。`replaced: false` = 没换成(还是撞墙/还是确认不了/这期间已经有人动过它),
原样如实说,别反复重试。

### 4. 用户问「这篇我存过吗」

```bash
bash $G --json --state "https://example.com/post"
```

只读:不抓取、不起管道、不写一个字节。也用来回查上一次 `pending` 的那几条此刻
走到哪了。

## 几个要知道的边界

- **绿泡泡公众号文章**(`mp.weixin.qq.com`)多半会撞上对方的验证页 → `failed`。
  那条路由另一条通道负责(读本机绿泡泡客户端已经同步下来的库),不是这里的事,
  **不要绕**它。`detail` 里会写清去处,照着转述。
- **X 单条推文**走公开接口,不需要登录态,长文连正文一起取;X 的时间线/列表地址
  不是单条推文,收不了。
- 默认会**等它真写进知识库**(通常几秒,上限 120 秒,可 `--timeout` 改)。不想等
  就加 `--no-wait`,那时结果一律是 `pending`,稍后用 `--state` 查。
- 一次收一批时:后面几条会撞上前一条起的那一轮同步,命令行自己会在收尾时补一轮,
  不用你操心。但整批可能比单条慢。
- 收完想确认检索里真有,用 `kb_search` 工具搜标题(如果这个 MCP 工具可用)。
- 退出码:有 `failed` / `unknown` 才非 0;`pending`、`absent` 都是 0。
