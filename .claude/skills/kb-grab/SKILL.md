# kb-grab:把链接收进知识库

knowbase 的「手动收录」是第六类来源 `inbox`:给一条链接 → 抓正文 → 入库 → 写成
vault 里那一篇 → 进全文索引。本 skill 是它的**非网页入口**,和面板上那颗
「存入知识库」按钮**打同一个接口、同一套判断**。

唯一的命令(下称 `$G`,它自己会找到仓库、必要时起服务):

```bash
bash ~/.claude/skills/kb-grab/scripts/grab.sh --json <链接>...
```

skill 若随仓库走,路径是 `<仓库>/.claude/skills/kb-grab/scripts/grab.sh`;
找不到检出时设 `KB_HOME`。

## 怎么做

### 1. 把链接拿出来

用户可能给的是:一条裸地址、一句话里夹着地址、一堆地址、一个文件、剪贴板。

```bash
bash $G --json "https://example.com/post"            # 一条或多条,空格隔开
pbpaste | bash $G --json -                           # 剪贴板那段文字里的链接
bash $G --json - < links.txt                         # 文件里的链接(一行一条也行)
```

`-` 表示从标准输入读。连续的行**攒成一段一起看**(一个链接的目标可以写在下一行 ——
逐行各看一遍会把它切成两截,拼出来的是另一个地址),**空行断段**。
**整行就是一条地址**的那些原样收、一个字符都不动,但**只在它前面还没有正文行时**
(一行一条的清单正是这种);段一开始攒之后,后面的行一律由语法说了算 —— 不然
`[原文](` 换行之后那个目标本身往往也整行像一条地址,又被原样拿走、带着 Markdown 的
收尾 `)` 收错一篇。边界**给定**的那些照原样收:上面那一档,以及行内 `<地址>`、
`"地址"`、`'地址'` 这样圈出来的 —— 一个字符都不动。
Markdown `[文字](目标)` 也算边界给定,但它**按语法取目标**:显示文字整段跳过(哪怕
它本身就是一条地址、或者里面有 `` ` `` 包着的代码)、目标里的括号数深度、`\(` 这类转义
和 `&#40;` 这类字符实体都还原成它们表示的字符(**认不出的实体原样保留** ——
`&notanentity;` 不是实体,一个字符都不动)。**链接指向我们收不了的地方时**
(`[文字](#锚点)`、相对路径),那一段整段跳过、一条都不产出 —— 显示文字里写着的地址是
**文字**,把它收进来就是收了另一篇。嵌套那种(`[外 [内](A)](B)`)按 CommonMark 算:
成立的是**内层**那条(链接里不许再有链接),外层剩下的 `](B)` 整段跳过、**一条都不产出**
—— 那个 `)` 是 Markdown 的收尾不是地址的一部分,拼进去就是另一篇。
**图片不算链接**:`[看 ![图](img.png) 这个](文章)` 收的是**文章**那一条(插图不收);
单独一张 `![图](img.png)` 一条都不产出。**引用式**分两处看:`[文字][标签]` 和简写的
`[标签]` 自己说不出要收哪一篇,那一段整段跳过、一条都不产出;真正的地址写在**定义行**
`[标签]: 地址` 里,那一条照旧收 —— 所以一段带参考链接的文字收到的是定义里那个目标,
一条。定义行是块级的(一段里有过正文行之后 `[x]: y` 就只是文字了),写在引用**之后**、
或者写在 `>` 引用块里都算。
**夹在文字里的 HTML、注释、`` ` `` 包着的代码也都整段跳过**,里面的 `[文字](地址)` 不是
链接(但标签的属性值 `href="https://…"`、以及反引号里**整段就是一条地址**的那种照旧收 ——
那两档的边界是写的人自己画的)。属性值按 **HTML 自己**那一套解字符引用
(`&#47B` 这种缺分号的数字引用照样算),不是 Markdown 那一套。
**粘进来的文字里残片太多时**(没配对的括号、没收尾的引号)会报一句「认不全」并以 2 退出,
一个请求都不发 —— 那不是「这一行没有链接」,把要收的地址单独一行贴过来就好。
其余那些**裸写在行文里**的地址按空白断,**一个标点都不剥** ——
所以「见 https://x/a。后面还有话」这种紧贴中文标点的会连标点一起收,多半抓不到、
报 `failed`。**这是故意的**:剥掉那个标点之后的地址可能真的存在,那就会静默收进
**另一篇文章**。碰到这种就把地址放进 `<…>` 再来一次,或者一行一条。

地址合不合法由后端判,别自己先过滤掉可疑的、也别替用户改写地址。

`--api` 只认 `http://主机:端口` 或带路径前缀的形式(反代挂在 `/kb` 下面没问题),
**不能带查询串或锚点** —— 接口路径会拼在它后面,拼出来就不是要打的那一条了,
那种参数当场退 2。

### 2. 读那一行 JSON,按 `status` 汇报

`--json` 下**一条输入对一行 JSON**(失败路径上也成立,所以别自己拿输入去对数)。
**只许按 `status` 说话**:

| `status` | 事实 | 怎么跟用户说 / 下一步 |
|---|---|---|
| `saved` | 已写成 vault 里那一篇、进了全文索引 | 「已写入知识库,检索里搜得到了」+ 标题 |
| `duplicate` | 这条早就收过而且走完整条链了 | 「早就在知识库里了」,不必再做什么 |
| `pending` | **内容已存下,但还没写进知识库**(`--refetch` 没换成而那一篇还欠导出/索引时也是这一档) | 照 `detail` 说(它自带「欠哪一步 + 去哪儿点一次」)。**不是失败,别重投** |
| `bad_content` | 收下的那一份看不出是正文(多半撞上了登录/验证墙) | 说清楚,并问用户要不要 `--refetch` 重抓 |
| `unchanged` | (`--refetch`)**库里那一份没动、而且已经搜得到**:这次抓到的和它一样、这期间已经有人换过、或者又撞上关卡 | 照 `detail` 说。**不是质量问题**(库里那一份完好),也不要反复重试 |
| `gone` | **收下过,现在不在库里了**:后端确认收下(`added`/`replaced`/`duplicate` 有一个为真),之后这一行被清理或删掉了 | 说清是「收下之后又没了」,别说成没收下。要不要再投一次交给用户 —— 删掉它的可能正是他自己 |
| `failed` | 没收下,一个字节都没写 | 原样转述 `detail`(它就是原因 + 下一步) |
| `absent` | (`--state`)这条还没收进来 | 如实说没有 |
| `unknown` | **结果核不到**:投出去了但回包丢了、此刻库里还没有这一行(**可能还在抓**)、重抓换没换成不知道,或者 `--state` 这一问连不上服务 | 说「结果不确定」,照 `detail` 给下一步;**别说成成功,也别说成失败**。它说「别急着重投」时就别重投 —— 原来那次动作可能正在写 |
| `not_tried` | 前面那一条就打不通服务了,这条**压根没投** | 如实说没试过,服务恢复后再来一次 |

**三条红线:**

1. **只有 `saved` 才能说「已写入知识库」。** `pending` 是「存下了、还搜不到」——
   把它说成已完成,用户去检索里找不到,而再投一次只会得到同一句话。
2. **`failed` / `bad_content` 时不要自己换个方式再抓一遍**(别用 WebFetch 取正文
   再塞进去):抓不到正文一律不入库是硬约束。普通重投**按 URL 去重**,所以
   **已经是好正文的那一份不会被它动一个字节**;而**库里那一份被判成看不出是正文时,
   普通重投会自动替它重抓一次**(确认得了就换掉 —— 那正是最该换的那几篇)。
   绕过准入塞进去的东西因此只有两条出路:它自己这一档,或者下面那条显式重抓。
3. **不要 import `kb.feeds.grab` 自己抓,也不要直连数据库。** 判断只有服务端那
   一份;进程外写进去的内容还得靠管道才写得进知识库,而管道跑在 kb-web 进程内。

### 3. 用户说「刚存那篇不对」

```bash
bash $G --json --refetch "<同一条链接>"
```

它会**不管库里那一份的质量**都重抓一次,**确认得了才替换**。所以它管的是
「质量判据漏放的那几篇」—— 库里那一份看起来是正文(`content_ok=true`)、而其实不对,
普通重投会按 URL 去重挡住、一个字节都不动,只有这一档换得了。
(反过来:库里那一份**本来就被判成看不出是正文**时,普通重投自己会走受控恢复、
替它重抓一次,不必非得加 `--refetch`。)因为它会覆盖已收下的内容,**先跟用户确认一句**
再跑。`replaced: false` = 没换成(还是撞墙/还是确认不了/这期间已经有人动过它),
原样如实说,别反复重试。**但「没换成」只是那一次动作的回答,不是「这一篇好了」** ——
交付结论一律看 `status`:它报 `pending` 就说明那一篇还欠导出/索引(命令行自己会去求
一次补写),这时候别照着 `replaced: false` 说成「库里那一份没动,到此为止」。

### 4. 用户问「这篇我存过吗」

```bash
bash $G --json --state "https://example.com/post"
```

只读:不抓取、不起管道、不写一个字节。也用来回查上一次 `pending` 的那几条此刻
走到哪了。

## 几个要知道的边界

- **绿泡泡公众号文章**(`mp.weixin.qq.com`)多半会撞上对方的验证页 → `failed`。
  那条路由另一条通道负责(读本机绿泡泡客户端已经同步下来的库),不是这里的事,
  **不要绕**它。`detail` 里会写清去处,照着转述。
- **X 单条推文**走公开接口,不需要登录态,长文连正文一起取;X 的时间线/列表地址
  不是单条推文,收不了。
- 默认会**等它真写进知识库**(通常几秒;轮询预算 120 秒,可 `--timeout` 改 ——
  那是「还发不发下一个请求」的预算,不是整段等待的硬上限)。不想等
  就加 `--no-wait`:那时**起跑了的那几条**报 `pending`(稍后用 `--state` 查),而
  早就走完的仍报 `duplicate`、拒了的仍报 `failed`、内容不对的仍报 `bad_content`
  —— 照 `status` 说就行,不要一律说成「还在写入」。
- 一次收一批时:后面几条会撞上前一条起的那一轮同步,命令行会在收尾时让**服务端**
  按那一条自己的归属把后半条链补起来(一条最多补两次),不用你操心。但整批可能比
  单条慢。
- 收完想确认检索里真有,用 `kb_search` 工具搜标题(如果这个 MCP 工具可用)。
- `pending` 那一行有时会说「补这一步的接口跑着的那个 kb-web 还没有（它比代码旧）」:
  那是**代码更新了而服务没重启**,内容已经在库里、一个字节没坏 —— 照着转述
  (`./kb.sh restart` 之后再 `--state` 查一次),**别自己去重启服务**(那会打断正在
  跑的同步)。
- 退出码:判据是「这一条此刻在知识库里躺好了吗」。`failed` / `unknown` /
  `not_tried` / `gone` 非 0;`pending`、`absent`、`duplicate`、`saved`、
  `bad_content`、`unchanged` 都是 0。打不通服务时整批可能全是 `unknown` /
  `not_tried`。**2 是另一回事** —— 参数不对(`--api` 写错了也在内)、或者一条链接都
  没给出来,那时一个请求都没发,别按「收录失败」去重试。
